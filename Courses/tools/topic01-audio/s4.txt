[focus] 上一段我们把形状走了一遍，Q、K、V 都准备好了。这一段讲它们凑齐之后干了什么，也就是注意力真正干活的那几步。

[friendly] 先给一个直觉。你读一句话，读到第五个字，要理解它，得回头看看前面四个字，并且判断哪几个字更重要。

[casually] 打分做的就是这件事。区别只在于，模型有一百二十八个头，等于一百二十八套不同的判断标准同时在看。

[focus] 请看这张五步的流水线图。第一步，点积，决定谁该看谁。拿当前位置的 Q，去跟每个位置的 K 做点积。

[thinking] 方向接近，点积就大，意思是这个位置该多看一眼；不相干就小，甚至是负的。每个头各做一遍，所以产出是一百二十八张方阵，每张十三万一千零七十二乘十三万一千零七十二。这张方阵请先记住，后面它会炸。

[thinking] 第二步，除以根号一百九十二，这是防饱和。一百九十二个维度累加，点积会跟着维度一起变大，直接送进 softmax，几乎全部权重会压给一个位置，其余变成零，梯度也跟着没了。

[curiosity] 为什么是根号 d？假设每个分量独立、均值为零、方差为一，那点积是 d 项之和，方差正好是 d，标准差就是根号 d。除以它，标准差回到一。

[thinking] 原论文对这点的措辞是「我们怀疑」，这是个好用的直觉，不是定理。分母用一百九十二而不是一百二十八，是因为 Q 和 K 每个头就是一百二十八维内容加六十四维位置，点积在一百九十二维上做。

[seriously] 第三步，遮住未来：第五个位置不许看第六个。做法是把方阵上三角设成负无穷，softmax 之后就是零。

[thinking] 这一步不是为了省什么，是为了对。不遮的话，训练时模型就是在抄答案，曲线很漂亮，可推理时后面的字还不存在，立刻就垮。

[focus] 第四步，softmax。请看下面那张八乘八的小方阵和右边的柱子。softmax 按行归一化，做完每一行加起来正好是一。

[thinking] 这一行就是一个概率分布，翻成人话是：我这个位置的信息，百分之三十从第一个位置取，百分之四十七从第五个位置取。图上这些是示意值。

[realization] 注意力做的全部事情，就是给每个位置算一个概率分布，决定它从前面各个位置各取多少信息。也正因为 softmax 是逐行、逐头做的非线性运算，一百二十八个头到这里就再也合并不回一个矩阵乘了。

[focus] 第五步和第六步，加权求和，然后拼起来出去。拿这套权重对 V 加权求和，每个头吐出一个一百二十八维的向量。一百二十八个头拼成一万六千三百八十四维，过一次输出投影压回七千一百六十八，汇回残差流。

[seriously] 这块输出投影，是一层里最大的矩阵，也是一百二十八个头之间唯一交换信息的地方。在它之前，它们各算各的，谁也不看谁。

[thinking] 还要记住，打分这一段跟前后的投影根本不是一类计算。投影是又大又规整的矩阵乘，加速器最喜欢；打分是一百二十八个小矩阵乘批在一起，中间还夹着逐行的 softmax。而且它跟序列长度是平方关系，序列翻倍，它翻四倍。

[casually] 先把一层的权重账摆齐。请看这张五根横条的图，先看条长。一层 MLA 只有五块权重。

[friendly] 最上面那根，输出投影，一亿一千七百四十四万，占百分之六十二点八，一根顶下面四根加起来还多。它两头连着一万六千三百八十四和七千一百六十八，两头都宽，所以最大。

[casually] 它最大，和它是头之间唯一交换信息的地方，是同一件事的两面。中间三根依次是：Q 的升维，三千七百七十五万；K 和 V 的升维，一千六百七十八万；Q 的下投影，一千一百零一万。

[realization] 再看最底下那根几乎看不见的短条，K 和 V 的下投影，只有四百一十三万，百分之二点二，最大那根是它的二十八倍。可整张 KV cache 的账，恰恰只由这根最短的决定，因为存进 cache 的就是它写出的那五百七十六个数。权重最大的跟显存无关，权重最小的决定整张显存账。

[thinking] 五块合计一亿八千七百一十一万，乘六十一层，一百一十四亿。六千七百一十亿参数的模型，注意力只占约百分之一点七。

[seriously] 但参数少，不等于代价小。注意力有三笔账，彼此完全脱钩：权重只有一百一十四亿，很小；KV cache 跟序列长度成正比；算力跟序列长度成平方，在十二万八千的长度下，要吃掉整个前向的百分之八十一点八。而 MoE 正好相反，参数几千亿，算力却跟序列多长无关。

[thinking] 「参数占比」这把尺子，只量得了第一笔。下面三个数，就是来打掉这个直觉的。

[casually] 第一个数，五十七倍。同样十三万一千零七十二个 token，batch 等于一，bf16。MLA 的 KV cache 是 token 数乘六十一层乘五百七十六乘两个字节，八点五八个 GiB；换成标准注意力是四百八十八个 GiB，差五十六点九倍。

[friendly] 请看那条红色虚线，一个 TPU v7 device 的九十四点七四个 GiB。标准注意力要五张多卡才放得下，权重还一个字节没算；MLA 一张卡还剩九成。

[curiosity] 第二个数，更吓人，而且它从不出现在任何显存报表里，因为它从来没被存过。就是第一步那张分数矩阵：一百二十八个头，乘十三万一千零七十二，再乘十三万一千零七十二，每个数两个字节。

[seriously] 四点零零个 TiB，一层，一次。

[focus] 给两个对照。整个模型的全部权重是一点二二个 TiB，这张一层一次的中间矩阵，是它的三倍多。

[thinking] 再除以一张卡的九十四点七四个 GiB，是四十三点多，也就是要四十四张卡。请看右边那片红色小方块，每一格是一张卡。

[realization] 这不是算错。权重只跟模型有关，跟输入多长无关；这张矩阵跟序列长度成平方。序列一长，中间结果超过整个模型是必然的。

[seriously] 所以 FlashAttention 不是让它更快的优化，而是让它能做的前提：永远不把这张矩阵整个存出来，分块算，边算边累加，算完就扔。不这么做，不是慢一点，是根本跑不起来。

[curiosity] 第三个数，请看这条曲线和顶上那个滑块。注意力里有两处计算量是序列长度的平方，一是算分数，二是拿分数乘 V。其他所有部分，投影、MLP、MoE，都只是线性的。

[focus] 从四千开始往右推。四千的时候，平方项只占前向算力的百分之十二点三，没人觉得注意力是问题。

[excitement] 三万两千，百分之五十二点九，过半了。十二万八千，百分之八十一点八。一直推到一百万，百分之九十七点三。

[seriously] 请注意，模型一个字都没改。参数、层数、专家数全都一样，变的只是输入有多长，瓶颈就整个换了地方。这条线是按公式推算的，不是实测，但方向和量级是它说了算。

[thinking] 而且它是一个比值，batch 变大时分子分母一起变，约掉了，所以靠调 batch 绕不开。反过来，前两个数都是每个样本一份，跟 batch 成正比：batch 等于八，四个 TiB 就变成三十二个 TiB。

[contemplative] 在这个规模上，「模型有多少参数」已经不是算力的主要矛盾，序列有多长才是。如果注意力吃掉九成算力，下一步自然就是：别让每个 query 都去看全部 token。

[warmly] 第二步到这里就走完了。MLA 用五百七十六个数，把 KV cache 从四百八十八个 GiB 压到八点五八个 GiB，没让任何一个头做出牺牲；但真正决定长上下文能不能做的，是那张从没存过的四个 TiB 的矩阵，和那条涨到九成七的平方曲线。

[friendly] 注意力算完，结果汇回残差流，交给这一层的下半段。V3 的前三层，这里是一个普通的稠密 MLP，第四层起才换成 MoE。

[casually] 下一节第三步，我们先把稠密 MLP 讲清楚。它看着最简单，却是整个 MoE 的对照组：MoE 省下的每一分算力，都是拿它身上的好性质换来的。

[friendly] 这一节就到这里，大家有问题吗？
