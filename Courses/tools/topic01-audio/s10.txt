[warmly] 上一节，一个 token 从出口变回了概率分布。这一节不讲新东西，只做三件事：把账合起来，验一验这些账能不能信，再看它把我们引向哪里。

[friendly] 请看这张总表，这一路攒下来的全部都在上面。我不逐行念，先看最底下那一行合计：总参数六千七百一十亿三千万，激活参数三百六十六亿两千万。

[seriously] 第零节说过，这张表的每一个数都来自官方配置文件，没有一个是估的。官方口径是多少？总参数六千七百一十亿，激活三百七十亿。我们推出来的六千七百一十亿，对上了；三百六十六亿，四舍五入就是三百七十亿，也对上了。

[contemplative] 这两个数是把前面每一步的公式全加起来才得到的。MLA 的投影、每层两百五十七个专家、嵌入和出口那两份九亿多，任何一处算错、漏掉或者多数一份，合计都对不上。它对上了，就等于替前面所有推导做了一次验算。第零节那句话，到这里兑现了。

[friendly] 账对上了，现在用它回答三个问题。

[focus] 第一，一次十二万八千 token 的前向，要多少算力？五十二点五个 PFLOP。其中百分之八十一点八，是注意力里那个跟序列长度平方成正比的项。

[thinking] 可 MLA 的参数只有一百一十四亿，占总参数的百分之一点七。矛盾吗？不矛盾。参数量决定要存多少，跟输入多长无关；注意力的算力随序列长度平方涨。参数量是静态的，算力是随输入变的，拿一本账推另一本，一定出错。

[focus] 第二，常驻显存多少？权重一点二二个 TiB，加 KV cache 八点五八个 GiB，一共一点二三个 TiB。

[focus] 第三，要多少个 device？一点二三个 TiB，除以一个 TPU v7 device 的九十四点七四个 GiB。

[realization] 十三点三。不能有零点三个，所以是十四个。

[contemplative] 这个数本身不重要，重要的是它是除出来的。从开场到现在，我一次都没说过「大模型需要并行」这句话。我们只是一步一步算，它自己出现了。「为什么需要并行」，从今天起是一个除法的结果，不是一句口号。

[seriously] 但请千万别把十四记成答案。它是最乐观的可能值，建立在五个假设上：只算前向，batch 等于一，不含激活，不含临时缓冲，还假设权重能完美打包。每一个在真实训练里都不成立。

[focus] 请看这张三条横杠的图。第二条，把峰值激活四十一点八九个 GiB 加进去，十三点三变成十三点七，几乎看不出区别。

[thinking] 这四十一点八九怎么来的？先分清两个词。KV cache 是要留下来的，下一个字还要用，寿命是整段对话，所以跟层数相乘。激活是算完就扔的，第三层的中间结果进了第四层就没用了，所以不跟层数相乘，只看最胖的那一层，取三个候选峰值里最大的。MLA 那一层是三十二点零八个 GiB，MoE 那一层是二十六点零八个 GiB，最大的在出口：KV cache 八点五八，加 logits 三十一点五六，再加一份残差流一点七五，四十一点八九。最吓人的一项又是出口，那个 logits 比整段 KV cache 还大三倍多。

[friendly] 表里残差流要算两份，是因为一层开头先把进来的 x 原样存一份，再对它做 norm 得到另一块内存，子层算完还要加回最开始那份上。要加回去，那份就扔不得，于是两份同时活着。出口没有加回去这一步，所以只算一份。

[seriously] 但换成训练，就不是一个量级了。看第三条：每个参数十六个字节，bf16 权重两个、梯度两个、fp32 主权重四个、两个动量各四个。模型本身只占最左边两个字节，右边十二个字节全是优化器的。六千七百一十亿乘十六，九点七六个 TiB，除以九十四点七四个 GiB，大约一百零五个 device，多了将近八倍。

[thinking] 这张图要说的是形状：前两条几乎一样长，第三条长了八倍。因为它们问的不是同一个问题：权重放得下吗，跑一次前向放得下吗，能不能训。下次有人问「这个模型要几张卡」，先反问一句：哪个口径？

[thinking] 那实际是不是就用十四个？几乎不会。一是互连拓扑有形状要求，不是任意数量都能组成一个合法的切片；二是更重要的，十四本来就是不该当真的下限，真实规划要从训练那一百零五个起步。

[focus] 顺带把单位钉死：这里说的「个」都是 device，不是芯片。TPU v7 一颗芯片里有两个 device，所以一百零五个 device 是五十三颗芯片。

[friendly] 再换个感觉：这些算力是多长时间？单个 device 的 bf16 峰值大约每秒一千一百五十三个 TFLOP，是官方每颗芯片两千三百零七除以二得来的。理论极限，一个 device 要四十五点五秒；按百分之三十五的利用率，一百三十秒，两分多钟，就为了把一段输入过一遍，还只是前向。

[focus] 摊到十四个 device 上，九点三秒。但后面跟着一句话：假设并行完美无损。

[contemplative] 这句话，就是这门课剩下的全部内容。十四张卡绝不等于快十四倍：要互相传数据，要等最慢的那一个，还要为省显存重算一部分。那九点三秒实际能跑到多少？我们没测过，所以不给数。这句话的价值，就是把一个未知量明确地标了出来。

[focus] 可前面这些全是推导，能信吗？能验证，而且不用占一张卡。编译器本身就是静态分析器，把模型和并行配置喂给它提前编译一次，这条路叫 AOT，它不申请任何加速卡就能报出显存需求。排队等卡之前就知道答案，这是最省钱的一步。

[seriously] 但它该信到什么程度？下面三条是我们自己踩出来的，不是书上的定理。

[thinking] 第一，编译过了，不等于装得下。更麻烦的是，真正的编译失败常常被报成「装不下」，人就去调小 batch，方向完全错了。错误的错误信息，比没有信息更危险。

[thinking] 第二，报出来的只是临时缓冲，参数和优化器状态是另一笔账。而且它不随并行度缩小，切得再宽也纹丝不动。

[focus] 第三，贴着上限的那一带，它会失灵。请看这张三色横条：远离上限判得准，明显超了也判得准，中间紧贴上限那条红带判不准。我们判错过，错的全落在这一带。

[realization] 大家想想，真正值得一试的配置落在哪？几乎全挤在红带里，谁会去试明显装不下或明显浪费的配置？所以它最不准的地方，恰好就是你最需要它的地方。这不是工具的 bug，是它的性质。

[suggestion] 正确的用法是：拿它砍掉大头，剩下两三个老老实实上机器跑。当筛子，不当法官。

[contemplative] 还有一个反直觉的：同一个模型、同样的并行配置，只换一个算子实现，显存需求就会变，方向还不固定。显存不是模型的属性，是模型、实现、编译器三者的属性。

[warmly] 这一课讲完了。数字会忘，有几条结论希望大家带走。

[focus] 第一，MoE 省的是算力，不省显存。激活只有三百七十亿，显存要装的还是六千七百一十亿。第二，序列一长，瓶颈就从参数换成了序列：四千时注意力占百分之十二的算力，十二万八千时占百分之八十二。第三，最吓人的往往不是权重，是临时张量，算显存只算权重，一定会算错。第四，结构里有些数字是硬件逼出来的，比如先选四个组再选专家，就是为了别让通信跨太多机器。第五，显存是模型、实现、编译器共同的属性，静态分析帮你排除，不替你决定。

[contemplative] 最后留一个问题。今天我们从头到尾拿一个数当分母：九十四点七四个 GiB。算 KV cache 撞墙用它，算激活用它，算十四个 device 也用它。

[curiosity] 但我一次都没解释过它从哪来。为什么是九十四点七四，不是九十六，也不是一百二十八？为什么一颗芯片里会有两个 device？为什么有的卡叫 GPU、有的叫 TPU，它们看同一个模型的眼光有什么不同？

[warmly] 第一课，我们算出了模型要什么。下一课，我们去看机器能给什么。今天的任务，只是把「装不下」这个事实算出来，而不是说出来。

[friendly] 这一节就到这里，大家有问题吗？
