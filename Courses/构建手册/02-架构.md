# 02 · 架构：从一行 Python 到一页上线的课

> 这一篇讲整套东西怎么拼起来：有哪些文件、谁产出谁、按什么顺序跑、为什么这么排。

## 一、全貌

```
作者写的源（全是 Python）                       产物（WebPages/，GitHub Pages 从这里发布）
─────────────────────────                        ─────────────────────────────────────
tools/topic0N-fig-*.py  ──Fig.save()──▶ tools/fig*.svg ＋ fig*.src.html（出处片段）
        │  数字在脚本里现算 ＋ assert                         │
        │                                                     ▼
tools/manim/topic0N-anim-*.py ──render.sh──▶ WebPages/media/*.mp4（无声循环）
                                                              │
tools/topic0N-build.py  ── BODY 里直接写正文 HTML ──┐          │
   make_head → place_figs(内联 SVG ＋ 图注 ＋ 出处折叠) → add_figonly_toggle
   → finish(结构断言 → 锚点 → 吸顶目录 → arXiv 链接 → 写盘 → AI 味预算 → 查重 → SVG 标签)
                                                    ▼
                                         WebPages/topic-0N.html        （课件）
                                                    │  讲义脚本读成品课件对账
tools/topic0N-build-lecture.py ─────────────────────▼
                                         WebPages/topic-0N-lecture.html（讲义）
                                                    │
                             build-all.sh 最后跑一整套体检（版面、投屏、对账、指针、元信息、循环接缝）
```

三句话概括：

1. **图和页面分开生成**。每组图一个脚本，产出独立的 SVG；页面脚本只负责把 SVG 内联进来、配图注。
2. **页面是 HTML 直接写在 Python 字符串里**，没有中间格式。HTML 是唯一真源（见 [01 · 三](01-理念.md#三html-是唯一真源)）。
3. **讲义排在课件后面构建**，因为它要读成品课件来对账：讲义里指的图、报的数、说的小节，课件里必须真的有。

## 三、构建顺序和为什么这么排

`bash tools/build-all.sh` 按专题交错跑（开着 `set -e`，任何一步非 0 退出就中止）：

1. **GPU／TPU 显微镜页**，然后是**专题二 L300** —— 它是全课 CSS 的来源，其他页面的 `<head>` 从它切出来，所以要排在所有别的课件前面。
2. **每个专题依次**：先跑这一讲的图脚本，再生成课件，再生成讲义（讲义要读成品课件，所以永远排在自己那讲的课件后面）。
   图脚本怎么跑，各专题现状不一样：
   - 专题三：先 `rm -f` 旧 SVG，再用 glob 跑全部图脚本（最稳：删掉的图不会残留）
   - 专题四、五：用 glob 跑，不删旧图
   - 专题二外传：**手写的脚本清单**（还没改成 glob）
   新专题照专题三的写法。用 glob 而不是手写清单，理由写在脚本里：
   > 「一份要手工维护的清单」＋「漏了不报错」＝ 一定会漂 …… 是让清单消失。
3. **配色收尾**（`topic-repalette.py`）：直接改 `WebPages/` 产物（主色文字降深色、大面板去底色），
   所以必须在所有生成器之后、所有体检之前。
4. **体检套件**：版面、渲染后几何、投屏字号、讲义↔课件对账、跨节指针、讲义覆盖（目前只查专题二）、节号对账、
   退役说法、英文副标题、「丢给 AI」那一格、head 元信息、内联 SVG 标签、动画接缝。
5. 打印产物清单（每页大小、图数）。

两条顺序上的硬约束：

- **图必须先于页面生成。** 页面脚本找不到 SVG 会直接断言失败 —— 这是故意做成硬失败的，
  否则页面会悄悄内联一张旧图。
- **改了图脚本，要重跑图脚本再重跑页面。** 只跑页面，内联进去的还是旧 SVG。

## 四、页面脚手架提供了什么

`topic03_page.py` 让每一讲不用重复造这些轮子：

| 能力 | 说明 |
|---|---|
| `make_head` | 从 L300 切出 `<head>`，替换标题、og 信息，并**断言替换真的发生了**（见 [08 踩坑库 · str.replace 静默失败](08-踩坑库.md)） |
| `place_figs` | 把 SVG 内联进页面；图注按第一个 `<br>` 切开，后半段折叠；`.src.html` 包成默认收起的「出处与口径」；找不到图或占位符就断言失败 |
| `anchorize` | 给小节标题加 id；把正文里的 `§X.Y` 变成页内链接 —— 但跳过引文：arXiv 号、「论文／技术报告／报告／README／原文」、以及「专题五」这类跨讲引用后面、同一句里的节号，属于别的文档。想在引文里指回本讲，写「本讲 §X.Y」 |
| `build_nav` | 阅读进度条、吸顶目录（从 section 自动生成）、回到顶部、打印前自动展开出处 |
| 只看图开关 | 按 T 切换，收起正文只留图、导语和落点句；状态存 localStorage。投屏时用 |
| `.foldfig` | 整张图可折叠（用于次要的图或术语框） |
| 查重 | 图内文字、图注、正文三方两两比对，连续 14 字重合就报 |
| `finish` | 按顺序做：section／列表条数断言 → 锚点 → 目录 → arXiv 链接 → 写盘 → AI 味预算（只有专题四会因此中止，其余只打印）→ 图文查重（只报告）→ 内联 SVG 标签（中止）→ 自指链接检查。不是「全部体检」，其余在 `build-all.sh` 后半段 |

## 五、改一处东西，该动哪里

| 我要…… | 改这里 | 然后跑 |
|---|---|---|
| 改一句正文 | `topic0N-build.py` 的 `BODY` | `python3 topic0N-build.py` |
| 改一张图 | 对应的 `topic0N-fig-*.py` | 该图脚本 → `topic0N-build.py` |
| 改一个图注 | `topic0N-build.py` 的 `FIGS` 表 | `python3 topic0N-build.py` |
| 改动画 | `manim/topic0N-anim-*.py` | `render.sh` → 看拼接图 → 登记基线 → 页面脚本（见 [10 Manim 动画](10-Manim动画.md)） |
| 改讲义 | `topic0N-build-lecture.py` | `python3 topic0N-build-lecture.py`（必须在课件之后） |
| 改所有图的某种样式 | `topic03_draw.py`（基元） | `bash build-all.sh`，并对比改动前后的布局告警 |
| 新增一讲 | 见 [09 开工清单](09-新专题开工清单.md) | 要手动登记的只剩四处：`build-all.sh` 加步骤、`topic02-lint-cues.py` 的 `PAIRS`、`course_ai_trainer.py` 的 `DECKS`、`WebPages/index.html`。版面、可读性、跨节指针三个体检和产物清单 2026-09-25 起从目录现取页面，不用登记 |

提交前最少跑一次 `bash build-all.sh`，看退出码和末尾的体检输出。
哪些 ⛔ 会中止构建、哪些只是报告，见 [07 · 一](07-检查器与断言.md#一体检套件build-allsh-后半段)。

## 六、正文怎么写：HTML 词汇表

课件正文就是 `BODY` 字符串里的 HTML。下面这些写法是脚手架和各种检查器认的，照着用：

| 写法 | 用途 | 注意 |
|---|---|---|
| `sec("s三", "三", "第二刀：切权重")` | 开一节（生成 `<section>`、节号徽章、`<h2>`） | 节容器必须用它生成，吸顶目录按固定格式抓；`SECTIONS` 表同步登记 |
| `<h3>3.1　标题</h3>` | 小节标题 | 数字后面是**一个全角空格**；锚点、跨节指针、讲义对账都靠这个格式认小节号 |
| `<p class="lead">` | 一节开头那一段导语（只看图模式下保留） | —— |
| `<div class="note ok">` ＋ `<span class="t">标题</span>` | 提示框：`ok` 绿、`warn` 黄、`danger` 红 | 例：「一次实测」放 `note ok` |
| `<span class="sub">` | 灰色小字补充 | 专题五用了 18 处 |
| `<details class="foldfig"><summary>…</summary>…</details>` | 折叠块（术语框、次要的图） | summary 写清里面是什么，不许写「详情」「更多」 |
| `__FIG_TP_MLP__` | 图的占位符，由 `place_figs` 换成内联 SVG ＋ 图注 | 大写字母加下划线，**不要带数字**（`figpos` 的正则只认 `__FIG_[A-Z_]+__`） |
| `<div class="animgrid">` ＋ `<figure class="animcell" id="anim-…">` | 动画网格 | 见 [10 · 七](10-Manim动画.md#七嵌进课件) |
| 「本讲 §3.1」「§3.1」 | 指本讲小节，自动变链接 | 论文自己的节号写 `sec. 2.1`，不要用 `§`（重编号时会被误改） |

**`FIGS` 表的格式**：键是占位符，值是四元组 `(图 id, SVG 文件名, 图脚本名, 图注)`：

```python
FIGS = {
    "__FIG_TP_MLP__": ("fig-tp-mlp", "fig5-tp-mlp.svg", "topic05-fig-tp.py",
        '<b>列切接行切，中间结果不出卡。</b><br>'            # 第一句：看哪里（常显）
        '<em>这是 Megatron-LM 的切法。</em>'),               # <br> 后面：补充（自动折叠）
}
```

- **图 id 是承重的**：讲义的屏幕提示引用它，`topic02-lint-cues.py` 对账它，截图目检按 `figure[id^="fig-"]` 抓它。
- SVG 文件名约定 `fig<专题号>-<名>.svg`。所有专题的 SVG 都落在 `tools/` 这一个平铺目录里，不带专题号会撞名。
- SVG 和 `.src.html` 是构建产物，被 `.gitignore` 忽略（它们已经内联进 `WebPages/*.html`），**不用提交**；提交的是图脚本和生成的 HTML。
- 页面产物 `WebPages/*.html` 和动画 `WebPages/media/*.mp4` 是要提交的（GitHub Pages 从这里发布）。
