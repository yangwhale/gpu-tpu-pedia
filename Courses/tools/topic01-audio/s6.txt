[focus] 上一节我们把 dense MLP 立成了对照组，还摆出了四条好性质。这一节进入第四步，MoE。整个模型百分之九十七点八的参数，都在这五十八层里。

[friendly] MoE 只有一个核心思想，剩下的全是它的推论。

[thinking] 回想刚才那三层 dense。每个 token 都要把整层权重完整过一遍。参数越多，每个字就越贵。模型有多大，和每个字要算多少，是死死绑在一起的。MoE 要做的，就是把这个绑定拆开。

[casually] 做法是把一个宽的 MLP，拆成很多个窄的。V3 每一层有两百五十六个路由专家，外加一个共享专家。每个专家还是上一节那套三矩阵 SwiGLU，只是中间宽度从一万八千四百三十二，缩到了两千零四十八。

[focus] 每个 token 进来，一个门控网络像分诊台一样给它打分，只挑八个路由专家。再加上所有 token 都要过的共享专家，一共九个。剩下两百四十八个，这个 token 碰都不碰。共享专家装的是语法、常识这类人人都要的东西，省得两百五十六个专家每个都重学一遍。

[curiosity] 现在算笔账。一层两百五十七个专家，每个是三乘七千一百六十八乘两千零四十八，大约四千四百万参数，整层大约一百一十三亿。

[thinking] 但每个 token 只激活其中九个。折算下来，是三亿九千六百三十六万一千七百二十八个参数。

[contemplative] 这个数，我上一节讲 dense 的时候，说过一模一样的。

[realization] 不是接近，是完全相等。因为九乘以两千零四十八，正好等于一万八千四百三十二。请看这张图，九段拼起来，跟上面那根 dense 的条一样长。三个矩阵的形状全由中间宽度决定，宽度相等，参数就相等，计算量也相等。

[seriously] 所以这句话可以说得很硬：MoE 那一层，每个 token 在专家上做的计算，跟一层普通 dense MLP 严格相等。但那一层里躺着的参数，是 dense 的二十八点六倍。

[thinking] 严格说还多一点点。MoE 得先跑一遍门控矩阵，七千一百六十八乘二百五十六，大约一百八十四万参数，相对三亿九千六百万是千分之五左右。专家那部分一个都不多，外加千分之五的分诊费。

[contemplative] 这几个数全部来自公开配置，谁都能验算。但作者是不是特意设计成相等，公开资料里没说，我们只说这两个数相等。

[suggestion] 这个相等给了我们一把尺子：凡是 MoE 比 dense 多付出的，都不在 FLOPs 上。路由、通信、负载不均、显存，后面每一条麻烦，都能对回这句话。

[realization] 这就是参数量和计算量解耦的字面意思。模型可以一直变大，而每个字的账单不动。

[focus] 放到整个模型上。五十八层 MoE 的权重，占了六千七百一十亿的九成八。而每个 token 每层只用到九除以二百五十七，也就是百分之三点五。六千七百一十亿的模型，每个字只算三百六十六亿，主要就是这么来的。

[seriously] 马上澄清一个最常见的误解：那两百四十八个没被激活的专家，不占算力，但全额占显存。下一个 token 随时可能用到它们，权重必须全程躺在显存里。所以 MoE 省的是算力，不省显存。

[seriously] 还要当场纠正一件事。专家，不是那种专家。

[thinking] 听到 expert，多数人会想到按领域分工，这个管代码，那个管中文。不是的。它们就是训练出来的两百五十六个窄网络，编号没有任何人类能读懂的含义。

[focus] 这件事有人量过。请看这张红绿两半的图，来自 Mixtral 的论文。左边，他们把数学、生物医学、哲学的文本分别喂进去，看 token 被送给哪些专家。三条分布几乎重合，论文说，没有观察到专家分配跟主题有明显规律。

[curiosity] 那它跟着什么走？右边换了个问法：相邻两个 token，会不会被送到同一个专家？Mixtral 是八个选两个，随机的话是百分之十二点五。第零层量出来百分之十四点一，基本随机；中间层是百分之二十六点四，是随机的两倍还多。

[realization] 所以它跟的是局部的语法结构，不是学科。比如 Python 里的 self，总是走同一个专家。这马上就是系统问题：局部性高，做专家并行时更容易把某几个专家挤爆；反过来，也可以拿来做缓存。

[contemplative] Mixtral 的规模跟 V3 差了一个量级，具体数字不能照搬，能套过来的是那个否定结论：按学科分工这个直觉，实测里没有出现。

[focus] 为什么非纠正不可？因为如果专家是按领域分的，接下来的负载不均、分组限制都会显得莫名其妙。难就难在，根本没有领域这回事。

[curiosity] 好，接下来讲路由：分诊台怎么选出那八个。先给个数，可能跟大家想的不一样。

[realization] 门控网络就是一个七千一百六十八乘二百五十六的矩阵，大约一百八十四万参数，在一百一十三亿的那一层里只占万分之一点六。整个 MoE 最麻烦的东西，是这一层里最小的东西。

[focus] 请看这张路由的数据流图。token 乘上这个矩阵，给两百五十六个专家各打一个分。打分用的是 sigmoid，不是 softmax。

[thinking] softmax 让所有分数加起来等于一，一个专家分高了，别的就被压低，是零和的。sigmoid 是每个专家独立打分，谁也不影响谁。最后选中的八个还会归一化，但那是选完以后的事，竞争只发生在排序取前八那一步。

[focus] 真正的难点，是负载均衡。门控是学出来的，某几个专家早期表现好一点，就会被挑得更多，训练得更好，再被挑得更多。赢家通吃。

[curiosity] 这件事有多贵？请看这张四根条的图。专家摊在不同卡上，四张卡分到的 token 分别是百分之四十、二十、二十五、十五。这几个数是示意，真实情况取决于数据。

[thinking] 这一层要等最慢那张卡算完才结束。四张卡都陪着等到四十，一共一百六十份时间，真正干活的只有一百份，空转百分之三十七点五。掰匀成每张二十五，整层快一点六倍，就是四十除以二十五。

[realization] 而且它每层都重来一次，五十八层每层都要等齐。这不是损失几个百分点，而是一个木桶问题：整个集群按最慢那张卡的速度走。

[casually] 老办法是在损失函数里加一项惩罚，分得不匀就罚。问题是模型要同时优化答得对和分得匀，两个目标互相拉扯，两头都打折。

[focus] V3 的做法，是给每个专家挂一个偏置。谁最近吃太饱，就把偏置调低一点；谁一直没人选，就调高一点。这个偏置不是梯度学出来的，是每一步结束按实际负载直接调，完全不进损失函数。

[focus] 这一节的一个重点：偏置只管挑人，不管算账。请看图上的两条路。

[thinking] 蓝色这条带着偏置。原始分数加上偏置，拿去分组、选人，最后吐出八个编号，然后就被剪断了。绿色这条是原始分数，一路没碰过偏置。按那八个编号取回原始分数，归一化，这才是最后加权用的权重。

[realization] 所以偏置能把负载掰匀，却一点都没有改变模型的输出。调度归调度，不污染输出。偏置可以放心大力地掰，不抢梯度，想改策略也不用动模型。

[seriously] 但要补一个诚实。这套方法叫 auxiliary-loss-free，无辅助损失，名字比实情干净。论文原文写着，为了防止单条序列内部出现极端失衡，还另外用了一个系数极小的序列级均衡损失。

[thinking] 所以是两套机制，管两个尺度。偏置每步调一次，管某几个专家长期吃太饱；那个极小的损失管一步之内，某条序列碰巧全挤在少数专家上，偏置够不着。左边是策略，右边是保险丝。free 说的是主力不靠它，不是它不存在。

[focus] 最后一块，分组限制，这是这一节最重要的落点。两百五十六个专家分成八组，每组三十二个，一个 token 最多只能碰四组。每组拿组内前两名的分数相加当组分，挑出前四组，再在这一百二十八个候选里取前八。

[curiosity] 我问大家：这么限，是为了让模型学得更好吗？先想一想。

[seriously] 一点关系都没有。因为组，就是机器。

[thinking] 一个 token 挑中的八个专家，如果散在八台机器上，激活值就得发到八个地方，算完再收回来，这就是 all-to-all 通信。限制到四组，就是直接按住一个 token 最多打扰几台机器。论文写的理由一个字都不含糊：为了限制通信开销。

[casually] 那个前两名的二也是算出来的：总共选八个专家，最多去四个节点，八除以四，平均每个节点贡献两个。

[realization] 换句话说：一个通信约束，被直接写进了模型结构里。这两个数，分八组、挑四组，就明明白白写在 V3 的配置里，是模型定义的一部分。它当然有代价，最合适的专家散在五个组里时就选不全，这部分表达能力换来了通信可控。

[excitement] 论文还说，在通信代价不变的前提下，选的专家数其实能加到十三个，最后只填了八个。顺序是反的：不是模型要八个、系统去满足，是系统先划了线，模型在线里挑了个数。

[contemplative] 所以这一节的落点是：路由里几乎每一个设计，sigmoid、偏置、分组限制，都不是为了让模型更聪明，是为了让它能跑。

[warmly] 好，八个专家选出来了，而且尽量集中在四台机器上。可 token 还在原地，专家在别的卡上。接下来要看的是：选完之后，这些 token 怎么送到专家那儿去。

[friendly] 这一节就到这里，大家有问题吗？
