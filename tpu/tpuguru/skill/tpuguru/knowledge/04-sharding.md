# 分片：切哪个轴，决定一切

## 两种切法，常驻显存一样，但性质完全不同

以 MoE 权重 `(专家=192, embed=4096, mlp=1536)` 为例，FSDP 宽度 64：

| | 切 **embed 维** | 切 **专家维** |
|---|---|---|
| pspec | `P(None,'fsdp',None)` | `P('fsdp',None,None)` |
| 本地形状 | `[192, 64, 1536]` | `[3, 4096, 1536]` |
| 本地常驻 | **0.038 GB** | **0.038 GB**（一样） |
| 每卡拿到的 | 192 个**残缺**专家 | 3 个**完整**专家 |
| 需要 all-gather 吗 | **必须**（否则算不动） | 逻辑上必须，但 kernel 不会拒绝 |
| 出错时 | 编译器兜底 | **静默算错** |

**两种都是标准 FSDP：切开存、每层收齐、算完扔。常驻显存都是 1/N，不是「一个切一个不切」。**

## 跨卡量化收集（先量化再收集）

**唯一价值**：收的是量化后的权重，**字节减半**。

**约束链**（三处代码都卡在同一个判断上）：

```
要收集 → 各卡 scale 必须一致 → 只能用静态 scale → 必须 fixed 校准
                                                  ↓
                                          而 fixed 会伤收敛
```

**根因其实是 channel 轴选错了地方**：权重量化的 channel 轴选的是 mlp 维，
算动态最大值时**把专家维一起归约**了 —— 每卡只有 3 个专家，算出的 scale 各不相同。

> 若 channel 轴含**专家维**，每个专家一套独立 scale、完全由本地数据算出，
> **跨卡收集 + 动态 scale 就成立**。代码注释承认了这点，
> 未做的理由是「反向不能复用 scale」—— **工程权衡，不是正确性约束**。

**还有一个隐性代价**：它要求 `专家数 % FSDP == 0`，
192 个专家把 FSDP 锁死在 64，**另一半并行度只能给数据并行，而数据并行不分片权重**。
放弃跨卡量化收集换来 FSDP=128：每卡常驻权重 18.1 GB → 9.1 GB，
省出的显存把 batch 从 7 推到 13 —— **677.0 → 727.0**
（🔴 数字，64 芯片 v7 / 295B MoE / 2026-08-16 实测，换环境须重测）。

## 专家并行（EP）

实测大幅负收益：**64 芯片 EP=2 掉 39.6%，16 芯片 EP=4 掉 71%**。
除了 all-to-all 在 3D torus 上多跳，更致命的是**它逼着 FSDP 减半**，
每卡静态分片翻倍，batch 被压小。**不要用。**
