# 07 · 检查器与断言

> 这门课几乎每一条规矩最后都变成了一条检查：要么是构建时的 `assert`（不过就中止），
> 要么是 `build-all.sh` 里的一个体检（报告为主）。这一篇是它们的清单：查什么、为什么有、失败时会不会中止构建。
>
> 先记住一件事：`build-all.sh` 开着 `set -e`，**只有非 0 退出码才会中止构建**。
> 打印出一行 ⛔ 不等于报告了失败 —— 这一条本身就是踩出来的（见文末）。

## 二、构建期断言（写在各 build／fig 脚本里）

| 类别 | 例子 |
|---|---|
| **数字钉值** | 专题五 `assert abs(RIDGE - 3845) < 1`；专题四要求 128K 下复现 22.58／32.81／55.39／3.253 四个锚点 —— 改锚点必须写理由 |
| **钉关系，不钉值** | `_CROSS * 1.25 == W_WIDEST_V3`；并且断言旧值 5,734 不再出现 |
| **跨节一致** | §4.1 的表和 §5.1 的句子必须对得上 |
| **时长对账** | 分项之和 ＝ 合计；节标题分钟 ＝ 计划表；「可压到 N」≥ 地板 |
| **讲义 ↔ 课件** | 讲稿里的 TiB／GiB 数课件上必须有；`anim-*` id 必须在课件里 |
| **台词形态** | 一块台词 ≤200 汉字；舞台提示不许漏进台词；收尾语气只许在最后一节；一块台词不许跨多个面板 |
| **占位符与模板** | `_sub` 替换必须真的替换了；`place_figs` 找不到图或占位符就中止；替换后查有没有漏网的 `__XXX__` |
| **结构** | 标签开闭配平；`<h3>` 必须在某个 section 里；目录和正文 `<h2>` 逐字一致；标题说几条列表就正好几条 |
| **交叉引用** | 链接文字是节号的，必须跳到同号小节；站内锚点必须落地 |
| **副本上锁** | 四条判据必须跟总纲页逐句一致 |
| **图脚本** | 「图上那三句话必须是跑出来的」；环形 ReduceScatter 每一步都断言；共用 SVG 不许出现本课节号；`d` 必须以 `M` 开头 |
| **图文查重** | 图内／图注／正文三方比对（告警） |

## 三、写检查器时学到的十条

这些是写检查器本身时踩出来的，下次写新检查照着避坑：

1. **`str.replace` 匹配不上时是静默的。** 任何「替换模板里某一段」的操作，都必须断言它真的改了。
   而且要**前置和后置断言都有**。
2. **「一份要手工维护的清单」＋「漏了不报错」＝ 一定会漂。** 解法不是更小心地维护清单，是让清单消失（用 glob）。
3. **「0 条对不上」和「0 条被检查」在输出里长得一模一样。** 检查器要打印它检查了多少条；空集合不算通过。
4. **打印出错误 ≠ 报告了失败。** 退出码才是报告。xref 和 cues 都犯过同一个错（`main()` 没有 return）。
5. **整片一起错位时，任何只做「内部一致性」的检查都会放行。** 必须引入一个外部锚点。
6. **一个坏掉的验证器比没有验证器更危险。** 让正则先匹配自己的样例做自检。
   更坏的情况：验证器误报失败 ＋ 自动重试 ＝ 伤害放大。
7. **按标签扫 HTML 的检查器，第一步先挖掉不渲染的部分**（注释、脚本、隐藏块）。
8. **误报不收敛就降级。** 每修一次匹配规则只是换一批误报，就该把 lint 从「判定」降级成「清单」；卡死构建会逼人去绕过它。
9. **收紧检查器的一侧，另一侧的噪声会立刻变成误报。** 两侧的严格程度要一起调。
   同理，**要分清「证据不足」和「证据矛盾」**，把前者报成后者会把人引到错误的修法上。
10. **兜底检查要复用那个函数，不要复刻它的正则。** 复刻出来的第二份不会跟着第一份一起被修，只会跟着一起被信任。
    比死链更难发现的，是「指向一个真实存在、但内容不相干的地方」。

还有一条关于误报的：**两次同型误报之后，就别再调那个阈值数字了，换一个不靠数字的边界。**
（xref 的「引文放行窗口」从 14 字调到 28 字还是误报，最后改成「回看到最近的句读」。）

## 四、加一条新检查的流程

1. 先写下触发事故：哪次翻车、症状是什么、为什么现有检查没拦住。写进检查器的文件头。
2. 决定它是**断言**（确定性的、不会误报的，放在 build 脚本里）还是**体检**（有误报风险的，放进 `build-all.sh`，报告为主）。
3. 让它能**失败**：非 0 退出码。然后**故意制造一次错误，确认它真的会红**（突变测试）—— 全绿不是证据。
4. 打印它检查了多少项。
5. 在 [本文件](07-检查器与断言.md) 的表里登记一行。
