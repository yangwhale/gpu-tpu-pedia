# 03 · 四个保证：完整、准确、故事性、简洁

> 这四样是一门课能不能上台的底线。每一样都不靠「写的时候小心」，而是靠一组具体机制：
> 有的在写之前（结构），有的在写的时候（规矩），有的在写完之后（断言、评审、试讲）。
>
> 顺序按「出错代价」排：不准确最伤信任，所以准确排在完整前面讲。

---

## 一、完整：读者需要的前提，前面都给过

「完整」不是把所有东西都写进来，是**读者走到哪一步，那一步需要的东西已经在手上**。

### 机制

| 机制 | 怎么做 | 在哪 |
|---|---|---|
| **一句话主线 ＋ 逐节接力** | 每一节回答上一节留下的问题，所以不会跳步；漏了一步，接力句就接不上 | 课件文件头的「主线」块；讲义每节末尾的「这一节留下的问题」 |
| **承重词必须定义** | 一个词如果后面好几处结论都靠它，它必须被正面定义过一次。修复优先级排第三，因为「一句话就能补，不补那一整段对外行是空的」 | 评审「外行」眼镜专门抓这个 |
| **术语框** | 每讲开头一个折叠框「遇到不认识的词，回这儿查」，每个词一句话 | 例：`topic05-build.py` 第零节 |
| **关着折叠读一遍** | 关掉所有折叠从头读，正文必须依然通顺、不缺前提 | 写完每一节自查 |
| **讲义覆盖** | 课件主线的每一节，讲义里都要有讲稿；台上跳过的小节在讲义「别讲什么」里写明 | 专题五这类「讲义按节写」的：讲义构建断言节数 ＝ 课件节数。`topic02-lint-coverage.py` 是按小节查的，但目前写死只比专题二 L200，只报告不中止 |
| **易混词表** | 行话多的专题，在最后放「常被当成 X、其实不是的」和「同名不同义」两张表（专题五 §8.7、§8.8） | 课件末节 |
| **按顺序读才找得到缺口** | 关键词扫描会误报「缺口」（其实只是措辞不同），真缺口是按顺序读出来的 | 试讲轮、自学通读轮 |

### 两个真实的「不完整」

- 专题四「loss 怎么算」整条链缺失：五个外行审稿人里三个把它列为第一优先。
  全文搜「负对数」「困惑度」，0 次。
- 专题五自学通读（L18）报出 softmax、rank 从没定义过，「v7」和「v7x」混用没说明是同一代。
  都补进了术语框。

⭐ 判据：**作者看不见这种缺口，因为作者已经知道答案。** 所以「完整」主要靠外行视角的评审和试讲来保证，
而不是靠作者自查。

## 二、准确：不确定就查，绝不编

编出来的东西看起来最合理，所以最难被自己发现 —— 它总是长得像一条正确的知识。
这门课因此把准确性做成了一整套机制，而不是一句口号。

### 1. 数字在脚本里现算，加断言，找外部锚点

图里、正文里的关键数字，不手写，在图脚本里算出来，再用 `assert` 钉住：

```python
# tools/topic05-fig-zero.py
PSI = 671e9                     # DeepSeek-V3 总参数
N = 1024                        # 数据并行路数
_b = [per_dev_bytes(s) for s in STAGES]
assert abs(_b[0] / TIB - 9.76) < 0.01, _b[0] / TIB    # 跟专题四 5.1 的 9.76 TiB 对齐
assert abs(_b[3] / GIB - 9.76) < 0.01, _b[3] / GIB    # ZeRO-3：9.76 TiB → 9.76 GiB，正好 ÷1024
```

- **断言要窄。** 专题四精度边界原来写 `> 30`，33.7 和 30.7 都能通过；现在写 `abs(x - 30.7) < 0.05`。
- **外部锚点**：自己算出来的数，必须能对上一个不是自己挑的数。
  第一课按 config 算出 671.03B／36.62B 总参数与激活参数，对上官方 671B／37B，才验证了整套公式。
  **对不上任何锚点的孤立数字要格外小心。**
- **正文里手打的数也要锁**：图是脚本算出来的，但课件正文照样是手打的。专题五的做法：列一张表，正文里每个关键数必须在对应的 SVG 里也出现（`topic05-build.py` 的 `_NUM_LOCK`，14 个数）；图脚本常量一改、正文没跟上，构建当场失败。
- 截至 2026-09-25，专题五的图、课件、讲义、动画脚本里一共约 47 条 `assert`。

### 2. 架构断言扒 config，不看标签

最危险的一类错是「听起来像常识的架构关系」。几个真实的：

- 「7168 = 128 头 × 56」—— 被一句「哪有 head dimension 是 56 的」戳穿。
  `hidden = 头数 × 每头维度` 在标准 MHA 里成立，在 MLA 上不成立。
- 从 attention 类型推一个模型的血缘，推错了；拉 config 逐字段对比才发现它的 MoE 是另一个模型的一比一移植。
- DeepSeek-V4 被运行手册写成 MLA。config 里没有 `kv_lora_rank`、`num_key_value_heads: 1`；
  它的注意力是 CSA 与 HCA 交错堆叠。**更正时要写出正确的是什么，不能只写「不是 X」。**

### 3. 出处台账

每讲最后一节是出处台账：按「结论 ← 材料」排成表，写到 arXiv 号和节号、源码路径、实测记录。
专题五有 43 行。三种来源分开标：

| 标注 | 含义 |
|---|---|
| 论文／文档 ＋ 节号 | 查到的，读者能复查 |
| ⚠️ 本课推导 | 自己算的，必须给出推导链（例：「单向 0.6 TB/s ＝ 常说的 1.2 TB/s 收发合计的一半，这个拆分是推算」） |
| 本课程作者实测 | 我们自己的实验记录，写明配置和口径 |
| 本课归纳 | 定性的综合判断（例：「哪个没有定式，要看模型和负载」），不是某一篇文献的原话 |

给读者看的三个做法（专题五）：页首一句「自己推出来的数，都标了『本课推导』」；封面写「口径截至 2026-09」；**图里的例子和实测不是同一个模型时要明说**（例：「上面的图画的是 V3，实测用的是 V4-Pro」）。

外部文档的节号一律写 `sec. X.Y`，本讲小节才写 `§X.Y`。`anchorize` 会跳过「论文／报告／专题N」后面的节号，但它只是安全网：专题五就有「TUNING-v7 §4.1」这种文件名引文被链到本讲 4.1 的实例。

**估算必须标估算。** 专题五「KV 传输约 100 ms」原来写得像实测，审稿时查原始记录发现没有计时，
是按带宽算出来的 —— 改成「按带宽估算约 100 ms」，并在出处里写清三段、每段多少字节、按多少带宽。

### 4. 口径要说清

同一个数换一个口径就是另一个意思。专题五反复踩到的：

- **收发合计 vs 单向**：TPU v7 芯片间带宽常说 1.2 TB/s 是收发合计，而通信量算的是「每卡发出」，
  只能跟单向 0.6 TB/s 比。第一轮审稿前用错了，硬件门槛算成 1,922，实际是 3,845，TP 上限从「17 路」变成「约 8.4 路」。
- **总量 vs 每卡**：GB300 两种配置卡数不同（16 张 vs 20 张），运行手册里的「3.09 倍」比的是总吞吐，而且两边并发也不同（1,536 vs 512）；按每卡、同并发比是 2.09 倍。
- **同条件 vs 挑最好点**：「每卡 2.47 倍」是首字延迟 95 秒的那个并发点；同并发 512 下是 2.09 倍。头条用后者。
- **比较类断言最容易把方向写反**，而它读起来完全通顺（「序列比维度短时 RNN 计算量更小」—— 解一下不等式就知道是反的）。

### 5. 一个事实一个落点

**一个事实有 N 个落点，就会长出 N 个版本。** 有记录的同类错五次：各处各自自洽，互相对不上。

- 能引用就引用，不要复制粘贴一个数到三个地方。
- 讲义里的大数（TiB／GiB）由构建断言要求在课件里也存在；课件正文里的关键数，要求在图里也存在（见上面 1.）。**越是手打的那一份，越容易漂。**
- 撤回一个说法时，grep 全仓库把所有副本一起撤；`topic02-lint-retired.py` 专门抓判过假的话在别处复活。

### 6. 发现错误当场改源头

发现上游材料（运行手册、wiki、另一讲）写错了，**当场改源头**，不要只在下游注一句「那边是笔误」。
改之前先对权威来源核实，再 grep 出这个错的所有副本一次改完，在原处写一行更正说明。
**更正要写出正确的是什么，不能只写「不是 X」。**

自己课件里的更正写进台账（例：专题五台账那条「1,922 → 3,845」），正文保持干净，不在正文里留「我原来写错了」。

### 7. 公开仓库闸门

课程在公开仓库里：不放内部链接，不放个人信息。注意闸门只挡**渲染产物**，
生成器源码本身也在公开仓库里 —— 写在源码里的内部文本照样会公开。

## 三、故事性：一讲是一个故事，不是一份目录

### 1. 一句话主线

每一讲只立一句话，写在课件文件头，也写在讲义开头「如果只能让台下带走一句话」：

| 专题 | 那一句 |
|---|---|
| 一 | 跟着一个 token 走七站，每站问：权重多大、激活多大、多少算力、有没有东西在这里爆炸 |
| 五 | 用一种通信，换一份显存或一份算力 |

### 2. 每一节接着上一节：前一刀没管到什么，下一刀就补什么

专题五的主线结构：

```
零  一张卡装不下 → 得切
一  先认识五种通信 —— 后面每一刀多出来的都是其中一种
二  第一刀 切数据：DP → ZeRO → FSDP        ← batch 小了 FSDP 撑不住，补上 ↓
三  第二刀 切权重：TP / PP                  ← V3 的参数几乎全在专家里，补上 ↓
四  第三刀 切专家：EP                       ← 上下文一长，一条样本放不下，补上 ↓
五  第四刀 切序列：CP / DCP                 ← prefill 和 decode 要的切法不一样，补上 ↓
六  第五刀 不切张量，切工作：PD 分离 / AFD
七  摆到机器上：说得勤的放快线
八  全景地图（走完五刀回头看）
```

每节最后一句「这一刀留下的问题」接到下一节。**课件和讲义写法不一样**：

- **讲义**：上一节末句就是下一节的开场白，念一遍。讲义里写明这句「台上一定要念出来，台下才知道为什么要换刀」，而且「时间再紧也要念」。
- **课件**：上一节末尾**提出问题**，下一节导语**回答它**。两边只隔一屏，如果各把同一段话说一遍，读者会读到近乎逐字的重复（专题五对账时查出三处，已改）。

⚠️ **接力要真的成立，不要硬凑因果。** 专题五最初的说法是「每一刀都是上一刀逼出来的」，R7 审稿指出它只在两处成立（FSDP 在小 batch 下撑不住 → TP；切序列 → PD 分离）：V3 不用 TP 是选型，不是被逼；长上下文是模型换了形状。于是改成「每一刀都在补前面没管到的那一块」。**串起来的理由必须每一环都站得住**，一环是硬凑的，懂行的听众会从那一环开始不信整条线。

⛔ **反模式有明文**：「一旦讲成『接下来介绍另一种并行』，这条线就断了。」

### 3. 暗线

除了主线，每讲有两三条暗线，讲义开头「上台之前」列出来，每一站都要点名一次。
专题五的两条：「每一刀都付一种通信」「每一刀都在补前面没管到的那一块」。
专题三的外部评审批评过「作者给自己的暗线少点了四成」—— 暗线要真的在每一站兑现，不能只写在开头。

### 4. 开场和收尾扣在一起

- **开场要把问题立全。** 专题五第零节初版只讲了「装不下」（显存），被评「太简单、不够深入」；补上「就算装得下也算不完」（V3 全部训练 278.8 万 H800 卡时，一块卡要算 318 年）和「还没算激活」之后，一句话主线里「换显存或换算力」的两半才都有来处。
- **开场钩子要落在主线上。** 反例：用「94.74 GiB」开场，结果台下从头到尾只想着显存。
  好的开场是一个能被指认的问题或者冷开场（「PaLM 训练炸了 20 次，论文说没找到原因」），
  而且不要在第三段就剧透结局。
- **收尾回答开头那个问题。** 专题五结尾回到开场那一句；专题三把第一章那个盒子请回来当最后一个画面。
  「首尾呼应」的前提是「首」得是一个能被指认的位置。

### 5. 比方

- 找一个「**结论对读者而言已经是常识**」的类比，不是找一个「像」的类比。
- 同一个比方全讲只用一种意思；一个比方在两节里指两样东西，就会让读者整节理解错。
- 比值用**时间**讲，不要用**配料**讲：「每搬一个字节配 312 次运算」会被读成配方。
- 专题五用过的：班级与班长（集合通信）、批卷老师（数据并行）、砌墙师傅和小工（「每搬一个字节换多少计算」这个比值，FSDP 和 TP 共用）、笔记和提问（KV 和 Q，全讲用得最多）、医院分诊（MoE）、厨房（PD 分离）。
- **相邻就会被听成因果**：两件没有因果的事挨着讲，台下会自动补上「所以」。专题五讲义第七节专门写了「别把 X 接在 Y 后面讲」。

### 6. 先让读者真的信，再推翻

要推翻一个说法，得先让读者真的相信过它。直接说「常见的误解是 X」，读者没有被推翻的感觉。

## 四、简洁：说人话，一件事只说一遍

### 1. 行话的判据：两头都断着

一个说法往上接不住原因、往下接不住后果，就是行话。
例：「双线性形式」是行话，改成「softmax 是套在外面的一层壳」。

自查信号：**一句话里出现两个以上抽象名词，就该改。** 不要上帝视角，不要夹元评论（「这里很重要」「值得注意的是」）。

### 2. 一件事只说一遍：图文查重

课件里同一句话最容易出现三遍：图里一遍、图注一遍、正文一遍。
构建时自动把**图内文字、图注、正文**三方两两比对，连续 14 个字重合就报。
折叠内容和开头那块不参与比较 —— 判据只有一个：读者会不会看见两遍。

查重只挡得住照抄，挡不住改写。所以另一条规矩是：**每写完一章，截图看一遍。**

### 3. 加粗瘦身

判据：**一段里加粗的部分拎出来读，应该正好是这段的骨架。**

- 最常见的病是每段第一个分句被加粗 —— 引导句是路牌不是目的地，最不该加粗。
- 被否定的说法不要加粗。
- `course-metrics.py` 量全页加粗占比，目标 ≤30%（专题五 2026-09-25 为 9%）。

### 4. 炼钢：不只做加法，还要做减法

四条标准：元评论删；铺垫和落点合成一句；同一件事说第二遍就删；自我叙事下沉。
**数字、出处、判据一律不许砍。**

实测「出率」（同样的标准，一轮能削掉多少字）跟这一节之前被审过几轮成反比：专题四从没被正面审过的节削掉 21%，审过一轮的 6–10%，被红队正面审过的 9%（`reviews/FORGE-STATE.md`）。出率掉下来，就是这一节快到底了。

### 5. 补丁味

多轮修改之后，文字会长出「补丁味」：嵌套括号、括号里的更正说明、「（注意：……）」、同一个解释重复三次。
读者会觉得自己在偷看别人改稿。专题五 L18 专门做了一轮去补丁味：
把括号里的推导挪进出处台账，把重复三次的解释收成一处，其余位置只留一句指针。

### 6. 字数预算

- 图前那段不超过 80 个汉字（`topic02-lint-readability.py` W3）。
- 讲义一块台词不超过 200 个汉字（讲义构建断言）。
- 图的落点带最多**两条**：一条「换来了什么」，一条「代价是什么」（每条渲染出来可以折成两行）。第三条起会被自动收进「出处与口径」。

## 附：四个保证各自靠什么

| | 写之前（结构） | 写的时候（规矩） | 写完之后（验证） |
|---|---|---|---|
| **完整** | 一句话主线、逐节接力 | 承重词定义、术语框 | 关着折叠读、外行评审、试讲、覆盖体检 |
| **准确** | 标的选真模型、口径固定 | 数字现算 ＋ 断言、扒 config、台账、标推导／估算 | 专家评审、对抗式、台账抽查、讲义↔课件数字对账 |
| **故事性** | 一句话主线、暗线、首尾扣 | 名词跟着问题出场、比方选常识、禁止「接下来介绍」 | 讲师试讲、全篇串讲 |
| **简洁** | 课件只留 highlight ＋ 图 ＋ 图注 | 两头断着就是行话、加粗骨架、字数预算 | 图文查重、加粗占比、文字眼镜、炼钢 |
