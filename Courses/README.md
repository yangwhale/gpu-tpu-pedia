## 这门课给谁

**目标读者**：会写 Python、懂深度学习基本概念、在 GPU 上跑过训练，但**没碰过 TPU**的工程师。

**不是给谁的**：
- 想要 API 手册的 —— 那个看官方文档更快
- 只想跑通一个 demo 的 —— 直接去 `tpu/` 下找对应项目的 README
- 找论文解读的 —— 去 `Learning/`

**学完之后应该能**：
1. 看着一个模型和一批卡，判断出该用什么并行策略、装不装得下
2. 独立把一次预训练从零拉起来，包括数据、checkpoint、故障恢复
3. 拿到一份 profile，说得出瓶颈在哪、下一步该动哪个旋钮
4. 把一个 PyTorch 模型迁到 TPU 上，并解释清楚数值对不上时该怎么查

## 编排原则

写之前先把规矩定死，否则写着写着就变成文档堆砌。

**1. 每一章都从「一个具体的坑」开始，不从定义开始。**
不要「TPU 是一种 ASIC……」。要「你把 batch 调小了，VMEM 还是 OOM —— 为什么？」
定义在解决问题的过程中自然出现。

**2. 所有数字必须是实测的，并且标出在哪一代硬件上测的。**
仓库里已有的实测数据是这门课最值钱的部分。没实测过的推论要明确写「推测」。
——这条跟 `tpu/tpuguru` 里 `evidence` 分三档是同一个原则。

**3. 讲清楚「为什么错的直觉是错的」。**
最贵的知识都是反直觉的：降 batch 治不了 VMEM OOM；编译通过不等于装得下；
块越大不等于越快。每一条这样的知识都值一个小节。

**4. 边走边算，不留到最后总结。**
「算账」不是一门独立的课，是**每讲一个部件就立刻算它的代价**。
学会算 FLOP、算显存、算 arithmetic intensity 之后，每个设计选择都能自己推一遍
—— 这样结论是**算出来的**，不是背下来的。

**4b. 拆真模型，不讲通用架构。**
不讲"Transformer 一般长什么样"，而是拆 DeepSeek V3 这一个具体的模型，
所有数字取自它的官方 `config.json`。通用规律在拆的过程中自然浮现，
但**每个数都能对回一个真实字段**。

**5. ⭐ 控制深度：讲方向和量级，不讲具体参数值。**

**听众是普通技术人员，不是大模型调优工程师。**
他们要的是"这件事大概是怎么回事、代价多大、什么时候该用"，
不是"某个开关在某个规模上是 +1.22% 还是 −0.74%"。

判据很简单：

| ✅ 该讲 | ❌ 不该讲 |
|---|---|
| **数量级**（"省掉大部分激活"） | 精确到小数点的实测值 |
| **比例关系**（"算力从 3× 变 4×"） | 具体参数名和它的取值 |
| **方向**（"用算力换显存"） | 只在某个模型上成立的细节 |
| **反直觉的结论**（"换规模可能反向"） | 支撑那个结论的一整张消融表 |
| **硬件常数**（一张卡 94.74 GB） | 整除约束、分片形状这类调参细节 |

> **拿 recompute 举例，正确的讲法是**：
> 「它把激活那一大块显存基本省掉，代价是多跑一次前向 ——
> 总算力从 3 倍变成 4 倍，大约多 33%。所以它是一笔明确的交易：
> **用三分之一的算力，换掉大部分激活显存。**」
>
> 而不是列出 `remat_policy=full` 在 16 芯片和 64 芯片上各是多少个百分点。
>
> ⚠️ **我们自己的实测数据也要按这条过一遍** ——
> 它的价值在于**佐证一个方向性结论**（"这类参数不可跨规模照抄"），
> 不在于那个数字本身。**留结论，砍表格。**

**6. 每章末尾有一个能真跑的练习。**
不能真跑的课程只是读物。练习要能在最小规模上完成，不要求读者有 64 卡。
能判分的（跑得通测试）优于只能读的。

**7. 中文先行。**
先把中文写透、迭代稳定，最后再一次性翻译。不要中英并行改。

## 专题序列

**分三层。** 不是所有人都要听所有专题 —— 主线走完就能独立判断
「这个模型、这批卡，该怎么跑」；深入和实操按角色选。

### 主线（6 个，必修）

| | 专题 | 一句话 |
|---|---|---|
| 一 | [**拆开 DeepSeek V3**](专题01-拆开-DeepSeek-V3.md) | 一个 token 走完全程，每走一步就把账算一遍 |
| 二 | [**TPU 与 GPU**](专题02-TPU-与-GPU.md) | 一个从游戏显卡长出来，一个一开始就为矩阵乘造 |

学会怎么切 → 换到推理场景重算一遍 → 学会定位和调优。

## 目录结构

扁平：**一个专题一个 markdown**，素材集中放。

```
Courses/
├── 01-拆开-DeepSeek-V3.md        ⎫
├── 02-注意力演进.md              ⎪
├── …                            ⎬ 一个专题一个文件
├── 07-性能调优与工具链.md         ⎭
├── README.md                    本文件 —— 专题序列
├── DESIGN-NOTES.md              设计笔记（累积式，含被推翻方案的理由）
├── 参考-CS336课程安排.md          外部参考
├── LICENSE.txt                  CC BY-NC-SA 4.0
├── 素材/                        各专题共用的原始材料
└── tools/                       可复用的工具链
```

> 📌 **文件名用两位阿拉伯数字前缀，不用中文数字。**
> 中文数字按 Unicode 码点排序 —— 一(4E00) 七(4E03) 三(4E09) 二(4E8C)
> 五(4E94) 六(516D) 四(56DB) —— 在 GitHub 上会显示成
> 「一 七 三 二 五 六 四」这种乱序。文档标题里仍用「专题一」这种中文序号。

### 三条规矩

1. **素材集中放 `素材/`**，不按专题分 —— 同一份东西常常好几个专题都要用
2. **每份素材要说清楚哪来的、什么许可、能不能公开**。这个仓库是 public 的
3. **产物入不入库看重建成本**：小、稳定、但重建要搭一套环境的入库；
   一条命令能重来的不入库。**无论如何，生成它的脚本必须在库里**
