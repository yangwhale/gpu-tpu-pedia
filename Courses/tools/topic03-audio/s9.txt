[focus] 到这里，这一讲的「想法」部分全讲完了。剩下这一章，全是机器说了算。

[thinking] 前面每一章都在说省了多少倍。可倍数是相对的，毫秒才是绝对的。请看这张图。先说清楚它量的是什么：走一步，要从显存里搬多少字节。不是算多少，是搬多少。

[friendly] 两段颜色。灰色是权重，所有人共享，每一步都得把它整个搬一遍。DeepSeek V3 每个 token 激活三百七十亿参数，用 FP8 存，就是三十四点四六个 GiB。红色是你一个人的 KV cache。

[realization] 看这五根柱子，灰色那一段完全一样，五根都顶到同一条线。因为权重就那么多，跟你说多长的话没有关系。差别全在红的那一段上。

[contemplative] 大家还记得第一章那句话吗？每走一步，都得把全部权重从显存里搬一遍。那句话到今天一个字都没过期，它就是这根灰的。

[seriously] 而「KV cache 是瓶颈」这句话，我们从第三章说到现在，到这儿才算被画出来。在 MHA 那一步里，要搬的字节有百分之九十三点四，是一个人的 KV。

[curiosity] 再除以带宽，字节就变成了毫秒，这里出现两件反直觉的事。一个 v7 device 的带宽是每秒三点六八五个 TB。MHA 一个人就装不下，要十二张 device，一步大约十二点七毫秒；MLA 只要七张，一步大约一点七九毫秒。

[thinking] 显存省了五十六点九倍，可一步只快了七点零八倍。剩下的去哪了？一大块被共享的权重吃掉了，每步还得读那三十四点四六个 GiB，谁都省不掉；还有一块，是 MHA 被迫多用的那五张卡。所以 MLA 真正省下的，不只是时间，更是那五张卡，它们可以拿去服务别人。

[seriously] 第二件：MLA 之后再上稀疏，一个人用的时候，只再快一点二一倍。因为红的已经被压得几乎没了，瓶颈整个搬到了灰的那一段。在一条路上继续使劲，收益是会到头的，这也正是第八章要几条路一起走的又一个理由。

[casually] 不过这一条只对一个人成立。权重是大家分摊的，KV 是每人一份的，人一多，红的那段又会长回来。同时伺候六十四个人的时候，稀疏带来的提速就回到一点九八倍。同一个模型，问法不同，答案就不同。

[focus] 更要命的是，这些聪明办法，绝大多数是在 GPU 上长出来的。而一台机器擅长什么，是写在它的出厂设计里的。换一台，前提就换了。

[thinking] 二零二五年，有人真的把 NSA 移植到 TPU 上，写了一份工作日志。他的结论是一句话：动态稀疏，在这套栈的每一层都难。我把「每一层」拆开说，三层，一层比一层底下。

[casually] 第一层，编译器。编译器不喜欢运行时才知道的变量和分支，而「挑哪几块」恰恰是运行时才知道的。第二层，写 kernel 的框架。它强制按顺序一格一格走，而挑出来的块是跳着的。

[seriously] 第三层，硬件本身，这一层最狠。那个把散落的块取回来的活，落到了一个专管算数的部件头上，而不是那套专门搬东西的硬件。这个部件干活的方式是，同一个动作，对一排几百个数一起做。你让它一个一个去不同地方捡东西，一排几百个位子只用得上一个，其余全在干等。

[thinking] 第六章欠下的那一笔，在这里到期了。当时说，挑中的那些散落在各处，搬起来很碎。「很碎」翻成机器听得懂的话，是两件事。一趟大搬运被拆成很多趟小的，每一趟都要付一次起步钱；而且要等挑完才知道去哪儿拿，推车没法像平时那样，提前一两趟就把下一车备好。

[realization] 光是把索引改写成编译器友好的形式，他就快了二百八十六倍，算法一个字没改。

[contemplative] 这不是五年前的旧账。Google 自己二零二六年四月的一篇论文，摘要里就写着：现有的推理 kernel 和服务系统基本都是以 GPU 为中心的，还没有一套成熟的办法，把这些负载高效地映射到 TPU 上。已有的解法，形状都一样：把运行时才知道的一个临时决定，换成开工前就备好的几套，来了挑一套。这是一个还在打开的工程战场。

[suggestion] 但真正值得记住的不是那个二百八十六，是下面这一条。它听起来像个无关紧要的工程调整，改个常数而已。

[seriously] 为了对齐芯片里那块矩阵乘单元的形状，他不得不把论文里的块大小，从三十二改成六十四。而他自己写道：这可能会完全改变训练动态。块大了，挑中的那一块里会夹进更多无关的东西，模型在大海捞针这类细活上可能会变差。

[focus] 读懂这一条，这一讲那条暗线就走完了全程。硬件管的事，一路在往上爬。第二章，硬件决定了用哪个公式，点积赢了，因为它能写成矩阵乘。第四章，硬件决定了一个超参，八组，因为一台机器装八张卡。第五章，硬件否决了一个漂亮的数学，压缩件不按头分，多卡切不开。第六章，硬件决定了怎么挑，散着取不行，只能整块取。

[realization] 到这里，硬件直接改了训练动态，而它改的那个数，会影响模型聪不聪明。一开始，它只管用哪个公式；到最后，它管到了模型的智商。

[curiosity] 好，开场我请大家猜过一个数。二零二零年的 GPT-3 记两千零四十八个 token，今天的模型记一百万，整整五百一十二倍。这五百多倍里，真正靠买更好的硬件换来的，占几成？现在揭晓。

[focus] 请看这张图。先问那句老话：省的是哪一样？这五百一十二倍，其实是两笔账，一笔是显存，一笔是带宽。

[thinking] 显存这一笔，一个 token 要占多少。第一段，MLA 把每一份压小，五十六点九倍，就是四百八十八个 GiB 到八点五八个 GiB。第二段，混合三比一，四层里只有一层是全注意力，再省四倍。两段相乘，二百二十七点五倍，都是「把每个 token 变便宜」换来的。

[realization] 末尾只露出很小的一截红，二点二五倍。五百一十二倍里，只有这二点二五倍，是剩给「多买硬件」的。

[seriously] 这一截要老实交代。它是前两段除完之后剩下的，我并没有单独去查它。它里面至少还混着两样今天没讲的东西：一是 KV 用更低的精度存，今天各家默认就这么干，光这一项就近乎再减半；二是前缀复用。所以真把这两样拆出来，属于多买硬件的那一份只会更小。这让结论更硬，不是更软。

[thinking] 带宽这一笔，一步要读多少。稀疏注意力每步固定只读两千零四十八个，一百零四万八千五百七十六除以两千零四十八，正好五百一十二，一整条全被它抵掉了。上下文涨了五百一十二倍，每步要读的一个字节都没涨。但它不省显存，所以它不进上面那根条。

[suggestion] 顺带提醒一句，这两根条不是一本账，别加起来。上面量的是一个 token 占多少，下面量的是一步要读多少。
