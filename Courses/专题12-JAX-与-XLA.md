## 这个专题要回答的一个问题

一个会写 PyTorch 的人第一次看 JAX 代码，通常有三个反应：

1. 「函数都是纯的？那状态放哪？」
2. 「为什么到处都是 `jit`？」
3. 「这个 `shard_map` / `PartitionSpec` 是什么鬼？」

**这三个问题背后是同一件事：JAX 不是另一个深度学习框架，
它是一个「把 Python 编译成计算图」的系统。** 一旦接受这个前提，
上面三条全都变得自然。

## 一 · 心智模型的切换

| | PyTorch | JAX |
|---|---|---|
| 执行 | **立即执行**，写一行算一行 | **先追踪成图，再整体编译执行** |
| 状态 | 模型对象里带着参数 | **参数是显式传进去的数据** |
| 随机数 | 全局种子 | **显式传 key**，可复现 |
| 副作用 | 随便 | **纯函数**，副作用要特殊处理 |
| 调试 | 打印、断点 | **打印看到的是抽象值** |

> ⭐ **一句话**：PyTorch 你写的是"做什么"，JAX 你写的是"要算什么函数"。
> 前者是命令，后者是描述。

**要讲透的一个例子**：为什么 JAX 的随机数要显式传 key ——
因为纯函数不能有隐藏状态，而这恰恰换来了**完美可复现**。

## 二 · `jit` 到底做了什么

- **追踪（tracing）**：用抽象值跑一遍你的函数，记录下所有操作 → 得到 jaxpr
- 转成 **HLO** → XLA 编译 → 机器码 → 缓存
- **下次同样形状的输入直接命中缓存**

**由此推出几条实用规则：**

- ⚠️ **形状变了就重新编译** —— 这是 TPU 上最常见的性能杀手
- ⚠️ **Python 层的控制流在追踪时就被固化了** ——
  `if x > 0` 里的 x 是抽象值，判断不了
  → 要用 `jax.lax.cond` / `jax.lax.scan`
- **打印看到的是 tracer 对象**，不是数值 → 调试要用 `jax.debug.print`
- **静态参数**（`static_argnums`）：哪些参数参与编译期决策

**要讲的调试技能**：
- 怎么知道重编译了（打点、看日志）
- 怎么看 jaxpr、怎么 dump HLO

## 三 · 数组变换：JAX 的核心几件套

- `jit` —— 编译
- `grad` —— 自动微分。**它是个函数变换，不是一个方法**
- `vmap` —— 自动批处理。⭐ 用它可以写单样本的逻辑，自动变成批量
- `scan` —— 循环，且**只编译一次循环体**（对 61 层的模型很重要）
- 组合起来用：`jit(grad(vmap(f)))`

> ⭐ **`scan` 值得单独讲**：61 层如果展开成 61 份 HLO，编译要很久、
> 图也巨大。用 scan 表达成循环，编译一次、复用 61 遍。
> 这是 MaxText 里 `scan_layers` 那个开关背后的东西。

## 四 · 并行：从单卡到多卡只改标注

**这是 JAX 最漂亮的地方，也是它跟 Megatron 最不同的地方。**

- **mesh**：把物理设备排成一个命名的多维网格
- **PartitionSpec**：告诉编译器"这个张量的第几维沿 mesh 的哪根轴切"
- **编译器自动插入通信** —— 你不写 all-reduce，它替你写

```
   单卡代码  +  几行 sharding 标注  =  多卡代码
```

- **`shard_map`**：需要手动控制时的逃生口 ——
  在里面你看到的是本地分片，可以自己写集合通信
- **GSPMD**：编译器怎么把标注传播到没标注的张量上

⚠️ **代价**：标错一个 spec，编译器会**默默插入一堆通信**，
性能崩了但不报错。→ 怎么检查（看 HLO 里的 collective、看 profile）

## 六 · 从 PyTorch 过来的人最容易踩的坑

一份清单，每条配一个最小复现：

- 形状不固定导致反复重编译
- 在 jit 里用 Python 的 `if` / `for` 依赖数据
- 忘了 JAX 数组是**不可变**的
- 就地更新的写法（`.at[].set()`）
- 累加精度：`jnp.dot` 的默认精度在 TPU 上可能不是你以为的那个
  （`matmul_precision` 这个坑）
- donate / buffer 复用
- 什么时候会隐式地把数据搬到 host（然后性能塌方）

## 七 · 一个能真跑的练习

**目标**：从一个单卡的小 Transformer 开始，
一步步加上 jit → scan → sharding，最后跑在多卡上。

每一步都能看到：编译时间怎么变、HLO 里多了什么、profile 长什么样。

> 这是全课少数几个**能在小规模上完整跑通**的练习之一 ——
> 4 芯片甚至 CPU 就够。
