## 为什么是 DeepSeek V3

早就不是 GPT-3 175B 那个时代了。**V3 是当下事实上的黄金标准** ——
后来的开源模型基本都从它出发再改。要讲清楚"现在的大模型长什么样"，
拆它一个，比泛泛讲十个有用。

而且它一次把三件互相牵制的事做成了：**MLA 把 KV cache 压下去、
细粒度 MoE 把激活参数压下去、FP8 把训练成本压下去**。
每一件都直接对应硬件上的一个瓶颈 —— 这正是这门课要建立的那条因果链。

**这一课的目的**：让一个 token 走完全程，
**每走一步就把账算一遍** —— 这一步产生多大的矩阵、吃多少显存、要多少算力。

走完之后，"为什么这个模型需要一个机房"就不是一句口号，而是一串算出来的数。

## 全课统一的算账口径

后面每一站都按这一套口径算，**中途不换**：

| | |
|---|---|
| 序列长度 | **128K = 131,072 token** |
| batch | **1**（先把单条算清楚，要乘再乘） |
| 精度 | 权重与激活都按 **bf16（2 字节）** |
| 方向 | **只算前向**。反向与优化器状态留到后面的课 |
| 参照物 | **TPU v7 单 device 可用 HBM ≈ 94.74 GB** |

> 为什么先只算前向：前向的账是**事实**，一步一步能推出来。
> 反向要牵进 recompute 怎么选、优化器状态放哪、梯度要不要累积 ——
> 那些是**决策**不是事实，混在第一课里会把主线搅浑。

## 路线：跟着一个 token 走完全程

```
文字 → token → embedding → ┌ MLA ┐→┌ MLP(前3层) / MoE(后58层) ┐→ …×61 → norm → lm_head → 概率
                            └──── 残差流一路贯穿 ──────────────┘
```

**每一站问同样的四个问题：**

1. 这一站的**权重**有多大？
2. 它产生的**激活**有多大？
3. 它要做多少 **FLOPs**？
4. **有没有什么东西在这里爆炸？** ← 往往第 4 个才是重点

---

## 站 1 · 从文字到向量

**讲**
- 分词：词表 129,280 怎么定下来的，大小的两头权衡
- 嵌入：一次查表，仅此而已

**算**
- 嵌入矩阵参数量：129,280 × 7168 = ?
- **128K token 查完表，那个张量多大？**
  → 第一个让人坐直的数字：还没进第一层，显存已经掉一块
- 这个张量此后每一层都要被读写一次（残差流）

---

## 站 2 · MLA：注意力，以及 KV cache 的战争

**整课的重头，也是 V3 最值得讲的地方。**

**讲**
- 标准 MHA 在长上下文下的死穴：KV cache **随序列线性增长、又随层数线性增长**
- 演化路线 MHA → MQA → GQA → **MLA**，每一步在省什么、代价是什么
- MLA 的做法：
  - KV 压成一个 **512 维**隐向量（`kv_lora_rank`），要用时再升回 128 头
  - 位置信息单独走一路 **64 维** RoPE（`qk_rope_head_dim`）—— 为什么必须分开走
  - Q 也走低秩（1536），但那是为了省参数，不是省 cache
- RoPE 与 YaRN：4K 训练怎么外推到 163,840

**算**
- 五个投影矩阵（`q_a` `q_b` `kv_a` `kv_b` `o`）各多大，一层合计多少
- **每 token 每层的 KV cache = 512 + 64 = 576 个数**
  → 128K × 61 层是多少 GB？
- 对照：**同样 128K，标准 MHA 要多少？** ← 这个差值就是 MLA 存在的理由
- ⚠️ **注意力分数矩阵**：128 头 × 128K × 128K 如果真物化出来是多少？
  → 大到荒谬（PB 量级）
  → **这就是 FlashAttention 必须存在的原因 —— 不是为了快，是为了根本放得下**
- FLOPs：$QK^\top$ 与 $AV$ 两处都是序列长度的**平方项**
  → 上下文越长，attention 在总算力里的占比怎么爬升

## 站 3 · 前三层：Dense MLP

**讲**
- `first_k_dense_replace = 3` —— 为什么最前面几层不做 MoE
- 结构：gate / up / down 三个矩阵 + SiLU（SwiGLU 家族）

**算**
- 一层 dense MLP 参数量（`intermediate_size` 18432）
- 跟下一站的 MoE 层做对照，为"稀疏化的为什么是 MLP"铺垫

---

## 站 4 · MoE：671B 的主体

**讲**
- 为什么被稀疏化的是 MLP 不是 attention（回到站 3 的参数占比）
- **细粒度专家**：`moe_intermediate_size` 只有 2048 —— 专家做小做多
- **共享专家**：1 个所有 token 都过，兜住通用能力
- 路由：sigmoid 打分 → **分组限制**（8 组里选 4 组）→ top-8
- `noaux_tc`：不靠辅助损失做负载均衡，靠一个可学习的偏置
- ⚠️ 分组限制是为了什么 —— **限制一个 token 要跨多少台机器去取专家**。
  这是一个被硬件逼出来的纯工程设计，写在模型结构里

**算**
- 单个专家：3 × 7168 × 2048 = ?
- 一层（256 routed + 1 shared）= ?
- 58 层合计 = ? → **671B 的绝大部分在这儿**
- 但每 token 只过 **8 + 1 = 9 个专家** → 实际激活多少？
- 关键对照：**总参数 671B vs 激活 37B，差 18 倍**
- ⚠️ 稀疏不是白拿的：专家分散在不同卡上 →
  **每层一次 all-to-all**，通信量怎么算

---

## 站 5 · 把 61 层摞起来

**讲**
- 残差流：所有层从同一条总线上读、往同一条总线上写
- RMSNorm 摆在哪（pre-norm）
- 一层的完整数据流，然后 ×61

**算**
- 单层激活峰值
- **61 层的激活如果全留着**是多少？
  → 这个数大得离谱，于是自然冒出一个问题：*凭什么要留着？*
  → 答案在反向传播里 —— **但那是后面的课。这里只把问题立住。**

---

## 站 6 · 出口

**讲**
- 最后一次 RMSNorm
- `lm_head`：7168 → 129,280，回到词表
- MTP（`num_nextn_predict_layers = 1`）：多预测一个 token，训练时的额外信号

**算**
- lm_head 参数量 —— 跟嵌入矩阵一样大，而且 `tie_word_embeddings = false`，**是两份**
- **logits 张量**：128K × 129,280 有多大？
  → 又一个容易漏掉的爆点：**出口这一下比中间任何一层都吓人**

## 站 7 · 把账合起来

**一张总表**：

| | 权重 | 激活 | FLOPs | 备注 |
|---|---|---|---|---|
| 嵌入 | | | | |
| MLA ×61 | | | | 含 KV cache |
| Dense MLP ×3 | | | | |
| MoE ×58 | | | | 含 all-to-all |
| 出口 | | | | logits 爆点 |
| **合计** | **671B** | | | |

然后回答三个问题：

1. **一次 128K 前向，总共多少 FLOPs？**
2. **峰值显存多少？** 拆成：权重 / KV cache / 激活 / 临时缓冲
3. **对着 94.74 GB 一除，要多少个 device 才装得下？**

> 到这里，"为什么需要并行"不用讲了 —— **它是算出来的结论。**
> 怎么并行、切哪一维、通信怎么藏，是后面的课。

## 这一课明确不讲

写清楚是为了让边界清楚，不是遗漏：

- **反向传播与优化器状态** —— 前向的账是事实，反向的账掺着策略，混讲会讲不清
- **并行策略** —— 这一课只负责把"装不下"这个事实算出来
- **FP8 训练** —— V3 的一大贡献，但那是精度与数值的话题，单独讲
- **推理**（prefill / decode 的差异、连续批处理）—— 全程按训练的前向算
- **训练数据、后训练、RL** —— 跟架构无关
