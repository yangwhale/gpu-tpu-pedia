[friendly] 上一节最后那个问题，答案是能，而且 2017 年真有人这么干了。不过先纠正一件很多人搞混的事：注意力不是 2017 年发明的。它 2014 年就有了，一开始只是长在 RNN 身上的一个小配件。那一刀真正干的事，不是发明注意力，而是把长着配件的那条链整个扔掉，只留配件。

[curiosity] 在那一刀落下之前，先说说这个配件自己是怎么来的。它不是谁灵光一闪想出来的，是被人一次次嫌弃出来的。

[casually] 2014 年，Bengio 的实验室里有一个实习生，叫 Bahdanau，做机器翻译。他试了两次都不满意。第一个方案太复杂，做不出来；第二个能跑，但很笨，只会死板地按顺序一个对一个，原文第三个词就配译文第三个词。然后有一天，他想到了一件事。他话里的解码器，就是正在往外吐译文的那一半。

[warmly] 「我忽然想到，要是能让解码器自己学会该把游标放在原文的哪个位置，那该多好。这个念头多少是中学学英文时做翻译练习来的。你翻译的时候，目光会在原文和译文之间来回移动。」

[contemplative] 这就是注意力的出身。不是什么宏大理论，是一个学生想起自己做翻译作业的时候，眼睛是怎么动的。

[focus] 他把这个「软搜索」写成了一个叫 softmax 的东西。softmax 大家就理解成一句话：把一堆分数，变成一组加起来正好等于百分之百的比例。请记住「加起来正好百分之百」这几个字，它今天后面会闯一次大祸。

[amused] 第一次跑就成了。他给这个架构起名叫 RNNSearch，后来自己说，这名字不怎么样。「注意力」这三个字，是 Bengio 在最后几轮修改里加进去的。Bengio 也讲过，为什么它必须是软的。

[warmly] 「这就好比先把整本法文书从头读到尾，然后凭印象把英文版写出来，肯定会丢细节。办法是：写每一个英文词的时候，都允许回头去看法文书里的任意一处细节。而为了能用反向传播训练，注意力必须是软的：不是挑中某一个位置，而是有一份总额固定的注意力，可以分摊到所有位置上。」

[realization] 总额固定、分摊到所有位置，就是刚才那个 softmax 换成了人话。它是优点：硬挑一个位置没法求导，按比例分摊才能求导，这个东西才训得出来。所以这不是哪个数学家的偏好，是为了能被梯度下降训练而必须付的形状。

[seriously] 但请把它记在心里，到第六章，它会变成一个 bug 的病根。还是上一节那句话：一个设计的毛病，十有八九跟它的好处是同一条性质。

[focus] 请看这张图，注意力被逼出来一共三步。第一步，2014 年：一个向量装不下一整句话，于是让解码器每写一个词，都回头软搜索一遍原文。第二步，2015 年：打分太慢。原来每一对词都要过一个小网络去算像不像，n 个词就是 n 的平方次小网络。换成点积之后，整张打分表一次矩阵乘就出来了。

[seriously] 这里请注意论文给的理由：两种打分理论复杂度相仿，但点积快得多、省内存，因为它能用高度优化的矩阵乘来实现。这句理由里，没有一个字在讲哪种更准。选点积，不是因为它更准，是因为它能变成矩阵乘。这是今天的第一条暗线：硬件反过来决定公式。后面它还会出现三次，一次比一次露骨。

[casually] 第三步，就是 2017 年那一刀：既然回头看这么好使，那还要 RNN 干什么？把循环整个拿掉。论文的标题就是这个意思：你只需要注意力。

[excitement] 这一刀换来了什么？换来了并行。上一章那一万步得排一万轮，现在所有的字可以同时开工。请看这张对比图：左边那条链，第一个字想影响第六个字，得经过五跳，每一跳都要排队。右边换成一张 n 乘 n 的表，每一格是一个字对另一个字的打分，任意两个字之间只隔一格，整张表一次算完。规模，就是从这一刀之后才起得来的。

[thinking] 表里有一半是灰的。那是因果遮罩：每个字只能看见自己和自己左边的字，未来那些格子在 softmax 之前被置成负无穷。

[seriously] 可是请注意，账单也在这张图上。要算的格子从 n 变成了 n 的平方。更要紧的是，被换掉的不只是那根横箭头，那个盒子也一起没了。上一节说的那个好处，每步要搬的东西不随长度变，从这一刀落下的那一刻起，不成立了。

[curiosity] 那盒子没了，它靠什么记住前面说过的话？答案很直接：它不记了。每要吐一个新字，它就回头把前面所有的字重新看一遍。可要回头看，前面那些字就得留着。这就是账单的第一页。

[focus] 那回头看，具体怎么看？请看这张图。每个位置拿自己的向量乘三个不同的矩阵，长出三样东西：query，我想找什么；key，我这儿有什么；value，被选中了我交出什么。为什么要分三样？就像去图书馆找书，你脑子里的需求和书脊上的标题不是一回事，书脊和书里的内容又是另一回事。

[casually] 然后最后那个字，拿自己的 query 去跟每一个字的 key 打分，过 softmax 变成一组加起来等于一的权重，再按权重把大家的 value 加起来。它不用等谁传话，直接问全场，按各家报的价把货收回来。而且六个位置是同时在做这件事的。

[thinking] 这里最容易听岔：注意力不是挑出最像的那一个，而是按比例把几家的货混成一碗。看这个例子。打分除以根号 d k，也就是每个头维度的平方根之后，「抽屉」拿到百分之五十二，「放进」百分之二十八，「钥匙」百分之十三，混出来的这一碗才答得上问题。如果不除，最高分那家就拿走百分之九十九点九，整碗货被一家吃掉。

[focus] 这个根号 d k 不是玄学。两个向量的点积，是 d k 个乘积加起来，方差跟着维度线性长，标准差就是根号 d k。除掉它，就是把打分的尺度拉回来，不然 softmax 会被推到几乎全是零和一的角落，梯度就没了。

[focus] 再往下，多头。请看这张图左边：一个 query 同时想去三个地方，上一个词、这句话的主语、三段之前那个人名。三个方向一平均，那根线又短，又哪个都没真指到。这就是单头的毛病：不是不够用，是会把该分开的东西平均掉。

[realization] 办法是把五百一十二维切成八份，每份六十四维，各看各的，最后拼回来。这八份，就叫八个头。多头买的不是算力，是分辨率：总维度没变，参数量也没变，只是切开了。

[seriously] 但代价是：每个头都要留自己的 K 和 V，要存的东西当场乘以八。这个八，就是第四章第一刀要砍的那个八。顺便说，八只是 2017 年那篇论文的取法。我们的老朋友 DeepSeek V3 是一百二十八个头，每头一百二十八维，拼起来一万六千三百八十四，比它的模型宽度七千一百六十八还大二点二九倍。2019 年就有人点名了这个代价：训练很快，可一个字一个字往外生成时很慢，因为要反复从显存里读那一大堆 K 和 V。

[focus] 最后看这一层算完，桌上剩下什么。请看这张图，分三堆。第一堆，模型权重，所有字共用一套，本来就在那儿。第二堆，中间算出来的那些打分，拌完就扔。第三堆，每个字的钥匙和内容，也就是 K 和 V：下一个字还要拿它们比、拿它们拌，所以必须留着，而且每来一个字就多一格。

[curiosity] 为什么不扔掉，每次重算呢？因为重算不是再算一遍，而是每一步都把整段历史重算一遍。吐第一百个字要把前九十九个重过一遍，吐第一百零一个再重过一遍，整段生成的开销就从正比于长度的平方，变成正比于长度的立方。所以这不是省一点，是能不能用的分界线。

[seriously] 如果把一层里每个张量的形状写全，会有一堆字母：几个人同时在问、这次问几个字、历史有多长、每层多宽。里面只有一个字母是聊着聊着自己长出来的，就是历史长度 S，别的都是开工前就定死的。这一讲的主角，就是这个 S。后面每一章，你只要问一句：这一招是让 S 前面的系数变小，让每步读到的 S 变少，还是干脆让 S 从形状里消失？

[realization] 而 S 会变长，是因为每来一个字，都得把它那份 K 和 V 存下来。这堆存货，就叫 KV cache。它就是在这里出生的，2017 年那一刀落下的同一秒。1990 年那个盒子，换成了一条会一直变长的格子：盒子永远那么大，但只能一个一个来；格子能一次算完，但会一直长下去。

[amused] 最后留一句给发明注意力的那个实习生。Transformer 那篇出来的时候，他的反应是：「我当场就跟同组的人宣布：RNN 死了。」他说对了一半。下一节你会看到，它在另一个地方活得好好的。

[friendly] 这一节就到这里，大家有问题吗？
