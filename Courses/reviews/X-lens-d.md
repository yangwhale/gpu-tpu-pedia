## 一、⭐ loss 到底怎么算 —— 这是全讲最大的断裂

**跟不上。而且断在第一步。**

§1.2 开头一句「起点很朴素 —— loss 是一个数。（这一点后面是全部关键，先记着。）」，然后直接跳到「第一个梯度 ＝ 你猜的，减去正确答案」。

中间**整整一层被跳过了**：一条 4K 序列有 **4096 个位置，每个位置都在预测下一个词，每个位置都有自己的交叉熵**。从 4096 个标量到 1 个标量，要先按位置平均、再按 batch 平均。我全文 grep 过：「每个位置」「逐位置」「按 token 平均」**零命中**，「交叉熵」只出现 3 次且都在 §1.2 那一格。

具体卡在哪：

- **fig-vote Ⓒ 用「样本 1 / 样本 2 / 样本 3」讲平均**（`1116-1137`）。我读的时候理解成"三条训练样本"，也就是 batch=3。但在语言模型里，这三个"人"其实主要是**同一条序列里的三个位置**。这一格接着说「多卡训练里那一道跨卡汇总，干的就是这个平均」—— 于是我建立的图像是：**平均只发生在卡与卡之间**。错得很彻底：绝大部分平均发生在单卡内部、在 loss 变成标量之前就做完了。
- 因此 §1.2 那句「⚠️ 那个减不是对概率求导，是对 logits 求导」我理解不了它的**形状**。种子到底是一个 `[词表]` 的向量，还是 `[序列长度, 词表]` 的矩阵？照 §1.3「往回传的是一整个张量，形状跟这一层的输出一模一样」，应该是后者 —— 可 §1.2 画的是前者（4 个字的柱状图）。**§1.2 和 §1.3 画的是两个不同形状的东西，中间没有过渡。**
- 那个 `1/N` 因子从来没出现过。于是 §1.8「跨卡汇总……得取平均」我分不清：这是**又一次**平均，还是**同一次**平均的分布式实现？（是后者，但文里读不出来。）
- §5.1 有一句非常漂亮的话：「94 条 128K 还是 3,000 条 4K，对显存是同一件事」。**这句话成立的前提正是"loss 和激活都只认 token 总数"** —— 而那个前提在 §1.2 被跳过了。所以到 §5.1 我是"接受"而不是"看懂"。

**建议**：在 §1.2 的图之前加**一格**（不用图，三行字就够）：「一条 4K 序列 = 4096 次预测 → 4096 个交叉熵 → 求平均 = 1 个数。fig-vote 里那"一屋子人"，就是这 4096 个位置（再乘上 batch）。」这一格补上，§1.2→§1.3 的形状断裂、§1.8 的"平均到底平均几次"、§5.1 的"只认 token 总数"**三处一起接上**。

### 长度口径：4K / 128K 在同一个模型上来回切，且没打招呼

这一条是我被绊得最狠的地方，而且它影响的不只是直觉、是**结论本身**：

| 位置 | V3 用的序列长度 |
|---|---|
| §1.7 基准单位（`2140`） | **131,072** |
| §2.2 / §2.3 / fig-per-byte | **131,072** |
| §1.8（`2308`）引 V3 真实 batch | **「4K 上下文」** |
| §5 全部 | **131,072** |

同一个模型、同一讲，两个差 32 倍的长度，**从来没有一句话说明"128K 是长上下文扩展阶段，V3 的主预训练是 4K"**。

后果不是审美问题，是**结论翻转**：

- fig-per-byte 算出 V3 的交点是 **S ≈ 5,734**。V3 真实预训练的 **4,096 < 5,734** —— 也就是说，**在 V3 自己真正的训练配置下，attention 落在交点左边，2022 年那篇论文和 Megatron 的 `core_attn` 默认值仍然是对的。**
- 而 §2.5 的落点是「Megatron 那个默认是 2,048 年代选出来的最优解……但它还在那里当默认」，§2.3 的表把 attention 标成「**绝不**」。把 §2.3 那个 175.92 按长度折回 4K：`175.92 × 4096/131072 ≈ 5.5` —— 正好落在"边际"档（专家输出 2.20，gate/up 7.70），**既不是"绝不"，也不该被那条"小于 3"的线切掉**。
- 作为读者，我合上书记住的是"attention 绝不重算"。**这个 take-away 只在 128K 上成立，而它是这讲最响亮的一句。**

**建议**：§2.4 那张图上加一根 **4K 竖线**（图上已经有 1K/4K/16K/64K/256K 的刻度，加一根竖线几乎零成本），并在落点里写一句：「注意 V3 自己的预训练是 4K —— 它落在交点**左边**。128K 那一栏是长上下文阶段的账。**同一个模型，两个阶段，两个相反的最优解**。」这句话不但不削弱这一节，反而**是这一节那个"必然相交"论点最强的例证**：连同一个模型的两个训练阶段都能翻转。

## 二、⭐ 反向那一段：哪些是新的，哪些可以删

**有新东西，而且是我在教科书上没见过的三条**（这一段整体很强）：

1. **§1.5 Ⓓ「从窄的那一头起步」**（`1969-1986`）。我学过链式法则，从来没人告诉我"两个方向算出来一模一样，差的是你要走几遍"，更没人给反例（10 参数 → 100 万维输出时反向传播反而亏）。这是全讲最值钱的一格。
2. **§1.3 的"两支乘的东西不一样，所以合并不了"**（fig-3x Ⓑ）。教科书写 `dW = XᵀdY`、`dX = dYWᵀ` 就完了，从来不说"这是两个不同的问题、一个都省不掉、3 倍是数出来的"。而且它顺手解释了冻结层为什么便宜。
3. **§1.6 的闭环**：反向必须乘前向的值 → 激活扔不掉。这条把"数学"和"显存账"焊死了，是全讲的枢纽，而且 fig-vote Ⓑ 那句「**上游越亮的那根线，加粗越划算**」是我见过这件事最好的人话版本。

**可以删的：**

- **§1.4 的前半（`1652-1660`）跟 fig-slider Ⓑ 是同一句话说两遍。** Ⓑ 已经用一台调音台把"偏 = 按住不动"讲透了；§1.4 的 note 又写一遍「其它全部按住不动，只动这一个」。§1.4 真正的新内容只有**两段**：「所以自动微分能做成一个通用库」和「61 层展开的解析式写不出来」。建议把这两段并进 §1.3 末尾，**整个 §1.4 的小标题和前三段可以删掉**。
- **fig-circuit（`1341-1650`）的 Ⓐ 和 Ⓑ 是 CS231n 讲义的逐字复述**（a=2, b=−3, c=4 那个电路就是 CS231n 的原例，figsrc 自己也承认了）。对"学过 ML 基础课"的我，加法门/乘法门/max 门的反向规则不是新知识。**但 Ⓒ 必须留**（「反向要乘它 → 所以扔不掉 → 每一层每一步 → 于是变成这么一片」）—— 那是全讲唯一一处把"一个乘法门"放大成"整张激活账单"的画面。建议：**Ⓐ 保留（跟着数走一遍确实有用），Ⓑ 折进 `details`，Ⓒ 提到最前面。**

## 三、小模型直觉被推翻、却没明说"这跟你以为的不一样"的地方（最值钱的一类）

按"推翻力度 × 没提醒程度"排：

**① ReLU 治好了梯度消失 —— 这条在现代 Transformer 上早就不成立了，文中却是全讲唯一的结论。**
fig-vanish Ⓒ（`1772`）：「这就是为什么 ReLU 一换上来，深网络忽然就训得动了 —— 它把每层那个"先天往下压"的系数，从 ¼ 变回了 1。」这是我脑子里的旧知识，读完被**加固**了。可 §1.7 的表里写着 **SwiGLU**（导数不是 1），§6.5 说真正治梯度的是 **归一化放哪儿 + 残差**，而 §6.5 那段 Post-LN 的 `2^(−l/2)` 分析讲的是**归一化本身在制造梯度消失** —— 跟激活函数一点关系都没有。**这两处隔着 4000 行，中间没有一句"注意：到了 Transformer 时代，ReLU 那条线索已经不是主因了"。** 我读完带走的是一条 2012 年的知识。
→ fig-vanish Ⓒ 下面加一句就够：「⚠️ 但这是 2012 年的答案。今天的模型用的是 SwiGLU（导数不是 1），真正扛住深度的是**残差 ＋ 归一化的位置**（§6.5）—— 这一格讲的是机制，不是当代治法。」

**② §0 的头号结论，在 §5.4 被自己的例子推翻了，而且没有回头认账。**
hero + §0：「最大的那一块，既不是权重，也不是激活 —— **是优化器状态**。」
§5.4（`5793`）：「⭐⭐⭐ **激活 2.11 GiB ＞ 常驻 1.86 GiB**」—— 激活(2.11) 是优化器状态(1.40) 的 **1.5 倍**，在一个 1.25 亿参数、序列才 1024、batch 才 8 的玩具模型上。
更狠的是，拿这讲自己的数往 V3 的**真实**配置上代：每 token 激活 = 106.75 GiB ÷ 131072 ≈ 0.834 MiB；V3 真实 global batch = 15360 × 4096 = **62.9M token** → 激活 ≈ **52 TiB**，而常驻 9.76 TiB。**在这一讲的旗舰模型的真实配置下，激活是优化器状态的七倍。**
§5.1 有一句正确的话「谁最大不是模型的属性，是这次训练配置的属性」，可它**藏在 fig-step Ⓑ 的图注里**，而且从来没有回去改写 §0。作为读者，我最后同时持有两个互相矛盾的 take-away，而响亮的那个是错的那个。
→ §0 那句改成带条件的版本（「在 batch 不大的时候，最大的那一块是优化器状态 —— 而什么时候不再是，§5 会给你那个分水岭」），并在 §5.4 那个框里明写「**这就是 §0 那句话的边界，现在我们把它补上**」。这是全讲最需要的一个"转折"，材料已经全在了，只差把两头接上。

**③ "既然优化器状态最大，为什么不用 SGD？"—— 全讲没有回答。**
fig-optimizers Ⓐ 第一格白纸黑字：**SGD = 0 份状态**。我看完 Ⓑ（16 B，其中 12 B 是优化器）第一个念头就是：换 SGD，16 → 4 字节，省 75%，比 Muon（16→12）猛三倍。文里给的省状态方案是 Muon / Lion / Adafactor / 8-bit，**一个字都没说为什么不能直接退回 SGD**。
答案其实就在 fig-onelr（一个学习率伺候不了所有参数，而且"中间那个折中不存在"），可那张图的落点写的是「出路只有一条：给每个参数配它自己的那一个」，**从来没回头说"所以那 8 字节是买路钱，退不掉"**。两张图隔着 1000 行，中间缺一句话。

**④ "重算就是拿时间换空间" —— 这条对了一半，文中拆得很好，但漏了最反直觉的一半。**
§2 把兑换比（33% 算力换 97% 显存）讲得非常清楚，§2.5b 补的"重算还有一笔不在账上的代价"写得极好（随机数/副作用/逐比特）。但**漏了一条**：省下显存之后可以开更大的 batch / 更少的并行切分，于是**重算经常是净赚时间的**。文里只说「重算占已执行算力的四分之一……所以 MFU 看起来低」，语气上仍是"纯付出"。对一个从小模型来的人，"开了它反而更快"是最反直觉的那一条。

**⑤ 混合精度省显存 —— 拆得非常好，是全讲的范本。**
`3048-3068` 那张 `纯fp32 16 B vs 混合精度 16 B` 的两行表，是整讲最干净的一次"推翻旧直觉"：明确写「⛔⛔ 顺手拆掉一个最顽固的误解」、给两边算一遍、再说清它换来的到底是什么。**其他几条都该照这个模板写。**

## 六、该问没问的问题（读的时候冒出来、文中一直没回答）

1. **既然优化器状态最大，为什么不能用 SGD？**（见上，最要命的一条）
2. **反向到底存不存 `dY`？** §1.3 说"往回传的是一整个张量，形状跟这一层输出一模一样"。那这些 `dY` 本身占不占显存？它们和"激活"是同一本账吗？§5 的 fig-step 里"梯度"那条带只有 1.22 TiB（= 参数量 × 2 B），显然指的是**权重梯度**，那**激活梯度**去哪了？全讲没有一处交代（它是逐层用完即释放的，峰值约 1–2 层 —— 但这句话必须有人说）。
3. **那 12 字节的 fp32，前向的时候它在干嘛？** §5.1 说「只有优化器状态那 7.32 TiB 是纯开销……只在每一步的最后那一瞬间被用一次」—— 那我第一反应就是：**那为什么不 offload 到 CPU？** §4.3 提了一句 offload，§7.0 提了 `MUST_CPU_OFFLOAD`，§3.7 提了 V3 把 EMA 放 CPU —— **三处线索，一次都没连起来回答这个显而易见的问题。**
4. **"3 倍算力"在 128K 上还成立吗？** 这讲自己算出 attention 占一层前向的 82.1%，而 FlashAttention 的反向要**重算一遍分数矩阵**（§1.7 自己说了 flash 不落盘）。那 attention 那部分的反向/前向比就不是 2。粗算一下整体应该在 **3.4× 上下**，不是 3×。fig-3x 的 figsrc 只免责了"忽略 norm/激活/偏置/通信"，**没免责这一条**。⚠️ 这条我没有去核框架实现，只是按这讲自己的 82.1% 推的，**列在这里请作者确认，不敢当结论**。
5. **多久算"一步"？** 全讲反复说"每一步""十万步"，但从没说一步是多少 token、跑多久。§3.5 引 V3 的"2000 步 warmup"、PaLM 的"回滚 100 步"、§3.2 Ⓒ 的"半衰期 693 步" —— 这些数我全都换算不了。**"一步 = 一个 global batch"这句话值一行字。**
6. **梯度累积和 batch 到底什么关系？** §1.8 讲了累积省什么，fig-batch 讲了 batch 该开多大 —— 但没说 micro-batch × 累积次数 × 数据并行度 = global batch。到 §5.1 出现"94 条"的时候我不知道该往哪个变量上挂。

## 七、⭐ 故事线：记住的是**两条线加一堆点**

**主线是清楚的，而且很好**：
> 专题一算完前向说"装不下" → 可那只是半张账 → 反向要付 3 倍算力 ＋ 扔不掉的激活（§1）→ 第一个真取舍：拿算力换显存（§2）→ 可最大的那块根本不是激活，是优化器状态（§3）→ 于是 ZeRO 的三级是从账单里长出来的（§4）→ 合成一张总账（§5）

这条线**在 §4 之前一直很紧**。转折点也都在：
- §1.5 的"从窄的那一头起步"（最漂亮的一次转折）
- §2.4/2.5 的"同一条判据，2022 年给出相反答案"（全讲最好的一段叙事）
- §3.2 的"被 V3 一条实测打中，于是把判据从'累不累加'收紧成'老的贡献走不走'"（元级的转折，很少见）

**但有三个地方断了：**

**（a）§3.3 撑爆了。** 这一节顶着「梯度是怎么变成更新的 —— 中间那个折算系数」的标题，实际装了 **10 张图/动画**（fig-descent、anim-descend、fig-saddle、anim-saddle、fig-momentum、anim-momentum、fig-onelr、anim-onelr、fig-beststep、fig-muon），**全讲 28 张图里有 10 张在这一个 h3 底下**。§三整节 3.6 万字，是 §一的 2.2 倍。它讲的其实是**四件事**：为什么梯度下降可以（鞍点）／动量／一个学习率不够用／自适应与 Muon。我读到 fig-muon 的时候已经完全不记得这一节的标题是"折算系数"了。→ **拆成 3.3a（为什么下降可以 + 鞍点 + 动量）和 3.3b（那一步该迈多大：量纲 → 一个 LR 不够 → 除以二阶导 → Adam → Muon）。** 后者才是"折算系数"。

**（b）§6「训不崩」不在这条线上。** 全讲的脊梁是"账"，§6 一笔账都没有（它自己承认是"扫完十四份大纲之后补的"）。内容质量很高（PaLM 那个消融、ST-MoE 那张 4/6 vs 3/3 的表都是好东西），但它读起来像**另一讲的第一节**。而且它一来就把 §5.5 那个漂亮的收口（"四条里有三条写着同一个字：切"）给冲掉了。→ 要么放到附录前、明确说"这一节换个话题"，要么**给它一句接口**：spike 也是一本账 —— 每崩一次要回滚 100 步、扔掉 200–500 批数据，那是**可以换算成 GPU 小时**的。这么一接，它就回到主线上了。

**（c）该有转折却平铺的地方：§5.4 那个 125M 的例子。**
它手里握着全讲最大的一次反转（"一个 1.25 亿的玩具模型，激活就已经比常驻大了"—— 直接推翻 hero 的论断），可它的落点写的是「所以重算不是大模型的专利」和「换了 5000 倍规模，比例基本没变」。**这是把一颗炸弹当成一句注脚用了。** 它应该是第六节，标题叫「⭐ 回头看 §0 那句话 —— 它有个我们一直没说的前提」。

**顺带：§0 太短了。** 329 字，0 张图，是全讲唯一没有图的节。它承担"提出全讲论点"的任务，却只有一段话加一个提示框。对比 §一的 1.6 万字，读者还没热身就被推进 MLA 拆解表了。
