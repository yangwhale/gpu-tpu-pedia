## 这门课给谁

**目标读者**：会写 Python、懂深度学习基本概念、在 GPU 上跑过训练，但**没碰过 TPU**的工程师。

**不是给谁的**：
- 想要 API 手册的 —— 那个看官方文档更快
- 只想跑通一个 demo 的 —— 直接去 `tpu/` 下找对应项目的 README
- 找论文解读的 —— 去 `Learning/`

**学完之后应该能**：
1. 看着一个模型和一批卡，判断出该用什么并行策略、装不装得下
2. 独立把一次预训练从零拉起来，包括数据、checkpoint、故障恢复
3. 拿到一份 profile，说得出瓶颈在哪、下一步该动哪个旋钮
4. 把一个 PyTorch 模型迁到 TPU 上，并解释清楚数值对不上时该怎么查

## 编排原则

写之前先把规矩定死，否则写着写着就变成文档堆砌。

**1. 每一章都从「一个具体的坑」开始，不从定义开始。**
不要「TPU 是一种 ASIC……」。要「你把 batch 调小了，VMEM 还是 OOM —— 为什么？」
定义在解决问题的过程中自然出现。

**2. 所有数字必须是实测的，并且标出在哪一代硬件上测的。**
仓库里已有的实测数据是这门课最值钱的部分。没实测过的推论要明确写「推测」。
——这条跟 `tpu/tpuguru` 里 `evidence` 分三档是同一个原则。

**3. 讲清楚「为什么错的直觉是错的」。**
最贵的知识都是反直觉的：降 batch 治不了 VMEM OOM；编译通过不等于装得下；
块越大不等于越快。每一条这样的知识都值一个小节。

**4. 先给工具，再给结论。**
学 CS336 的做法：「算账」不是最后的总结，而是**前置的基础能力**。
学会算 FLOP、算显存、算 arithmetic intensity 之后，后面每讲一个设计都能自己算一遍代价
—— 这样结论是推出来的，不是背下来的。

**5. 每章末尾有一个能真跑的练习。**
不能真跑的课程只是读物。练习要能在最小规模上完成，不要求读者有 64 卡。
能判分的（跑得通测试）优于只能读的。

**6. 中文先行。**
先把中文写透、迭代稳定，最后再一次性翻译。不要中英并行改。

## 课程序列

**顺序的依据**：先有模型，才有对硬件的需求，才有硬件的样子。
每一课都只依赖它前面的课。

### 第一部分 · 模型（1 课）

| 课 | 主题 | 状态 |
|---|---|---|
| **[第一课](第一课/)** | **模型架构** —— 从「预测下一个词」到 MoE 与 attention 变体，八节讲透 | 🚧 大纲已立 |

跟模型架构相关的**全部**收在这一课里：tokenization、embedding、RoPE、
Attention、MLP、残差流与归一化、智商从哪来、现代架构演化、参数账。
一次讲透，后面不用回头补。

### 第二部分 · 从模型到机器（3 课）

| 课 | 主题 | 要点 |
|---|---|---|
| 第二课 | **算账** | FLOPs 怎么数、显存怎么估、**arithmetic intensity**；为什么 Attention 卡带宽而 MLP 卡算力 |
| 第三课 | **硬件** | TPU 芯片解剖、HBM 与 VMEM 两层内存、chip vs device、从芯片到 Pod 的 ICI 与 3D torus、跟 GPU 的对照 |
| 第四课 | **编程模型** | 为什么是 JAX、`jit` 到底做了什么、编译期思维、`shard_map` 与 mesh、怎么读 HLO |

> 第二课是全课的**枢纽**：它把第一课的模型知识翻译成硬件需求。
> 这一段是我们必须原创的部分 —— CS336 讲 GPU 视角，我们讲 TPU。

### 第三部分 · 规模化（3 课）

| 课 | 主题 | 要点 |
|---|---|---|
| 第五课 | **并行策略** | 数据/张量/流水/专家四种切法、FSDP 在 TPU 上、MoE 的 all-to-all、显存账怎么算、**先选拓扑再调参** |
| 第六课 | **训练实战** | MaxText 配置系统、数据管线、checkpoint、提交作业与抢占、跑起来之后看什么、故障恢复 |
| 第七课 | **性能工程** | MFU 什么时候会骗人、抓 profile、三种瓶颈长什么样、通信隐藏、XLA flag 的依赖关系、精度与量化、**调参的天花板** |

### 第四部分 · 落地（2 课）

| 课 | 主题 | 要点 |
|---|---|---|
| 第八课 | **推理** | 跟训练的根本差异、KV cache、静态形状与分桶、vLLM / SGLang 在 TPU 上、吞吐与延迟的取舍 |
| 第九课 | **迁移** | 重写 JAX / torchax / PyTorch-XLA 三条路、算子对不上怎么办、**数值验证方法论** |

### 第五部分 · 边界之外（2 课，概览）

> **刻意放在最后**，因为这两块跟模型架构和加速器系统都不直接相关。
> 只讲它们「对系统提出了什么不同的要求」，深入的部分指向 CS336。

| 课 | 主题 | 我们的切入角度 |
|---|---|---|
| 第十课 | **数据**（概览） | 数据管线本身就是个吞吐问题 |
| 第十一课 | **后训练与 RL**（概览） | RL 的并行模式跟预训练完全不同 —— 这是我们有积累的角度 |

### 贯穿全课 · 工程素养

不单独成课，分散进各课的侧栏。列在这里是为了保证不漏：

- 测量纪律：一次只改一个变量；temperature=0；跑三次取中位数
- 证据分级：实测 / 编译器输出 / 推测，不许混着报
- 失败要留证据：日志落盘、开 verbose
- 反直觉清单：全课收集到的「看着对其实错」的判断

## 每一课的目录结构（约定）

**每一课都长成一样**，找东西不用想。新建一课时照抄这个骨架：

```
第N课/
├── README.md          这一课讲什么 + 大纲 + 练习
├── 教学材料/           ← 相关的东西都往这里放
│   ├── README.md          材料清单：哪来的、什么许可、能不能公开
│   ├── <来源>文字版/       抓下来的原文
│   ├── <来源>图/           渲出来 / 下载的图
│   └── ...                我们自己写的、画的
├── RENDER.md          （按需）图怎么生成的
└── *.sh               （按需）能重跑的脚本
```

### 三条规矩

1. **材料先进 `教学材料/`，别散在别处。** 想不清楚放哪就先扔进去，之后再归类。
2. **每样材料都要在 `教学材料/README.md` 里有一行**，
   写清楚三件事：哪来的、什么许可、**能不能进公开仓库**。
3. **产物入不入库，看重建成本。**
   - 小、稳定、但**重建要搭一套环境**的 → 入库（例如渲出的图）
   - 大、易变、或**一条命令就能重来**的 → 不入库（视频、编译产物、缓存）

   无论入不入库，**生成它的东西必须在库里**：脚本、抓取命令、场景引用。
