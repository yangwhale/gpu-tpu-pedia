[warmly] 各位好，欢迎来到专题一，一个 Token 的一生。

[curiosity] 开始之前，先请大家猜一个数。拿 DeepSeek V3 这个模型，喂给它一篇十二万八千个 token 的长文档，做一次 prefill，也就是把整篇文档读进去，还没开始往外吐字。读完这一遍，有一样东西必须留在显存里：后面每生成一个字，都要回头用到前面每一个字、在每一层算出来的 K 和 V。这份东西就叫 KV cache。

[thinking] 问题是：这一次读完，留下的 KV cache 有多大？给大家一个参照：一个 TPU v7 device 能用的显存，大约是九十四点七四个 GiB。四个选项：大约 4 个 GB，大约 9 个 GB，大约 30 个 GB，还有大约 500 个 GB。大家先想一想，心里选一个。

[realization] 答案是八点五八个 GiB，差不多是一张卡的百分之十。

[friendly] 这个数怎么来的？三步，每一步只乘一个数。第一步，一个 token 在一层里要存五百七十六个数。五百一十二是压缩以后的 K 和 V，另外六十四是带位置信息的那一小截。每个数两个字节，一共一点一个 KiB。第二步，乘以六十一层。每一层各存各的，谁也替不了谁，于是一个 token 走完全程就是六十八点六个 KiB。第三步，乘以十三万一千零七十二个 token，就得到八点五八个 GiB。

[contemplative] 这里有个地方值得停一下：为什么它非得乘层数？一般的中间结果算完就能扔。第三层的激活进了第四层就没用了，寿命只有一层，所以不跟层数相乘。KV cache 不一样。生成第 n 加一个字的时候，前面 n 个字在每一层的 K 和 V 都还要再用一遍。所以它的寿命是整段对话，要跟六十一层相乘，随着长度一直往上涨，中途不释放。判断的办法就一句话：问一问下一个 token 还要不要用它。要用，就是 KV cache；不用，算完就扔。

[curiosity] 再说另外三个选项。它们不是随便编的干扰项，每一个都是真数字，只是换了一种存法。

[seriously] 最传统的做法，一百二十八个头各存一份，每个 token 每层要存三万两千七百六十八个数，整篇文档是四百八十八个 GiB，这就是那个五百 GB。把一百二十八个头分成八组，每组共用一份，这是 Llama 那一类的做法，是三十个 GiB 左右。所有头只共用一份，最省，三点八一个 GiB，就是那个 4 GB。V3 的做法是把 K 和 V 压成一个五百一十二维的小向量，落在八点五八。

[realization] 同一个模型、同一篇文档，只因为每个 token 每层存几个数不一样，答案就差了一百二十八倍。四百八十八个 GiB 是什么意思？光是 KV cache 就要五张多卡，模型权重还一个字节都没放，而且这还只是一个用户。八点五八个 GiB 呢，一张卡的十分之一，顺手就放下了。一个是得先想办法凑机器，一个是随手就装下，差别就这么大。

[thinking] 大家可能会问：最省的那个只要三点八一，比 V3 还省，为什么不直接用它？这个问题请先记着。简单说一句：最省的那种，是让所有头共用同一份 K 和 V 省出来的，省下显存的同时，表达力也真的丢了，找不回来。V3 省得几乎一样多，却没有让任何一个头做出牺牲。它是怎么做到的，第二步整整一节都在讲这件事。

[friendly] 不过今天的重点不是这几个数字，而是你能不能自己把它们算出来，以及算的过程中会撞见哪些反直觉的东西。这一课就干这一件事：跟着一个 token 走完全程，每走一步就把账算一遍。

[casually] 那为什么偏偏拆 DeepSeek V3？三个理由。第一，它是事实上的标准。后来的开源模型，基本都是从它出发再改。举个例子，2026 年腾讯开源的混元 3，MoE 那一部分几乎是逐项照着 V3 做的：sigmoid 路由、不用辅助损失的负载均衡、共享专家、多 token 预测，连「前几层保持稠密」那个配置项的名字都一样，只把注意力换掉了。所以把 V3 拆明白了，再看后面那一批模型，看到的是同一套零件的不同排列。

[seriously] 第二，它一次做成了三件事：MLA 把 KV cache 压下去，细粒度的 MoE 把激活参数压下去，FP8 把训练成本压下去。第三，这三件事各对着一个硬件瓶颈，分别是显存、算力、带宽。三个瓶颈，三个答案，这正是这门课要建立起来的那条因果链。

[curiosity] 请看这张图，六千七百一十亿参数到底是个什么概念。深色的条是总参数，也就是显存要装的；浅色的条是激活参数，也就是每个 token 实际要算的。稠密模型这两个数相等，MoE 模型把它们掰开了。V3 的总参数是 GPT-3 的三点八倍，可每个 token 实际要算的只有它的零点二一倍。更大和更贵，从 2024 年以后就不再是一回事了。这门课后面所有的账，都建立在这个分裂之上。

[focus] 好，要算账，先得有尺子。算账最容易出的问题不是算错，而是中途换了尺子。所以我们先把口径钉死，后面一路不改。

[casually] 一共五条。第一，序列长度取 128K，也就是十三万一千零七十二个 token，差不多一本小书。第二，batch 等于一，先把单独一条算清楚，要乘再乘。第三，精度按 bf16，每个数占两个字节。第四，只算前向，不算反向。第五，参照物是一个 TPU v7 device 的九十四点七四个 GiB，所有算出来的数，最后都拿它来比一比，不然没有感觉。

[thinking] 这五条里最需要解释的是第四条：为什么只算前向？因为前向的账是事实，反向的账里掺着决策。前向就是一步一步的矩阵乘，每一步多大都是确定的，没得选。反向不一样，你得先做决定：算完的中间结果留着，还是用到的时候再重算；优化器状态放哪张卡；梯度要不要攒几步再更新。这些都是策略，不同的人选法不同，算出来的数就完全不一样。把决策混进事实里，这笔账就说不清了。所以这一课只算所有人都必须付的那部分，反向留到专题四，那时候大家已经会算账了，再谈策略才谈得动。

[friendly] 尺子有了，再发一份底牌。请看这张模型配置表。它有二十多行，但大家千万别一行一行去记，今天只需要挑出四样东西。

[casually] 第一个数，hidden size，七千一百六十八。这是残差流的宽度，也就是贯穿全程的那条主干道有多宽。后面每一步算激活，都是拿 token 数乘以它。如果只能记住一个数，就记这个。

[curiosity] 第二个数，六十一层。这个数本身不稀奇，稀奇的是紧挨着它的那一行：前三层是普通的稠密 MLP，从第四层开始才是 MoE。所以准确地说，V3 是三层稠密加五十八层 MoE。这个三和五十八，后面算参数量的时候要反复用到。

[thinking] 第三个其实不是数，是一个 false：进门那张查词表的大矩阵，和出门那张把向量变回词的大矩阵，不共享权重，是两份独立的。很多模型选择共享，能省一份参数；V3 选择不共享，多出来九亿多个参数。大家可以想一想，为什么有的模型共享、有的不共享？这个问题留到最后，我们走到出口的时候再回答。

[seriously] 第四样不是一个数，是一句话，也是这张表最重要的一句：表里的每一个数，都来自 DeepSeek 官方公开的配置文件，没有一个是估的，也没有一个是我们自己测的。后面所有的推导都从这张表出发。等到最后合账那一步，我们会算出总参数六千七百一十亿、激活三百六十六亿，刚好对上官方公布的口径。到那一刻，这句话就兑现了。

[friendly] 最后看一眼路线。一个 token 从文字进来，从一个概率分布出去，中间一共七步。第一步，嵌入，从文字变成向量。第二步，MLA，也就是注意力，以及 KV cache 的那场仗。第三步和第四步共用一格，是二选一，不是先后：前三层走稠密 MLP，后五十八层走 MoE。第五步，层和层之间的残差流。第六步，出口，从向量回到文字。第七步，把账合起来。一路贯穿全程的，是残差流这条总线，每一层都从它这里读，再往它这里写。
