## 这门课给谁

**目标读者**：会写 Python、懂深度学习基本概念、在 GPU 上跑过训练，但**没碰过 TPU**的工程师。

**不是给谁的**：
- 想要 API 手册的 —— 那个看官方文档更快
- 只想跑通一个 demo 的 —— 直接去 `tpu/` 下找对应项目的 README
- 找论文解读的 —— 去 `Learning/`

**学完之后应该能**：
1. 看着一个模型和一批卡，判断出该用什么并行策略、装不装得下
2. 独立把一次预训练从零拉起来，包括数据、checkpoint、故障恢复
3. 拿到一份 profile，说得出瓶颈在哪、下一步该动哪个旋钮
4. 把一个 PyTorch 模型迁到 TPU 上，并解释清楚数值对不上时该怎么查

## 编排原则

写之前先把规矩定死，否则写着写着就变成文档堆砌。

**1. 每一章都从「一个具体的坑」开始，不从定义开始。**
不要「TPU 是一种 ASIC……」。要「你把 batch 调小了，VMEM 还是 OOM —— 为什么？」
定义在解决问题的过程中自然出现。

**2. 所有数字必须是实测的，并且标出在哪一代硬件上测的。**
仓库里已有的实测数据是这门课最值钱的部分。没实测过的推论要明确写「推测」。
——这条跟 `tpu/tpuguru` 里 `evidence` 分三档是同一个原则。

**3. 讲清楚「为什么错的直觉是错的」。**
最贵的知识都是反直觉的：降 batch 治不了 VMEM OOM；编译通过不等于装得下；
块越大不等于越快。每一条这样的知识都值一个小节。

**4. 边走边算，不留到最后总结。**
「算账」不是一门独立的课，是**每讲一个部件就立刻算它的代价**。
学会算 FLOP、算显存、算 arithmetic intensity 之后，每个设计选择都能自己推一遍
—— 这样结论是**算出来的**，不是背下来的。

**4b. 拆真模型，不讲通用架构。**
不讲"Transformer 一般长什么样"，而是拆 DeepSeek V3 这一个具体的模型，
所有数字取自它的官方 `config.json`。通用规律在拆的过程中自然浮现，
但**每个数都能对回一个真实字段**。

**5. 每章末尾有一个能真跑的练习。**
不能真跑的课程只是读物。练习要能在最小规模上完成，不要求读者有 64 卡。
能判分的（跑得通测试）优于只能读的。

**6. 中文先行。**
先把中文写透、迭代稳定，最后再一次性翻译。不要中英并行改。

### 一 · 拆开 DeepSeek V3

不泛讲「Transformer 是什么」，而是**拆一个真模型**：跟着一个 token
从分词一路走到出口，七站，**每站问同样四个问题** ——
权重多大、激活多大、多少 FLOPs、**有没有什么东西在这里爆炸**。

口径固定：**128K 序列、batch=1、bf16、只算前向**。
走完之后，「装不进任何一块卡」是**算出来的结论**，不是一句口号。

> 为什么是 V3 而不是 GPT-3：早就不是 175B 那个时代了。
> V3 是当下事实上的黄金标准，后来的开源模型基本都从它出发再改。
> 而且它一次把三件事做成了 —— MLA 压 KV、细粒度 MoE 压激活、FP8 压成本，
> **每一件都直接对应硬件上的一个瓶颈。**

### 二 · 注意力演进

MLA、GQA、SWA、DSA、NSA、CSA、HCA、DeltaNet、GDN、KDA……
**它们在解同一道题，只有三个旋钮**：
每 token 存多少 · 每 query 看多少 · 换一套数学。

两条动机线要分开讲：**硬件账**（KV cache 随长度和层数双重增长，必须省）
与**信息账**（注意力矩阵本来就极稀疏、远近关注性质不同，可以省而不太亏）。

### 三 · 反向与优化器

专题一只算前向。这里把账补全，会发现：

> **最大的一块既不是权重也不是激活，是优化器状态。**

bf16 混合精度 + AdamW 下，每个参数在显存里有五个分身，合计 **16 字节** ——
其中三份 fp32（主权重 + 一阶动量 + 二阶动量）就占 12 字节，
是 bf16 权重的六倍。**模型本身反而是账单上最小的一项。**

再往下拆：ZeRO 三级各自的账、为什么 ZeRO-1 几乎不随卡数下降、
以及 FSDP 下 bf16 权重根本不常驻而是**流动的**。

### 四 · 并行策略

专题三算完账，这里回答「那怎么切」。骨架是一张按**切哪一维**分类的表：
batch / 隐藏维 / 序列 / 层 / 专家 / 跨 DCN。

> ⭐ 表里最要紧的是**频率**那一列：TP 每层来两次，只能待在最快的互联里；
> DP 每 step 才一次，所以能横跨数据中心。**这条规律直接决定拓扑怎么映射。**

含 DP · ZeRO/FSDP/HSDP · TP · SP 与 CP（澄清这两个最容易混的名词）·
PP/VPP 的调度演进 · EP 家族（EP / ETP / EDP）· 跨 DCN，
以及 **strong scaling vs weak scaling** 这个评价维度。

### 五 · 最新开源模型对比

专题一拆透一个，这里横着看一排：DeepSeek V3.2 / V4-Pro / V4-Flash、
Kimi K3、Qwen、混元 3、GLM、MiMo、MiniMax、Ling……

一张主表 + 三张分表（注意力路线 / 专家配置 / 其它创新）。
数字**只从各家的 `config.json` 来**，二手材料在这个专题里特别危险
—— 同一个模型不同文章报的参数量能差一倍。

> ⭐ 分表 A 里最要紧的一列是 **「每 token 每层的 KV 字节数」**：
> 各家方案名字五花八门，折算成这一个数就完全可比了，
> 而且它直接决定推理时能服务多少并发。

价值不在表本身（那会过期得最快），而在**读表的方法**和几条趋势判断：
哪些已经收敛可当定论、哪些还在分叉值得深挖、以及**从表里能读出什么硬件信号**。

### 六 · TPU 与 GPU

不罗列参数 —— 那种对比解释不了为什么同一个模型在两边要用完全不同的方式跑。
真正的答案从**出身**说起：

> **GPU 从图形渲染长出来，基因是「大量独立小核 + 运行时灵活调度」；
> TPU 一开始就是为神经网络造的 ASIC，基因是「少数巨大的矩阵单元 +
> 编译期把一切排好」。**

这条差别一路向下贯穿：芯片结构（上百个 SM vs 巨大的 MXU）→ 内存层次
（**HBM 与 VMEM 是两层**）→ 互联（NVLink 域 vs ICI torus）→
编程范式（**静态 vs 动态**）→ 软件栈（Megatron vs MaxText、
CUDA/Triton vs Pallas、vLLM/SGLang 两边的落地）。

一句话收束：**差别不是谁更强，是把控制权交给谁** ——
交给人就得有人写得出来，交给编译器就得接受它的脾气。

> ⭐ 这个专题的分量在最后一节：**同一个模型两边都跑过** ——
> 混元 3 295B 在 GB300 和 TPU v7 上都完整调过。
> 网上讲 TPU vs GPU 几乎全是纸面对比，这种数据别人给不了。

### 七 · 性能调优与工具链

模型跑起来了，MFU 只有 20% —— **剩下那 80% 去哪了？**

大多数人的做法是开始试参数、抄别人的 flag。**那不叫调优，叫碰运气。**
真正的调优只有两步，而且顺序不能反：**先定位，再动手。**

- **判据**：屋顶线 + **算术强度**。它把「感觉慢」变成「落在图上哪个位置」
- **硬件**：MXU / VPU / SparseCore / HBM / VMEM / ICI 各管什么 ——
  **它们能并行工作，所以「MXU 利用率 90%」不等于好**
- **编译栈**：JAX → HLO → LLO → 机器码。融合成不成常常就是快慢的分界
- **工具**：XProf 各页什么时候看；kernel 内部要用 **Percale**
- **定位顺序**：step 稳不稳 → 有没有空洞 → 通信盖住没 →
  MFU 与带宽的组合 → **最后才看单个算子**
- **手段按代价排**：XLA flag → tile size → recompute → 并行拓扑 → 改实现 → 写 kernel

> ⭐ 这个专题素材最厚（光调优战役记录就上万行），工作主要是**做减法**。
> 也是唯一要正式讲「**什么时候该停下来**」的地方 ——
> 混元 3 从 445 调到 645 之后，八格参数扫下来零收益，
> 那时候该换的是思路不是参数。

### 八 · 后训练与 RL

前七个专题讲的都是预训练。后训练的不一样**不在算法上，在系统上**：

> **预训练的循环里只有训练。RL 的循环里，训练和推理是交替的。**

模型先要生成一批回答（推理），再据此更新自己（训练）。
于是一套 RL 系统里同时住着训练框架和推理引擎，共享权重、抢同一批卡。

- **脉络按「砍掉了什么」讲**：PPO 要 4 个模型同时驻留，DPO 砍到 2 个，
  GRPO 用组内相对比较砍掉 critic。
  **算法演进史从系统角度看，就是一部削减模型数量的历史** ——
  DPO / GRPO 的流行很大程度是被系统成本推动的
- ⭐ **generation 吃掉 80-90% 的墙钟时间**（HuggingFace 16 框架横评）——
  也就是说 **RL 训练系统首先是一个推理系统**，优化训练那一侧的天花板只有 10-20%
- **rollout 那一节是核心**：权重同步、角色放置、
  以及「生成是带宽受限、训练是算力受限，同一批卡两个阶段瓶颈完全不同」
- **四个引擎**：veRL（事实标准）· AReaL（全异步，蚂蚁+清华）·
  slime（THUDM）· **Tunix（Google，JAX 原生 —— TPU 侧的答案）**。
  行业已收敛到同一架构：推理训练拆池、中间 buffer、权重异步同步
- **异步 RL 是纯粹为硬件利用率做的算法妥协** —— 又一个硬件塑造算法的例子
- **长推理链把前面的账全部重算一遍**，而且条件更苛刻

> 算法脉络参考了 [Large-Model-King](https://github.com/yangwhale/Large-Model-King)
> 第四篇「御兽之法」—— 那边把 o1、R1、GRPO 这条线讲得很好看，
> **这里讲的是另一半：每一代对系统提了什么新要求。**

### 九 · Diffusion 与 DiT

前八个专题全是 LLM。这一个换一族模型，**用同一套框架再走一遍**。

从"它在干什么"讲起（不碰数学）：加噪与去噪、为什么必须在 latent space 里做、
VAE 的下采样与上采样、U-Net 的卷积怎么让位给 DiT 的注意力、条件怎么注入。

> ⭐ **DiT 取代 U-Net 的三个理由，正好是全课主线在另一个领域的复现**：
> scaling 更好、能复用 LLM 的整套基础设施、
> **大而规整的矩阵乘正是 MXU 想要的**（卷积那种滑窗访存反而别扭）。
> **架构在趋同，因为硬件和工程栈在趋同。**

落点是一张对照表 —— Diffusion 跟 LLM **处处相反**：

| | LLM（decode） | Diffusion |
|---|---|---|
| KV cache | 头号瓶颈 | **没有** |
| 序列长度 | 变长 | **固定** |
| 瓶颈 | 带宽受限 | **算力受限** |
| 对 TPU | 要跟静态形状搏斗 | ⭐ **天生合拍** |

这一块我们的实战素材极厚：DiT 实现分析、2000 行 VAE 的
PyTorch→JAX 迁移全过程、Splash Attention 调优、
HunyuanVideo / CogVideoX / Wan / Flux / SDXL 的 TPU 部署与实测加速比。
