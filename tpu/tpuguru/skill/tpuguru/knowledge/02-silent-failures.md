# ★ 会静默出错的组合（最重要的一篇）

> 这些的共同特征：**跑得通、不报错、loss 照常下降**，唯一症状往往是「快得离谱」。
> 判断这类问题**必须看「实际走到了哪条代码路径」**，只看「编译通过了」毫无意义。

## 通用判据

> **把维度 N 切成 N/k，而下游能把 N/k 当成一个合法的小 N 来用时，分片错误就会静默。**

对照两种切法：

| 切法 | 本地形状 | kernel 看到的 | 后果 |
|---|---|---|---|
| 按 **收缩维**切（如 embed） | `[192, 64, 1536]` | 192 个**残缺**专家，维度对不上 | **算不动** → 编译器被迫插 all-gather |
| 按 **组维**切（如专家） | `[3, 4096, 1536]` | 3 个**完整**专家，形状合法 | **算得了** → 静默算错 |

**安全的切法是切到「切了就算不动」的维度上**，让编译器替你兜底。

## 案例一：MoE 权重漏 all-gather（花了两天）

**触发**：专家维分片 + `fixed` 校准 + **非** tokamax kernel，三者同时成立。

**后果**：kernel 只对本地那几个专家建组元数据（`num_nonzero_groups = rhs.shape[0]`），
**其余专家的行完全不参与计算**。

**代价**：曾报 ~~1,014.8~~ per-chip（**已作废，任何地方看到都当无效**），补齐 all-gather 后 **637.0**（掉 1.59×）。
那「+49.9% 的提升」全部来自漏算。

**为什么代码会这样**：`all-gather` 与反向的 `psum_scatter` **只写在一条分支里**
（它被当成一个通信优化特性，而不是分片布局的正确性要求）。另一条分支的
kernel 函数签名里**根本没有这个参数** —— 指令传进去了，没人执行。
**前向漏收、反向漏散，成对出现** —— 典型的「加功能只改了一条分支」。

**怎么发现的**：
1. profile 里 `tgmm` 输出是 `[3,4096,1536]` 而不是 `[192,...]`
2. 只打前向补丁不打反向时，JAX 形状检查直接报
   `scatter dimension size 3 must be divisible by shard_count 64` —— **编译器自己说出是 3**
3. kernel 单独计时：metadata 自报「覆盖行 3,582 / 229,376」

## 案例二：tile 参数漏传

MoE 模型不传分块参数 → **静默回退默认 tile**：BF16 慢 **26%**，FP8 直接崩。
而且注入式的 monkeypatch 可能**打在没启用的那条路上** ——
加计数器实测「被调用 0 次」，却照常打印「patched」。

## 案例三：只开一半开关

只开分片开关、不配对应的校准方式 → **静默失效，不报错也不变快**。
（因为它退回了另一条安全路径。）

## 排查这类问题的三步

1. **把实际走到的代码分支打出来**（trace 期 print，不是猜）
2. **把 kernel 的实际入参形状打出来** —— 注意可能看到的是「变换之前」的中间态
3. **对照一个已知正确的配置**跑同样的探针，比形状而不是比结论

## 怎么当场验证（每条都给动作，不要只记结论）

### 验「kernel 实际收到几个专家」

trace 期在 kernel 入口打印入参形状：

```python
def w(lhs, rhs, group_sizes, *a, **k):
    print(f"KERNEL rhs={getattr(rhs,'shape',None)} "
          f"gs={getattr(group_sizes,'shape',None)} "
          f"wga={k.get('weight_gather_axes')}", flush=True)
    return orig(lhs, rhs, group_sizes, *a, **k)
```

**读数**：`rhs` 第 0 维 == 完整专家数 → 正常；== 专家数/分片宽度 → 查有没有收集。

⚠️ **可能看到的是「变换之前」的中间态** —— 编译器可能把收集提到了外面。
要交叉验证：看 HLO 里有没有从分片形状到完整形状的转换算子。

### 验「收集到底发没发」

在 profile 里按算子名找收集类算子，看两个数：

| 看什么 | 正常 | 异常 |
|---|---|---|
| **执行次数** | 每步一次（编译器提升出循环了） | 每层一次（手写的，没提出去） |
| 输入→输出形状 | 从分片形状变成完整形状 | 找不到这样的算子 = **没收** |

### 验「tile 参数有没有真的生效」

给注入点加计数器。实测遇到过**打印了「已安装」但被调用 0 次** ——
补丁打在了没启用的那条路上。

### 验「量化有没有生效、用的哪种校准」

从日志抓配置回显，**不要看你传了什么，要看它解析成了什么**。

### 验「这个改动有没有改变数值」

见 `09-verification.md`。**不要用短程 loss。**
