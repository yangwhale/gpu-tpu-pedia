[friendly] 好，我们进入第一节：先认识卡和卡之间会说的几种话。

[curiosity] 先问大家一个问题。一千张卡，要把各自算出来的结果加在一起，最省事的办法是什么？很多人第一反应是：找个班长，大家都交给他，他加完再发回来。可这样一来，班长一个人要收发九百九十九份。换个办法，大家围成一圈，每人只跟邻居说话，每个人只需要传一点九九八份。差了五百倍。这一节就讲这是怎么做到的。

[thinking] 通信的名字看着一大堆，其实每一种只回答两个问题：谁发给谁？东西到了之后，是拼起来，是加起来，还是原样放着？

[friendly] 先花十秒学会看图，后面所有的图都是这个画法。屏幕上有四张卡，一张一个颜色：卡 0 蓝，卡 1 橙，卡 2 绿，卡 3 紫。每张卡的数据切成四小块，虚线框表示空的。最要紧的一条：哪一块上面出现了竖条纹，就说明它被加过了；条纹里有几种颜色，就是几张卡的数加在了一起。

[focus] 我们用一个班级来想。四个同学，每人一份作业，切成四块。最简单的几种都有一个班长，就是卡 0。左上，班长把一整份作业给每个人发一份，这叫广播。右上，班长把一份作业拆开，一人分一块，这叫分发。左下，大家把自己那一块交给班长，班长拼起来，这叫收集。右下，大家把整份交给班长，班长把对应位置的分数加起来，这叫归约。

[realization] 大家看这几段小动画的时候，注意一件事：收集和归约只差一个动作。东西都送到了班长那儿，一个是拼起来，一个是加起来。你看归约之后班长手里那四块，条纹里四种颜色都有，就是四个人的数加在了一起。

[seriously] 班长模式有个毛病：按最朴素的做法，所有东西都要挤过班长那一条线。人一多，班长就堵死了。所以训练里真正天天在跑的，是名字前面带 All 的那几个。All 的意思是：结果人人都有一份，不用再去找班长要。

[focus] 请看下一张图。左上是全收集，AllGather：开始每人一块，结束时每人四块都有，只拼不加。右上是归约分散，ReduceScatter：开始每人一整份，结束时卡 0 只拿第 0 块的总和，卡 1 只拿第 1 块的总和，先加，再分。左下是全归约，AllReduce：开始每人一整份，结束时每人都有四块的总和。数据并行同步梯度，用的就是它。右下那个长得不太一样，先放着，最后讲。

[excitement] 接下来是今天最重要的一个等式：AllReduce，等于 ReduceScatter 加上 AllGather。先加，每人拿到一块总和；再拼，每人拿到全部的总和。结果跟一步到位完全一样。

[curiosity] 为什么要拆开？因为拆开以后，这两半可以放到不同的时间去做，中间还能塞进别的动作。下一节你就会看到：中间塞进一次「更新」，每张卡就能少存一大块东西，而通信一个字节都不多。

[thinking] 那没有班长，怎么做到人人一份？答案是围成一个环，每人只跟右边的邻居说话。先做 ReduceScatter：每一步，每张卡同时把手里的一块发给右边，再从左边收一块，加到自己同号的那一块上。大家看动画，第一步之后，有的块是两个人的和；第二步之后，是三个人的和；四张卡转三步，每人手里都有一块是四个人的总和，就是条纹四种颜色都齐了的那一块。注意卡 3 那块，它不是往左飞，而是从右边出去，绕回卡 0，大家始终都往右发。

[focus] 接着用同一个环再转三步，这一次只拼不加，把各自那块总和传给所有人。这后三步就是 AllGather，前后合起来，就是一次 AllReduce。

[realization] 我们数一下每张卡发了多少。每一步发四分之一份，一共走六步，加起来一点五份。换成一千张卡，每一步发千分之一份，走一千九百九十八步，加起来一点九九八份，这就是开头那个数。

[friendly] 请看这张对比图。同一个 AllReduce，有两种拼法。左边是班长做法：先全加到卡 0，再从卡 0 发回去，卡 0 要发三份，别人各发一份。中间就是刚才的环，每张卡都只发一点五份。结果一模一样，差的只是谁在干活。右边那张小表，班长那一列跟着卡数一路往上涨，环那一列永远不到二。所以这个等式不光成立，它还是赢家。

[seriously] 环也有代价：步数跟着人数涨。数据很大的时候，比的是每个人的带宽，环几乎最省；数据很小的时候，比的是一步一步的等待，步数多反而吃亏。所以通信库会按数据大小自己挑算法，小数据改走树形。TPU 更直接：用专用快线连在一起的一整块芯片叫一个切片，大切片上的芯片之间，本来就连成了环。

[curiosity] 最后一种最特别，叫 AllToAll，全交换。每个人手里都有要给每个人的一份，而且每一份都不一样，就像每个人各做一次分发。

[focus] 它在专家并行里最典型。请看这张图：每个 token 已经由路由定好要去哪张卡。派发的时候，所有卡同时往所有方向寄，线越粗寄得越多；每人寄给每人的数目都不一样，收件那边也忙闲不均，卡 0 收了十一个，卡 3 只收了六个。专家算完，再沿着原路寄回去，这叫合并。每份一样大的时候，它正好是把一张表转置一次，但那只是特例。

[seriously] 为什么网络最怕它？第一，每一份都是写给某一个人的私信，路上没法边走边合并。第二，前面几种都能排成只跟邻居说话的环，它不行，任意两张卡之间都有东西要走，拼的是整个网络的横截面有多宽。第三，每一份多大，要等模型算到这一层才知道。大家记住它，后面切专家的时候，每一层都要用它两次：寄过去一次，原路寄回来又一次。

[thinking] 数一下。刚才我们看了八个名字，但带班长的那四个只是积木。日常真正用到的就五种：AllReduce、AllGather、ReduceScatter、AllToAll，再加最朴素的一对一收发。后面把模型按层切成几段的时候，段和段之间传东西，用的就是一对一收发。

[friendly] 这一节，大家带走两件事就够了：AllReduce 能拆成两半；AllToAll 是人人给人人发不一样的东西。开场那张路线图上，每个盒子那一行过路费，都是这五种里的某一种。话认全了，下一节，第一刀：切数据。第一节就到这里，大家有问题吗？
