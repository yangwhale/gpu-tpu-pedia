## 这一课的规矩

第一次讲，**不求全，求讲透**。四条硬要求：

| | 具体到做法 |
|---|---|
| **引人入胜** | 每节从一个能让人愣一下的问题或画面开始，不从定义开始 |
| **浅显易懂** | 一个概念只用一个比喻，讲完就用它贯穿到底，不换喻 |
| **言简意赅** | 每节 10-15 分钟，讲不完的砍掉，别压缩 |
| **图文并茂** | **每节 4-6 张图**，图是主角，文字是旁白 |

**砍掉了什么**（都留给后面的课，不是遗漏）：

- 架构演化（MLA、线性注意力、MoE、现役模型对照）→ **单独一课**，它自己就值一小时
- 可解释性的深挖（induction heads、circuit、attribution graph）→ 第 4 节只留一段，其余单独讲
- 归一化与 pre-norm/post-norm 之争、RoPE 的数学 → 各留一句，不展开
- 分词的细节（BPE 怎么合并） → 一张图带过

## 五节

### 1 · 一台会接话的机器（10 min）

**开场**：给你一份剧本，人物的话都在，AI 的回答被撕掉了。
你手上有一台机器，能对任意一段文字预测下一个词。你会怎么把剧本补完？

- LLM 的定义就这一句：**一个预测下一个词的函数**。
  它不给一个确定的词，给的是**所有可能词的一个概率分布**
- 聊天机器人只是在前面加了一段「用户与 AI 助手对话」的开场白，然后反复接龙
- **模型是确定的，回答每次不一样** —— 因为是采样，不是取最大。
  故意选一些不那么可能的词，出来的文字才自然
- 「大」在哪：参数就是旋钮，**几千亿个，没有任何人手动设过其中任何一个**
- 训练在做什么：把最后一个词遮住让它猜，然后微调所有旋钮，
  让真答案的概率高一点点、其它的低一点点。重复几万亿次
- 为什么 2017 年之后是 Transformer：之前的模型**一个词一个词地读**，
  Transformer 一次把整段吞进去 —— **它能并行**
  > 🔑 埋第一个钩子：**架构的选择，从一开始就被硬件的形状塑造着。**

### 2 · 词变成向量，方向是有含义的（10 min）

**开场**：计算机只会算数。那「猫」这个字怎么变成能做乘法的东西？
而且变完之后，为什么「国王 − 男人 + 女人」会约等于「女王」？

- 先切成 **token**（不完全是词，是词的碎片）—— 为什么不按字也不按词，一张图带过
- 每个 token 查表变成一个**向量**：GPT-3 是 12,288 维
- **核心直觉：方向有含义。** 训练之后，空间里的某些方向会对应某种概念
  - 性别方向：king − man + woman ≈ queen
  - 复数方向：cats − cat，拿它跟 one/two/three/four 做点积，值单调上升
- **点积衡量对齐程度** —— 记住它，第 3 节整个 attention 都靠这一个运算
- 位置信息要额外补进去（Transformer 天生看不见顺序）—— **一句带过，不展开**
- 这一步只是查表，**每个向量还只知道自己**。让它们互相认识，是下一节的事

| 图 | 用来讲 |
|---|---|
| `embedding/DiscussTokenization` | 一句话被切成 token |
| `embedding/IntroduceEmbeddingMatrix` | 嵌入矩阵：每个词一列 |
| `embedding/ThreeDSpaceExample` | 词落在高维空间里（投影到三维看） |
| `embedding/ManyIdeasManyDirections` | 一个方向 = 一个概念 |
| `embedding/DotProducts` | 点积在量什么 |

### 3 · Attention：让词互相通气（15 min）

**开场**：*bank* 这个词，放在 *river* 旁边和放在 *money* 旁边，是同一个意思吗？
查表查出来的向量并不知道这件事 —— 它只认得自己。

- 要解决的问题：**一个词的含义由上下文决定**
- **Query / Key / Value** 三个矩阵，用一个招聘的比喻贯穿：
  - Query =「我在找什么样的人」
  - Key =「我是什么样的人」
  - Value =「配上了的话，我把什么交给你」
- 用**点积**算 Q 和 K 的匹配度 → softmax 变成权重 → 加权取 Value
- **Causal mask**：训练时一次算完整句，但每个位置都不许偷看后面
- **多头**：一次问多个不同的问题（GPT-3 每层 96 个头）
- 关键一句：**这一步不产生新知识，只做信息的搬运和路由**

|---|---|
| `attention/AttentionPatterns` | ⭐ 主图：整张权重矩阵 + ΔE 更新 + E′ 结果 |
| `attention/QueryMap` | Query 矩阵在干什么 |
| `attention/KeyMap` | Key 矩阵在干什么 |
| `attention/ShowMasking` | causal mask：不许偷看未来 |

### 4 · MLP：事实存在这里（15 min）

**开场**：问模型「Michael Jordan 打什么球」，它答篮球。
这条知识，**具体存在哪几个数字里**？

- 跟 attention 正好相反：向量之间**不通气**，每个各走各的，完全并行
- 三步：**升维（4 倍宽）→ 非线性 → 降维**
- 一个事实是怎么被存进两个矩阵的（用 Michael Jordan 走一遍）：
  - 升维矩阵的某一行在问：「你是不是叫 Michael Jordan？」
  - ReLU 把答案压成一个干脆的**是 / 否**
  - 降维矩阵的对应列说：「是的话，就把『篮球』这个方向加回去」
  - 本质上是一个 **AND 门**
- ⚠️ **紧接着必须纠正**，否则上面这个例子会误导：
  真实模型里，**单个神经元几乎从不对应一个干净的概念**
  - 如果要求方向严格垂直，N 维空间最多放 N 个概念
  - 但只要放宽到「近似垂直」（比如 85°–95°），能放的数量**随维度指数增长**
  - 12,288 维、85° 容差 → **400 亿个方向以上**
  - 所以一个特征不是一个神经元亮，是**一组神经元的特定组合**亮 —— 叫**叠加**
  > 🔑 这一条同时解释了两件事：模型为什么难以解释，**以及为什么把模型放大收益这么大**。
  > 维度翻 10 倍，能装的独立概念远不止翻 10 倍。
- 收尾一句话点题：**关联在 Attention，记忆在 MLP。**
  （深挖留给可解释性那一课）

### 5 · 一千七百五十亿是怎么摞出来的（10 min）

**开场**：我们已经把零件都看完了。现在数一数，这些零件各占多少参数？
**猜猜看，attention 和 MLP，哪个更大？**

| 部件 | 算法 | 参数量 | 占比 |
|---|---|---|---|
| 嵌入矩阵 `W_E` | 50,257 × 12,288 | 6.18 亿 | 0.35% |
| 反嵌入矩阵 `W_U` | 同上转置 | 6.18 亿 | 0.35% |
| 注意力（全部） | 每头 ~630 万 × 96 头 × 96 层 | **约 580 亿** | ~33% |
| MLP（全部） | 每层 12 亿 × 96 层 | **约 1160 亿** | ~66% |
| **合计** | | **约 1750 亿** | |

- **反直觉①：大头在 MLP，不在 attention。** 三分之二在那儿。
  「attention 得到了所有的注意力，但大多数参数在它旁边那些块里。」
- **反直觉②：那 1160 亿正好就是第 4 节说的「事实存放处」。**
  模型的记忆容量，物理上就是这堆矩阵
- 最后一步：unembedding + softmax → 概率分布（温度在这里起作用）

**收尾 —— 把钩子抛给下一课：**

> 假设你每秒能做 **10 亿次**加法和乘法，训练最大的那些语言模型要花你**一亿年以上**。
>
> 换个角度：1750 亿参数，用 bfloat16 存，**光权重就是 350 GB**。
> 训练时还要存优化器状态。而一块 TPU v7 的一个 device，能用的高带宽内存约 **94.74 GB**。
>
> **光是把它放下，就得几十个 device。那这笔账到底该怎么算？** → 第二课

## 练习（课后，都不需要加速器）

1. **纸笔**：给定词表大小与嵌入维度，手算嵌入矩阵参数量
2. **十行代码**：跑一个现成小模型，打印下一个词的概率分布，
   把 temperature 从 0 调到 2，看分布怎么变
3. **观察题**：找一句有歧义的话（*bank*、*model*），换上下文，
   看下一个词的分布怎么变 —— 亲眼看见 attention 在起作用

> 想动手写零件的，去 CS336 Assignment 1 Section 3（`~/learning/cs336/`），
> 有完整测试套件判分。讲义已验证：一台 M4 Max 上，MPS 不到 5 分钟
> 就能训出会讲儿童故事的小模型。
