# 11 · 故事性蒸馏：向讲得最好的人借讲法

> 一讲写完、审完、试讲完之后，内容通常已经**对**了，但不一定**好听**。
> 这一篇讲怎么补上这一块：去读外面把同一个话题讲得最好的人，把他们的**讲法**借回来，
> 让听的人「感兴趣、串得下来、带得走、学得会」。
>
> 它是专题五 2026-09-25 夜里 20 轮迭代的总结（原话见下）。那一夜新增了 9 张「为什么」图、
> 六个开场钩子、七道自测题，比方从 16 个收成 4 条主线，并在复核时抓到两处引用错。
> 过程记录在 `DESIGN-NOTES.md` 2026-09-25 夜条。
>
> 这一篇是课程仓库里的**公开正本**；同一套做法另有一份通用版的 agent skill（`explainer-distill`，不限于课程，也用于报告和方案讲稿），两处冲突时回头同步。

> 原话：「针对我们的专题 5，每一小节你都去网上搜『天才网友们』的相关文章、博客和讲义……
> 重点关注像台大教授李宏毅、苏剑林这种又专业、讲的又平易近人的内容……
> 蒸馏他们相关的内容，以及学习他们的讲法，来优化我们自己的课件的故事性……
> 让听的人感觉到兴趣，而且还能够把故事串下来，能够把知识带走，然后能够学会。」

---

## 一、它补的是哪一块

前面几种迭代各管一件事（[06](06-评审与迭代.md)）：AI 评审抓**错**，试讲抓**讲法和衔接**，真人听讲抓**浅**。
这一种抓的是**闷**：内容对、也够深，但听的人提不起兴趣，或者听完串不起来、带不走。

它最适合放在**最后**：前面把错、断、浅都清掉了，这时候改讲法才不会改在沙子上。

## 二、协议：四种轮次交替

| 轮次 | 做什么 | 谁来做 | 抓到的（专题五实例） |
|---|---|---|---|
| **按节借讲法**（每节一轮） | 派一个研究 agent，只读外面把这一节讲得最好的材料，回来写一份蒸馏报告；主会话挑能用的落地 | 研究 agent ＋ 主会话 | 每节一张「为什么」图（见第四节表） |
| **讲师串讲**（一两轮） | 把整堂课在脑子里从头讲到尾，只看衔接、比方打架、时长 | 讲师 agent（任务书 D 的变体） | 接力线两处断点；「合同」一词两用；比方 16 个太多 |
| **麻瓜分段读**（每两节一轮） | 聪明但不懂行的读者，真的截图看图，报「想跳过／没看懂／看反了／带走了什么」 | 麻瓜 agent（任务书 A 的变体） | β₂ 刻度尺是岔路；「最乐观的红线」没说清看着矛盾；DEP8 先用后定义；一张图被看反 |
| **补薄弱处 ＋ 复核**（最后几轮） | 针对麻瓜报的薄弱处再找讲法；最后把今晚新加的每条事实对原文 | 研究 agent ／ 核查 agent | 尺子换成朴素问法；开场钩子；自测题；两处引用错 |

**轮次安排（专题五 9 节 → 20 轮）**：R1–R9 按节 → R10–R11 串讲 → R12–R15 麻瓜四段 → R16–R18 补薄弱处 → R19 复核 → R20 收尾（设计笔记 ＋ 手册）。
每轮都走完「落地 → 构建 → 截图目检 → 只 add 自己的文件 → 提交 → 追踪文件记一行」。

**夜间无人值守**：用定时任务每 20 分钟叫醒一次、一轮一节；追踪文件开头写原话和配额（[06 · 五](06-评审与迭代.md#五记录和汇报纪律)），
每轮末尾把下一轮要用的待办写进「蒸馏待办池」，第二天醒来看一个文件就知道做到哪了。

## 三、研究 agent 的任务书要点

整段可粘贴的任务书见 [模板/评审任务书.md](模板/评审任务书.md) 的 **M（外部蒸馏）**、**N（麻瓜分段读）**、**O（新增事实复核）**。写任务书时守住这几条：

1. **点名来源，并说明要借什么。** 例：「李宏毅怎么开场」「苏剑林怎么讲负载均衡」「Playbook 的 PP 章节有什么反转」。只说「找好文章」会拿回一堆综述。
2. **把我们现有的讲法一并给它。** 不给的话，它会把我们已经有的东西当新发现报回来。
3. **明说只借讲法、不抄内容**，引用要短、要标出处。
4. **⛔ 不编造**：没读到原文就写「没找到」，二手笔记要标二手。专题五里「李宏毅讲多卡并行的那讲其实是助教讲的」「苏剑林没有专讲并行的文章」都是这样如实报回来的。
5. **输出固定三块**：各来源怎么讲 → 可借讲法表（借什么／用在哪／为什么有效）→ 最多 6 条按收益排的改进。

**高手清单的起点**（按话题换）：中文有李宏毅（课程讲义）、苏剑林（科学空间，「MoE 环游记」系列）、李沐（论文精读）、扎哥（zartbot 公众号，AI 基础设施的工程视角）；
Google《How to Scale Your Model》有我们自己翻译的中文版（GitHub `yangwhale/scaling-book-cn`），roofline、集合通信、FSDP／TP 的临界 batch 都有现成的图和讲法；
英文还有 3Blue1Brown、Andrej Karpathy、Lilian Weng、Hugging Face 长文、Horace He、Stas Bekman。**先翻已经存在本地的书架，再上网**：快，不怕登录墙。

⚠️ **研究 agent 报回来的数字和引用，照样要复核。** 专题五 20 轮里的两处引用错（徒步第三件装备是斧头不是锅；DistServe 的 7.4 倍对的是 DeepSpeed-MII 不是 vLLM），都出自「读过原文」的报告。

## 四、借回来的讲法：九种可复用的手法

### 1. 把接力线画出来

外部讲得最好的几份材料（Hugging Face《Ultra-Scale Playbook》、yeasy 的中文书、Google《How to Scale Your Model》）都是同一个写法：**每一节结尾交代下一种方法出场的理由**。
我们本来就有「这一刀留下的问题」，缺的是把它**画成一张图放在开场**：盒子里写这一刀切什么、付什么过路费，盒子下面红字写留下的问题（`fig5-roadmap`）。
配一句更具体的主线：「切一刀，付一笔通信；切完发现还有一块没管到，再切一刀。」

### 2. 反例和对照组：先让人看到错的那条路

最有「啊哈」感的几张图，结构都一样：**错的做法 vs 对的做法，同一组数算两遍**。

| 图 | 错的那条路 | 对的那条路 |
|---|---|---|
| `fig5-tp-order` | 横切在先：GeLU(2)＋GeLU(−3)＝1.950 | 先加再过 GeLU：−0.159 |
| `fig5-ar-two-ways` | 班长做法：卡 0 发 3 份，一千张卡发 999 份 | 环：人人 1.5 份，永远不到 2 份 |
| `fig5-softmax-merge` | 各除各的再平均：14 | 分子加分子、分母加分母：11 |
| `fig5-pd-ratio` | 混着做：接 10 个请求要 7 张卡 | 拆开：3 张卡 |

⭐ 等式的「啊哈」不在它成立，在它**是赢家**：把输掉的那种拼法并排画出来。

### 3. 用「闲忙」「时间线」讲顺序

ZeRO 三级按「谁大先削谁」讲是一张表，按「**谁闲先削谁**」讲就是一个故事：优化器状态最大、却整整一步干放着，只在更新那一下用（`fig5-zero-busy`）。
⭐ 画时间线、流水线、环这类图时，**挑一个对象从头跟到尾**，看它每一格在哪 —— 专题五的 AFD 旧图就是这么查出「回程没地方走」的（[08 踩坑库](08-踩坑库.md)）。

### 4. 数据当场模拟，比一句「会收敛」有说服力

负载均衡的偏置调节，用固定种子模拟 8 个专家、每步加减一点分，最忙专家从平均的 2.26 倍压到 1.08 倍（`fig5-ep-bias`）。
图上标明「示意模拟」和跟真实配置的差别（8 选 2、调得比 V3 快）。

### 5. 比方少而贯穿

一节换一个比方，人记不住。专题五串讲时数出 16 个比方，收成 **4 条主线**，其余尽量回扣到主线上：

| 主比方 | 贯穿哪几节 |
|---|---|
| **过路费**：每一刀付一笔通信 | 零、一、二、七、八 |
| **师傅和小工**：那把「搬一次能用几回」的尺子 | 三、六、七 |
| **笔记＝KV cache** | 四、五、六 |
| **快线／慢线**（第七节展开成写字楼） | 一、二、三、六、七、八 |

⭐ 同一个比方跨节回扣最省力：第二节每层复印一份的原稿，就是第三节 FSDP 送的「工具」；砌墙、装修队并成同一个工地。
⛔ 一个词别在两节里指两件事（专题五的「合同」：第六节指长问题、第七节指 TP → 改掉一处）。
⛔ 比方要跟机制对得上：「送砖」讲不出「token 多就不用等」（砖用一次就没了），改成「送一趟料／送工具」。
⛔⛔ 2026-09-26 真人听讲纠正：ZeRO／FSDP 原来用 Stas Bekman 的「结伴徒步，把别人背的装备**借**过来用」——可「借」意味着对方就没了，而 AllGather 是**复制**：每张卡留着自己那份，把别人那几份复制过来，用完扔掉复制件。改成「合写一本书，每人保管几章原稿，用哪章就复印一份，用完扔掉复印件」，反向的 ReduceScatter 也顺势对上：「对每一章的修改意见交给那一章的保管人合并」。**名家的比方也要逐个动词对一遍机制。**
⭐ 2026-09-26 同一场又升级两次：合写书「太薄」→ **四库全书**（全部权重＝整套书，61 间书房＝61 层，阁数用 V3 真实的 128／64／16，不用乾隆的七阁）。
  FSDP 要画成**按长度等分、切口落在书中间**：单独一段读不了，拼回才能读；跟 EP「整架分、拿着就能用」对照。⛔ 画成「每阁分到几本完整的书」就把 FSDP 讲成了 EP。
⭐ **机制里流动的每样东西都要配实物**：「小工跑腿」只讲了工具（权重），被追问「活（激活）是什么东西」→ 门板（每 token 一块、在工序间传的半成品），隐藏维＝门板尺寸，PP＝门板流水线。
⛔⛔ **比方够用就停，别往上升级**：同一场又试了制琴坊（「谁一次做 4000 把琴」）、三体智子（太复杂）、印刷厂、晶圆厂，全被否，最后退回门板；想把比方扩到 attention／上下文（琴与琴「合练」）也被判牵强。
  判据三条：数量合理（一批几千件是常态）、一句话讲得清、只覆盖它对得上的那部分机制，对不上的部分**不打比方，心里有数就行**。

### 6. 开场钩子：六种套路

每节第一句不讲定义，讲一个让人想听下去的东西。专题五用到的套路：

| 套路 | 例 |
|---|---|
| **算账出丑** | 80 亿参数的小模型，一张 80 GB 的卡也放不下 |
| **你一定以为……** | 你一定以为找个班长最省事？班长要收发 999 份 |
| **反直觉现象** | 拆给两批机器听上去更费卡？结果 3 张顶 7 张 |
| **先卖关子** | ZeRO-3 故意多付一半通信，大模型却几乎都在用 —— 换回了什么？ |
| **先给用处** | 开场埋一行 V3 配置：「现在看是天书，下课前你会读懂它」，第八节收回来 |
| **接住上一集** | 「上一节留下的问题是……其实不只切法，连吃的东西都不一样」 |

⚠️ 钩子只用课里已经核过的数；挖的坑必须在这一节里填上。

### 7. 先问朴素的问题，再给术语

「每搬一个字节换来多少 FLOPs」对普通人是天书；先问「**一份东西搬过来一次，能被用几回？**」，再给这个比值。
等式也配一句直观解释：一个参数 2 字节、每个 token 一次乘加 2 次运算，一约就掉 —— 送来一个参数，卡上有几个 token 就用几回。

### 8. 就地定义、防看反

麻瓜读者最常卡在三类地方，照着查：
- **先用后定义**：DEP8、「头」、Ψ —— 第一次出现就补半句白话，别让人翻到第八节。
- **看着自相矛盾**：正文说「已经在线下」、图上是「勉强在线上」，理由藏在折叠里 —— 在正文点明「图上画的是最乐观的那条线」。
- **图会被看反**：第二条比第一条短，会被读成「调参调坏了」 —— 直接在图上标「总数 ＋45%，每卡 −28%」和「条越长越好」。

### 9. 首尾呼应和自测，让人「带得走、学得会」

- 收尾给**三问**（切什么？付哪种通信？放哪根线？），再拿开场那行配置按三问读一遍。
- 每节末尾一道折叠的「考考自己」：只读一遍会觉得懂了，自己答一次才知道懂没懂。

## 五、代价和边界

- **时长会涨。** 专题五封面从 52′ 涨到 60′（讲义地板 58′）。加的是图和讲法不是字，但要盯住：每轮都让讲义地板断言兜底，超了就压旁边的重复，而不是一路往上调计划。
- **课件的字也会涨。** 守住「多画图少说话」：新讲法优先做成图；解释进讲义；岔路（专题五的 β₂ 刻度尺）收进「细一点」折叠。
- **别为了故事改事实。** 钩子、比方、模拟都要标清楚哪些是示意；借来的例子写明出处和口径（例：DistServe 的 1.6／5.6／10 rps 是 OPT 模型上的一个算例）。
