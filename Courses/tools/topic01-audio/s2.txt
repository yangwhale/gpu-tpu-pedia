[focus] 上一节走完了第一步，还没进第一层，三点四八个 GiB 已经没了。这一节进第二步，全课最重的一段：注意力，以及 KV cache 的那场仗。

[thinking] 开头那一节我们看过结果：同一篇文档，四种存法，KV cache 从三点八一个 GiB 到四百八十八个 GiB，差了一百二十八倍。这一节回答三件事：它为什么会失控，能改的地方有几处，V3 是怎么改的。

[friendly] 先说这东西为什么非存不可。生成文字是一个字一个字往外蹦的，每蹦一个新字，都要回头看前面所有的字。

[seriously] 如果什么都不存，每蹦一个字，前面几万个字的中间结果都得重算一遍。整段生成下来，总计算量从线性变成平方，没人这么干。所以把每个字算出来的 K 和 V 存下来，下次直接拿，这就是 KV cache。这一步本身没毛病，所有模型都这么干。

[focus] 麻烦出在它有多大，而且有两个方向在同时长。序列越长，存得越多；模型有多少层，每一层都得存自己那一份。

[seriously] 单看哪一个都不吓人，但它俩是相乘的。KV cache 等于序列长度，乘以层数，乘以每个 token 每层存几个数，再乘以字节数。一个东西同时沿两个方向线性长，乘起来就是灾难。

[casually] 我们把账堆出来。先假设 V3 用最传统的存法。请看这张阶梯图。第一根柱子，一个 token、一层，存三万两千七百六十八个数，也就是 K 和 V 两份，乘以一百二十八个头，乘以每头一百二十八维，六十四个 KiB，微不足道。第二根，乘以六十一层，三点八一个 MiB，还是不痛不痒。

[seriously] 第三根，乘以十三万一千零七十二个 token。四百八十八个 GiB。

[realization] 这张图的纵轴是对数刻度，每格十倍。从左到右跨了将近八百万倍，中间只做了两件再普通不过的事：乘层数，乘 token 数。

[focus] 换成能感觉到的说法：照这个存法，一段两万五千四百四十六个 token 的对话，光缓存就吃满一整张卡，模型权重还一个字节都没放。整篇文档那四百八十八个 GiB，要五张多卡才装得下。换成 V3 实际的存法，同一张卡能撑到一百四十四万七千六百零八个 token。而且这只是一个用户。权重是所有人共享一份，KV cache 是每个用户各一份，人越多，它占得越多。

[thinking] 再看它随长度怎么变。请看这张图，横轴序列长度，纵轴 KV cache。红线是传统存法，蓝线是 V3 的存法。两条都是直线，但斜率差了将近五十七倍，也就是三万两千七百六十八除以五百七十六。

[realization] 于是它们从同一个原点出发，越走越张开。中间那片红色的口子，就是换一种存法能省下来的。它不是一个固定的数，是一个随长度张开的口子。所以长上下文一出现，所有人都在改注意力。

[thinking] 有人会想到用 fp8 来存，每个数从两个字节变成一个，四百八十八直接变二百四十四。这是真在用的手段，但它是把每个数存小一点。我们要找的是另一件事：少存一些数。两者可以叠加。

[curiosity] 到这儿，该怎么办已经不用我说了。大家先想一想：要是你来改，能动哪里？

[friendly] 能改的地方，一共就那么几个。把每个 token 每层存几个数拆开：等于二，乘以 KV 头数，乘以每头维度。二是 K 和 V 各一份，动不了。剩下的，再加上层数，就是全部旋钮。

[seriously] 第一个旋钮，存几份，也就是 KV 头数，V3 是一百二十八。它最猛：拧到八就是除以十六，拧到一就是除以一百二十八。代价也最直白，多个 Q 头被迫共用同一份 K 和 V，丢掉的表达力找不回来。

[thinking] 第二个旋钮，每份多宽，业界基本钉在一百二十八。砍窄了每个头都变笨，而且计算内核只对几个固定宽度优化过，省了显存却跑不快。第三个旋钮，存几层，比如相邻几层共用一份，或者只让部分层看全长。它改的是存不存，不是存多少，我们这里不展开。

[friendly] 请看这张四代的图。四代的历史，其实就是第一个旋钮从一百二十八拧到一的历史。

[casually] 第一代 MHA，Transformer 原版，每个头一份，三万两千七百六十八个数，质量最好，cache 最大。第二代 MQA，所有头共用一份，只存二百五十六个数。它当年要解决的其实不是装不下，是生成时每一步都要把 K 和 V 重新读一遍，搬不动。第三代 GQA，分组共用，比如一百二十八个头分八组，存两千零四十八个数，整篇文档三十点五个 GiB，是前两代的折中，成了业界默认。

[curiosity] 开头那一节留过一个问题：MQA 只要三点八一个 GiB，比 V3 还省，为什么不直接用？

[seriously] 看这三代，思路是同一个：让多个头共用同一份 K 和 V。一百二十八个 Q 头本来各有各想找的东西，一共用，就只能在同一堆材料里各找各的。共用得越多，显存越省，表达力丢得越多，而且删掉的回不来。MQA 省到了极致，代价也付到了极致。

[realization] 现在看第四代，MLA。它一个旋钮都没拧。

[focus] 一百二十八个头还是一百二十八个头，每头还是一百二十八维，六十一层一层不少。它换的是存什么：不存展开后的 K 和 V，改存一个五百一十二维的压缩向量，外加六十四维单独走的位置信息，一共五百七十六个数。

[curiosity] 五百七十六，卡在 GQA 的两千零四十八和 MQA 的二百五十六中间，质量却比两个都好。大家想一想，这哪里不对？

[thinking] 在同一根轴上，这不可能：省得比 GQA 多，质量还比 GQA 好，没这种好事。它做得到，正是因为它根本不在那根轴上。

[seriously] 这一段的落点就一句话：前三代拿质量换显存，MLA 拿算力换显存。

[realization] 前三代是把信息删掉。MLA 是把信息压起来，要用的时候，现场展开成一百二十八个头，每个头拿到的都是自己那一份 K 和 V，没有哪个头被迫跟别人共用。这就是开头那个问题的答案：它省得几乎一样多，却没让任何头做出牺牲。代价是每次用，都要多算一遍。

[contemplative] 这个形状，做过训练的人应该眼熟：不存中间结果，要用时重算一遍，那就是重计算。某种意义上，MLA 就是对 KV cache 做重计算。

[focus] 这里必须补一句边界：MLA 省显存，是一句推理侧的话。因为训练里根本没有 KV cache。

[thinking] 缓存是解码才有的：一次吐一个字，前面的 K 和 V 要留给下一步复用。训练是整条序列一次前向，没有下一步，无从缓存。训练侧对应的是激活显存，而到了这个量级重计算是开到顶的，一层只留入口那条残差流，展开的 K 和 V 算完就扔。所以这笔账上 MHA 和 MLA 打平，不是 MLA 赢。

[suggestion] 但也别反过来说 MLA 对训练没用。重计算松一档时，它可以只存那个五百一十二维的压缩向量；多张芯片之间传 K 和 V 时，传的也是压缩向量，通信量按同样的倍数往下掉。

[friendly] 好，那 MLA 具体怎么做？一句话：存的时候压，用的时候升。

[focus] 一个 token 的 KV 信息，不按一百二十八个头分别存，先压成五百一十二维存起来。真要算注意力时，再用一个矩阵把它升回一百二十八个头。这个升，每次用都要做一遍。显存里躺着五百一十二个数，算的时候现场变出一百二十八个头。

[thinking] 生成阶段卡的是显存带宽，不是算力。多算一点、少搬很多，是拿没那么缺的换更缺的，所以划算。当然，这是有损压缩，五百一十二维装不下三万两千七百六十八维的全部信息。但那三万两千多个数里，本来就没有那么多真正独立的信息，所以损失可以接受，实测质量反而更好。为什么，后面会专门讲。

[casually] 压缩这一半好懂。更难的一半是：为什么位置信息不能跟着一起压？

[thinking] 先说 RoPE 是什么。注意力本身看不见顺序，把句子里的词打乱，算出来一模一样，所以要额外告诉它谁在前谁在后。RoPE 不给向量加任何东西，而是按位置把向量转一个角度：打个比方，第一个 token 转一度，第一百个转一百度。两个向量做点积，结果自然带上角度差，也就是相对距离。

[focus] 麻烦就出在这个转上：转多少度，取决于 token 排在第几位。如果先转、再压，压缩向量里就掺进了位置。而这个旋转夹在两个矩阵中间，矩阵乘法不满足交换律，挪不出来。

[seriously] 这里要说准：坏掉的不是正确性，模型照样能训、能跑，答案也对。坏掉的是推理时一个很值钱的省法，代价是每生成一个字，都得把前面所有 token 的 K 重算一遍。是哪个省法，后面讲形状时讲透。

[realization] 所以 V3 把每个头的 K 劈成两半：一百二十八维不带位置，负责内容，可以压；六十四维带位置，负责顺序，不压，直接存。每个头打分时实际用的是一百二十八加六十四，一百九十二维。请看这张小图，五百一十二加六十四，五百七十六，就是每个 token 每层存的全部东西。

[amused] 而且那六十四维是一百二十八个头共用的同一份。排第几位是这个 token 的属性，不是某个头的属性。要是每个头各存一份，就得多存一百二十八乘以六十四，八千一百九十二个数，cache 会从五百七十六涨到八千七百零四，MLA 就白做了。那 Q 那一侧为什么不共用？因为 Q 不进 cache，共用省不到东西，只会白丢表达力。

[realization] 最后，这一段要带走的一句话：这个五百七十六，跟头数没有关系。一百二十八个头是它，二百五十六个头还是它。头数从这笔账里彻底消失了。

[seriously] 前三代是在头数上做除法，MLA 是直接把头数从公式里拿掉。做除法总有除尽的那一天，拿掉了，就没有这个上限。

[warmly] MLA 的思路到这里讲完了：压内容，隔离位置，存五百七十六，用时展开。可它具体长什么样，七千一百六十八怎么撑到一万六千三百八十四，一路形状怎么走，那个被保住的省法又是什么，接下来我们就细看它的形状。

[friendly] 这一节就到这里，大家有问题吗？
