## 一、同一个概念，人家有更好的直觉／比喻／画面

### 1.1 反向传播：我们给了定义，3B1B 给了来源

**我们现在怎么讲的**（§1.3「往回传的不是一个数」）：「往回传的是一整个张量，形状跟这一层的输出一模一样。它的含义是：loss 对我这一层输出的每一个位置各有多敏感。」然后直接给两件事：算权重梯度、算往下传的敏感度。

**人家怎么讲的**（3Blue1Brown Ch.3，https://www.3blue1brown.com/lessons/backpropagation）：他不定义「敏感度张量」，他**造**出来。对一张「2」的图片，输出层十个神经元各有一个愿望：2 那格要变大，其余九格要变小，**愿望的大小正比于错得有多远**。想让某一格变大只有三条路：抬 bias、抬权重、改上一层的激活。前两条能直接动；第三条动不了，**但可以记下来**。然后关键一句：上一层每个位置收到的，是**十个输出神经元各自愿望的加和**——「It's impossible to perfectly satisfy all these competing desires. The best we can do is add up all the desired nudges.」这个加和，就是要往回传的那个张量。

**好在哪**：我们说「往回传的是一个张量」，读者只能接受；他说「往回传的是十份互相打架的愿望加起来的结果」，读者自己就推出来了张量的形状必须等于该层输出的形状——因为每个位置都攒了一份愿望。而且这一步顺带解释了两件我们完全没讲的事：为什么梯度在分叉处要相加（CS231n 里那条 `+=` 而不是 `=`），以及为什么残差连接的反向是「两条路的梯度加起来」。

**我们能怎么借鉴**：§1.3 那句「往回传的是一整个张量」之前插一段 150 字的「愿望清单」，并把 §1.2 的「第一个梯度 ＝ 你猜的减去正确答案」改成它的**结论**而不是它的**起点**——「你猜的减真值」正好就是「每一格的愿望大小正比于错得有多远」这句话的公式版。两处目前是断开的，接上之后 §1.2 和 §1.3 变成一件事。

### 1.2 「激活为什么扔不掉」：我们说数学要求，3B1B 说它有意义

**我们现在怎么讲的**（§1.6）：「反向必须用到前向的值——不是谁设计得不好，是反向的数学本身要求它在场。」

**人家怎么讲的**（3B1B Ch.4）：`∂z/∂w = a^(L-1)`，然后点破——「It's telling us that changing the weight has a stronger effect when the previous neuron is more active. This is where that biological idea that *neurons that fire together, wire together* is mirrored in our math.」

**好在哪**：同一个公式，我们用它论证「所以激活得存着」，他用它论证「**所以那个激活值本身就是这条权重该改多少的度量**」。后者让读者记得住——一条权重该改多少，取决于它上游那根线当时有多亮。有了这句，「激活扔不掉」就不是一条工程约束，而是一件本来就该如此的事。

**我们能怎么借鉴**：§1.6 开头那句「回头看 1.3 那两件事里的第①件」后面加一句：「注意这一步在说什么——**一条权重值不值得动，取决于它上游那个输入当时有多大**。输入是 0 的那条线，这一步怎么改都不影响输出，所以它的梯度就是 0。反向要用前向的值，不是记账需要，是这个乘法本身就是答案。」

### 1.3 Karpathy：反向传播是个「漏抽象」——正好是我们 §1.4 的反面

**我们现在怎么讲的**（§1.4）：「偏导数是局部的……这就是为什么自动微分能做成一个通用库……没有任何人需要手推整个网络的导数。」我们把反向传播卖成一个**已经解决了、可以放心用的抽象**。

**人家怎么讲的**（Karpathy 2016，https://karpathy.medium.com/yes-you-should-understand-backprop-e2f06eab496b）：「The problem with Backpropagation is that it is a **leaky abstraction**.」然后四个具体例子，全都只有看局部导数才看得见：

- sigmoid 的局部梯度 `z(1-z)` 最大值是 **0.25**，所以梯度每过一个 sigmoid 门至少衰减到四分之一——初始化稍大一点就直接饱和成 0；
- dead ReLU：前向被夹到 0 的神经元，`dW = outer(z>0, x)` 就是 0，**永久死亡**，「像不可逆的脑损伤」，训完一个网络可能 40% 的神经元全程没亮过；
- RNN 反向就是同一个矩阵连乘 T 次，所以要看它的最大特征值；
- 真实 bug：某份 DQN 代码用 `clip_by_value` 裁 delta，前向看着很合理，**但 clip 在范围外的局部梯度恒等于 0**，等于把那些样本的梯度全掐了——他们真正想要的是 Huber loss。

**好在哪**：我们的 §1.4 和 §6（训不崩）现在是两件事——§1.4 说「你不用关心反向」，§6 说「loss 飞了怎么办」。Karpathy 这条把它们接成一件事：**训练出问题的那些模式，全都是「某个算子的局部梯度在某些输入下变成 0 或者变成很大」**。有了这条，QK-norm（attention logits 长疯 → softmax 塌成 one-hot → 局部梯度趋 0）、z-loss（指数对输入误差极敏感）、梯度裁剪，就都是同一条线索的不同位置，而不是三个并列技巧。

**我们能怎么借鉴**：§1.4 结尾加一条转折，大意是「这个抽象好用，但它会漏。漏在哪 —— 第六节整节都在讲这件事」；§6 开头回引一句「§1.4 说自动微分让你不用手推导数。这一节讲的是**它没替你挡掉的那部分**」。不用抄他的四个例子（sigmoid/RNN 对 LLM 已经过时），但 `clip_by_value` 那个「前向合理、反向是 bug」的模式值得单独留一句——它跟我们 §3.3 讲 AdamW 那个「权重衰减被自适应分母除了一遍」是同一个形状的错误。

### 1.4 混合精度：HF 那句反直觉的话，我们完全没有

**我们现在怎么讲的**（§3.1–3.2）：五格 16 字节，三格 fp32 两格 bf16，判据是「累不累加」。读者读完会带走一个印象：混合精度是省显存的。

**人家怎么讲的**（HF Ultra-Scale Playbook, "Memory for weights/grads/optimizer states"）：

> "Interestingly, mixed precision training itself **doesn't save memory**; it just distributes the memory differently across the three components, and in fact **adds another 4 bytes** over full precision training if we accumulate gradients in FP32."

算一遍就明白：纯 fp32 是 4（权重）＋4（梯度）＋8（m,v）＝ 16 B/参数；混合精度是 2＋2＋4＋4＋4 ＝ **也是 16**；开 fp32 梯度累加变 20。混合精度真正买到的是两样：矩阵乘走低精度单元（快），以及**激活那一大块减半**——而激活恰恰不在这五格里。

**好在哪**：这是一句纯赚的反直觉事实，而且它跟我们全篇的记账风格完全同频。更重要的是，它把「为什么还要留 fp32 主权重」从一条需要记的规则变成了一个自然结论——你根本没省下什么，你只是把预算重新分配了一下。

**我们能怎么借鉴**：§3.1「一个参数到底要占多少字节」开头直接放这个对照：「纯 fp32：4＋4＋8 ＝ 16。混合精度：2＋2＋4＋4＋4 ＝ 16。⛔ 一个字节没省。」然后再讲五格。这一句会让后面整节都更好懂。

### 1.5 ZeRO：我们讲「切」，人家讲「本来就是重复劳动」

**我们现在怎么讲的**（§4.2）：「切的顺序只有一条原则：谁最大、谁最少被用到，就先切谁。」并且写「ZeRO-3 通信代价是三级里最高的」。

**人家怎么讲的**，两句话，出自两处：

- HF playbook, "ZeRO-1"：「In vanilla DP, all ranks gather the same gradients and **simultaneously perform identical optimizer steps**. This seems like a lot of **duplicated work**. Can we avoid it and reduce memory usage at the same time?」——ZeRO-1 不是一笔交易，是把本来就白干的活删掉。
- Scaling Book, "FSDP"：「an AllReduce can be decomposed into an **AllGather and a ReduceScatter**…… ZeRO-3 turns a backward-pass AllReduce into an AllGather and a ReduceScatter, which have **the same total comms volume**……我们的 FLOPs/comms 比值跟纯数据并行**完全一样**，所以只要纯 DP 是 compute-bound，就可以放心升到 FSDP。」

**好在哪**：「AllReduce ＝ AllGather ＋ ReduceScatter，所以把它拆开放到两个时刻，总量不变」这一句，一次性解释了为什么 ZeRO-1/2/3 三级的通信 roofline 差不多、为什么 FSDP 几乎白拿。而我们那句「通信代价是三级里最高的」虽然在**绝对字节数**上没错（HF 算的是 3Ψ vs 2Ψ），但读者读完会以为 ZeRO-3 是个昂贵选项——两份材料都明确说相反：HF 说配上 prefetch，DP ≤ 512 时开销可忽略；Scaling Book 说「we can basically always do ZeRO-3 sharding」。

**我们能怎么借鉴**：§4.2 加一小段「为什么切得起」：把 AllReduce = AllGather + ReduceScatter 这个恒等式写出来，然后把 ZeRO-3 那条改成「**通信字节数最多（3Ψ vs 2Ψ），但 roofline 没变**——因为它只是把同一个 AllReduce 拆成两半放到了不同时刻；真正的限制是 all-gather 要能被下一层的前向盖住，实践上 DP 超过 512 左右才顶不住」。这是措辞问题不是事实错误，但它现在给的暗示是反的。

### 1.6 Muon：苏剑林还有三条我们没取的

我们的 fig-muon 已经取了苏剑林四条（矩阵符号函数三特例 / 迹 / 范数视角 / 空窗），credit 也给了。漏掉的三条里有两条我认为比已取的更该要：

**(a) 一条可迁移的判据：什么叫「自适应」。** 苏文一开头就给了两个性质：①**把 loss 乘一个常数，优化轨迹不变**（Σ 被同比放大，但 msign 把它拍成单位阵）；②各分量更新幅度尽量一致。这正是 Adagrad/RMSProp/Adam 共有的两条。我们 §3.3 只对 Adam 说了「量纲被除掉了」，没把它抽成一条**任何优化器都能拿去测**的判据。而「loss 乘 10，你的训练会不会变」是一个外行也能理解、还能真的跑一遍的检验。

**(b) Muon 的第四条限制，而且是对 infra 课最要命的那条。** 我们 §3.4 列了三条（只管二维、每步更慢、要多做几轮矩阵乘）。苏文列了第四条，我们完全没有：

> 「如果一个矩阵被划分到不同设备上，那么用 Muon 时就需要将它们的梯度汇聚起来再计算更新量，而不能每个设备独立更新，这增加了通信成本。……比如 Multi-Head Attention 一般是通过单个大矩阵投影到 Q，然后 reshape 得到多个 Head，这样参数里只有单个矩阵，但它本质上是多个小矩阵，按道理需要拆开独立更新。」

Element-wise 优化器可以「一个大矩阵切成两个小矩阵独立处理，不改变优化轨迹」——这是张量并行能成立的隐含前提。Muon 打破了它。**这条直接通向专题五**，是我们这一讲最该留给下一讲的钩子之一，而现在丢了。

**(c) Newton-Schulz 那三个系数的来历。** 官方代码里是 (3.4445, −4.7750, 2.0315)，作者没给推导，只有一段语焉不详的注释；苏剑林把它反推成一个「让任意初始奇异值收敛最快」的优化问题，解出来发现**作者那组大约是迭代 5 步、方阵时的最优解**，而且最优系数依赖矩阵形状。这条是可选的，但它示范了一个很值钱的动作：**遇到一组没解释的魔数，先假设它是某个优化问题的解。**

**我们能怎么借鉴**：(b) 必加，就一句话加在 §3.4 那三条限制后面，并在 §5.4 的「交给下一讲」里点名。(a) 加在 §3.3「自适应那条线」的开头当判据。(c) 放出处栏。

### 图 A：一个带数字的小电路，前向绿、反向红

**出处**：CS231n《Backpropagation, Intuitions》，https://cs231n.github.io/optimization-2/ 的那张 circuit diagram。

**画的是什么**：一个只有三个数的表达式 `f = (x+y)·z`，取 `x=−2, y=5, z=−4`。图上每根线标两个数：**绿色是前向算出来的值**（x+y=3，f=−12），**红色是反向传回来的梯度**（df/dz=3，df/dq=−4，df/dx=df/dy=−4），红色数字从右往左流。旁边三条读法：

- **加法门是分配器**：把收到的梯度原样复制给所有输入（本地导数是 1）。
- **max 门是路由器**：全部给前向时较大的那个输入，另一个拿 0。
- **乘法门是交换器**：本地导数是**对方**的输入值——所以两个输入一大一小的时候，它会给小的那个一个巨大的梯度。

**为什么有效**：它让「链式法则」变成一个可以用手指头跟着走的动作，而不是一个公式。而且第三条那个「乘法门会给小输入巨大梯度」直接能解释一件实务：**把输入数据统一乘 1000，权重的梯度就会大 1000 倍，你必须把学习率同比调小**——CS231n 原文就是这么收尾的。这和我们 §3.3「梯度尺度差好几个数量级，SGD 只能折中」是同一件事，但他给的是一个能算的两位数例子，我们给的是一句断言。

**放哪**：§1.3 之前，当作 fig-3x 的前置。现在 fig-3x 一上来就是 `[S,k]×[k,n]` 的层级视角，中间少了一级台阶。

### 图 B：浮点分辨率数轴

**出处**：HF Ultra-Scale Playbook, "Mixed precision training" 那两张（`mixedprecision.png` / `mixedprecision_2.png`）。

**画的是什么**：两张并排。左边是**量程**：一条横向的数量级坐标，fp32 横跨 80 个数量级，bf16 跟它一样长，fp16 明显短一截，e5m2 跟 fp16 一样长、e4m3 更短。右边是**分辨率**：只取 [1, 2] 这一小段，在上面撒 10000 个点，每个点被舍入到各格式最近的可表示数——于是 fp32 是一条几乎连续的实线，bf16 变成稀疏的刻度，**e4m3 在 [1,2] 里只剩 7 个刻度，e5m2 只剩 3 个**。

**为什么有效**：这是我读到的、把「bf16 的量程跟 fp32 一样，缩的是精度」讲清楚的唯一一张图。它同时一次性支撑了我们三处论证，而这三处现在全是口头的：

- §3.2「bf16 只有 8 位尾数，小的加上去会被直接舍掉」——图上就是：那个增量落在两根刻度之间，于是被吸回原刻度。
- §6.6「bf16 不需要 loss scaling」——左边那张图上 bf16 和 fp32 一样长，fp16 短一截，下溢就发生在短掉的那一段。
- 以及给 FP8 那一讲留的伏笔（我们 §3.2 结尾已经点了）。

**放哪**：§3.2「哪些量必须高精度」开头。它能替掉现在那两段关于位数的文字。

### 图 C：一次真实 step 的显存 profile，以及「第一步长得不一样」

**出处**：HF Ultra-Scale Playbook, "Profiling the memory usage"（PyTorch profiler 实测曲线，可交互）。

**画的是什么**：横轴是一个 step 内的时间，纵轴显存，堆叠着画。形状跟我们 fig-step 的 Ⓐ 是同一个（激活前向堆高、反向释放，梯度反着来）。但它多了两件我们完全没有的东西：

1. **它是量出来的，不是画出来的**——曲线毛糙、有台阶、有 allocator 的锯齿。
2. **第一步跟后面几步长得不一样**：第一步激活冲上去之后会有一段平台（caching allocator 在做预分配），而且**优化器状态是第一步之后才出现的**。HF 由此点破一个现象：「Ever noticed how sometimes the training succeeds in the first step but then OOMs during the following training steps? This can be explained by the buildup of the optimizer state after the first step.」

**为什么有效**：第 2 条是一个真实训练里人人撞过、但几乎没有教材讲的事，而它是我们 §5.3「查 OOM 要先问是哪一项的峰」的**最好的一个具体案例**。我们那一节现在只有原则，没有场景。

**放哪**：§5.3。不需要重画他们的实测图（我们没有实测数据，画了就是编）——但那句「第一步跑过了、第二步 OOM，因为优化器状态是第一步之后才建起来的」可以直接作为文字加进去，配我们已有的 fig-step。如果要画，就在 fig-step 的 Ⓐ 左边补一个「第 1 步」的小画面，和后面的稳态并排。

### 图 D：常驻块 vs 激活，随序列长度的两条线

## 三、人家讲了而我们完全没讲的（都在「反向＋优化器」范围内）

### 3.1 学习率与 batch size 的定量关系——这是最大的一个洞

**我们现在怎么讲的**（§3.5）：GPT-3 七档表 ＋ 一句「⛔ 注意这张表里 batch 和学习率是一起变的——这是最容易漏的一条：你不能只调学习率不看 batch，它俩绑在一起。」然后就停了。我们**指出了这件事存在，但没给任何可用的关系**。

**人家怎么讲的**（苏剑林 10542 + 11260，转述并推导了 OpenAI《An Empirical Model of Large-Batch Training》）。整条线索是这样的，而且每一级都比上一级更接近实用：

1. **√B 缩放**（Krizhevsky 2014）：让 SGD 增量的**方差**保持不变。B 变 n 倍 → 协方差缩到 1/B → 要保持 η²/B 不变 → η ∝ √B。
2. **线性缩放**（Goyal 等 ImageNet-in-1-hour）：实践上常常更好。理论依据是把 SGD 看成 SDE 的离散化——关键一步是「**SDE 的噪声项步长是非噪声项的平方根**」，所以要保持 SDE 形式不变必须 η ∝ B。
3. **OpenAI 的二阶展开**，这是最值钱的一条，因为它把上面两条统一了。把学习率本身当优化变量，对 loss 做二阶展开求最优 η，得到

   **η\* ≈ η_max / (1 + B_noise / B)**

   这是一个**单调递增但有上界**的函数。B ≪ B_noise 时退化成线性缩放；B > B_noise 之后 η\* 饱和在 η_max，**再加 batch 就是纯烧钱**。
4. **怎么算 B_noise**：真值 `tr(ΣH)/gᵀHg` 要 Hessian，算不了；实践中假设 H ≈ 单位阵的若干倍，约掉，得到 **B_simple = tr(Σ)/gᵀg**——噪声强度除以信号强度，就是信噪比的倒数。而 tr(Σ) 只要对角线，**数据并行场景下每张卡的梯度天然就能拿来估**。
5. **η_max 不用算**：在小 batch 上网格搜一个 η\*，结合估出来的 B_simple 反推。
6. **顺带白拿一条**：把 η\* 代回去，得到 **(S/S_min − 1)(E/E_min − 1) = 1**——训练步数和消耗 token 数之间的一条双曲线关系，而且 B_noise = E_min/S_min，给了第二条估计 B_noise 的路（多跑几组 (S,E) 拟合）。
7. **Adam 不一样**：换成 SignSGD 近似之后，小 batch 时是**√B**（不是线性），而且大 batch 时可能出现「**Surge 现象**」——超过某个 B 之后最优学习率**反而要降**。苏剑林的解读很漂亮：这本质上是自适应策略次优性的体现，**适量的梯度噪声本来在修正 sign(g) 的次优方向，batch 大了噪声没了，修正机会也没了**。

**好在哪，以及为什么这对我们是个洞**：我们 §1.8 花了一整段论证「batch 越大，通信被摊得越薄，所以大模型都在爬 batch」，还举了 GPT-3 / PaLM / V3 三个例子。但我们从头到尾**没说它们为什么会停下来**。读者读完 §1.8 会得到一个「batch 越大越好」的印象，而 §3.5 又告诉他「batch 大了学习率要调小」，两节之间是断的。`η* = η_max/(1 + B_noise/B)` 一个式子同时补上这两个缺口：它既解释了为什么爬、也解释了为什么在某个点停。

**我们能怎么借鉴**（具体到改哪）：
- §1.8「为什么大模型都在爬 batch」那一条后面，加一句止损：「⛔ 但它有上界。OpenAI 那条二阶展开的结论是 η\* = η_max/(1 + B_noise/B)——超过 B_noise 之后，加 batch 换不来更大的学习率，只是在烧钱。」
- §3.5 第二段「峰值设多少」，在 GPT-3 那张七档表之后加一小节，讲这条有界律 ＋ B_simple = tr(Σ)/gᵀg 的可计算性 ＋ 「Adam 是 √B 不是线性」。**这一小节的价值在于把七档表从『抄一个数』变成『你能自己估一个数』**，正好接上我们 §3.5 落点那条「别从零猜」。
- 顺带解决 §3.5 一个现存的小别扭：我们用「V3 的 671B 学习率反而比 GPT-3 的 175B 高，因为它每 token 只激活 37B」解释了偏差。这个解释对，但加上 batch 那一维（V3 的 batch 是 15360 序列，GPT-3 是 3.2M token）会更完整。

### 3.2 存档点该隔多远——√L，一行代数

**我们现在怎么讲的**（§2.1）：「就像游戏存档——不存整个过程，只存一个存档点，要用的时候从那儿重打一遍。」比喻很好，但它立刻引出一个问题：**存档点该隔多密？** 我们跳过了，直接进「全量／选择性／不开」三档菜单。

**人家怎么讲的**（Lilian Weng 转述 Chen et al. 2016《Training Deep Nets with Sublinear Memory Cost》）：L 层网络均分成 d 段，只存段边界。显存 ≈ `L/d + d`（段内要重跑的 L/d 个中间结果 ＋ d 个存档点），对 d 求极值，**d = √L 时最小，总显存 O(√L)，代价恰好是一遍额外前向**。

**好在哪**：它把「存档」这个比喻**闭上了**。而且 O(L) → O(√L) 这个量级跃迁，跟我们 §2.2 那个「付 1/3 换掉 97.5%」的兑换比例是同一件事的两种说法——我们给的是一个具体模型的具体数字，他给的是它为什么在任何深度上都成立。

**我们能怎么借鉴**：§2.1 末尾加三行：「存档点隔多远？均分成 d 段，显存 ≈ L/d ＋ d，d ＝ √L 时最小。⭐ 所以一个 61 层的网络理论最优是每 8 层存一个——**而实践里大家都存每一层，因为 Transformer 的层边界是天然的存档点，而且每层存一份已经把激活压到只剩几十分之一了**。」最后半句很重要：它解释了为什么理论最优在这里不重要，避免读者去找一个不存在的调参空间。

### 3.3 重算有一个正确性面，我们一个字没提

**我们现在怎么讲的**：§2 全程把重算当成一笔纯粹的「算力 ↔ 显存」交易。没有风险栏。

**人家怎么讲的**（PyTorch `torch.utils.checkpoint` 官方文档）：整页文档里**分量最重的是警告，不是 API**：

> "If the `function` invocation during the backward pass differs from the forward pass, e.g., due to a global variable, the checkpointed version may not be equivalent, potentially causing an error being raised or **leading to silently incorrect gradients**."

以及 RNG 那条：默认会 stash／restore RNG 状态，就是为了让 dropout 在重算时抽到同一个 mask；`preserve_rng_state=False` 能省一点开销，但「if any checkpointed functions involve randomness, this may result in **incorrect gradients**」。还有一条更隐蔽：多设备时它只保存**一种**设备类型的 RNG 状态，其余忽略；如果你在被 checkpoint 的函数里把张量搬到一个新设备上，**确定性就不再保证**。另外有个 `determinism_check`，默认会比对重算出来的张量和原张量的 shape/dtype/device——这本身就说明这类事故常见到需要内建检查。

**好在哪**：这是一整类我们完全缺席的失效模式，而且它的症状是**静默的**——不报错、loss 曲线看着正常、梯度是错的。这跟我们 §3.7 那条「数据读到哪儿了忘了存，恢复后重训一遍同样的数据，loss 曲线看着完全正常」是**同一个物种**的 bug，我们对那条写得很好，说明我们本来就吃这一口。

**我们能怎么借鉴**：§2.2 后面加一小节「⛔ 重算不是无风险的——它有一条正确性前提：**重跑那一遍必须跟第一遍算出一模一样的东西**」。三个具体来源：dropout 之类的随机算子（框架要存 RNG 状态）、依赖全局状态的算子、以及在被重算区间里搬设备。落点一句：「它错起来不报错，只是梯度偷偷不对——所以框架才要内建一个『重算出来的张量 shape/dtype/device 跟存的那份对不对得上』的检查。」

### 3.4 选择性重算在框架里是一个 policy 函数——我们的判据有个落点，但我们没说

**我们现在怎么讲的**（§2.3）：推出「每字节代价 ＝ 输入宽度」这条闭式解，排出一张八行的名次表，然后止于「你拿 config 自己也能排一遍」。

**人家怎么讲的**：
- **PyTorch SAC**：`create_selective_checkpoint_contexts(policy_fn)`，`policy_fn` 对每个算子返回 `MUST_SAVE` 或 `PREFER_RECOMPUTE`。文档给的例子就是「`ops_to_save = [aten.mm]`，其余全重算」。
- **JAX/Scaling Book**：`jax.remat` 的两档 policy 有名字和数字——**block remat**（只存每层输入，前向 FLOPs 基本重跑一遍）和 **"big matmuls only"**（只存大矩阵乘的输出），后者把「每层要存的中间张量」从约 **20 个降到约 7 个**。

**好在哪**：我们推了一整节的判据，读者读完会问「那我怎么把这个名单告诉框架」。答案是：**你逐字把它敲进一个 policy 函数**。这一句能让 §2.3 从一个漂亮的推导变成一件能干的事。而 JAX 那个「20 → 7」是一个很好的量级锚点，正好可以和我们 §1.7 那张「一层 MoE 块留了些什么」的表对照——我们表上一层列了 13 项，跟「20」同一个量级，互为旁证。

**我们能怎么借鉴**：§2.3 名次表之后加两句，点名 PyTorch 的 `MUST_SAVE / PREFER_RECOMPUTE` 和 JAX 的 `jax.remat` policy，并指出**两边的默认 policy（「存矩阵乘，其余重算」）正好就是我们这张表的前六行**——这又是一个「我们自己推的判据跟人家实际配的对上了」的外部锚点，跟 §2.4 引 DeepSeek-V3 那条是同一个动作，而且这个锚点是**框架默认值**，比单个模型的配置更有说服力。

### 3.5 「attention FLOPs 什么时候开始占主导」有一条比我们更好记的门槛

**我们现在怎么讲的**（§5.2）：「attention 占一层前向算力的 82.1%，所以 6ND 低估了五到六倍」——一个模型专属的数字，而且我们自己在 §7.2 标了它是自己推的。

**人家怎么讲的**（Scaling Book, "Fractional cost of attention with context length"）：

> "dot-product attention FLOPs only become dominant during training once **T > 8D**. For D ~ 8k, this would be ~64K tokens.……for smaller models, e.g. Gemma-27B with D=4608, attention becomes dominant around 37k sequence lengths."

**这条我自己验算了一遍，推导链如下**（他们只给结论，公式在同页的表里）：MLP 每层训练 FLOPs = 18·B·T·D·F，attention 投影 = 24·B·T·D·N·H，点积 attention = 12·B·T²·N·H。取标准 MHA 的 N·H = D、F = 4D，则 MLP = 72BTD²、投影 = 24BTD²、点积 = 12BT²D，比值 = 12T²D / 96TD² = **T/(8D)**。等于 1 时 T = 8D。

**好在哪**：`T > 8D` 是一条能记住、能对任何模型套的门槛，而 5,734 只对 V3 成立（我们自己也这么标了）。两者回答的不是同一个问题——我们那个是「重算的每字节代价谁高谁低」的交点，他们那个是「算力占比谁大谁小」的交点——但读者关心的那句「我这个配置算不算长上下文」，他们的版本更好用。

**⚠️ 这条我要标一句不确定**：`T > 8D` 的前提是 dense、MHA、F = 4D。V3 是 MLA ＋ MoE：每 token 只激活 37B，非 attention 那一侧的 FLOPs 被 MoE 砍掉了一大块，所以门槛会左移、attention 占比会比 T/(8D) 给出的更高。代 V3 的数（T=131072, D=7168）进 T/(8D) 得 2.29，即 attention ≈ 总量的 69.6%，而我们算的是 82.1%——**方向一致（MoE 让 attention 占比更高，符合预期），量级一致，但不是同一个口径下的数，不能直接说「互相验证了」。** 判据是：两式的分母不同，他们的分母是 dense MLP，我们的分母是 MoE 激活部分。

**我们能怎么借鉴**：§5.2 在 82.1% 旁边加一句外部锚点：「⭐ 一条更好记的通用门槛：对 dense、MHA、F＝4D 的模型，attention 的点积部分在 **T > 8·d_model** 时开始超过其余全部 matmul（Scaling Book）。V3 的 d_model 是 7,168，所以门槛在 5.7 万左右，而它跑的是 13.1 万——已经过了两倍多。⚠️ V3 是 MLA＋MoE，非 attention 那侧比 dense 小得多，所以它的实际占比比这条通用门槛给出的更高，两个数不是一个口径。」这样 82.1% 从一个孤立估算变成有外部参照的估算，正好符合我们 §7 结尾自己立的那条规矩。

### 3.6 梯度通信的两个工程细节：bucketing，和「梯度累积时必须关掉 sync」

**我们现在怎么讲的**（§1.8）：「省通信——K 个 micro-batch 只汇总一次。」写得像是自动发生的。

**人家怎么讲的**（HF playbook 有专门两节 "Second optimization: Bucketing gradients" 和 "Third optimization: Interplay with gradient accumulation"；Lilian Weng 也提了 DDP 的 bucketing）：

- **Bucketing**：梯度是从后往前一个一个出来的，如果每出来一个就发一次 all-reduce，你会发一大堆小得只剩启动开销的集合通信。所以要**攒够一桶再发**。
- **梯度累积的交互**：默认情况下每个 micro-batch 的反向都会触发一次同步，**你必须显式在前 K−1 个 micro-batch 上关掉它**（PyTorch 里是 `no_sync()`），否则「K 个只汇总一次」根本不成立，你汇总了 K 次。

**好在哪**：第二条直接把我们 §1.8 那句「省通信」从一条性质变成一个**你可能忘了打开的开关**。这跟我们全篇「不能照抄别人的收益」的立场是一致的——这里的收益需要你做一件事才拿得到。

**我们能怎么借鉴**：§1.8「顺带把 ④ 说清楚：梯度累积到底省什么」那五条里，「省通信」那条后面加半句：「⚠️ 但这一条**不是自动的**——默认每个 micro-batch 的反向都会触发一次同步，你得显式把前 K−1 次关掉（PyTorch 里是 `no_sync()`），不然汇总的还是 K 次。」再加一句 bucketing 到「藏起来」那一段：「而且不能一出来一个就发一次——那样每次集合通信都小到只剩启动开销。实践上是攒够一桶再发。」

### 3.7 线性衰减到 0 有理论支持，而且「不存在一劳永逸的 schedule」

**我们现在怎么讲的**（§3.5 第三段）：cosine 和 WSD 两派，「差别不在哪个收敛更好，而在它们各自要求你什么时候做决定」，两派终点都落在峰值的 10%。写得很好，但它把 schedule 呈现成了一个**没有对错的风格选择**。

**人家怎么讲的**（苏剑林 11494，跟着《Optimal Linear Decay Learning Rate Schedules and Further Refinements》）：

- 常数学习率下，**终点损失**的收敛速度只能到 O(√(ln T / T))；换成 **η_t = α(1 − t/(T+1))** 的线性衰减，能做到 **O(1/√T)**，而这已经是信息论下界，不可能再改进。
- 他还用变分法给了这个结论**为什么是线性衰减**：把问题连续化成最小化 `c/S_0 + ∫(Ṡ_t)²/S_t dt`，代欧拉-拉格朗日方程解出 `S_t = S_0(1−t/T)²`，求导就得到 η_t ∝ (1 − t/T)。
- 落点那句最狠：「**不存在『一劳永逸』的学习率策略**，根据训练步数精调学习率策略，才能获得最佳的终点收敛结果。」换句话说，那些「不需要预知总步数」的 schedule（α/√t、α/t）之所以实践表现不好，是有理论原因的——**终点收敛要求 schedule 知道终点在哪**。
- 他还转引《Straight to Zero: Why Linearly Decaying the Learning Rate to Zero Works Best for LLMs》，声称线性衰减到 0 比 cosine 还好。

**好在哪**：这给了我们 §3.5 那条「⛔⛔ 单报一个学习率数字是没有意义的，它必须连着 batch、schedule 形状、总 token 数一起报」一个**理论上的理由**，而不只是一条经验规矩。而且它顺带解释了 WSD 为什么长成那个别扭的样子——WSD 的「什么时候开始降」本质上就是在把「必须预知 T」这个约束推迟到最后。这正好是我们自己给两派下的判语（「差别在什么时候做决定」）——我们给对了结论，但没给理由。

**我们能怎么借鉴**：
- §3.5 第三段加第三个流派：**线性衰减到 0**。它现在缺席，而它是三个里唯一有收敛性证明的。
- 那句「⭐⭐⭐ 两派的差别不在哪个收敛更好，而在它们各自要求你什么时候做决定」后面加一句理论支撑：「⭐ 而这不只是工程上的别扭：有一条收敛性结果说明，**终点损失要跑到理论最优的 O(1/√T)，schedule 就必须知道 T 在哪**——常数学习率只能到 O(√(ln T/T))。所以『不需要预知总步数』的 schedule 在原理上就吃亏，WSD 的那个长平台其实是在把这个决定往后拖到不能再拖。」

### 3.8 优化器状态可以整块搬下卡——我们自己推出了理由，但没说结论

**我们现在怎么讲的**：§4.1「优化器状态……最大。而且它只在更新那一刻用一次。」§4.3 提了一次「offload」这个名词。§3.7 提了 V3 把 EMA 放 CPU。

**人家怎么讲的**（DeepSpeed ZeRO tutorial）：ZeRO-Offload 把优化器和梯度状态搬到 CPU 内存（配在 ZeRO-2 里）；ZeRO-Infinity 进一步搬到 NVMe，「offload more data than ZeRO-Offload and has more effective bandwidth utilization and overlapping of computation and communication」。都是配置文件里的一个 key。

**好在哪**：我们 §4.1 那句「最大、而且只在更新那一刻用一次」是**offload 存在的全部理由**，我们已经把理由写出来了却没连上结论。这是我们自己的推导链断了一节，不是别人讲得更好——但别人把它讲完了。

**我们能怎么借鉴**：§4.3 那条「offload——针对暂时用不到的那些项」改成有具体落点的：「⭐ 而 §4.1 那句『最大、而且只在更新那一刻用一次』，正好就是 offload 的全部理由：**用得越少、越该搬得越远**。DeepSpeed 把这条做成了两档——ZeRO-Offload 搬到 CPU 内存，ZeRO-Infinity 搬到 NVMe。」

### 3.9 一条决策流程

**我们现在怎么讲的**（§5.3 结尾）：「你去查 OOM，光知道『峰值 xx GiB』没用——要知道是哪一项在那一刻最大……激活大就开重算／上 CP；优化器状态大就上 ZeRO——这两条路走反了，一点用都没有。」

**人家怎么讲的**（HF, "Finding the Best Training Configuration"）：三步，明确编号：**Step 1 先让一个 step 装进显存**（分 GPU-rich / GPU-poor 两个分支，各给规模区间和推荐组合）→ **Step 2 打到目标 global batch**（要涨：加 DP 或加梯度累积；长序列加 CP。要降：反过来）→ **Step 3 优化吞吐**。

**好在哪**：我们那两句是**诊断**（症状 → 病因），他们是**流程**（从零到可跑）。我们的诊断比他们的好——他们那三步里没有「先问是哪一项的峰」这个动作，直接就开始试组合。但我们完全没有流程。

**我们能怎么借鉴**：这一条的借鉴方式不是抄流程（并行策略是专题五的事），而是**把我们那两句从段落里提出来做成一个明确编号的三问**，放在 §5.3 的落点位置：①这一刻哪一项最大？②它是常驻的还是随 batch×seq 涨的？③常驻的切（ZeRO／offload），随 batch 涨的要么重算要么按序列切（CP）。这样它就是我们自己版本的「决策流程」，而且判据在前、动作在后——比 HF 那个「先按参数量查表」的顺序更符合我们这一讲立的方法论。

## 四、我们讲得比人家好的地方（后续精简别动这些）

这一类我查得比较用力，因为它决定哪些是不能改的。以下每一条我都在上面那 15 份材料里确认过**没有对应物**。

**4.1 重算判据的闭式解：每字节代价 ＝ 输入宽度 k。**
这是全讲最值钱的原创教学对象，而且我确认它是原创的：HF 只说「作者们详细分析了哪些激活最大而重算最便宜，结论是 attention」；Scaling Book 只说「只存大矩阵乘的输出」；EleutherAI 直接给一个背下来的公式 `sbhL(34 + 5·n_heads·s/h)`。**没有一份给出「2·S·k·n FLOPs ÷ S·n·2 字节 ＝ k，S 和 n 全约掉」这个推导。** 它把一条需要查表的事实变成了一条扫一眼 config 就能重推的判据。绝对不能删。

**4.2 2022 → 2024 的判据不变、结论翻转。**
我特地检查了 HF playbook 怎么处理 Korthikanti 那篇——它在 2025 年仍然原样复述「GPT-3 省 70% 付 2.7%」，只补了一句「现代框架用 FlashAttention，所以你已经在用选择性重算了」。**没有任何一份材料指出那条建议已经反过来了，更没有一份指出翻转的原因只是序列长度从 2,048 变成了 131,072。** 我们 §2.5 ＋ fig-per-byte（两条斜率不同的线必然相交，两根竖线标出 2,048 和 131,072）在这批材料里是独一份。这是本讲最差异化的东西。

**4.3 ZeRO 三级是推出来的，不是列出来的。**
HF、DeepSpeed、EleutherAI、Lilian Weng 四份全都是枚举式：「Stage 1 切优化器状态，Stage 2 加梯度，Stage 3 加参数。」Scaling Book 推了通信但没推**顺序的理由**。只有我们给了「谁最大、谁最少被用到，就先切谁」这条原则，并且明说「把 §4.1 那个顺序倒过来读一遍，你就把它推出来了」。这是把一个需要背的名词变成一个不用背的推论——保留，而且 §4.2 开头那条元判据（「一个名词值不值得进正课，看它能不能被前面的内容推出来」）更要保留。

**4.4 精度判据「看它会不会无限累加」，以及它被 V3 打脸后的收紧。**
HF 和 Lilian Weng 都给三条规则（fp32 主权重 / loss scaling / fp32 累加），**都不抽象成判据**。我们不但抽了判据，还拿 DeepSeek-V3「m、v 都用 bf16，没有可观察到的性能退化」把自己第一版判据证伪，再收紧成「看它是不是老的贡献永远不走」。**把判据被打破再修好的过程show 出来，比直接给修好的版本有价值得多**——这是全讲最好的一段方法论演示。而且我们还在 §3.6 又拿 PaLM 的 β₂→0.9999 反过来给这条判据加了个前提，并诚实标注「这一条是我们自己推的，当猜想看」。三段连起来是个完整的认知过程。一个字都别动。

**4.5 §7 那两张溯源表。**
十五份材料里没有任何一份区分「这个数有论文出处」和「这个数是我自己按算子推的，它可能错在哪」。而 §7 结尾那句是全讲最该留下的方法论：「82.1% 之所以可信，不是因为算得仔细，而是因为专题一用完全独立的另一套算法给出了 81.8%。孤立的估算没法验证；能对上一个外部锚点的估算，一次就把整套公式验了。」这条比这一讲任何一个数字都值钱。

**4.6 Update RMS 0.2 → 「常数就能当接口用」。**
苏剑林原文给的是**推导**（数值模拟 0.225 ＋ 平均场 √((1−β₁)/(1+β₁)) = 0.2294），以及一个应用（Match Adam Update RMS 迁 Muon）。他**没有**把它抽成一条可迁移的设计原则。我们那句「先把某个量做成常数，常数就能当接口用」是我们加的，而且是这一讲少数几条能带出机器学习之外的思路。另外我们那句「⚠️ 这一条我原来写错了，而且错得很典型：『量纲抵消了』只说明它是常数，没说明它等于 1」——把自己的错误当教材，这个动作本身也没有对标物。

**4.7 「梯度只告诉你往哪走，优化器决定走多远」＋ 三答谱系。**
所有对标材料对优化器的处理都是清单式（Lilian Weng 甚至只在「Memory Efficient Optimizer」标题下列了 Adafactor / SM3 / ZeRO 三个名字）。我们那条「几十年的演化全都在回答同一个问题——这个『多远』该由谁说了算：SGD 说由你说了算；AdaGrad/Adam 说由梯度自己的历史尺度说了算；Muon 说由矩阵的几何说了算」，是一句能把整个优化器动物园串起来的话，我在任何一份材料里都没看到同等的组织句。

**4.8 训练稳定性整节。**
HF、Scaling Book、Lilian Weng、EleutherAI **四份通用教材全都不讲训练稳定性**（HF 只在 FP8 那节提了一句 "stability"）。我们 §6 整节没有对标物。而且其中两条特别好：ST-MoE 那张「收紧 update clipping 稳定 3/3，但质量从 −1.755 掉到 −4.206」的表，以及那句落点「只看稳没稳的话，把学习率设成零是最优解」。另外 §6.2 那个 PaLM 消融（同一批数据从更早的 checkpoint 重喂就不飞 → spike 是数据和参数状态撞出来的，不是数据坏）也是独一份，而且我们诚实转述了论文自己那句「由于训练成本太高，没能找到一个有原则的缓解办法」。

**4.9 MoE 的九份激活复制费。**
Scaling Book 把 MoE 当「E 个 MLP，激活 k 个」，讨论的是 AllToAll 通信；HF 的激活公式是 dense-only；EleutherAI 的公式也是 dense。**没有一份把「派发时激活被复制 k+1 份」放进激活账。** 我们 §1.7 那句「MoE 在参数账上很划算，可在激活账上要付九份的复制费——而它在专题一那张参数量的表上完全看不出来」，是一条真正的原创观察，而且它是这一讲和专题一的最好接缝。

**4.10 「峰值必须连着『哪一项的峰』一起问」。**
HF 展示了那条 profile 曲线但没提炼原则；Scaling Book 只算总量。我们 §5.3 那条「把几条形状不同的曲线叠起来之后，总和的峰未必落在任何一条单独的峰上」是一条能带出本领域的通用判据。

## 五、顺带：三处我认为我们可能说错或说窄了

不在任务范围内，但既然读到了就报。

**(1) §2.6：「为什么 MFU 看起来那么低：分母里有一大块被重算吃了。」**
按 HF playbook 的定义，MFU 的分子是 **model FLOPs**——**明确不含重算**（含重算的那个叫 HFU）。所以重算并不是「进了 MFU 的分母」，它是**让 step 变长**，从而压低 MFU。我们那句话的方向感是反的（听起来像重算被算进了某个分母里）。**判据**：HF 原文「an alternative is to compute model FLOPS utilization (MFU), which, in contrast to HFU, **only takes into account the required operations for the forward and backward passes through the model and does not include recomputation** in the measured FLOPs.」建议改成：「重算做的功不算进 model FLOPs，但它实实在在占了时间——所以 MFU 会被压低。想看『芯片到底忙不忙』要看 HFU，想看『训练效率高不高』才看 MFU。」顺带这就把 HFU/MFU 这对我们没讲过的概念补上了。

**(2) §4.2：「ZeRO-3（≈FSDP）……通信代价是三级里最高的。」**
字节数上没错（3Ψ vs 2Ψ）。但两份最权威的材料都在强调相反的实践含义：Scaling Book 说 FSDP 的 FLOPs/comms 比值跟纯 DP **完全一样**，「we can basically always do ZeRO-3 sharding」；HF 说配 prefetch 之后开销「not a big deal」，经验上限是 DP ≲ 512。**判据是这两句原文。** 建议保留「字节最多」这个事实，但把「代价最高」这个评价换成「它是三级里唯一在前向也要通信的，所以它对 prefetch 是否做得好最敏感——做好了几乎白拿，做不好就是它最先顶不住」。

**(3) §1.8 论证爬 batch 时缺一个上界。**
见 3.1。现在的写法会让读者相信 batch 越大越好，而 §3.5 又说 batch 大了学习率要调小，两节互相拆台。加一句 B_noise 就能焊上。
