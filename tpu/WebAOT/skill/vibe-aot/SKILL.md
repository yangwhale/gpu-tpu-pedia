# vibe-aot — AOT 体检的知识与工具

**定位**：WebAOT 的大脑。程序只做确定性的三件事（正则解析、跑 docker、读写存储），
**其余判断、解释、拆解、映射、兜底都在这里**。

**改知识改这里，不改代码、不发版。**

---

## 何时用

| 触发 | 用哪个 playbook |
|---|---|
| 用户贴了一条训练命令 | `playbooks/parse.md` |
| 用户贴了一份模型 config | `playbooks/new-model.md` |
| AOT 报了 OOM | `playbooks/oom.md` |
| 跑通了但比预期慢 | `playbooks/slow.md` |
| 出现没见过的失败 | `playbooks/unknown.md` —— 读原始日志现场分析，**并产出一条候选规则** |

---

## 三条硬约束

1. **确定性优先。** 能用 `scripts/extract.py` 抽出来的字段，不要自己读日志猜。
2. **输出走契约。** 每个场景的 JSON schema 在 `prompts/`，前端直接渲染，
   **不要返回自由文本**（除非是 `ask` 这种纯对话场景）。
3. **每个数字标出处。** 「实测 64 芯片 v7」比「据说更快」有用一百倍；
   没有出处的数字不要写进结论。

## 工具

| 脚本 | 干什么 |
|---|---|
| `scripts/submit.sh <config.json>` | 下发一次 AOT（docker，CPU），返回 `run_id` |
| `scripts/collect.sh <run_id>` | 采集 stdout / HLO / LLO 到工作目录 |
| `scripts/extract.py <run_id>` | 从产物抽结构化字段：显存、编译时间、代码路径、集合通信清单 |
| `scripts/lint.py <config.json>` | 跑 `rules/` 里的静态规则，不需要编译 |

**典型链路**：`lint.py` →（无 fatal 才）`submit.sh` → `collect.sh` → `extract.py` → 按 `prompts/` 组织输出。

## 领域知识索引

细节在 `knowledge/`，与 [PARAMS.md](../../PARAMS.md) 同源。这里只放**判断时最常用的几条**：

### 硬件常数

- TPU v7：**2 device / chip**。`tpu7x-128` = **64 芯片**，最常见的规模误判来源
- 单 device HBM 上限 **94.74 GB**；bf16 峰值约 **1,154 TFLOP/s**
- **AOT 对显存的预测逐位准确**，已两次独立验证（一次成功配置、一次 OOM 配置，
  两边都报同一个 `95.51G`）→ **显存问题一律先问 AOT，不要占卡**

### 会静默出错的组合（最重要）

| 组合 | 后果 |
|---|---|
| 专家维分片 + `fixed` 校准 + **非** tokamax kernel | **只算本地那几个专家**，不报错、loss 照常降 |
| MoE 模型不传 tile 参数 | 静默回退默认 tile：BF16 慢 26%、FP8 直接崩 |
| 只开分片开关不配 `fixed` 校准 | 静默失效，不报错也不变快 |

**共同特征：配置在语义上错了，但形状合法，编译器发现不了。**
判断这类问题**必须看「实际走到了哪条代码路径」**，不能只看「编译通过了」。

> 可推广的判据：**把维度 N 切成 N/k，而下游能把 N/k 当成一个合法的小 N 来用时，
> 分片错误就会静默。** 切到「切了就算不动」的维度上（如收缩维），编译器才会替你兜底。

### 量化

- `fixed` 静态 scale **会损害收敛质量**，它唯一的正当理由是跨卡收集时 scale 必须一致
- 不用跨卡收集就**必须用 `absmax`**
- 代价：`absmax` 要动态归约缓冲，实测吃掉两档 batch
- **主权重永远 fp32** —— 每步梯度相对权重量级极小，bf16 尾数不够，更新会被舍掉

### 通信

- 集合通信**能不能被藏住，取决于是编译器插的还是手写的**：
  编译器插的可以提前发、跟计算重叠；手写在依赖链中间的钉死在原地（实测差 178 倍）
- SparseCore 卸载那一族 flag **有依赖，不能挑着开**

## 兜底原则

遇到 `knowledge/` 里没有的情况：

1. **读原始日志**，不要猜
2. 给结论时**明确标注置信度**，区分「实测过的」和「推断的」
3. **产出一条候选 lint 规则**（`prompts/propose_rule.json` 的格式），
   人工确认后进规则库 —— 这样每踩一个新坑，下次就自动拦住

## 反面清单

- ❌ 不预测吞吐。AOT 没有实测时间，任何 TFLOP/s 都是猜的
- ❌ 不替代真机数值验证。数值等价性要看 logits 上的 KL
- ❌ 不静默改写用户的配置。任何自动补全都要标出来让用户确认
- ❌ 不用短程 loss 判断分片改动对不对 —— 前十步模型在学词频先验，**测不出来**
