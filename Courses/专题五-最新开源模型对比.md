## 这个专题要回答的一个问题

专题一拆透了 V3。但 V3 只是一家的一个选择。

**把当下的主流开源模型摆成一排，会发现：有些设计所有人都采用了，
有些还在激烈分叉。**

- **收敛了的**，说明那是定论 —— 不用再纠结，照做
- **还在分叉的**，说明代价还没算清楚 —— 那正是值得深挖的地方

讲完这个专题，应该能拿到任何一个新发布的模型 config，
**十分钟内说出它站在哪条路线上、跟谁像、赌的是什么。**

---

## 方法：数字只从 `config.json` 来

跟专题一同一条规矩：**每个数都要能对回一个真实字段。**

- 一律拉官方 `config.json`（HuggingFace 上的），不引二手总结
- 拉不到的（未开源权重、只有技术报告）**明确标注来源与不确定性**
- 我们自己实测过的，**单独标出来** —— 那是别人没有的东西

> ⚠️ 二手材料在这个专题里特别危险。同一个模型不同文章报的参数量能差一倍
> （总参数 vs 激活参数没说清楚），专家数常常把 shared 算进去又不说。
> **一律回到 config。**

## 对比表：列怎么定

**一张主表 + 三张分表**。主表求全景，分表求深度。

### 主表（全景）

| 列 | 为什么要这一列 |
|---|---|
| 总参数 / 激活参数 / **稀疏比** | 稀疏比（总 ÷ 激活）是这一代模型最核心的一个数 |
| 层数 · hidden size | 决定形状是"深瘦"还是"浅胖" |
| **注意力路线** | 最大的分歧点，见下面分表 A |
| **专家配置** | 见分表 B |
| 最大上下文 | 竞赛焦点 |
| 训练 / 权重精度 | BF16 / FP8 / FP4，直接对应成本 |
| **主打的那一件事** | 每家都有一个最想让你记住的点 |

### 分表 A · 注意力路线（接专题二的三个旋钮）

| 列 | 说明 |
|---|---|
| 基础机制 | MLA / GQA / Gated MLA / … |
| 是否混线性 | KDA、GDN 之类，以及**配比**（比如 K3 是 3:1） |
| 是否稀疏 | DSA / CSA / HCA / SWA，以及压缩率与 top-k |
| KV 每 token 每层的字节数 | ⭐ **这一列最能说明问题**，把所有花活折算成一个可比的数 |
| 长上下文靠什么撑 | 压缩？稀疏？线性？还是纯靠堆卡 |

> ⭐ **「每 token 每层的 KV 字节数」是这张表的灵魂**。
> 各家的方案名字五花八门，但折算成这一个数就完全可比了 ——
> 而且它直接决定推理时能服务多少并发。

### 分表 B · 专家配置

| 列 | 说明 |
|---|---|
| routed 专家数 | |
| shared 专家数 | 0 / 1 / 更多 —— 这是个有分歧的选择 |
| top-k | |
| **专家中间层大小** | ⭐ 细粒度程度的直接指标 |
| 单专家参数量 | 中间层大小 × hidden × 3 |
| dense 层数 | 前几层不做 MoE 的有几层 |
| 路由打分 | softmax / sigmoid |
| 负载均衡 | aux loss / noaux_tc / QB / hash |
| 分组限制 | 有没有、几组选几组 —— **这一列反映的是通信约束** |

### 分表 C · 其它值得单列的创新

残差结构（mHC）、优化器（AdamW / Muon）、激活函数、MTP、
量化方案 —— 谁用了什么，是不是已经扩散开。

## 分析：光有表不够，要读出趋势

**这一节才是专题的价值所在**，否则就是一张查询表。

### 1 · 已经收敛的（可以当定论）

初步观察，需要用表验证：

- **MoE 是标配** —— dense 大模型基本消失了
- **RMSNorm + pre-norm + SwiGLU + RoPE + 无 bias** —— 几乎没人再动
- **细粒度专家 + shared 专家** —— 从 V2 开始的这套已被广泛采用
- **稀疏比一路走高** —— 从早期的 8 倍到现在的 20-30 倍
- **1M 上下文成为新的竞赛线**

### 2 · 仍在激烈分叉的（值得深挖）

- ⭐ **注意力路线是最大的分歧**：
  - 纯 MLA 压缩（DeepSeek V3）
  - 压缩 + 稀疏挑选（V3.2 的 DSA、V4 的 CSA/HCA）
  - 混线性注意力（K3 的 KDA、Ling 的 Hybrid KDA）
  - **三条路赌的是不同的东西** —— 这一节要说清楚各自赌什么
- **shared 专家要几个** —— 0、1、还是更多
- **优化器** —— AdamW 还是 Muon，这是个显存决策（见专题三）
- **精度往下压到哪** —— FP8 训练已成主流，FP4 权重刚开始

### 3 · 从表里能读出的硬件信号

回到全课主线：**每一个设计选择都在对硬件提要求。**

- 稀疏比越高 → **显存压力不降，算力压力降** → 卡的选型逻辑变了
- KV 字节数越小 → 推理并发越高 → **同样的卡能服务更多人**
- 分组限制越严 → 说明厂商在**迁就跨机带宽**
- FP4 权重 → 需要硬件原生支持，否则反而更慢

### 4 · 我们独有的角度

别人只能看 config 和技术报告，**我们跑过其中几个**：

- 混元 3：64 卡 v7 上从 445 调到 645 TFLOP/s 的完整过程
- Ling3-Flash：128K prefill 的加速实测
- GLM / Qwen / DeepSeek 的 TPU 推理部署
- KDA kernel 的实现经验

> 表里那些纸面数字，落到真实硬件上会走样多少 —— **这是我们能讲、别人讲不了的部分。**
