## 这个专题要回答的一个问题

[专题一](专题01-一个-Token-的一生.md)的出口那一节算过一笔账：
训练时每个位置都要产生一条 129,280 维的 logits，
**128K 个位置就是 31.56 GiB —— 比全部 61 层注意力的权重还大 1.48 倍**，
而 lm_head 只占前向算力的 0.46%。

那一节算的是**它有多大**。这一课问的是另一半：

> **付了这么大一个张量，我们从里面拿回来了多少信息？**

答案是：**用 one-hot 标签的话，拿回来的少得可怜。**
而蒸馏做的事只有一件 —— 把那个硬标签换成老师模型的完整分布。
就这一下，换来的东西超乎直觉。

**但故事没这么简单。** 真正在生产里跑的蒸馏，
**几乎没有一家在传 logits** —— 包括手里明明有完整 logits 的那些。
这一课的后半程讲的就是为什么。

## 一 · 起点：one-hot 到底浪费了什么

### 1.1 先承认它是对的

标签「要么 1 要么 0」，跟真实的下一词分布差得很远 —— 这个直觉是对的，
**但目标函数在期望上是正确的**：

```
最小化  E[ −log p_θ(y|x) ]  ≡  最小化 KL( P_数据 ‖ p_θ )  +  H( P_数据 )
                                                        ↑ 常数，跟 θ 无关
```

**关键一句：one-hot 不是「对分布的断言」，是「从分布里抽的一个样本」。**
抛硬币每次都是 0 或 1、从来不是 0.5，但抛一万次平均下来就是 0.5。
同一个前缀在语料里出现很多次，每次推不同的词，梯度平均出来就是经验频率。

两条推论要讲（都反直觉）：

- **模型永远到不了 1，而且是梯度下降主动拦着它** ——
  一旦对某前缀输出 one-hot，在同一前缀的其他出现上 loss 就是 −log(0) = ∞
- **训练 loss 的地板不是 0，是语言本身的熵** ——
  loss 停在大于零的地方不是训练失败；真趋近 0 反而说明它在背语料

### 1.2 那它慢在哪 —— 三个层次

**① 梯度层面：绝大多数词根本拿不到信号**

```
one-hot   ∂L/∂logit_i = p_i − y_i    y 全是 0，而模型本来就给它们 ~0
                                     ⇒ 129,279 个错词这一步几乎没有梯度
软标签    ∂L/∂logit_i = p_i − q_i    q 是老师给的值
                                     ⇒ 每个跟老师不一致的词都拿到推力
```

**② 方差层面：one-hot 是抽样，所以它抖**

Hinton 原话 —— soft targets *"provide much more information per training case
than hard targets and much less variance in the gradient between training cases,
so the small model can often be trained on much less data … and using
a much higher learning rate."*

老师的分布对同一个前缀每次都一样，没有噪声要平均掉。
**「可以用高得多的学习率」这句话，就是这么来的。**

**③ 信息层面**（这一步是按词表大小推的，不是论文原文）

```
one-hot 每个位置最多携带   log₂(129,280) ≈ 17 bit
软分布  每个位置携带       整条 129,280 维的形状
```

> ⭐ **这一节的落点**：算力一分没多花，付的 logits 一字节没少，
> 拿回来的信息差几个数量级。**「快」的来源就在这儿。**

## 二 · Hinton 那套：word-level / logit 蒸馏

主要出处：Hinton, Vinyals, Dean 2015,
*Distilling the Knowledge in a Neural Network*（arXiv:1503.02531，
NIPS 2014 Deep Learning Workshop）。**下面每个数字都出自原文，已逐句核过。**

### 2.1 dark knowledge —— 老师真正教的是那些小数之间的比值

> *"one version of a 2 may be given a probability of 10⁻⁶ of being a 3 and 10⁻⁹
> of being a 7 whereas for another version it may be the other way around.
> **This is valuable information that defines a rich similarity structure
> over the data**."*

百万分之一和十亿分之一都小到不值一提，**但它们的比值有意义** ——
它说的是「这个 2 写得偏 3，不偏 7」。

**one-hot 把这张「谁像谁」的关系图整个扔了。** 后来大家管它叫 *dark knowledge*。

### 2.2 温度：不升温等于没蒸

老师自己也是拿 one-hot 训出来的，所以它在 `T=1` 时的输出**同样接近 one-hot** ——
那些 10⁻⁶ 和 10⁻⁹ 全被压在地板上。**升温就是把地板上的东西照亮。**

```
高温极限下（论文 Eq. 4，要求 logits 逐样本零均值）：
    ∂C/∂z_i ≈ (1 / N·T²) · (z_i − v_i)        ⇒ 蒸馏退化成直接对齐 logits

推论：梯度按 1/T² 衰减 ⇒ 软硬两个损失混用时，软的那项要乘回 T² 才不会被压没
```

**有多要紧**：论文里提到另一组人也做蒸馏，但用的是 `T=1` ——
他们只补回了大小模型差距的 **28%**，而升温之后是 **80% 以上**。
*同一个方法，温度选错，收益掉到三分之一。*

### 2.3 快多少倍 —— 三组实测收成一张表

| 实验 | 硬标签 | 软标签（蒸馏） | 结论 |
|---|---|---|---|
| **语音识别 · 只给 3% 数据**<br>（论文 Table 5） | 测试帧准确率 **44.5%**<br>严重过拟合，只能早停 | 测试帧准确率 **57.0%**<br>没早停，自己收敛 | **全量数据基线 58.9%** ——<br>**1/33 的数据，只差 1.9 个点** |
| **MNIST**<br>大网 1200 单元 / 小网 800 单元 | 小网自己训 **146 个错**<br>（大网 67 个错） | 小网学软标签（T=20）<br>**74 个错** | 差距 146−67 = 79 个，<br>蒸馏补回 146−74 = 72 个<br>**= 91%**（这一步是自行推导） |
| **10 个模型的 ensemble**<br>语音，帧分类准确率 | 把 ensemble 的收益蒸进单个模型 | 同左 | 原文：*"More than 80% of the<br>improvement … is transferred"* |

> ⭐ **最硬的那个数字是 33 倍。** 同样的模型、同样的 3% 数据，
> **换标签这一件事**把测试准确率从 44.5% 抬到 57.0%。
> 而且要注意训练准确率反而是硬标签那组更高（67.3% vs 65.4%）——
> **它不是学不动，是在背那 3% 的数据。**
>
> **所以蒸馏省的不是算力，是数据；换来的不是拟合，是泛化。**

### 2.4 一个值得单独讲的实验：让它学一个从没见过的类

把训练集里的**数字 3 全部删掉** —— 对蒸馏出来的模型来说，3 从没见过。

```
直接测      206 个错，其中 133 个错在那 1,010 个 3 上
            （错因：3 这一类的 bias 学得太低 —— 它从没被正例推高过）
bias +3.5   109 个错，其中只有 14 个错在 3 上
         →  98.6% 的 3 认对了，而它从没见过一个 3
```

**老师从来没有直接教过 3。** 但它在教 8、教 5 的时候，
每一次都顺带说了一句「这个有点像 3」——
*那张关系图里，3 的位置是被周围所有类挤出来的。*

## 三 · 现实的墙：这套东西在 LLM 上做不了 ⭐

**上面那套是 2015 年在 MNIST 和语音上做的。搬到今天的大模型有三堵墙。**

### 3.1 闭源模型给不了完整分布

OpenAI 的 Chat Completions 有 `logprobs` / `top_logprobs`，
但文档写得很清楚：`logprob` 只在**前 20** 之内才是真值，
不在前二十的一律填 `-9999.0`。

> ⭐ **这一节最该讲的反直觉**：
> **top-20 保住的是概率质量，扔掉的恰恰是 dark knowledge。**
>
> 回看 2.1 —— 老师真正教的是 10⁻⁶ 跟 10⁻⁹ 那个比值，
> 而这两个数**永远进不了 top-20**。
> 所以「能拿到 logprobs」和「能做 logit 蒸馏」是两回事。
> 你拿到的是分布的**头**，而蒸馏要的是分布的**尾**。

- **待核**：Anthropic Messages API / Gemini API 各自暴露到什么程度 ——
  写这一节前现查文档，不要凭印象

### 3.2 词表对不齐

logit 蒸馏要求老师和学生**逐 token 对齐**。
两个不同厂家的模型 tokenizer 不同、词表大小不同，
第 *i* 维根本不是同一个词 —— 这不是工程细节，是**结构性障碍**。

（V3 是 129,280，别家各不相同。跨家做 logit 蒸馏得先解决对齐，
而对齐本身就是一个开放问题。）

### 3.3 条款

大部分商业 API 的服务条款明确禁止拿输出去训练竞品模型。
**这一条不是技术问题，但它决定了很多方案能不能做。**

## 四 · 于是主流走了另一条路：sequence-level ⭐

**做法**：让老师**生成**语料（完整的回答、完整的思维链），
再拿这批语料对学生做普通的 SFT。**标签仍然是 one-hot，只是数据换了来源。**

这条路在文献里有名字，叫 **sequence-level knowledge distillation**
（跟 Hinton 那个 word-level 相对）。
*—— 待核：命名出处印象中是 Kim & Rush 2016，写之前核一下。*

### 4.1 最强的证据：手里有 logits 的人也选了不用

**DeepSeek 把 R1 蒸到 Qwen / Llama 的时候，用的是自家模型，
完整 logits 想怎么取怎么取。** 结果论文附录 B.4.3 写得明明白白：

> *"For distillation, we fine-tune the corresponding base model for 2–3 epochs
> using the 800k data described in Section B.3.3."*

**就是 SFT，一个 logit 都没对齐。** 六个模型全是这么来的：

| 蒸出来的模型 | 基座 | 初始学习率 |
|---|---|---|
| DeepSeek-R1-Distill-Qwen-1.5B | Qwen2.5-Math-1.5B | 1 × 10⁻⁴ |
| DeepSeek-R1-Distill-Qwen-7B | Qwen2.5-Math-7B | 8 × 10⁻⁵ |
| DeepSeek-R1-Distill-Qwen-14B | Qwen2.5-14B | 7 × 10⁻⁵ |
| DeepSeek-R1-Distill-Qwen-32B | Qwen2.5-32B | 6 × 10⁻⁵ |
| DeepSeek-R1-Distill-Llama-8B | Llama-3.1-8B | 5 × 10⁻⁵ |
| DeepSeek-R1-Distill-Llama-70B | Llama-3.3-70B-Instruct | 2 × 10⁻⁵ |

（来源同上，Table 6。max context 32,768，batch size 64。）

> ⭐ **这个证据的分量在于：不是「拿不到所以只能这样」，是「拿得到也不这样」。**

### 4.2 为什么？因为要传的东西变了

- **逐 token 对齐分布**，学的是「下一个词的品味」
- **采样出完整的思维链**，学的是「整条推理路径」

R1 要传的是后者。一条正确的 32K token 推理链里，
**价值在于它走对了顺序，不在于第 4,096 个词的概率是 0.31 还是 0.34。**

### 4.3 那 33 倍的红利还剩多少

**诚实讲：per-token 的方差红利没了，你退回 one-hot。**
但另外两条还在，而且在 LLM 上可能更值钱：

| 剩下的红利 | 为什么 |
|---|---|
| **数据分布对了** | 老师生成的语料干净、在目标分布上，还能**定向生成**（想补哪块补哪块）—— 比从网上抓强太多 |
| **可以拒绝采样** | 同一道题跑 16 条只留对的那条。**这本身就是一种降方差** —— 你在拿验证器替代老师的软标签 |

> ⚠️ **不要把 33 倍搬到这儿。** 那是 word-level 在语音任务上的实验数字，
> 换了方法就不成立了。**这一课要讲清楚这条边界，别让人把两个数混着用。**

## 五 · 系统账：这才是分水岭 ⭐

**这一节是这个专题独有的部分。** 别处讲蒸馏都在讲算法，
而这门课的规矩是**每讲一个部件就算它的代价**。算完你会发现，
第四节那个「大家都选 sequence-level」的现象，**根本不需要算法层面的解释。**

### 5.1 存 logits 比存 token id 贵 64,640 倍

离线蒸馏（先把老师的输出存盘，再喂给学生）是唯一能规模化的做法 ——
老师和学生同驻会把显存和调度复杂度都翻倍（这一点跟
[专题十](专题10-后训练与-RL.md)的 rollout 是同一个问题）。

那就来算存下来要多少。仍用[专题一](专题01-一个-Token-的一生.md)的口径：

```
存完整 logits   131,072 × 129,280 × 2 B  =  31.56 GiB       ← 一个 batch
存 token id     131,072 ×           4 B  =     512 KiB

比值 = 129,280 × 2 ÷ 4 = 64,640 ×                           ← 自行推导
```

> ⭐ **六万四千倍。** 这不是「贵一点」，这是**根本不可能**。
> 一个 T 级 token 的蒸馏语料，存 id 是几 TB，存 logits 是**几百 PB**。
>
> **所以 sequence-level 成为主流，首先是一个存储问题，其次才是算法选择。**

### 5.2 那存 top-k 呢 —— 一个漂亮的死循环

自然的折中是只存 top-k logits（比如 top-20），体积降到可接受。
**但第 3.1 节已经说了：top-k 扔掉的恰恰是 dark knowledge。**

```
存全量  → 存不下（64,640 倍）
存 top-k → 存得下，但省掉的正好是蒸馏唯一想要的那部分
```

> ⭐ **这个死循环值得单独用一页讲。** 它是这门课反复出现的那类结构：
> **一个约束把两条路同时堵死，于是大家绕道走第三条。**
> （对照[专题三](专题03-注意力演进.md)：KV cache 存不下 → 要么少存要么换数学。）

### 5.3 在线蒸馏的显存账

真要做在线（老师学生同驻），用[专题四](专题04-反向与优化器.md)的口径算：

- **学生**要训练 → 全套（权重 + 梯度 + 优化器状态 + 激活）
- **老师**只做前向 → 只要权重，**但它更大**

这跟[专题十](专题10-后训练与-RL.md)里 PPO 那张「四个模型同时驻留」的账
是同一类，可以直接复用那套算法。**结论也类似：大模型上很少有人这么干。**

### 5.4 蒸馏在推理侧的回声：draft model

投机解码里那个小的 draft model，通常就是蒸出来的 ——
它要的正是「跟大模型品味一致」，而不是「自己足够聪明」。
**这是 dark knowledge 少数真正被用上的场景。**

- **待核**：V3 的 MTP 模块能不能直接当 draft model 用（印象中论文提过），
  写之前翻原文确认。这条如果成立，跟[专题一](专题01-一个-Token-的一生.md)
  讲 MTP 那一段正好接上

## 六 · 收束：三种「知识迁移」是同一件事的不同预算档

| 做法 | 传的是什么 | 前提 | 成本 |
|---|---|---|---|
| **logit 蒸馏**（word-level） | 每个位置的完整分布 | 老师开权重 + 词表一致 | 存不下 → 只能在线 |
| **样本蒸馏**（sequence-level） | 老师生成的完整序列 | 只要能调用老师 | 存 id 就行，**主流** |
| **拒绝采样 / 自蒸馏** | 老师自己筛过的样本 | 要有验证器 | 最便宜，效果依赖验证器质量 |

> **一句话收尾**：软标签的信息不是凭空出现的，
> 是老师当年用海量 one-hot 一点点平均出来的 ——
> 蒸馏只是**把那份已经平均好的结果直接交出去**，省掉重走一遍。
>
> ⭐ **所以预训练仍然是唯一能「无中生有」的那一步。它慢，但它不需要老师。**
