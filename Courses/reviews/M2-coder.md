## ⭐ 特别项一：loss 到底怎么算 —— 整条链缺失

**§1.2（line 1014）第一句就是**："起点很朴素 —— loss 是一个数。（这一点后面是全部关键，先记着。）"

然后直接跳到"第一个梯度 ＝ 你猜的，减去正确答案"。中间这几步**一步都没有**：

| 缺的那一步 | 后果 |
|---|---|
| **loss 本身的定义**：一个 token 的 loss ＝ −log(模型给正确答案的概率) | 我知道它的**导数**长什么样，却不知道它**本身**长什么样。全课 grep「交叉熵」：topic-01/02/03 **零命中**，本讲只在 line 1017 出现一次「拿最常见的交叉熵来说」，没有定义 |
| **序列里每个位置都算一次 loss** | 这是最伤的。`fig-vote` 建立的画面是"样本 1 想要『的』、样本 2 想要『了』、样本 3 想要『在』"——**一条样本 ＝ 一个诉求**。可基准是 4K 序列，那是 **4096 个诉求**。我到 §5 看见「global batch ＝ 1 条」＝ 131072 个预测时，跟 §1.2 建立的画面直接打架 |
| **那个 1/N**（对 B×S 个位置求平均）| 没有它，我解释不了「为什么 batch 翻倍梯度不翻倍」；也接不上 `fig-vote` Ⓒ 那句"加起来取平均，那个平均就是梯度"——**平均的分母是什么，从没说** |
| **logits 张量（S × vocab）占的显存** | 见下面，这条能被当场证伪 |

**⛔ 最硬的一条：`§5.4` 那个 125M 的手算例子，激活表里没有 logits。**

表（line 5779–5788）只列了 12 层 transformer 块里的张量，合计 11,520 数/token → 2.11 GiB。可 GPT-3 125M 的词表是 50,257：

```
8,192 token × 50,257 × 2 B = 0.77 GiB
```

**这一块比任何一层都大，占它自报总量的 36%，而它不在表上。**（V3 128K 那边更极端：129,280 × 131,072 × 2 B ≈ 31.6 TiB，所以真实实现必须分块算 loss ——这恰好是个值得讲的工程点，现在是个洞。）

这一小节的卖点就是"你能自己算一遍"。我算了，对不上。

## ⭐ 特别项二：4K vs 128K —— 场景错位

这一讲**自己知道** V3 预训练是 4K：§1.8（line 2308）写着"V3 从 3072 条序列爬到 15360 条（**4K 上下文**，折合 12.6M → 62.9M token）"。

可 §1.7 之后的全部账都是 **128K × 1 条**：

- `4.15 TiB` / `106.75 GiB` 激活（§1.7、§2.2、§5）
- 交点 `S ≈ 5,734`（§2.4）
- `6ND 低估五到六倍`（§5.2）
- `94 条` 分水岭（§5.1）

V3 的 128K 是**长上下文扩展阶段**，不是预训练。后果对我这个读者很具体——**这三条结论在 4K 上全部翻过来**：

| 结论 | 128K 上 | 4K 上 |
|---|---|---|
| attention 该不该重算（§2.4） | 绝不（175.92 FLOPs/字节，最贵） | **该**（4096 < 交点 5734，比大多数线性层还便宜） |
| 6ND 准不准（§5.2） | 低估 5–6 倍 | 误差几个百分点，好用 |
| 激活 vs 常驻谁大（§5.1） | 要 94 条才追平 | 4K 下 3000 条就追平 |

§2.6 那条"序列长度翻转的不是收益大小，是收益的正负号"是全讲最好的判据之一——**可它自己就踩在这上面**：整讲把读者训练在 128K 的直觉上，然后送他去跑 4K。

§5.1（line 5674）那句"**94 条 128K，还是 3,000 条 4K，对显存是同一件事**"是全讲唯一把两者接起来的地方，它出现在第五节——太晚了，而且只管显存那一半。

## 只能改 5 处的话，按对工程师帮助排

**① 补齐 loss 那条链，并把 logits 加进两张激活表**（B1–B4）
一段话（一个 token 的 loss ＝ −log p(正确答案)；序列里**每个位置**都算一次；B×S 个数求平均得那个标量；所以 d(loss)/d(logits) ＝ (p−y)/N）＋ 两张表各加一行。理由：这是全讲的**起点**（§1.2 那颗种子），也是唯一一处"结论对、过程整条缺"；而 §5.4 那个 125M 例子明说"你能自己算一遍"——我算了，缺 36% 的显存。**一份材料被当场证伪一次，后面所有数都不再被信任。**

**② 在 §1.7 开头用一句话把 128K 和 4K 的关系立住**（B5）
比如："下面按 128K 算，是为了让 §2.4 那条斜线看得见；V3 预训练实际是 4K × 15360 条，换算只看 token 总数（见 5.1）。⛔ **在 4K 上，§2.4 和 §5.2 的结论都是反的。**"理由：现在读者带着 4K 的真实场景读完，会把三条工程判断**全部搞反**，而这一讲自己在 §2.6 立的判据就是"序列长度翻转的是正负号"。

**③ 修那三处结构 bug：§4.1 空节、§6.7 丢标签、论文节号误链**（G1/G2/G3）
§4.1 是"ZeRO 从账单推出来"这条主线的支点，空着整条就断了；误链直接伤"出处可核"这个**这份材料全部可信度所依赖的东西**——一个工程师点一次"PaLM §5.1"跳回本讲，就会开始怀疑所有引用。

**④ 写出 Adam 的四行更新式（含 ε），顺带给 §1.3 那两笔加上 shape**（E1 + E5）
理由：这是"看得懂符号想不出实现"清单里最贵的两条。一个后端工程师读完全讲，仍然**写不出 `optimizer.step()`**，也仍然要自己数格子才能确认 1+2＝3。而这两处各只需三四行。

**⑤ 给那批漏网的空降数字补推导链或降级**（D1 2571 TFLOP、D2 dense 40 GiB、D4 λ、D5 33 个数量级、D6 1/256 vs 1/128、D11 七/八档）
理由：§7.2 立了"自己推的必须连推导一起给，否则它冒充的是事实"——这六处恰好是逃出那张表的。其中 **D1 是 1.9% 那个招牌结论的分母**，**D5/D6 是两个能被一次除法当场抓住的自相矛盾**。
