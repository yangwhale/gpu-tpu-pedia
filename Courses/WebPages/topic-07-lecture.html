第零节　一步快了 50%，你信吗？（4′）计划 4′ · 含互动 4.1′

🖥 本节主屏：课件 第零节　一步快了 50%，你信吗？

🎯 这一节只留一句：好消息先别庆祝，也先别怀疑：花一分钟估一下，这个数可能吗？

🧭 开讲前先带到位：「我们现在在课件第零节「一步快了 50%，你信吗？」。」先切过去、让大家找到，再开讲。

「先讲一件我们自己碰到的事。混元3 是腾讯的 MoE 大模型，两千九百五十亿参数，每层有一百九十二个专家，每个 token 只挑八个来算。我们在六十四颗 TPU v7x 上用 FP8 训它，FP8 就是每个数只占一个字节。有一天改了一组参数，再跑一次，一步从十一点七六秒掉到了七点八四秒。」

「先交代一个背景，后面一直用得到。专家的权重太大，一张卡装不下全部，所以切成六十四份，每个 device 只存一份，要用的时候再从别的卡拼回来，这叫 FSDP。一颗 v7x 芯片有两个 TensorCore，profile 里算两个 device；六十四颗芯片，就是一百二十八个 device。」

🖥 屏幕：切到 0.1 两行步时，先指上下两行步时，再指底下那行 1.50。

「十一点七六除以七点八四，等于一点五：同样的时间多跑一半的 token。同一个配置又跑了两次，七点八四六、七点八四零，不是抖动。」

💬 互动：问台下：这个数，你信不信？举手就行：信的、不信的、说不好的。三种都有人举了就往下，先不评谁对。

🖥 屏幕：切到 0.2 改了什么，从上往下指表里三行。

「改了什么？两份配置逐行比，只差十三行。十二行是专家矩阵乘的 tile，tile 就是 kernel（芯片上实际跑的那段计算程序）每次搬进片上存储、一起算的那一块有多大，从一千零二十四调到两千零四十八和一千五百三十六。还有一行叫 use_tokamax_gmm，从 True 改成 False：专家矩阵乘从 tokamax 库的 kernel，换成 MaxText 自带的那一套。」

🖥 屏幕：点开 0.3 末尾「遇到不认识的词」折叠块，只指「专家矩阵乘（gmm／tgmm）」那一行。

「分到同一个专家的 token 凑在一起做一次矩阵乘，trace 上叫 gmm；算前向和对输入的梯度用 gmm，算对专家权重的梯度用 tgmm。」

「换了实现、调大了分块，矩阵乘变快，听起来完全说得通，我们当时也没觉得哪里不对。可心里也没底：这是真快了，还是哪里出了问题？我也不确定。不确定的时候，先别急着打开 profile（跑的时候录下的每个算子的起止时间），先花一分钟，估一下。」

🖥 屏幕：停在 0.3 不确定，就先估一下 那句 ⭐。

「估什么？就一个问题：这个数，在这台机器、这种模型上，可能吗？估得出来，打开 profile 的时候就知道该找什么。」

⚠️ 被问时再讲（正讲不念）
  • 被问「快 50% 说的是吞吐还是步时」：吞吐，11,758.2 ÷ 7,842.1 ＝ 1.499；换成步时是少了三分之一（0.667）。0.1 折叠块。
  • 被问「profile 里的步时和日志里的对得上吗」：profile 中位步 11,758.2／7,842.1 ms，MaxText 主机计时 11.765／7.853 s，含派发，长约 0.1%。
  • 被问「原配方 tile 1024 是它真用的吗」：不是。原配方走 tokamax 时 tile 是启动脚本另外注入的，编译后的程序里写着 (512, 2048, 1536)；所以「1024 → 2048」不等于 kernel 真用的分块变了（0.2 折叠块）。
  • 台下有人不认识 gmm、tile、FSDP、all-gather 这些词：0.3 末尾「遇到不认识的词」折叠块有十个词，讲到时再就地讲，别在这里念词表。
  • ⛔ 这一节不评对错、不暗示结论；「信不信」只是让台下先押一个。

第一节　先估：这个数可能吗？（9′）计划 9′ · 含互动 9.4′

🖥 本节主屏：课件 第一节　先估：这个数可能吗？　·　主图 fig-t7-ruler

🎯 这一节只留一句：DeepSeek-V3（MoE）换 FP8 只多出两成；改后拿到的是稠密模型的涨幅——可疑，该打开 profile 找那 3.9 秒。

🧭 开讲前先带到位：「我们现在在课件第一节「先估：这个数可能吗？」。」先切过去、让大家找到，再开讲。

「估要拿尺子。第一把尺子叫 MFU：每颗芯片实际每秒做了多少浮点运算，除以它的峰值。TFLOP/s 就是每秒多少万亿次。v7x 每颗芯片 BF16 峰值是两千三百零七 TFLOP/s。算 FP8 我们也除这个数，好让两种精度站在同一把尺子上比。」

🖥 屏幕：切到 1.1 第一把尺子：MFU 那张表，先指两行公开 MoE，再指混元3 BF16 和原配方，最后指红色那行，和最底下的 405B。

「公开的 MoE，Qwen3 和 DeepSeek-V3，都在百分之二十七上下。混元3 BF16 是二十八点七，FP8 原配方二十九点三，也挤在这一堆里。改后这一行一下子跳到四十四，离最底下稠密的 Llama 405B 只差一截。」

「这个数怎么来的？MaxText 每一步记一个运算量，每个 device 三千九百八十一 TFLOP。一颗芯片两个 device，乘二，再除以步时。两份 FP8 记的运算量一模一样，所以 MFU 涨了多少，完全是步时短了多少。光看 MFU，只能说它跳出来了，说不清该不该跳。」

🖥 屏幕：点开 1.1 下面「MFU 的分母」折叠块，指 4,614 那一条。

「顺便说一个常见的坑：FP8 的峰值是 BF16 的两倍，每颗芯片四千六百一十四。要是拿它当分母，改后这份的 MFU 就只剩百分之二十二，凭空减半。同一个数换个分母就变，所以报 FP8 的 MFU，一定写明除的是哪个峰值。我们这里统一除 BF16 的峰值，两种精度才能放在一起比。」

🖥 屏幕：点开 1.1 下面「自己算一遍」折叠块，指那八行代码里取步时和取运算量的两行，再指 676.2、1,013.7。

「这把尺子不用信我们，自己就能量：MaxText 把每一步的步时和运算量写进 TensorBoard 的事件文件，八行 Python 读出来，取中位步，乘二除一下。我们拿两份事件文件各跑了一次，六百七十六和一千零一十四，和表里差千分之一，只是取的步不一样。」

🖥 屏幕：切到 1.1 末尾「五条口径」 那张五行表，从上往下扫「坑」那一列。

「这一课从头到尾用这五条口径，每一行都是我们自己踩过的坑。步时取中位，躲开写 profile 的那一步；运算量照 BF16 那样数；分母写死两千三百零七；显存看运行时的峰值。自检只有一句：算出来的每 device TFLOP/s 要是超过峰值，口径一定错了。」

💬 互动：问台下：FP8 让一个数从两个字节变成一个字节，一个矩阵乘最多能快几倍？整个一步呢？等到有人说出「矩阵乘最多两倍，一步到不了两倍」再往下。

🖥 屏幕：切到 1.2 屋顶线图，先只指左边：斜坡、平顶、拐点，再指蓝顶升到橙顶。

「第二把尺子叫屋顶线，回答一个算子最快能多快。横轴是算术强度：每从显存搬一个字节，做几次运算。左边是斜坡，快慢看搬得多快；右边是平顶，快慢看算力峰值；两段交在拐点。FP8 让平顶抬高一倍，同一个矩阵乘的强度也翻一倍，所以一个矩阵乘最多快一倍。」

「可一步里不只有矩阵乘。路由、按专家重排 token、逐元素运算、通信，都不在这张图上，FP8 帮不了它们。」

「这里有个前提：FP8 只动矩阵乘。原配方其实还把专家权重先量化成 FP8 再收，通信的字节也减了半；可这份 profile 里没被计算盖住的通信每步只有零点二秒左右，算进去结论也不变。」

🖥 屏幕：还在这张图，指右边那条曲线和上面的红点；图下那条落点带先别念，它是后面互动的答案。

「右边这条线是我们自己推的：一步里矩阵乘占 p，FP8 最好也就把这部分砍半，一步最多快一除以一减二分之 p 倍。改后这一份比混元3 BF16 快了一点五三倍，倒推回去，一步里至少七成得是矩阵乘。」

「拿同一个式子去量别人，就有了参照：DeepSeek-V3 换 FP8 快了一点二一倍，倒推它一步里矩阵乘至少占三成五；稠密的 405B 快了一点五三倍，倒推出来也是七成。稠密模型一层就是几个大矩阵乘，占七成说得过去。」

💬 互动：问台下：一个 MoE，每层还要路由、重排 token、从别的卡收专家权重，矩阵乘能占到一步的七成吗？等有人说「占不到」或「不确定」，再切下一张图。

🖥 屏幕：切到 1.3 同类比尺子，先指最上面两行：稠密 +52.8%、DeepSeek-V3 +21.4%；再指混元3 原配方 +2.2%；最后指红行 +53.2%。

「拿同类比。同一种芯片、同样换 FP8：稠密的 405B 多出百分之五十二点八；DeepSeek-V3 是 MoE，只多出二十一点四；混元3 原配方自己，只比 BF16 多出二点二。改后这一份，多出五十三点二，和稠密模型一样多。」

「图上混元3 的三个点都是我们在六十四颗芯片上实测的，另外几行是转引的公开实测。尺子不精确，但它量的是同一件事：同一种改动，在同类模型上，一般能多出多少。」

💬 互动：问台下：一个 MoE 拿到了稠密模型的涨幅，你第一反应是哪个：这一改太厉害了，还是哪里漏了？举手押一个，不揭晓，带着这个押注往下看。

「要么这一改，把 MoE 的老毛病一下子全治好了；要么，有什么东西不对。估到这里，判不了真假，可已经知道打开 profile 该找什么了。」

🖥 屏幕：切到 1.4 估完：带着问题去打开 profile 那张两列表。

「少掉的三点九秒，总得落在某些算子上。如果是真快，同样那些算子都还在，只是每个变短了，主要是专家矩阵乘，通信该多少还是多少。如果有问题，会有一类算子整块不见，或者短得离谱，通信也跟着少。」

「这张表不是结论，是一张待查清单。左边一列要是对上了，我们就庆祝；右边一列要是对上了，就得往下挖。两边都没对上，说明尺子本身有问题，那要回头查口径。带着这张表，去打开 profile。」

⚠️ 被问时再讲（正讲不念）
