04 功能验证阶梯

  • 目标：1 台 host 到 10+ 个切片，每种形状建得出、跑得通、拆得净。
  • 为什么分级：每级坏法不同（Warden 拦 pod、Topology 缺层、sub-slice 占 cube、网卡复位），直接上 10+ 片分不清哪层坏了。
  • 前提：03 出口满足；上一级没过不进下一级（排期）。
  • 「实测」框 = 本章脚本的记录。
  • 9 级 阶梯 L0–L8：4 芯 → 数千芯
  • 芯片 × 2 10+ × 4x8x8 的 JAX device 数（v7x 每芯片 2 个 device）
  • 114–136 s 10+ 片全 ACTIVE
  • 1–2 h 整套排期（独占窗口）
  • 3 次 10+ 片 DCN 基准提交，都没出数

判定规则
  • WARN（两线之间或仅离群样本超标）可接受，备注原因与同时在跑的任务；低于 WARN 线或不通 = FAIL。单次 FAIL 先重跑，同批 cube 仍 FAIL 才算（例：C3 的 8x8x16 塌陷）；被抢占的一轮不算（优先级）。
  • 阈值 = 实测基线减余量，全部 [推断]，来历见 4.10 各卡。基线：实测集群，jax 0.11.2 / libtpu 0.0.49（DCN 0.11.0 / 0.0.48）。
  • 冻结：换 libtpu 或使用方第一轮后改 04-bench/thresholds.csv 与自建的 DCN 阈值表（4.8 第 3 步）；交付前把其 git commit 记进交付记录，之后收紧只用于回归（09 时间线 T+14）。

通用：JobSet 骨架（Kueue 路径）

取自一个跑通的 8x16x16 与 JIT 基线作业，只留切片字段：

yaml
apiVersion: jobset.x-k8s.io/v1alpha2
kind: JobSet
metadata:
  name: <≤20字符>                              # workload 名字长度限制；多片时更紧：ns + 名字 + worker + 下标位数 ≤ 32（ns=default、10+ 片 → ≤17），04-gen-jobset.sh 会算
  labels:
    kueue.x-k8s.io/queue-name: multislice-queue
spec:
  failurePolicy:
    maxRestarts: 0
  replicatedJobs:
  - name: worker
    replicas: <切片数>                          # Kueue 为每个 replica 建一个 Slice
    template:
      spec:
        backoffLimit: 0
        completionMode: Indexed
        parallelism: <每片主机数 = 芯片数/4>
        completions: <同上>
        template:
          metadata:
            annotations:
              cloud.google.com/gke-tpu-slice-topology: <AxBxC>
          spec:
            restartPolicy: Never
            hostNetwork: true
            dnsPolicy: ClusterFirstWithHostNet
            nodeSelector:
              cloud.google.com/gke-tpu-accelerator: tpu7x    # 不要自己写 gke-tpu-topology，Kueue 会加
            tolerations:
            - {key: google.com/tpu, operator: Exists, effect: NoSchedule}
            containers:
            - name: main
              image: <测试镜像，按 digest>
              command: [<测试命令>]
              resources:
                requests: {google.com/tpu: "4"}
                limits:   {google.com/tpu: "4"}

  • 测试命令（GA 指南 multislice 示例，镜像 python:3.12）：
bash
pip install -U --pre jax jaxlib libtpu requests -f https://storage.googleapis.com/jax-releases/libtpu_releases.html

验收任务的优先级

📊实测：没写优先级的验收任务被抢占了8×4x8x8 DCN 基准准入约 2 min 后被更高优先级的训练任务抢占（按设计）：Evicted → Preempted（Preempted to accommodate a workload ... due to prioritization in the ClusterQueue）→ Requeued。

时段 怎么定
交付前 验收即最高优先，不写也不会被抢
交付后、和生产训练共用 ClusterQueue 验收给低（./04-gen-jobset.sh ... --priority low，档位见 03-kueue-priority.yaml），被抢写进报告；或错开窗口
任何时候 别给高：10+ 片训练被抢 = 全部重切（见经验教训第 38 条），代价由使用方付

给「低」的两个前提：

  • 生产 PRIO > 100（kubectl get workloads -A -o custom-columns=NAME:.metadata.name,PRIO:.spec.priority）：生产不写优先级（kueue.x-k8s.io/priority-class 与 pod priorityClassName 都不写）按 0 算 [推断：Kueue 默认；实测集群上也是这样]，比 low=100 低，验收反而抢占生产；06-jobset.sh 默认 POD_PRIORITY=high。
  • WorkloadPriorityClass 存在（kubectl get workloadpriorityclass）：指向不存在的 WPC，JobSet 静默永远 suspend（实测集群一个都没有）。--priority 会先查；只有 PriorityClass 的集群用 --pod-priority <PC>。

本节可能踩到的问题：排队与抢占

4.1主机巡检（每台 host 一个 2x2x1）

一次全量主机巡检的做法（覆盖大部分主机，按 wave 标签分批）：每台 host 一个手动 2x2x1 Slice（partitionIds = 该 host 的 gke-tpu-partition-2x2x1-id）+ 单 pod Job，输出一行 NODE_BENCH_RESULT {json}。

Job nodeSelector：kubernetes.io/hostname、cloud.google.com/gke-tpu-topology: 2x2x1、cloud.google.com/gke-tpu-accelerator: tpu7x、cloud.google.com/gke-accelerator-count: "4"；hostNetwork: true；镜像 <H2D 基准镜像> /scripts/run_node_bench.sh。

巡检 Job 放 $INSPECT_NS（默认 rb-inspect）：03 已把它排除出 Kueue 管理（managedJobsNamespaceSelector）源scripts/03-kueue-values.yaml 文件头，不占配额（slice-controller 的 mjob.kb.io webhook 不看 namespace，照样过）→ 只在维护窗口、队列清空时做。

放受管 ns 不带队列名，本书 manageJobsWithoutQueueName: true 下「will be suspended and never started unless they are assigned a queue and eventually admitted」源https://kueue.sigs.k8s.io/docs/reference/kueue-config.v1beta2/（实测集群是 false，没挂起：抽查的两个作业都 .spec.suspend=false）；带队列名则 TAS 钉不到指定 host [推断]。

做法

说得出（先自己答，再点开对答案）

  • 一个 4x8x8 切片要多少 pod、JAX 里看到多少 device？
    64 pod；512 device
  • 为什么巡检切片不能和多 cube 任务同时存在？
    2x2x1 占着的 cube 编不进大切片，JIT 基线作业因此多等了约 6 min
  • 10+ 片 all-reduce 为什么要合并小张量？
    每次跨片 all-reduce 有一个固定地板（不随消息变小而下降）；合并后 28 个梯度约快 2.7 倍
  • 多切片卡在第一次跨片 all-reduce、而节点全绿，先查什么？
    GVE 网卡复位：tcp-data-split 和 dmesg
  • 大切片准入了却一直 SliceCreationFailed，message 里 external slice ID 是一个手工切片名，会自愈吗？
    不会：手工 Slice 占着 cube；删 JobSet，过 05-avoid-manual-slices.py 重提 → 经验教训第 33 条
  • insufficient unused quota 和 allows to fit only X out of Y slice(s) 有什么区别？
    前者配额不够；后者配额够、空闲完整 cube 拼不出形状
  • 4x8x8 的片内 all-reduce 只有 170 GB/s、4x4x4 有 365，是链路坏了吗？
    不是：单轴都 ≈ 85；链路看单轴 ≥ 78，整片按本形状的线
  • 报「每芯片 1,808 TFLOP/s」时还要说什么？
    功耗档；占官方峰值 78%、默认档天花板约 91%
  • 223.6 GB/s 和 43 GB/s 哪个是 host→device 带宽？
    都是，口径不同：raw DMA 对 JAX device_put
  • 任务结束后怎么确认拆干净？
    无残留 Slice、partition id 不重复、节点没挂已删切片的标签
