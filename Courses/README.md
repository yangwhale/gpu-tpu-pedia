## 这门课给谁

**目标读者**：会写 Python、懂深度学习基本概念、在 GPU 上跑过训练，但**没碰过 TPU**的工程师。

**不是给谁的**：
- 想要 API 手册的 —— 那个看官方文档更快
- 只想跑通一个 demo 的 —— 直接去 `tpu/` 下找对应项目的 README
- 找论文解读的 —— 去 `Learning/`

**学完之后应该能**：
1. 看着一个模型和一批卡，判断出该用什么并行策略、装不装得下
2. 独立把一次预训练从零拉起来，包括数据、checkpoint、故障恢复
3. 拿到一份 profile，说得出瓶颈在哪、下一步该动哪个旋钮
4. 把一个 PyTorch 模型迁到 TPU 上，并解释清楚数值对不上时该怎么查

## 编排原则

写之前先把规矩定死，否则写着写着就变成文档堆砌。

**1. 每一章都从「一个具体的坑」开始，不从定义开始。**
不要「TPU 是一种 ASIC……」。要「你把 batch 调小了，VMEM 还是 OOM —— 为什么？」
定义在解决问题的过程中自然出现。

**2. 所有数字必须是实测的，并且标出在哪一代硬件上测的。**
仓库里已有的实测数据是这门课最值钱的部分。没实测过的推论要明确写「推测」。
——这条跟 `tpu/tpuguru` 里 `evidence` 分三档是同一个原则。

**3. 讲清楚「为什么错的直觉是错的」。**
最贵的知识都是反直觉的：降 batch 治不了 VMEM OOM；编译通过不等于装得下；
块越大不等于越快。每一条这样的知识都值一个小节。

**4. 每章末尾有一个能真跑的练习。**
不能真跑的课程只是读物。练习要能在 4 芯片这种最小规模上完成，
不要求读者有 64 卡。

**5. 中文先行。**
先把中文写透、迭代稳定，最后再一次性翻译。不要中英并行改。

## 模块划分（草案）

### 第 0 部分 · 为什么需要另一种加速器

- 0.1 从矩阵乘说起：为什么 CPU 不够，GPU 怎么解决的
- 0.2 GPU 的代价：SIMT、显存墙、通信墙
- 0.3 脉动阵列（systolic array）：TPU 的另一条路
- 0.4 两条路各自擅长什么 —— 不是谁替代谁

> 素材：`gpu/`、`tpu/tpu-v7-vs-b200-20260311.html`

### 第 1 部分 · 硬件：你手上到底是什么

- 1.1 一颗 TPU 芯片的解剖：TensorCore / MXU / VMEM / HBM / SparseCore
- 1.2 **两层内存**：HBM 和 VMEM 是完全不同的两回事
- 1.3 从芯片到 Pod：ICI、3D torus、切片（slice）与拓扑
- 1.4 chip 和 device 不是一回事 —— 各代的比例与它带来的坑
- 1.5 跟 GPU 的对照表：算力、带宽、互联，以及**为什么峰值不能直接比**

> 素材：仓库各处的实测数据；`tpu/tpuguru/backend/`

### 第 2 部分 · 编程模型：JAX 与 XLA

- 2.1 为什么是 JAX：函数式 + 编译优先
- 2.2 `jit` 到底做了什么：从 trace 到 HLO 到机器码
- 2.3 编译期思维：静态形状、重编译的代价
- 2.4 `shard_map` 与 `mesh`：把张量摊到多少个设备上
- 2.5 读 HLO：怎么看一个算子被融合成了什么

> 素材：`tpu/torch_to_jax_jumpstart`、`tpu/kernel-equivalence-validation`

### 第 3 部分 · 并行策略：把模型塞进去

- 3.1 四种切法：数据 / 张量 / 流水 / 专家
- 3.2 FSDP 在 TPU 上是怎么回事
- 3.3 MoE 的特殊性：路由、负载均衡、all-to-all
- 3.4 **显存账怎么算**：参数、优化器状态、激活、临时缓冲，各占多少
- 3.5 选拓扑比调参数重要 —— 先选对形状再抠细节

> 素材：`tpu/Hunyuan3-295B-Pretraining`、`tpu/Qwen3-235B-Pretraining`

### 第 4 部分 · 训练实战：从零拉起一次预训练

- 4.1 MaxText 是什么、它的配置系统怎么读
- 4.2 数据管线：从原始语料到能喂进去的 token
- 4.3 Checkpoint：存什么、多久存一次、怎么恢复
- 4.4 提交作业：GKE、队列、抢占与重试
- 4.5 训练跑起来之后看什么：loss、梯度范数、吞吐、什么算不正常
- 4.6 故障恢复：节点掉了怎么办

> 素材：`tpu/Hunyuan3-295B-Pretraining`、`tpu/ant-pretrain`、`tpu/lustre-with-xpk`

### 第 5 部分 · 性能工程：从能跑到跑得快

- 5.1 先量后调：MFU 怎么算，以及它什么时候会骗人
- 5.2 抓 profile：XProf 怎么用、看哪几张图
- 5.3 定位瓶颈：计算受限 / 带宽受限 / 通信受限，各自长什么样
- 5.4 通信隐藏：让 all-gather 藏进计算里
- 5.5 XLA flag：哪些真有用、哪些有依赖关系不能单开
- 5.6 精度：BF16、FP8，量化在哪里会毁掉收敛
- 5.7 **调参是有天花板的** —— 什么时候该停下来换思路

> 素材：`tpu/v7_perf`、`tpu/cloud-diagnostics-xprof`、`tpu/tpuguru/backend/flags.py`

### 第 6 部分 · 迁移：把 PyTorch 模型搬过来

- 6.1 三条路：重写 JAX / torchax / PyTorch-XLA，各自的代价
- 6.2 算子对不上怎么办
- 6.3 **数值验证方法论**：怎么证明搬过来的模型跟原来是同一个模型
- 6.4 常见的坑清单

> 素材：`tpu/torch_to_jax_jumpstart`、`tpu/HunyuanVideo-1.5`、`tpu/kernel-equivalence-validation`

### 第 7 部分 · 推理

- 7.1 推理跟训练的根本差异：延迟、批处理、KV cache
- 7.2 静态形状与分桶（bucketing）
- 7.3 vLLM / SGLang 在 TPU 上的现状
- 7.4 服务化：吞吐与延迟的取舍

> 素材：`tpu/vllm-torchtpu`、`tpu/sglang-jax`、`tpu/tpu-inference`

### 第 8 部分 · 工程素养（贯穿全课）

这一部分不单独成章，而是分散进前面各章的「侧栏」。列在这里是为了保证不漏。

- 测量纪律：一次只改一个变量；temperature=0；跑三次取中位数
- 证据分级：实测 / 编译器输出 / 推测，不许混着报
- 失败要留证据：日志落盘、开 verbose
- 反直觉清单：全课收集到的「看着对其实错」的判断

## 每一课的目录结构（约定）

**每一课都长成一样**，找东西不用想。新建一课时照抄这个骨架：

```
第N课/
├── README.md          这一课讲什么 + 大纲 + 练习
├── 教学材料/           ← 相关的东西都往这里放
│   ├── README.md          材料清单：哪来的、什么许可、能不能公开
│   ├── <来源>文字版/       抓下来的原文（第三方，通常不入库）
│   ├── <来源>图/           渲出来 / 下载的图（产物，不入库）
│   └── ...                我们自己写的、画的（这些才入库）
├── RENDER.md          （按需）图怎么生成的
└── *.sh               （按需）能重跑的脚本
```

### 三条规矩

1. **材料先进 `教学材料/`，别散在别处。** 想不清楚放哪就先扔进去，之后再归类。
2. **每样材料都要在 `教学材料/README.md` 里有一行**，
   写清楚三件事：哪来的、什么许可、**能不能进公开仓库**。
   这个 repo 是 public 的 —— 往里放东西等于对外发布。
3. **产物入不入库，看重建成本。**
   - 小、稳定、但**重建要搭一套环境**的 → 入库（例如渲出的图：
     重建一次要装 LaTeX + OpenGL + manim，不该让每个读者都走一遍）
   - 大、易变、或**一条命令就能重来**的 → 不入库（视频、编译产物、缓存）

   无论入不入库，**生成它的东西必须在库里**：脚本、抓取命令、场景引用。
