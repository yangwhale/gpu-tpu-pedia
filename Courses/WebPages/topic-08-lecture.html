第一节　什么叫对齐（7′）

🎯 这一节只留一句：TPU 跟 GPU 的差，不能比 GPU 自己跟自己的差大。

▍一　开场：一件真事，三道题

「先讲一件真事：一个模型从 GPU 搬到 TPU，第一步几乎一样，可一千步下来，TPU 的 loss 一直低万分之一点五。按别的项目上线用的门槛，这早能交差；我们偏要查，最后查到一个谁都没怀疑的地方。」

🖥 屏幕：课件 s一 最上面的「🎯 开场热身」，点开（三道题会一起露出来），先只念第一问。

「先做一道浮点的小题。BF16 和 FP32，指数位一样多，都是 8 位。那 BF16 比 FP32 少的是什么？少了几位？」

💬 互动：等台下说出「尾数」「少 16 位」，再点开答案。

「对，少的是尾数：23 位只剩 7 位。所以两者能表示的范围一样大，差的是精度。在 1 附近，BF16 一格就有千分之八那么宽。这一格，后面整整一讲都绕不开。
再留两道预习题，不用现在答。第二问：同一个 GPU 程序跑两遍，会一位不差吗？第三问：就是刚才那件事 —— TPU 算错了吗？」

▍二　一位不差，做不到

「今天的问题只有一句：一个模型在 GPU 上已经训稳了，搬到 TPU 上，怎么证明训的还是同一个模型？
你一定会想：那让两边一位不差不就行了？」

🖥 屏幕：fig-assoc，先指左格，再指右格。

「看这个最小的例子：三个数相加，1 加两个 2 的负 8 次方，也就是 0.0039，正好半格。左边先加前两个，结果正好落在两格中间；正好在中间时，规矩是舍到末位为偶数的那一格，1 就是，所以舍回 1；再加一次，又舍回 1。右边先把两个小数加起来，正好一格，1 加上它落在格点上。
同一个式子，换个加法顺序，差了一整格。」

「有人做过更夸张的：八个大小悬殊的数，随机打乱顺序加一万次，加出一百零二种结果 —— 用的还是 64 位双精度，精确答案是 0。」

「一次矩阵乘就是成千上万次这样的加法。GPU 和 TPU 切块不同、加的顺序不同，末位必然不同。混元 3 是 MoE 模型，每个词由路由器挑几位「专家」来算；末位一不同，某个词可能就挑了另一个专家，几百步之后两条轨迹必然分开。
预习第二问的答案也在这儿：GPU 自己跑两遍，也不一位不差。」

「为什么？前向通常是确定的，两次运行第一步的 loss 一样；分叉从反向开始。反向里有些算子，比如注意力的反向、MoE 把 token 合回原位的那一步，要很多线程往同一个格子里加数，谁先算完谁先加进去，每次的先后都不一样。加法换了顺序，就是刚才那张图。
所以「完全相同」根本不是一个能达到的目标。」

▍三　尺子：GPU 自己跟自己的差

🖥 屏幕：fig-ruler，先只指灰色那一段，蓝点先不讲。

「既然一位不差做不到，就得换一个问法：TPU 跟 GPU 的差，不能比 GPU 自己跟自己的差大。
GPU 上跑出来当标准答案的那条记录，我们叫 golden。同样设置的 GPU 多跑几次，彼此之间的差，就是噪声。」

「横轴是第三百零一到一千步 loss 平均偏了多少，零是第一份 GPU 自己。灰色这一段，是 GPU 一共跑了十次、都对第一份比，落下的范围。这就是尺子。」

「再看蓝点：同一份代码在 TPU 上的三种跑法：原样、不开重算、改编译器的片上内存上限，只改执行方式、不改数学。三个点自己也散开万分之零点六，跟灰段差不多宽 —— 是整团挪到了左边，离 GPU 的均值 2.9 到 5.3 个标准差。逐步看，原样那条稳定在负万分之一点五上下。
有了尺子，「万分之一点几」才有了大小。这三个蓝点，就是今天要查到底的那件事。」

▍四　从哪查起：五级

🖥 屏幕：fig-funnel，指左右两根箭头；红色那级要一位不差，蓝色几级比噪声或比 FP64 真值。

「从哪查起？分五级。最底下 L0 是地基：数据、权重、配置，喂进去的东西，必须一位不差。往上是单个算子、单层、整网第一步、一千步。
验收从下往上，低一级不过，上一级的结论不可信；出了问题从上往下，一级一级缩小范围。」

▍五　这一讲跟着的那一次

「开头那件事，就是混元 3 截前 4 层，从八张 B200 搬到 TPU v5p（8 颗芯片）：地基全部逐位，第一步 loss 只差百万分之二点五；一千步下来 loss 低万分之一点五，参数范数也多涨了一截。
前五节备工具，后五节回来查它。
另外还有一个更新的模型，我们管它叫「第二次迁移」：同一套方法在它身上又走了一遍，课上拿它当旁证，每次用到都会先报名字；它多了几样混元 3 没有的结构，用到时再说。」

「第一步，先把地基铺平：数据、权重、配置，怎么做到一位不差？」

⚠️ 这一节最容易跑偏的地方 ⛔ 不要在这一节讲任何判定细节（N 怎么取、2 倍、参照对数）。那是第三节的事；这里只立「尺子」这个概念。
⛔ 不要提前说出案例的结论（GPU 输出头 dgrad 那次长求和有偏）。第三问的答案在第七节揭晓。
❓ 台下可能问：「为什么不拿 FP64 当标准答案？」—— 答：对齐的目标是 GPU，模型是在 GPU 上调稳的；FP64 只在第一步那几级（单算子、单层、整网第一步）帮我们判断差是谁带来的，第四节讲。
❓ 台下可能问：「GPU 为什么不开确定性模式，把噪声关成零？」—— 答：生产训练不开它；尺子要量的是生产配置下会有的执行噪声。
❓ 台下可能问：「到底是万分之一点五还是一点七？」—— 答：原样那条逐步稳定在一点五上下，第三百零一到一千步平均是一点六六。

第二节　地基 L0：输入必须一位不差（5′）

🎯 这一节只留一句：地基这一级只有一个标准，一位不差；第一步 loss 是最便宜的自检。

▍一　为什么要一位不差

「L0 只有一条要求：两边的输入一位不差。这一级不过，后面所有比较都没有意义，你量到的差，说不清是算出来的还是喂出来的。
三样东西：数据、权重、配置。」

▍二　数据：原样回放

🖥 屏幕：fig-replay，指上下两排颜色一一对上的那些格子。

「数据不重读，原样回放。GPU 训练的时候，把每一步、每张卡、每一个微批吃进去的东西原样存下来，每一份记一个指纹。TPU 不读数据集，按同样的顺序回放：设备 d 的第 m 份，就是 GPU 第 d 张卡的第 m 份。
一千步乘八张卡乘两小份，一万六千个单元，每个单元的 token、标签、掩码、位置各一个指纹，逐个比，全部相同。」

「最下面那根条值得看一眼：换成 TPU 自己的数据加载器，读的是同一份数据，内容也逐位相同，可只有八分之一落到同号的设备上。两边切小份的方式不一样。
加一步重排其实能全部对上；但对齐阶段直接回放，少一个要额外证明的环节。生产管线另外验。」

▍三　权重：转过去再转回来

💬 互动（超时先砍）：切到下一张之前问「抽 100 个张量比，全对，算转对了吗？」等有人说「不算，要全量」。

「权重的办法是：转过去，再转回来，跟原始文件按字节逐个张量比。一千七百八十一个张量，全部相同，不抽样。
加载到设备上以后，再读出来比一遍。为什么第一步 loss 对上还不够？主权重，就是优化器手里那份 FP32 的权重，上面不到半格的错，前向时被舍成 BF16 舍掉了，要等第二步才可能露出来。
这里有个缺口：GPU 那边只抓下来 50 个张量的 FP32 主权重，所以主权重这一项只比了这 50 个。」

▍四　配置：对实际生效的值

💬 互动：切图之前问「GPU 的配置文件，TPU 照抄行不行？」

🖥 屏幕：fig-wd，先指虚线，再指实线，最后指右上红字。

「配置是最容易翻车的。权重衰减，GPU 的配置文件里写的是 0.1。可框架的调度器每一步都把它覆盖成 0.033。真正生效的是 0.033。
TPU 要是照抄配置文件，每一步多衰减三倍，而且不报任何错。」

「所以对照表要写实际生效的值，证据是运行时读出来的元数据，不是配置文件。混元 3 这张表有几十行：学习率、精度、批大小怎么切、重算怎么开，每行一条证据。
连批大小怎么切都要对：一次算两条，跟分两次各算一条再相加，舍入不同；GPU 只换这个切法，词嵌入梯度的差就是它自己重跑的 31 倍。」

▍五　第一步 loss 与续训

🖥 屏幕：§2.4 那个绿框「第 1 步 loss」（点小节标题下的「▸ 展开这一小节」）。

「最后一个最便宜、也最有用的自检：第一步的 loss。第一步还没有任何更新，两边只差前向的舍入。混元 3 是百万分之二点五。
第一步就差得离谱，别去查数值，先回头查地基。」

「还有一条容易忘：续训。第十步存档、恢复后接着跑到第二十步，跟一口气跑下来逐位相同。
生产训练一定会断点重启，这一条不过，一次重启就把两边的对齐打乱了。」

「地基平了，两边就开始各算各的了，每一步都会有一点差。一千步的差，怎么压成几个能判的数？」

⚠️ 这一节最容易跑偏的地方 ⛔ 不讲权重转换的细节（改名、拼接、转置怎么做）。台下只需要知道「转过去再转回来、逐字节比」这个办法。
⚠️ 口径：16,000 是「步 × 卡 × 小份」的单元数，每个单元四个字段各一个指纹；别说成 16,000 个样本。
❓ 台下可能问：「生产里 TPU 总要用自己的数据管线吧？」—— 答：对，生产管线要另外单独验；对齐阶段先用回放，把「喂」的差排除掉。
❓ 台下可能问：「v7x 只有 4 颗芯片，怎么对 8 张卡？」—— 答：v7x 每颗芯片是两个设备，正好 8 个。
❓ 台下可能问：「主权重只比了 50 个张量，剩下的呢？」—— 答：这是缺口，没补；要补就在 GPU 第 0 步全量抓 FP32 主权重。
❓ 台下可能问：「1,781 个张量怎么数出来的？状态互换那里怎么又是 1,193？」—— 答：开源命名一个矩阵一个张量：3 个 MoE 层 × 192 个专家 × 3 个矩阵 ＝ 1,728，加其余 53 个。GPU 框架把 q/k/v、gate/up 各合成一个，每个专家只剩 2 个矩阵：1,152 加其余 41 个 ＝ 1,193。元素一样多，切法不同。

第三节　指标（一）：逐步序列（18′）

🎯 这一节留三样：dₜ 怎么算、窗口里三种 reduce 各是一个数；N 怎么造、r 在两级上取最差；纯噪声也常落进 1–2，读 r 要先看纯噪声能拿几分。

▍一　比什么、跟谁比

「先说比什么。每一步记一个标量：loss 分全程和后段两个窗口，梯度范数取裁剪之前的值，参数范数是全部 FP32 主权重平方和开根号，混元 3 截四层约三千零四十二，再加学习率。第二次迁移的模型多几样，三百步看 8 条、一千步 9 条，用到时再说。」

「再说跟谁比。GPU 搬 TPU 时，参照是事先指定的一份 GPU golden；TPU 自己改代码时，参照是一次确认过的 TPU 运行。两种比较读的是同一种逐步记录，算法一模一样，只换了参照。」

▍二　dₜ 与窗口

「每一步先算一个相对差 dₜ：被测减参照，除以参照的绝对值，同一步，带正负号，单位是一，dₜ 等于 1e-5 就是十万分之一。例：混元 3 第一步 loss，TPU 11.465785、GPU 11.465756，相对差正的 2.5e-6。
分母一律用参照。」

🖥 屏幕：先滚到 §3.3 末尾的 fig-rpipe 上块，先指最左边那个黑点 d₀，再沿两根括号划过去，最后指右边那张小表。

「一千步就是一千个 dₜ。第一步单独拿出来报，叫 d₀，不进窗口：GPU 重跑第一步的 loss 常常逐位相同，差是零，当不了尺子。
窗口要事先写死，写成「a 冒号 b」，左闭右开。全程是第二到一千步，999 个数；混元 3 的后段是第三百零一到一千步，700 个数。前几百步两条轨迹还没分开，差还没长出来，会冲淡偏移。」

「关键一句：原始数据只有一份。两个窗口读的是同一条 dₜ 序列，窗口只决定拿哪一段来求平均。
在一个窗口里做三种 reduce，每种得一个数，是整个窗口算出来的，不是滑动平均：全程的带符号均值，就是那 999 个 dₜ 直接相加再除以 999。窗口写哪段，事先写进协议。」

▍三　三种 reduce

🖥 屏幕：滚回 §3.2 的 fig-dt，先只看上排灰点，再看下排蓝点；说到「最尖的一步」时指下排那个橙圈。

「上排是 GPU 第二次对第一次：点围着零上下抖。下排是 TPU 对 GPU：抖的宽度一模一样，可整团点往下沉。三种 reduce 各管一件事：偏多少，抖多大，最尖的一下。」

「偏多少，用带符号均值：dₜ 直接平均，正负抵消，随机的抖动就没了，剩下一直往一边偏的那部分；判的时候取绝对值，正负号另看方向。抖多大，用绝对值的平均，叫 MARE。最尖的一下，用最大单步，另报是哪一步，拦住某一步突然跳一下。
混元 3 这条的数在右边那张小表里，先只看一个：后段带符号均值负一点六六乘十的负四次方，最尖的一步在第三百八十步；其余几个留给课件。」

▍四　N 怎么造、怎么判

🖥 屏幕：fig-judge，先只讲三种颜色，不念点上的数。

「怎么判？要一把尺子 N，分四步造。一，同一设置的 GPU 重跑 K 份。二，两两配对，八份是二十八对，十份四十五对，十六份一百二十对。三，每一对一份当被测、一份当参照，用跟被测完全相同的窗口、分母、去掉第一步的规则，算出同样三个数。四，每个数取所有对里最大的那个。三个统计各有各的 N。」

🖥 屏幕：anim-ceiling（在 fig-judge 下面），先闭嘴看它把五份配成十对、挑出最高那根（约 26 秒）。

💬 互动：问「为什么取最大的那一对，不取平均？」等有人说出「被测如果只是噪声，就该落在已有样本的范围里」。

「对。被测要是纯噪声，它就是又一个同分布的样本，应该落在已有样本的范围里，所以拿范围的上沿当线。做线上实验的人管这叫 A/A 测试：两组都吃安慰剂，看差能有多大。
还有两条自动处理：窗口里逐位相同的参照对剔掉，不让它把 N 拉低；剔完不到三对，最多判待定。」

「还有一条规矩：比较只对一份事先指定的基线，不对几份取平均，也不挑最差的。尺子量的是两份运行之间差多少，被测也该跟一份运行比，口径才一致。代价是基线自己也是个样本，可能挪动一个噪声单位，所以 N 才取最大值兜住；课件里另有一张图量过：换成十份的中心，TPU 还是偏。」

「参照对也只能用同一种设置的运行。混元 3 开着分布式优化器的那组 GPU 运行，比别的组持续低一点点，原因没查清；混进来，尺子就被撑宽了，该抓的偏差就漏过去。确定性开关、分布式优化器开不开，都算设置。」

「然后除：被测的三个数各除以各自的 N，得三个 r。取最差有两级：一项检查，三个 r 里取最大的；一次比较，所有检查里再取最大的。不到 1，就像多跑了一次噪声，过；超过 2，噪声解释不了，不过；中间待定。2 是约定的余量，不是统计推导出来的。」

▍五　几对参照、纯噪声能拿几分

🖥 屏幕：fig-pairs，左边柱子、右边格子各指一次。

「参照要几对？道理一句话：被测要是纯噪声，它跟 n 对参照是同分布的 n 加 1 个样本，每个当最大的机会一样，所以超过其余 n 个的机会是 n 加 1 分之一。3 对是四分之一，10 对是十一分之一，28 对是二十九分之一。」

「右边是实测：第一阶段 100 步、一次本该全过的 GPU 对 GPU 演练，3 对参照时，46 条检查里 8 条判待定；凑到 28 对，只剩 1 条。所以签字前每种设置至少跑六到八份，凑出十五到二十八对。
混元 3 最后那份 golden 自己的尺子，起先只有五份、十对，几项落在一点零二到一点二四倍待定；补到十份、两两四十五对才全过，第十节讲坑时再说。」

🖥 屏幕：fig-loo，先指上排灰点里落进黄区的那一片，再指第二排。

「还有一个坑：一次比较不止看一个数。第二次迁移三百步看 8 项检查、每项 3 个统计，24 个 r，一千步 27 个，最差的说了算。就像有一幅很有名的软糖漫画（xkcd 882）：二十种颜色的软糖各测一次，总有一种「显著」。
纯噪声按这套判法能拿几分？拿 GPU 的重跑自己试。」

「怎么试，叫留一法：GPU 同设置的几份里，轮流挑一份当被测、另一份当参照；尺子用被测之外的那几份两两重算 —— 被测不进自己的尺子，参照进，跟 TPU 被测的处境一样；检查用同一张清单。三百步八份，一共 8 乘 7，56 种挑法，每种尺子 21 对；一千步十六份，240 种，每种 105 对。」

「结果：三百步那组，最差 r 过 1 的占 59%，过 2 的占 11%，最高 2.47；一千步十六份，过 1 的 22%，没有过 2 的，最高 1.82。」

「能不能先算出来？还是刚才那个 n 加 1 分之一；m 个统计要是各自独立，至少一个超的机会是 1 减（n 除以 n 加 1）的 m 次方。三百步 21 对、24 个，算出 67%，实测 59%；一千步 105 对、27 个，算出 23%，实测 22%。各统计彼此相关、各对又共用运行，所以实测略低。」

「所以 r 落在 1 到 2 之间，先拿纯噪声的最高分对一下：不超过它、第一步也没有离 FP64 更远的张量，就写「跟重跑分不开」。这条读法是看到结果以后才补的，只用来解读，不改判档；对齐记录先把它登记下来，再拿后来的新改动、新尺寸去检验。」

🖥 屏幕：fig-loo，最下面一行。

「那为什么不干脆把门槛 2 改大？纯噪声能拿几分，取决于份数和检查条数，刚才两组就差了一截，没有一个放之四海的数。有一种老办法（Bonferroni），看了几十个数，就把每一把尺子都按几十倍加严；这些数彼此相关，这样就严过头了。该做的是把份数补够，直接量「几十个里最差那个」在纯噪声下落在哪。」

「最下面一行就是份数不够的后果：只有 8 份时，六个 TPU 改动压线或越过 2；补到 16 份，全退回 1.19 到 1.64。可分不开不等于没改精度：六个里有两个动了精度，这把尺子量不出来。」

▍六　三类曲线谁更灵

🖥 屏幕：滚回 §3.2 的 fig-integrator，左块先指灰色那团，再指蓝线冲出去的地方；右块只指两支箭头。

「最后说三类曲线谁更灵。loss 是结果，范数是总量。只换求和顺序的差，在几亿个元素上正负随机，平方一加几乎抵消；丢了精度的差有固定方向，范数直接变。第二次迁移里故意让 loss 多乘 1.01，梯度范数 r 九十四点五，主 loss 只有五点二。」

「参数范数还是个累加器：每步的更新都加在权重上。随机的差这步正、下步负，像醉汉走路，只按步数的根号散开；固定方向的差每步加在同一边，按步数长，像赌场抽水，每把只抽一点，押几千把就压过了手气。每步只偏噪声的十分之一，平均四百步就追上噪声带的边。混元 3 那次，就是参数范数最先冲出去。」

「盲区也在这里，三条。一，范数只看长度，方向变了看不见。二，一组参数多涨、另一组少涨，平方和不变，相反的偏差会抵消。三，全模型的范数被大张量主导，归一化权重、偏置这些小张量上的错几乎看不见。」

「另外两条曲线也各有盲区。loss 是结果，只影响一部分梯度的小错要很大才显：MTP（多 token 预测，顺带预测后面几个词的那项辅助 loss）那一项的权重多乘 1.01、也就是相对偏 1e-2，主 loss 上才看得出来。路由偏置的均值本身在零附近来回穿，过零那几步 dₜ 除以一个接近零的数被放大，N 也跟着放大，最大单步的 N 到了 43.6 —— 这条只抓得到大的语义差，比如每步减不减均值；小差靠标准差那一条。
所以曲线之外，还得有第二类度量。」

「逐步的数只能告诉你偏了。偏在哪一层、哪个张量？那要比第一步里的一个个大张量。」

⚠️ 这一节最容易跑偏的地方 ❓ 台下可能问：「那份 FP32 修法在新版本上也全过吗？」—— 答：运行库 0.0.52 上三百步最差一点五五，仍跟 GPU 重跑分不开，第十节讲换版本
⛔ 不讲标准误这类辅助统计。它只做提示，不做判定；被问到再答。
❓ 台下可能问：「纯噪声都能拿到 2.47，超过 2 判不过，不会误杀吗？」—— 答：2.47 是 300 步、只有 8 份、二十几个数取最差的情况；签字前把份数补够，16 份时纯噪声最高 1.82。门槛不改，改的是份数。
❓ 台下可能问：「梯度范数逐步涨落 3%，带符号均值为什么天生偏正？」—— 答：dₜ ＝ a ÷ b − 1；a、b 各带一点独立涨落时，a ÷ b 的平均比 1 大一截，大小约是相对涨落的平方（本课推导），3% 的平方约 1e-3。混元 3 为此用过两边均值当分母；第二次迁移实测偏置只有 4e-7，统一回参照。
❓ 台下可能问：「窗口为什么是左闭右开？」—— 答：写成 a:b 指第 a 到 b − 1 步，跟 Python 切片同一个习惯；第 1 步总是单独报，所以「1:1001」实际统计第 2–1000 步，999 个。
❓ 台下可能问：「路由偏置、参数范数怎么记？」—— 答：有两条要说清怎么记。路由偏置：第二次迁移的小模型有 7 组路由，六个 MoE 层加 MTP 层，每组一条曲线；一项检查对 7 组各算三个统计，每个统计取 7 组里最差的，噪声对也一样。标准差用无偏的，除以 n 减 1。参数范数：TPU 每个参数在 FP32 里求平方和，再在 FP64 里合起来；GPU 整个在 FP64 里算。TPU 自比时 TPU 记的是这一步更新之前，GPU 重跑记的是更新之后，差一步，只用来取尺子的量级；GPU 搬 TPU 时两边都读更新之后，口径相同。
❓ 台下可能问：「1.82 跟哪一条比？」—— 答：1.82 是整次比较几十个数里最差的那个；单看一条，后段 loss 纯噪声最高 1.23，参数范数 1.58。拿哪一条去比，就比那一条的最高分。
❓ 台下可能问：「为什么不用 TPU 自己重跑当尺子？」—— 答：TPU 同一个程序重跑，换机器、换集群都逐位相同，尺子宽度是 0；硬造波动去撑宽，就成了被测给自己定门槛。
⚠️ 别把 2 倍说成统计推导出来的。它是约定的余量，用来把「刚比样本最大值大一点」和「明显大一截」分开。
❓ 台下可能问：「为什么用最大值，不用均值加三倍标准差？」—— 答：只有十来对样本，最大值不用假设分布。
❓ 台下可能问：「参数范数的相对差才 4e-7，为什么反而不过？」—— 答：r 是跟同一个量自己的噪声比，量级已经除掉了。

▍一　rel_L2、cos、ULP

「第一步的激活、梯度、权重，是另一类度量：一个张量压成一个数，整个拉直成一个向量来比。几个指标各管一类错，各有盲点。」

🖥 屏幕：fig-cos，左格、中格、右边小表依次指。

「主判是 rel_L2：差向量的长度除以参照的长度，就是红色虚线的长度占灰箭头的几成。
左格：被测是参照的两倍长、方向一样，cos 是 1，完全看不出问题；rel_L2 是百分之百。中格：一样长、转了两度半，cos 是 0.999，看着很近；rel_L2 已经百分之四点五了。」

「所以 cos 看方向，对整体放大缩小完全看不见。累加完忘了除以微批数，梯度整体大了一倍，cos 还是 1，只有范数比抓得到。
记一个换算：两支箭头一样长时，rel_L2 的平方等于 2 乘（1 减 cos），差很小时 1 减 cos 约等于 rel_L2 平方的一半。所以 cos 等于 0.999，rel_L2 已经是百分之四点五；cos 看着「很近」，差向量其实不短。」

「还有一个指标叫 ULP，数两个数在浮点格子上差了几格。它只诊断、不当门槛：GPU 自己两次运行第一步的梯度，按 BF16 数格，差一格的只占 1.3%，十七格以上的占 67%。跨芯片、经过长求和以后，健康的差也常有几十格，拿它判过不过会冤枉人。」

▍二　R 比：对 FP64 定责

🖥 屏幕：fig-rratio，先讲三圈底色，再指两个点。

「TPU 离 GPU 远了，是谁的错？第一步前向，GPU 自己重跑一位不差，噪声是零，当不了尺子。这时候请 FP64 出来：同一份输入，用 64 位浮点算一遍，当靶心。
R 等于 TPU 离靶心的距离除以 GPU 离靶心的距离，距离还是用 rel_L2 量。」

「R 约等于 1，两边离真值一样远，只是加法顺序不同。R 大于 1.2，TPU 这一步多舍了，去查 TPU。R 在 1.41 附近，像是多舍了一次同量级的数：两次独立舍入，误差平方相加，是根号 2。

「记住：对齐的目标还是 GPU，FP64 只在第一步帮我们定责：单个算子、单层、整网第一步；多步不用它。」

▍三　第一步四步定责

❓ 台下可能问：「rel_L2 到底是什么？只转了一下为什么不是 0？」—— 答：差向量的长度除以参照的长度，‖a − b‖ ÷ ‖b‖。展开是 rel² ＝ (k − 1)² ＋ 2k(1 − cos)，k 是范数比：前一项管长短，后一项管方向。等长转 θ，差向量就是两个箭尖之间那一段，长 2 sin(θ/2)；cos 0.999 就是百分之四点五。
❓ 台下可能问：「刚说第一步 GPU 噪声是零，fig-twoaxis 的横轴怎么还除以 GPU 噪声？」—— 答：噪声是零的是混元 3 第一步的前向；fig-twoaxis 比的是梯度，反向有原子加，GPU 三份大多不逐位。三份完全逐位的张量，尺子按一个很小的下限算，所以横轴能到上千。
❓ 台下可能问：「R 为什么通常在 1 附近？」—— 答：两边走同一条精度路径（BF16 乘、FP32 累加），每一步舍入同量级，只是顺序不同。两种情况别这么读：GPU 碰巧几乎正好，分母接近 0，R 被除得很大；两边精度路径本来就不同，比如路由打分 GPU 离 FP64 3.8e-6、TPU 4.8e-8，R 约 0.013，只说明 TPU 这一处更近真值。
❓ 台下可能问：「几十个张量是拼成一个大向量比吗？参数范数又是什么？」—— 答：判定逐张量：每个张量单独算，一条检查取最差的那个；拼起来，大张量会淹掉小张量上的错。参数范数是另一回事：每一步把全部主权重合成一个数，第三节比的是它。按能量把一组张量合起来，只用来说「整体差多少、整体谁更远」，不当门槛。

❓ 台下可能问：「抹零再讲慢一点？」—— 答：要点一句：张量核一单把 16 个乘积连同累加值对齐到最大的指数，只留约 25 位，挤出去的直接扔，所以误差永远朝零、越长越偏；十进制的例子在课件 §5.2 第一个折叠里，照着念。
❓ 台下可能问：「16 和 25 是 NVIDIA 的规格吗？」—— 答：不是。是我们从实测拟合的，按它重算能逐位对上，跟一篇公开论文的比特级模型一致；官方没有公开。
❓ 台下可能问：「HIGHEST 不就是 FP32 吗？」—— 答：不是。它是多遍 BF16 拼出来的近似。但还要看编译后的样子：第二次迁移里一处写着 HIGHEST 的四路加权和，编译器早改写成逐元素 FP32 乘加，跟 GPU 只差加法顺序。定责一律对 CPU 上的 FP64 整网重算，不对 TPU 自己跑的 FP32 参照。
❓ 台下可能问：「那个存成 BF16 的中间值，影响有多大？」—— 答：第 1 步只改它，loss 变化比 GPU 自己的噪声小几十倍。所以它不是靠数值抓到的，是逐格读代码读出来的；按写法判 bug，不按大小。
❓ 台下可能问：「病态那一项后来怎么了？」—— 答：前三问说明是病态在放大，第四问（同样的 f32 计算换 CPU 上的 PyTorch 算）指到 TPU 默认的 exp、log；换成高精度写法后 lse 的偏差从约负一格到零点零几格，300 步那一项的 r 从 3.67 到 0.01（同一代还开了另一个开关，没拆开）。只有 CPU 上也偏同样多时，才写「不过，已定责」。
⚠️ 船和船长的数是按比例换算的比方（lse 1 单位 ↔ 1000 吨），不是实测；实测的是「一格 ＝ KL 的 4.3e-3」。
❓ 台下可能问：「软件怎么把 exp 算准？」—— 答：拆成 2 的整数次方乘一个小余数，余数上用几项多项式；各家库的系数和项数不同，所以末位不同（课件 §5.8 图右是示意）。
❓ 台下可能问：「为什么 sigmoid 的高精度开关没用？」—— 答：读回是开，实际编出来的算子逐位没变，又是一个「开关说的不算」；要用高精度的 exp 自己搭。搭好以后单算子跟 GPU 一样准，整网先偏得更多；查到一处是反向公式：精确写法的反向由自动微分推出来，跟 GPU 的解析式不同，改成同一个解析式就收拢了。

▍二　步与步之间读状态

「所以在 TPU 上换三条路。第一条：步与步之间读主权重和两个动量，不碰训练程序；梯度就用第四节那个从动量倒推的办法，在 GPU 上对过直接抓的，相对差只有千万分之几。」

▍三　隔离回放

「第二条：隔离回放。第 k 层的输入直接用 GPU 那一层的输入，TPU 上只编译这一层。层与层的误差不串，第一个 R 超过 1.2 的，就是出错的那层。

▍四　状态互换

「还有一个工具后面要用：状态互换，把一侧某一步的整套状态搬到另一侧，用同一批数据各算一步。它能把「这一步算得不一样」和「状态早就不一样了」分开。」

第八节　案例二：DDP 和 FSDP 对不上（10′）

🎯 这一节只留一句：同一批数，两种并行加法的组织不同；高频词在 BF16 里一次次地加、后端又没排序，精度才丢。最好的修法是换切分；上卡之前，先从编译产物看清传什么。

▍一　数学等价，曲线却超出噪声；第一个假设

🖥 屏幕：滚到第八节，开头那张 2×2 是答案，先滚过去别停，停在 §8.1 那张五行小表。

「第二个案例在第二次迁移上，模型是混元 4 的缩小版。TPU 自比，基线是 FSDP 八卡，只改成纯数据并行。两种并行数学上等价，曲线最差 r 二点六二，超了；换不做梯度累积、也就是一步的两个微批并成一次算，换十六卡、换 v7x，都超。方向也固定：loss 一直偏高，梯度范数一直偏低。换张量并行、专家并行却都没事。」

「先定责：第一步两百零五个张量，各自对 FP64。只有一个丢了精度：词嵌入梯度，R 三点六二。范围从整个模型缩到一个张量。」

「先说词嵌入的反向在干什么：把每个 token 的梯度，按 token 号加到词表对应的那一行，这一步叫 scatter-add；token 号就是下标。最顺手的解释：FSDP 下词表按列，也就是按隐藏维切，每张卡只管自己那一百二十八维，不用跨卡求和；纯数据并行下每张卡一整张表，八张卡加完还要用 BF16 再相加。」

「现成的修法：一个让词嵌入梯度在 FP32 里累加的开关。一打开，r 冲到六百一十一，撞上一个编译器 bug，丢了一块梯度。修好以后 r 零点九八。接着有人追问：只把本卡的累加换成 FP32、跨卡仍传 BF16，行不行？也修好了，r 零点九三。跨卡还是 BF16 也够，这已经在暗示：跨卡不是主因。」

▍二　按行分组：误差全在三十九个高频词

🖥 屏幕：fig-ddprows，先左两组，再右边那组：紫柱比红柱，橙柱比红柱，最后指最矮的绿柱。

「把词嵌入梯度按行分组，每组对 FP64。红柱是纯数据并行八卡，绿柱是 FSDP。低频的一万多行，四种跑法几乎一样高。差全在三十九个高频词上，这张梯度九成的分量都在它们身上。紫柱跟红柱比：它不做梯度累积，每卡一次加八千多个，柱子高了一倍。橙柱跟红柱比：卡多一倍、每卡还是四千个，一样高。变的是本卡加几次，不是跨卡几路。第一个假设推翻了。」

「可这留下一个反常：最矮的是绿柱。FSDP 那一侧，每张卡要把八张卡的 token 收齐一次加完，同一个高频词加的次数是八倍，误差反而最小。为什么？」

▍三　先加后传，先传后加

🖥 屏幕：fig-ddpflow，一格一格走。上半块：卡的 dX → 红箭头加进整张表 → 橙框跨卡相加 → 右边八份相加。下半块：按列切段 → 橙框交换 → 卡 0 收齐 → 绿框先排序 → 只舍一次。两行写着门槛的红字、绿字先不念，色带里的数据量不讲。

「上面纯数据并行：每张卡把自己四千零九十六个 token 的梯度加进一整张 BF16 表，八张表再相加。先加后传。下面 FSDP：每张卡先把梯度按列切成八段送出去，管第 k 段的卡收齐八张卡的全部 token，三万两千多个，一次加完，不再跨卡。先传后加。」

「那次 scatter-add 本身，除了一次收多少个下标，要紧的差别只有一处：FSDP 那一份先按 token 号排了序，还带着「下标已排序」的标记。」

▍四　单算子：排序加标记才只舍一次；门槛随运行库变

🖥 屏幕：先滚过 fig-rmw，到下面的 anim-scatter，取消「连续播放」：第 1、2 步边点边讲；第 3、4 步的数不念，只指红、绿两根；再回到上面 fig-rmw，只看中间四格。

「看动画里词十七那一行。不排序时，它的更新散在别的词中间，后端每碰到一次就读出来、加上、舍回 BF16：出现六次，舍五次；真实的高频词一次加几十到几百次，就舍几十到几百次。排好序、带上标记，后端换一种写法：把表一块一块搬进片上的 FP32 缓冲，这一块的更新全部加完再写回，每行只舍一次。中间四格：只排序不带标记，照样每次舍；省舍入一关，也退回每次舍 —— 第五节那个 R 二十六就是它：让两边一样，不等于让两边都对。」

🖥 屏幕：fig-sweep，红线过了竖线掉下来那一下。

「谁来排序？编译器的后端自己。看红线：下标数往上加，误差一路涨，一过竖线就掉下来，后端自己插了排序。换几种表的形状找它开始排序的那个点：在当时用的 TPU 运行库（libtpu，编译器后端就在里面）0.0.46 上，门槛就是表行数的八分之一，十二万行，就是一万五千出头。FSDP 一次三万多，过线；纯数据并行四千，不过线。FSDP 加得多，恰好跨过了线。」

🖥 屏幕：往下到 §8.6 fig-sweep 下面那张跑法表，指最后一行。

「这个门槛不是 TPU 的固定规格。运行库升到 0.0.52 再二分，它跟表有多少列、哪一代芯片都有关了。看最后一行：v7x 纯数据并行不累积，每卡八千一百九十二个下标，0.0.46 上不排序，0.0.52 上门槛降到七千一百多、排了序。先离线编一遍看到排序，再上卡，r 从四点零六掉到零点八九。机理还是那条，门槛挪了。」

「但别急着当好消息：列越宽，新版本的门槛越高。搬到生产宽度六千多列，两代芯片的门槛都高过每卡的下标数，生产上纯数据并行照样不排序，照样要修；具体数第十节那张图的最后一行再指。」

▍五　结论和三种修法

🖥 屏幕：回到本节开头的 fig-ddp2x2，指右下那一格。

「所以这回的差在 TPU 纯数据并行那一侧：没有谁算错，是那次加法的组织方式，让高频词多舍了几十次。两个条件同时成立：高频词，加不排序，缺一个都不丢精度。修法是让这次累加落在 FP32：整次都用 FP32，或者本卡 FP32、跨卡 BF16，三百步回到噪声内，一千步跟 GPU 重跑分不开，步时多零点六到零点八个百分点。」

🖥 屏幕：fig-shard，先上面前向那条，再下面每卡存什么。

「第三种换了个思路：FSDP 那条先传后加，是编译器在「表按列切开」时自动切出来的。那就其余参数照旧纯数据并行，只把词嵌入表沿数据并行轴、按列切开。编译器对它生成了跟 FSDP 一条不差的通信：前向只换取到的行，不取整张表；反向就是上一张图下半那条，交换原始梯度，每卡收齐三万多个下标、排序、只舍一次。」

「精度跟前两种一样，词嵌入那份通信少了九成以上，显存也省，步时跟不修一样快，所以纯数据并行时首选它；切分组里所有卡合起来还不过门槛，再退回 FP32 那个开关。」

「换到自己的模型：先拿每卡一次加进词表的 token 数跟门槛比做初判，最后看编译产物里那次 scatter 有没有排序。」

▍六　方法：怎么从编译产物看通信

🖥 屏幕：fig-comm，先左块四步，再右块橙条。

「这一节里「传什么、在哪排序」，都是上卡之前看清的：把训练步按目标拓扑在 CPU 上编一遍，不占芯片，读编译后的程序。左边就是那条整表的跨卡相加，每步约十亿字节；右边只切词嵌入表那一行，橙条跟 FSDP 一样短。精度和快慢它看不到，还得上卡量。」

「两个案例查完。回到混元 3：GPU 的 golden 偏了，连精确轨迹也带着一份长累加的偏差。验收拿谁当基线？」

⚠️ 这一节最容易跑偏的地方 ❓ 台下可能问：「混元 3 也中招了吗？」—— 答：没有。按专家切 8 离线编译核过，词嵌入表沿隐藏维切，每卡收齐 32768 个下标、排了序；FSDP 8 那份观测程序里也排了序（运行库 0.0.46，v5p）。v7x 上交给 SparseCore，累加精度没测
⛔ 不讲后端指令条数、各道工序的名字，不讲那个编译器 bug 的细节。台上只说「后端自己插了排序」「撞上一个编译器 bug」；名字、条数和 bug 的机制在课件折叠和第十节，被问到再翻。
❓ 台下可能问：「PyTorch 的 FSDP 不是先算整表梯度再 reduce-scatter 吗？」—— 答：那是 PyTorch 的做法；这里是 XLA 在「表按隐藏维切」这个前提下自动切出来的：先 all-to-all 交换原始梯度，再在本卡加，见 fig-ddpflow 底下那行字。
❓ 台下可能问：「自查怎么算？」—— 答：按运行库 0.0.46 的规则，比如词表二十五万行，门槛三万一千二百五十；八张卡、每卡每个微批八千个 token，不过线，会中招；只切词嵌入表以后八卡合起来六万五千多，过线（按规则推断）。换了版本这个数就不能用了，以编译产物里有没有排序为准。课件那道考考自己就是这题。
⚠️ 口径：通信字节是按形状算的，不是线上实测，只适合几种跑法互相比；关省舍入那一臂三百步曲线 r 十三。
❓ 台下可能问：「GPU 为什么没这个问题？」—— 答：推断。PyTorch 的词嵌入反向，下标超过 3072 个就先排序、按段在 FP32 里累加，最后才转回 BF16，跟 TPU FSDP 排序后是同一种舍入结构；GPU 那边每卡每个微批 4096 个，超过 3072。读的是 PyTorch 主分支，GPU 镜像里那个版本没有逐行核过。
❓ 台下可能问：「我想自己数一遍通信。」—— 照着跑（公开仓库 yangwhale/janus 里的脚本，课件 §8.10 有链接）：先按目标拓扑离线编一遍、让 XLA 存下训练步的 after_optimizations.txt，再跑 python models/hunyuan4/analysis/hlo_comm_bytes.py ddp8=<文件> shard=<文件> --out comm.json；它列出每条集合通信的类型、形状、每步次数和字节，哪几行属于词嵌入要自己按形状和 op_name 认。
⚠️ 口径：第三种修法只在 v5p、缩小版、纯数据并行 8 ＋ 累积 2 上验证过；「步时不变是因为原来就重叠」是推断，没看 profile。
❓ 台下可能问：「三种修法在代码里怎么开？」—— 答：都是 MaxText 的配置开关，混元 4 的公开分支里有：embedding_grad_fp32、embedding_grad_fp32_local_bf16_comm、embedding_shard_over_data，默认都关；全部开关的说明在那个分支根目录的 HUNYUAN.md（课件 §8.9 有链接）。
❓ 台下可能问：「修法①是不是让通信翻倍了？」—— 答：没有。编译器把两路输入合成一次 FP32 跨卡相加，每个微批一次，字节跟原来两次 BF16 一样；另多了约 6.7e7 字节的点对点交换，词嵌入那份每步 1.06e9 对 9.90e8。只有一路输入的模型才会翻倍（推断）。
⚠️ 口径：门槛「表行数的八分之一」只对运行库 0.0.46 成立；0.0.52 上跟列宽、芯片代际都有关；表很小（按 FP32 放得进片上内存）时也不插。别说成 TPU 的固定规格。
⚠️ 口径：GPU 那条是读 PyTorch 主分支源码的推断，GPU 镜像里那个版本没有逐行核过。
❓ 台下可能问：「那 FSDP 就一定安全吗？」—— 答：不一定。按这条规则，FSDP 一个微批的 token 太少，也会落到不排序那边（推断，没跑过）。不过线、或拿不准运行库版本时，开 FP32 那个开关最稳，用修好编译器 bug 以后的代码。
❓ 台下可能问：「为什么次数翻倍误差接近翻倍，不是根号二倍？」—— 答：舍入误差有正有负、互不相关时，次数翻倍误差只涨约一点四倍；训练里接近线性，推断是舍入偏向一边，后加进去的小梯度被系统地吞掉一部分。这是这一步实测到的，不是一般规律。
❓ 台下可能问：「为什么 1000 步的 1.09、1.07、1.15 判略超，还说修好了？」—— 答：三种修法都只有梯度范数略过 1，没超过纯噪声自己能拿到的分（第三节的留一法），跟 GPU 重跑分不开。
❓ 台下可能问：「v7x 也一样吗？」—— 答：运行库 0.0.46 上一样：v7x 纯数据并行曲线 r 二点二一，过了 2 倍线，但没超过纯噪声的最高分，是第一步定责分开的；编译产物核过，跟 v5p 一样走不排序那条路。换到 0.0.52，v7x 不累积那种跑法过了门槛，r 四点零六掉到零点八九，词嵌入那一处消失（第一步另有几个多路残差的小参数离 FP64 远，靠豁免才判在噪声内，对齐记录还在查）；累积两份（每卡四千零九十六）还是不过线。

❓ 台下可能问：「后段还偏六点六乘十的负六次方，比 GPU 散布大三倍，主 loss 怎么还算过？」—— 答：判档看的是全程三个统计对 GPU 两两 120 对的最大差，不是后段这一截的均值；全程带符号均值三点五，上限四点六五，在线内。后段窗口的偏是用来查原因的，不是判据
❓ 台下可能问：「跑到两千步尾巴自己回落了，那还算问题吗？」—— 答：算。修之前的尾巴在一千到一千二百五十步到顶后回落，说明它不是一直往外跑，可对齐要比的是同一窗口里两边像不像；而且两头验证说明它有确定的来源，不是噪声
❓ 台下可能问：「小尺寸那截偏高跟 MTP、索引器蒸馏有关吗？」—— 答：MTP 同期反着走；两边把 MTP 和索引器蒸馏都关掉，后段照样往上（约剩六成），所以不是它们（fig-ihcroot）
❓ 台下可能问：「TPU 自己的扰动运行呢？」—— 答：九份扰动运行，八份不超过零点八五，剩一份的待定也在 TPU 自己的噪声里
❓ 台下可能问：「三点四五倍拆成哪几笔？到真精确还差多少？」—— 答：TPU 对精确轨迹多出千分之二点三五 ＝ 精确轨迹自己少漂千分之八点七，TPU 的梯度舍入少漂千分之六点八，其余多出万分之五。再往右到真精确还差零点零零六七：两边都把流进输出头反向的梯度存成了 BF16，两边共有，不算两边的差
❓ 台下可能问：「那三倍半是开 FP32 累加开关之前还是之后？」—— 答：之前那版 TPU；打开以后三点四五倍，几乎没动
⛔ 不逐行讲出处总表。只讲「每处改动一行、连没采用的也写」这个做法。
⚠️ 说实话：过了是因为基线修对了，别说成「TPU 本来就没偏」；对原来那份生产 golden 的差，第二关照实报。
❓ 台下可能问：「那 TPU 能不能上线？」—— 答：这是业务判断，不是数值判断；数值上我们能说清楚差多大、几成是谁的。
❓ 台下可能问（定案前）：「为什么不用精确轨迹自己扰动出来的散布当尺子？」—— 答：协议事先写定，验收中途不换尺子；扰动多大是我们挑的，量的不是真实的执行噪声。
❓ 台下可能问（定案前）：「为什么借 ③ 那组、不借 ② 生产那份？」—— 答：协议事先选定 ③；理由没有单独写下来，我们不替它编。
❓ 台下可能问：「补到四十五对才过，是不是把尺子放宽了？」—— 答：只有十对时几项落在一点零二到一点二四倍，先查出两处量法的问题（TPU 参数范数测得粗、梯度范数统计量两边不对称），再按协议补五份重跑；协议写的就是「待定先补参照」；十对时所有比值挤在 0.7 到 1.3、没有离群项；不改量法也过；TPU 九份扰动运行八份过，剩一份待定也在 TPU 自己的噪声里。
❓ 台下可能问：「还有哪些格子没过？」—— 答：原生加载器的顺序、v7x 第 2 层 MoE 块对 FP64 那一格（4096 个 token 里一个近平局选了别的专家，去掉它就过）、第一步整步的梯度（路由翻转，加上 TPU 三类参数的梯度先舍成 BF16；后一处有三个可选开关，第一步对 FP64 的 R 从 1.20 降到 0.67，路由那一份不受影响；打开后一千步 v5p 全过、v7x 梯度范数待定 1.05 倍，没加进正式配置）、加钩子改了融合；每一格都对上了机制，见课件 §9.4 的折叠。
❓ 台下可能问：「为什么不拿真精确当基线？」—— 答：真精确比的是「离精确值多远」，两边都舍了一次 dlogits，TPU 要单方面留 FP32 才过，步时多一成；定案选的是「生产对生产」。

第十节　工程化与教训（7′）

🎯 这一节只留一句：改完不逐位，先分清是换了顺序还是改出了 bug；日常回归先要求逐位；换运行库要先建新基准、把已知的几件重测。

▍一　TPU 的脾气

🖥 屏幕：fig-temper，先上块六堆的颜色，再下块挤在 1 附近的蓝点，最后指下面那六行：两行红的不能忍，四行橙的能忍。

「改完不逐位，算不算 bug？第二次迁移一样一样量过：重跑、换机器、起名字拆函数这类不改程序的重构，逐位相同；只换顺序的改动不逐位，但跟重跑分不开；一百二十种改动里，真有影响的归成六件，不能忍的只有两件：纯数据并行和关掉省舍入；另外四件，比如 RMSNorm 里多舍一次，曲线分不开，是第一步对 FP64 才抓到的，能忍（不算查机理时故意强制舍两次的那一次）。这张图基本都是在运行库 0.0.46 上量的。」

🖥 屏幕：fig-sens。

「这把尺子能抓多小？故意把学习率调大一点：大一乘十的负四次方就抓得到，r 四点一；大三乘十的负五次方就分不开了。只动一部分梯度的 bug，主 loss 藏得住，记下的那一项 loss 藏不住，所以每一项 loss 都要逐项比。」

▍二　换运行库

🖥 屏幕：fig-libtpu，先指左块最上面那个基准点，再指 RMSNorm 那根往右蹿的红箭头，最后右上的黄格和最后一行。

「运行库升到 0.0.52，又走了一遍。基准运行自己，新旧版本比，在噪声内，零点九九。按理说可以放心了？把六件在 v5p 上一件件重测：RMSNorm 多舍一次，从一点零六跳到五点五，主 loss 一直偏高，重跑逐位相同，不是偶然。右边就是第八节那张门槛表：黄格是变了的，最后一行是生产宽度。」

🖥 屏幕：fig-rms2r，先左上两排比一比，再右上那个坑，最后下面五根条：先第 3、4 根（5.50 → 0.84），再第 2 根（6.83）。

「为什么变强，查清了。默认写法是先把归一化值舍成 BF16、乘上那组可学的缩放系数 γ 再舍一次；「RMSNorm 多舍一次」这件改动，就是关掉单次舍入的开关、退回这种写法。老版本里最后一层这一段融成一颗 kernel，中间那次被省掉，就是第五节说的省舍入；新版本插了一步数据重排，把归一化值单独写回内存，两次都真舍了。」

「两次舍入本该有多有少、互相抵消；可第二次的输入已经在 BF16 格点上，乘一个贴近 1、又不等于 1 的 γ 再舍，结果系统地偏小。右上这条线贴近 1 的那段全在零下面。输出头的输入整体缩小一点五乘十的负四次方，预测被压平，loss 就高了。」

「下面五根条：只把最后一层改回舍一次，就回到噪声内；老版本上强制最后一层舍两次，一样偏高。机理跟版本无关，版本只决定编译器省没省那一次。
所以换版本不能当成只换了加法顺序：新版本先建基准，再把已知的几件重测。RMSNorm 单次舍入那个开关，对齐、生产都开着。」

▍三　指纹与日常回归

🖥 屏幕：fig-screen（§10.3 开头），先走左块三个出口，再指右块那根绿条。

「改完代码，最便宜的一步：只编译，比程序指纹。程序一样，结果一定逐位，不用跑。对齐记录做成了跑前离线筛：CPU 上编一次三分钟左右，回测一百多个上过卡的改动，能判的全部对上；刚才那种换运行库判不了，得上卡；升到新版本以后筛法照样能用，判不了的只是「换版本」这件事本身。」

🖥 屏幕：fig-regress，先走上面那条绿线，再走三条分流。

「日常回归证明今天的 TPU 和上次验过的 TPU 是同一个：参照是上一次全部通过的那次 TPU 运行，叫 LKG，last-known-good。TPU 同一个程序重跑逐位相同，所以数学不变的改动应当一位不变，大多数改动走上面那条绿线就结束了。」

「不逐位，就看改代码的人写的数值影响声明：写了数学不变，退回；执行级的改动，只改舍入位置，或者升级依赖，用 TPU 自己的执行噪声判；数学级的改动，要对 GPU golden 不变差。」

▍四　怎么记、踩过的坑

「再说怎么记，只问一句：下一个人从仓库里看不看得出查到哪了。一个问题一份案例文件，标题就是发现；事实带出处，推断标出来；排除了的也写下来。」

「一路走来十二步，四步走错，三步错在把参照当成了它名字说的那样（课件 §10.5 的 fig-journey）。挑三个坑：TF32 没关干净，差点判反了结论，就是第七节输出头那张图里更长的那根红柱；连精确参照也不精确：十二万长的 FP32 一次累加也偏；尺子太短：五份十对时几项待定，十份四十五对全过。
三个坑，各留一条规矩：读回值、工具输出，都要实测核对；先排除自己，再怀疑硬件；每个结论先问拿什么比。」

▍五　收尾

「回到开头：TPU 的 loss 低万分之一点五，按噪声尺子是真偏差。查到最后，大头偏在 GPU 的 golden：一次十二万长的求和，每一步都朝零少算了一点；改成分段累加，拿它当基线，全部在噪声内。第二个案例也留一句：同一份代码，换批大小、换切法，加法的组织就可能换一种，精度要重新看。」

「怎么证明训的还是同一个模型？迁移验收证明一次，日常回归天天守。今天的数字换模型、换版本就会过期，方法不会。课件 10.7 有动手清单、速查卡、排查表和练习，拿回去用。」

「所以这一讲只立一句话：TPU 跟 GPU 的差，不能比 GPU 自己跟自己的差大；超了，就查到底是谁的差。混元 3 这一次查到底了：对齐了，剩下的每一处差都说得清。」

⚠️ 这一节最容易跑偏的地方 ❓ 台下可能问：「指纹抓到过真 bug 吗？」—— 答：第八节那个：r 冲到六百一十一先报警，再读编译后的程序，一到七号卡的第一个微批全丢了（课件 §10.3 的 fig-bug）

⛔ 不逐条念坑表和记录规矩。挑三个讲，其余是会后查的。

❓ 台下可能问：「为什么只有最后一层要紧？」—— 答：对齐记录的推断：最后一层的输出直接进输出头，整体缩小直接变成 logits 缩小；层内的输出还要过投影、加回残差、再归一化，影响被冲淡，没有单独量。
❓ 台下可能问：「为什么第一步看不出来？」—— 答：初始化时模型预测接近均匀（loss 接近 ln 词表大小），输出整体缩小一点不改 loss；学会预测以后，缩小等于把预测压平，loss 才高。同一份权重上前向就高三点二乘十的负五次方；拿第三百零一步那一批，FP64 模拟三点一七、TPU 三点一三，对得上。「学会预测以后才显」是推断，只在第一步和第三百零一步两个状态上量过。
❓ 台下可能问：「v7x 上也这样吗？」—— 答：同一份代码在 v7x、0.0.52 上没有单独写回，曲线一点二二，跟 GPU 重跑分不开 —— 发不发生看融合，跟芯片、并行方式、模型结构都有关。
❓ 台下可能问：「离线筛说程序相同，就一定不用跑？」—— 答：同一个运行库、同一个镜像、同一代芯片下是的：TPU 上同一个程序重跑逐位相同，回测里判相同的二十三个全部逐位。换运行库、换镜像、换芯片、SparseCore 卸载的开关，规则上直接判「判不了」，要上卡。
⚠️ 口径：六件重测只在 v5p 缩小版、运行库 0.0.46 和 0.0.52 这一对上做过；别说成「新版本更差」或「新版本更好」，两个方向各有一件。
❓ 台下可能问：「「TPU 的脾气」和日常回归用的不是同一把尺子？」—— 答：对。「TPU 的脾气」借 GPU 重跑当尺子，回答「在不在 GPU 的噪声里」；日常回归用 TPU 自己的执行噪声，只回答「跟上次比变没变」。
❓ 台下可能问：「每天跑回归要多少资源？」—— 答：v5p 上 20 步那档一次约 10 分钟，1000 步那档约 25 分钟（提交到取回）。
❓ 台下可能问：「TPU 的执行噪声怎么造？」—— 答：只改执行方式的扰动臂，旧配置试了十四个、三项检查都过的七个，加上基线八份，两两二十八对；配置一换，在新配置下重跑、重新标定。数学级那道门对的是起点那份 GPU golden，设在两关验收定下来之前，还没换成最终 golden ⑤。
❓ 台下可能问：「LKG 怎么建立、怎么往前走？」—— 答：第一次建立要同一个提交跑两遍、逐位相同才算数；数值没变指针自己往前走，数值变了每次换代都要负责人点头。
❓ 台下可能问：「迁移验收签字前，LKG 的『全部通过』指什么？」—— 答：指回归那几项检查全过，跟迁移验收签不签字是两回事。
❓ 台下可能问：「扰动臂的三项检查是哪三项？」—— 答：臂自己重跑逐位；配置、版本、编译出的程序除了改的那一处都不变；第三项分两半：一千步 loss 对基线不超过 GPU 自己的噪声；第一步梯度离 FP64 不比基线远（GPU 噪声看不见路由翻转，而只改执行方式的臂也会翻）。当前配置六个臂，v5p 的 R 一点零零一到一点零零八、v7x 一点零零三到一点零三九，全过；所以 TPU 这把噪声尺里含着路由翻转。
