# TPU 显微镜 —— 结构大纲

对标 `../gpu-micro/`：同一套 `common.py`、同一份 `style.css`、同样的
「八张图 + 每张图配一节正文」骨架，以及同样的三级来源标注（官方 / 第三方 / 本文推导）。

原来那份 `tpu-embedding-gather` 是**单点深挖**（embedding 查表这一件事）。
这份把 scope 放大成**通用架构**，embedding / SparseCore 收缩成其中一节 ——
它仍然是全文最好的「具体案例」，但不再是主线。

## 两个版本，一份稿子

`build_doc.py --mode internal|public`。所有内部信息走 `gate.py` 的闸门，
不复制第二份稿子。理由与规则写在 `gate.py` 的模块注释里，一句话概括：
**复制出来的两份一定会漂移，而先发出去的偏偏是公开那份。**

公开版构建完还要过 `gate.lint_public()` 出厂自检（bug 号 / go 链接 / 内部域名 /
内部路径 / 内部来源署名），这是第二道防线。

## 八张图

| 图 | 主题 | 对应 GPU 那份的哪张 | 落点 |
|---|---|---|---|
| **T-1** | 一颗 v7 chip 全景：封装 → 2 个 device → TensorCore + SparseCore → HBM → ICI | G-1 | 同样是双 chiplet，TPU **反过来**暴露成 2 个独立 device |
| **T-2** | 一个 TensorCore 显微镜展开：MXU / VPU / 标量单元 / VMEM / SMEM / 向量寄存器 / DMA | G-2 | 没有调度器、没有大寄存器堆 —— 省下的面积去了哪里 |
| **T-3** | 并行层级 ↔ 硬件归属：lane / sublane / 向量寄存器 / core / chip / slice | G-3 | 层数少得多，少掉的那几层正是 GPU 用来藏延迟的 |
| **T-4** | MXU 一次吃多大、数怎么在阵列里流（脉动阵列真实数据流） | G-4 | 收缩边 256 是粒度不是上限；权重驻留 vs 流动 |
| **T-5** | SparseCore：第二种核，以及生产环境为什么绕开了 gather | G-5（都是「这一代新长出来的专用通路」） | 素材来自原 embedding 文档，压缩成一节 |
| **T-6** | 一个数走完全程：HBM → VMEM → 向量寄存器 → MXU → 累加器 → 回程 | G-6 | 中间那站是**暂存**不是缓存 |
| **T-7** | 延迟怎么被藏起来：VLIW 一拍多槽，编译期排班 | G-7 | 代价是算错了没有兜底 |
| **T-8** | 从一颗到一个 pod：ICI、3D torus、slice、集合通信 | G-8（都是全文落点） | **这是 TPU 相对 GPU 真正的结构性差异**：scale-out 是第一性设计，不是后加的 |

G-8 的落点是「切分粒度差 64 倍」；T-8 的落点是「一颗芯片的边界在哪」——
GPU 的协调主要发生在一颗芯片**内部**（148 个 SM），TPU 的协调主要发生在**芯片之间**。
两份文档的落点互为镜像，合起来才是完整的一句话。

## 硬要求（沿用 GPU 那份的教训）

1. **以画图为主**，图要精准、精致、信息密度高，能单独拿去讲课，不能全是字
2. 同一段说明**不誊第二遍** —— 对称结构靠形状表达，不靠把字写四遍
3. 图例必须和图上实际渲染**同源绘制**，不许两条路径
4. 灰色在一张图里**只允许有一个含义**（第三方来源）；未公开用虚线框表达
5. 每张图渲染 → 截图 → 目视核对，确认无遮挡无溢出才算完
6. 推导值必须写清推导链；查不到就如实标「查不到」
7. 任何推导口径，尽量找一代**四个变量全公开**的老芯片当验尸台
