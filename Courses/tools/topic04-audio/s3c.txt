[focus] 上一段把 Adam 的学习率讲成了每一步挪多远。那这个数到底设多少？先给一把尺子。

[thinking] 它不告诉你最优解，只告诉你离不离谱。量的是每一步的更新量除以参数本身，注意是更新量，不是梯度。经验值是千分之一，图上那条黑线就是它，贴着线就大致合适。

[curiosity] 可右边那一格会让你意外：学习率设得太大的那条，loss 反而更低。代价在别处。

[thinking] 权重被撑到了四点二倍，抖动大了约九倍，而学习率再乘二点一，就直接 NaN 了。所以这条比值不是让 loss 最低的指标，是看你离悬崖还有多远的指标。

[friendly] 再看学习率曲线。GPT-3 升完就一路下滑，V3 中间多了一段又长又平的平台。你只用做三个决定：从哪升上来，升到多高，怎么降下去。

[thinking] 先说 warmup。流行的解释是，Adam 一开始样本太少，二阶矩估不准。二零二四年有一篇专门做系统实验的论文说，这不是主因。

[focus] 在一条抛物线上，步子一旦超过二除以曲率，就不是慢一点的问题，是一步比一步远，直接翻出去。而训练刚开始，曲率特别高，高到你想用的那个峰值根本不合法。

[realization] warmup 干的事很具体：先用一段小到安全的步子，让网络自己走到曲率低的地方，那个峰值才变得合法。不是网络学会了忍受大步子，是曲面本身变平缓了。

[seriously] 所以它真正的价值，是让你敢把峰值设高。也因此，峰值固定的话，把 warmup 拉长基本没收益。

[confusion] 这儿一定有人问：开局是十二万九千多个词里选一个，那时候梯度不得特别大？loss 大，不等于梯度大。开局 loss 是十一点七七，可 logits 那一层的梯度是 p 减 y，每一项都夹在负一到一之间。

[thinking] 况且 Adam 已经把尺度除掉了，每步迈多远，基本就是学习率本身。Adam 除掉的是陡，除不掉弯。危险不来自梯度大，来自你脚下那块地的弯度。

[confusion] 还有人会问，是不是一开始分母还没攒够？这一条 Adam 自己防了，偏差校正专门补头几步。

[casually] warmup 用多长？GPT-3 是头三亿七千五百万个 token，占总量的千分之一点二五。短到可以不当超参看。

[friendly] 峰值设多少，有现成的表可以抄。GPT-3 论文把八个规模一起列了出来：一亿两千五百万参数用万分之六，一路到一千七百五十亿参数，用万分之零点六。

[seriously] 规律肉眼可见：模型越大，学习率越小，batch 越大。一千四百倍的规模差，学习率只差十倍。

[thinking] 注意那张表里 batch 和学习率是一起变的。单报一个学习率数字没有意义，它必须连着 batch、schedule、总 token 数一起报。

[thinking] 举个例子。V3 是六千七百一十亿参数，峰值学习率却是万分之二点二，比 GPT-3 那个一千七百五十亿的高出近四倍。看着不合规律，其实这两个数本来就不该放在一起比。

[focus] V3 的 batch 爬到最后，比它大了二十倍左右。曲线形状也不同，V3 的峰值要一路扛过十万亿 token。一条趋势，只在产生它的那张受控表里面才能用。

[friendly] 怎么降？两个流派。

[casually] 老派是余弦，GPT-3 在两千六百亿 token 内降到峰值的百分之十，之后一直保持。新派是先恒定、最后才降，V3 升到峰值以后一路平着跑，跑到十万亿 token 才开始降。

[thinking] 新派流行的理由特别实在。余弦要你一开始就知道总共训多少步，因为曲线形状依赖终点。恒定段却可以随时截断，接一小段衰减，就能出一个能用的 checkpoint。

[focus] 它把训多久这个决定，从开局推迟到了随时。而两派的终点，都落在峰值的十分之一附近。两个样本不构成定律，但足以说明，降到零不是默认做法。

[curiosity] 那 batch 自己该开多大？先说一句：batch 开大了更稳，这件事一点都不玄。梯度是一批样本各自意见的平均。

[thinking] 屋里坐八个人，混进一个特别偏激的，平均值被他拽走一大截；屋里坐八百个人，同一个人基本就听不见了。噪声大致按根号 B 分之一缩，batch 翻四倍，噪声减半。

[seriously] 那为什么不一直往大开？一种说法是，再加样本换不来等量的进步；另一种说法是，batch 大了学习率得跟着抬，可学习率抬不动。

[thinking] 听着是两条路，其实是同一条。最优学习率，等于它的上限，除以一加上噪声尺度比 batch，两边卡你的是同一个噪声尺度。

[realization] 给个好记的锚：batch 正好等于那个噪声尺度的时候，学习率预算刚好用掉一半，再往后翻多少倍，也只是慢慢逼近。所以稳定性随 batch 单调受益，样本效率却有拐点。选 batch，就是找那个刚好够稳、又还没开始浪费的位置。

[suggestion] 还有一句流传很广的：batch 开大就更快。它只在卡还没喂饱时成立。几百亿参数、几百张卡的训练，卡基本是满的，每步变贵的倍数正好抵掉步数变少的倍数，买到的是稳，不是快。

[focus] batch 往上爬，也不用一路加卡，调梯度累积，攒几次再更新就行，显存也不涨。V3 在头四千六百九十亿个 token 里，把 batch 从三千零七十二条爬到一万五千三百六十条，全程两千零四十八张卡，没加机器。花掉的只是更新频率。

[thinking] 反过来也要当心，global batch 等于每卡塞几条、攒几次、数据并行几路、序列多长，四样乘起来。你把张量并行开大，数据并行的路数就变少，global batch 跟着变小，学习率也就该跟着变。代码没改，换一套并行配置，loss 曲线就变了，原因在这儿。

[focus] 提醒一个坑：累积完必须除以累积次数。忘了除，就等于学习率乘了 K，代码不报错，loss 先降后飞。

[casually] Adam 剩下的 β1 和 β2，其实大家已经认识了，就是讲动量时那个记多久的旋钮，窗口大约是一减 β 分之一步。β1 取零点九，记十步左右，抹平方向的抖动。

[friendly] β2 管分母，零点九五大约记二十步，零点九九大约一百步。调大，尺子更稳但反应慢；调小，跟得紧但噪声大。

[thinking] 顺带一句 checkpoint。它要存的正好是那三份 fp32，十二个字节。

[focus] bf16 的权重和梯度都能重建。六千七百一十亿参数，一份约七点三个 TiB，模型本身只占三分之一。

[warmly] 最后说各位真会亲手跑的那种训练：LoRA。底座冻住，旁边挂一对很瘦的小矩阵。拿刚才那三本账对一遍。

[friendly] 常驻：七十亿参数的模型，全量微调要一百点四个 GiB，LoRA 只要十二点六八，差七点九倍。因为十六字节里有十四字节，只有要被更新的参数才需要。

[focus] 算力：冻住的层，权重的梯度不用算，前向一份、反向只剩一份，三倍变两倍。激活才是最容易误会的。

[thinking] adapter 挂在每一层上，最前面那层的也要梯度，而梯度只能从 loss 一路传回去，所以整条链的激活还得在场。LoRA 之后，激活往往成了新的大头，还是要开重算。

[seriously] LoRA 改的是有多少参数带着那十六字节，没改反向要穿过整个网络这件事。

[contemplative] 这一整节可以收成一句话：梯度只告诉你往哪走，优化器决定走多远。几十年的演化，都在回答这个多远由谁说了算。SGD 说，由你说了算。

[thinking] Adam 说，由梯度自己的历史尺度说了算。Muon 说，由矩阵的几何说了算。
