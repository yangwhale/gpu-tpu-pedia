## ⭐ 专项：4K vs 128K

全页 `128K/131,072` 出现 **13 次**，`4K` 只出现 **2 次**（§1.8 讲 V3 batch、§5.1 那句换算）。**整讲的激活账、算力账、重算排序表，全部建立在 S = 131,072 上**，而讲义自己在 §1.8 写着 V3 的实际预训练上下文是 4K。

把 4,096 代回讲义自己的公式：

| 讲义在 128K 下的结论 | 同一公式代 S=4,096 |
|---|---|
| attention 占一层前向算力 **82.1%** | **约 12.5%** |
| 6ND **低估五到六倍**（29.1→160 PFLOP） | 低估 **约 14%** |

| 一层 MoE 激活 **71 GiB** / 全模型 **4.15 TiB** | 2.2 GiB / **133 GiB** |

## C · 可疑（核下来对不上，或依赖未声明前提）

1. **§5.4「省了 6.7 倍。比例跟 671B 上那笔几乎一样。」**（`topic04-build.py:1913`）
   §2.2 白纸黑字写着 671B 那笔是 **约 40 倍**。6.7 ≠ 40。紧接着那句总结「换了 5,000 倍的规模，**那些比例基本没变**」因此也是错的 —— 只有「多付 33%」那个比例没变。
   两个原因叠加：(a) V3 的 MoE 层膨胀比 71.2/1.75 = **40.7×**，小模型只有 13,056/768 = **17×**，是架构差别不是规模差别；(b) **两处口径不一致** —— 106.75 GiB **不含**正在重算的那一层，0.32 GiB **含**。同口径下小模型是 13 倍。这三行全是手写 HTML，没有任何 assert 盯着。

2. **§2.4／2.5「GPT-3 自己最宽的线性层是 12,288」**（`topic04-build.py:563`；`topic04-fig-per-byte.py:45` 注释写明 `# 各自最宽的线性层（＝ d_model）`）
   ⭐ **这正是「听起来像常识的架构关系」那一类。** 按讲义自己的判据，每字节代价 = **输入宽度**；GPT-3 的 MLP 降维层输入宽度是 4h = **49,152**，不是 12,288。所以 GPT-3 自己的交点应在 ~49,152，被讲义少算了 **4 倍**。
   V3 那个 7,168 之所以对，是因为 MoE 专家窄（降维输入 2,048）—— 「最宽的线性层 = d_model」在 MoE 上碰巧成立，在稠密 FFN 上不成立。而这一格的标题恰恰是「判据：同一张图里出现两个模型时，每个模型的每一条线都要用它自己的常数」。
   *结论方向不受影响*（2,048 << 49,152，论文更没错），但那个数和那条线画错了。

3. **§5.1「94 条序列的分水岭」依赖一个未声明的前提：batch = 1。**
   讲义明说这一节算**全局总量、不分卡**。可 V3 的真实全局 batch，讲义自己在 §1.8 和 §3.5 报了：**15,360 条 × 4K = 62.9M token**，是那 1,230 万 token 分水岭的 **5.1 倍**。也就是说按讲义自己的两个数，真实训练里全局激活（开了重算也有 ~50 TiB）是常驻 9.76 TiB 的五倍多 —— 和全讲的主标题「最大的那一块是优化器状态」方向相反。这是**全文唯一一处 128K 口径的数和 4K 口径的数事实上被摆在一起、却没有人去做那个除法**。

4. **§6.6「33 个数量级，全是 bf16 存得下、fp16 存不下的」**（`topic04-build.py:2491`）
   脚本 `DECADES = log10(fp16 最小正规数 / bf16 下界) = 33.7`。可同一句话前半段自己就列了第三条线「fp16 归零线 5.96e−8」—— fp16 用次正规数能表示到那里。**真正 bf16 能存而 fp16 存不了的带宽是 30.7 个数量级**，不是 33。数和它自己的图注打架。

5. **§2.3 表「gate / up / 路由 / 降维（输入宽 7,168）9.14 GiB」**
   按 §1.7 反推，这一行该覆盖 gate 4.50 + up 4.50 + 路由 0.06 + Q降维 0.75 + KV降维 0.27 = **10.08 GiB**，差 0.94 GiB 对不上。而且「省显存」这一列在 `PER_BYTE_ROWS` 里**仍然是手填常量**（只有代价列由闭式解生成）—— 讲义那句「现在整张表由闭式解生成，手改不了」只对了一半，而它下面紧跟着的卖点正是「你拿 config 自己也能排一遍」。

   §2.2 白纸黑字写着 671B 那笔是 **约 40 倍**。6.7 ≠ 40。紧接着那句总结「换了 5,000 倍的规模，**那些比例基本没变**」因此也是错的 —— 只有「多付 33%」那个比例没变。
   两个原因叠加：(a) V3 的 MoE 层膨胀比 71.2/1.75 = **40.7×**，小模型只有 13,056/768 = **17×**，是架构差别不是规模差别；(b) **两处口径不一致** —— 106.75 GiB **不含**正在重算的那一层，0.32 GiB **含**。同口径下小模型是 13 倍。这三行全是手写 HTML，没有任何 assert 盯着。

2. **§2.4／2.5「GPT-3 自己最宽的线性层是 12,288」**（`topic04-build.py:563`；`topic04-fig-per-byte.py:45` 注释写明 `# 各自最宽的线性层（＝ d_model）`）
   ⭐ **这正是「听起来像常识的架构关系」那一类。** 按讲义自己的判据，每字节代价 = **输入宽度**；GPT-3 的 MLP 降维层输入宽度是 4h = **49,152**，不是 12,288。所以 GPT-3 自己的交点应在 ~49,152，被讲义少算了 **4 倍**。
   V3 那个 7,168 之所以对，是因为 MoE 专家窄（降维输入 2,048）—— 「最宽的线性层 = d_model」在 MoE 上碰巧成立，在稠密 FFN 上不成立。而这一格的标题恰恰是「判据：同一张图里出现两个模型时，每个模型的每一条线都要用它自己的常数」。
   *结论方向不受影响*（2,048 << 49,152，论文更没错），但那个数和那条线画错了。

3. **§5.1「94 条序列的分水岭」依赖一个未声明的前提：batch = 1。**
   讲义明说这一节算**全局总量、不分卡**。可 V3 的真实全局 batch，讲义自己在 §1.8 和 §3.5 报了：**15,360 条 × 4K = 62.9M token**，是那 1,230 万 token 分水岭的 **5.1 倍**。也就是说按讲义自己的两个数，真实训练里全局激活（开了重算也有 ~50 TiB）是常驻 9.76 TiB 的五倍多 —— 和全讲的主标题「最大的那一块是优化器状态」方向相反。这是**全文唯一一处 128K 口径的数和 4K 口径的数事实上被摆在一起、却没有人去做那个除法**。

4. **§6.6「33 个数量级，全是 bf16 存得下、fp16 存不下的」**（`topic04-build.py:2491`）
   脚本 `DECADES = log10(fp16 最小正规数 / bf16 下界) = 33.7`。可同一句话前半段自己就列了第三条线「fp16 归零线 5.96e−8」—— fp16 用次正规数能表示到那里。**真正 bf16 能存而 fp16 存不了的带宽是 30.7 个数量级**，不是 33。数和它自己的图注打架。

5. **§2.3 表「gate / up / 路由 / 降维（输入宽 7,168）9.14 GiB」**
   按 §1.7 反推，这一行该覆盖 gate 4.50 + up 4.50 + 路由 0.06 + Q降维 0.75 + KV降维 0.27 = **10.08 GiB**，差 0.94 GiB 对不上。而且「省显存」这一列在 `PER_BYTE_ROWS` 里**仍然是手填常量**（只有代价列由闭式解生成）—— 讲义那句「现在整张表由闭式解生成，手改不了」只对了一半，而它下面紧跟着的卖点正是「你拿 config 自己也能排一遍」。
