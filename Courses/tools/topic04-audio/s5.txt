[focus] 前面讲的都对，可全是六千七百一十亿参数、TiB 级的数，没有分母。这一节先把四项摆到同一条时间轴上，再把同一件事缩到一个你能自己算一遍的模型上。

[curiosity] 请看这张一个 step 的总账图。按全局总量算，一条十二万八千的序列。

[thinking] 最下面两层全程不动：权重一点二二个 TiB，优化器状态七点三二个 TiB，最厚，却只在最后一瞬间被用一次。上面两层薄得多：梯度一点二二个 TiB，激活开了全量重算，是一百六十二个 GiB。

[realization] 看那两条形状相反的带子。激活在前向刚结束时最高，梯度在反向刚结束时最高，两个峰根本不在同一时刻。几条曲线叠起来，总和的峰，未必落在任何一条单独的峰上。

[casually] 请看这段动画。显存在一步之内就有起伏：前向往上堆激活，反向一边用一边放。峰值出现在某一个瞬间，而你要买的，是那个峰值。

[seriously] 所以什么时候最挤，必须连着挤的是哪一项一起问。查 OOM 的时候，光知道峰值多少 GiB 没用。要知道那一刻哪一项最大，才知道该动哪个开关：激活大就开重算，优化器状态大就去切它。

[thinking] 那激活大，还是优化器状态大？没有固定答案。常驻那一块九点七六个 TiB，不随 batch 变。

[focus] 激活却随同时在场的序列数线性涨，要大约六十二条十二万八千的序列同时在场，才追得平。所以谁最大，不是模型的属性，是这次训练配置的属性。而且对显存来说，这些 token 怎么凑出来无所谓。

[thinking] 六十多条十二万八千的长序列，还是近两千条四千长度的短序列，是同一件事，因为激活只认 token 总数。算力就不是这样了，attention 那部分随序列长度的平方涨，它不在显存账上，却在算力账上。

[friendly] 现在缩小。一个一亿两千五百万参数的模型，就是 GPT-3 论文那张八档表的第一行：十二层，宽度七百六十八。一张卡，batch 八条，每条一千零二十四个 token。

[casually] 先把这一讲的三件事，在这台机器上各落一句。loss：八千一百九十二个位置，每个位置一个负的 ln p，取平均。刚初始化时它就是 ln 词表，跟第一节那把尺一模一样，只是词表小一点，起点低一点。

[friendly] 导数：一亿两千五百万个，代价是多跑两遍前向，不是一亿两千五百万遍。步长：Adam 为每个参数记两个滑动平均，占十二字节里的八个，剩下四个是混合精度带来的 fp32 主权重，跟 Adam 无关。

[focus] 常驻那一块，照搬十六字节。权重零点二三个 GiB，梯度零点二三，优化器状态一点四零，合计一点八六个 GiB。这个模型的权重只有零点二三，却要占掉一点八六，八倍，多出来的全是训练才要的。

[curiosity] 再数激活。一层里每个 token 留下的东西：两个 norm 的输出，Q K V，attention 的输出，MLP 里三份。

[thinking] 加起来一万一千五百二十个数，bf16 是二十二点五个 KiB。乘十二层，每个 token 两百七十个 KiB，再乘八千一百九十二个 token，二点一一个 GiB。

[realization] 大家注意这件事：激活二点一一，比常驻的一点八六还大。一个一亿参数出头的小模型，序列才一千零二十四，batch 开到八就够了。所以重算不是大模型的专利。

[thinking] 开了全量重算，每层只留入口那一份，再加正在重算的那一层。激活掉到零点三二个 GiB，省六点七倍，代价是算力从三倍变四倍，多付三分之一。这张小表，就是你笔记本上那个训练循环。

[focus] 还有一处故意的省略：最后那个 logits 没算。这一代沿用的词表大约五万，一次性把整个 logits 算出来要零点七七个 GiB，是那零点三二的二点四倍。真实实现分块算 loss，所以它不进总账，但那是口径选择，不是它不存在。

[contemplative] 多付三分之一，跟六千七百一十亿那边一模一样。可省的倍数，那边是二十点五倍，差了三倍多。为什么？

[thinking] 省多少，取决于两样：一层里挂了多少东西，一共有多少层。小模型一层的激活是入口那份的十五倍，只有十二层；V3 一层是三十一点七倍，有六十一层。V3 的一层挂得多，根子在 MoE，派发出去的激活和专家输出，各要复制九份。

[contemplative] 所以省多少倍换个架构就得重算。真正跟规模无关的只有三条：多付三分之一，每参数十六字节，激活只认 token 总数。
