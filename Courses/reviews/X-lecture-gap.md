### 3b. 作者自述 —— 这类更隐蔽，也更该拿掉 ⭐

| 位置 | 原句 | 判断 |
|---|---|---|
| **`1814`** | 「**这一条我原来写错了**，而且错得很典型：『量纲抵消了』只说明它是常数，没说明它等于 1。」 | ⛔ **应该删掉前半句、保留后半句。** 后半句是真知识（「量纲抵消 ≠ 等于 1」是个好判据）；前半句是备课日记。读者看到的效果是「我在偷看别人改稿」。而且它有副作用：一个新读者会开始怀疑**这一页上还有哪几条是没改的错**。 |
| **`2014`** | 「⛔ **我们以前把它们当两种东西讲**，那是把特例和一般情形讲反了。」 | ⛔ 同上。「向量做法本来就是矩阵做法的一个特例」这句要留，「我们以前讲错了」要走。 |
| `6.8` 尾注 | 「⛔ 这一节刻意一个我们自己的实测都没有……理由写在 §七：**这一讲已经有太多『自己推的』数了。**」 | ⚠️ 边界情况。前半句（「本节全部来自公开论文」）是对读者的**信息**，该留；后半句是**编辑决策的理由**，是写给自己的。建议截断在「并逐条核过原文」。 |

### 3c. 「2026-09-16 现场原话」这类 —— 全部在 HTML 注释里，读者看不到，但仍有风险

我逐行扫过（剔除注释后再匹配），**页面上没有任何一句「现场原话」或日期戳**。它们全在 `<!-- -->` 里，例如：
- `:846` 「2026-09-16 现场原话：『loss 是怎么变成梯度的？……这么多年了都没有人真正讲明白。』」
- `3.2` 上方 「2026-09-16 现场问：『为啥梯度是 bf16 的，它不是 fp32 的呢？』」
- `3.4` 上方 「现场：『……还有一个最开始的叫 G 什么来着？』」
- `1.8` 上方 「**PLAN 里写着『梯度通信』，我没写。**」

渲染上是安全的。**但它们在发出去的那份 HTML 里**：任何人 `Ctrl+U` 看源码、或者把页面存下来，就能读到学员的原话和作者的自我检讨。如果这门课会发到 CC Pages / GitHub Pages，建议在 `topic04-build.py` 出稿时加一道**剥注释**（注释是写在生成器里的，剥掉不影响可维护性 —— 源在 `.py` 里）。

> ⚠️ **这条我不确定**：我没查这门课的发布范围。判据是——这些注释里有可辨识的第三方引语，而且 `topic-04.html` 本身没有任何「内部」标记。**如果只在内网讲，可以不管。**

### 3d. 顺带：六套 CSS 是死的，连带六段长注释也是

`tkaway / think / aside / guess / foldfig / msdeep / jstep` 在 `topic-04.html` 的 body 里**用量全为 0**（`.landing` 57、`.lead` 24、`.capmore` 9 是活的）。跟着搬过来的注释也就跟着失真了，比如 `:739` 那条在描述「点开『课前勿点』只剩选项、没有问题」这个 bug —— **这一页根本没有「课前勿点」这个块**。另外 `:751` 那条说「图注是折叠模式下最大的一块字（**48 条共 4960 字**）」—— 本页只有 **9** 条图注。这些数字是从专题三抄过来没改的。不影响读者，但会误导下一个改这份文件的人。

**Q1. 「那我自己拿一张卡训个小模型，这些数该怎么换算？」**
全讲每一个数都是 671B × 128K 口径：4.15 TiB、106.75 GiB、9.76 TiB、125 张卡、S≈5,734、94 条序列。**整份教材没有任何一个小规模的算例。** 更糟的是 3.5 给的建议是「找一个规模和架构都接近的公开配置抄过来」—— 可 GPT-3 表 2.1 最小档是 350M，而且紧跟着那句「500 倍规模差，学习率只差 5 倍」会**直接诱导错误外推**到 10M 级别。这是这个受众最想问的一句，材料给不出任何抓手。

**Q2. 「微调呢？LoRA 呢？我又不预训练。」**
grep 确认：`LoRA` **0 次**、`fine-tun` **0 次**、`预训练` **0 次**；`微调` 只有 **1** 次，而且埋在 `fig-3x` Ⓒ 格的 SVG 文字里（「比如只微调最后一层」）—— **正是讲义从不打开的那一格**（见 B6）。这个受众里做微调的人多于做预训练的人。而微调会把这门课的头号结论翻过来：LoRA 下优化器状态只挂在 adapter 上，「最大的一块是优化器状态」直接不成立。**必须准备一句一分钟的回答，并顺手把 fig-3x Ⓒ 加进 §1 的 board。**

**Q3. 「这些是在什么卡上？H100 还是 TPU？160 PFLOP 要跑多久？」**
grep：`H100` / `A100` / `GPU` / `TPU` / `小时` 全部 **0 次**。5.1 那个 80 GiB 被三处（5.1 正文、附录 7.2、讲义 warn）反复声明「是随手设的换算基准，不是某款具体的卡」。立场是严谨的，**但效果是：全讲没有一个硬件锚点，也从不把 FLOP 换成时间。** 台下会把这种回避听成「他不肯说」。建议准备一句**不指名的量级换算**（「一张当代旗舰卡大概每秒几百 TFLOP，所以这条 128K 序列一步大概是……」），标清是量级。

**Q4. 「所以训一次到底要多少钱／多久？」**
6ND 是全讲唯一给出的成本估法，然后 5.2 把它判成**低估五到六倍**，接着说「要记的不是这个倍数，是那个公式什么时候会骗你」。对研究员这是好话，对爱好者这是**把唯一的工具拿走了却没给替代品**。附录 7.2 还诚实地写着这条「目前没有第三方实测佐证」。讲义的 TODO 里也认了这一条。**没有答案，只能准备一句诚实的「这一块我们自己也只有量级」。**

**Q5. 「课件里那些默认值 —— 裁剪 1.0、β₂=0.95、weight decay 0.1 —— 我照抄行不行？」**
材料在这里**自己跟自己打架**：一边把 GPT-3 七档表、V3 全套 schedule 端上来说「这是免费的先验，不用猜」「放心抄」（附录 7.1 标题就叫「查得到出处的（**放心抄**）」），一边把判据 ③ 立成「**凡是会改变数据分片形状的参数，都不能跨规模照抄**」，还在本讲重复三次。**哪些能抄、哪些不能抄，材料从没划过线。** 这是最会被追着问的一条，而且问的人是对的。

**Q6. 「重算、ZeRO 这些，我在代码里怎么开？」**
grep：`PyTorch` 0、`API` 0；没有任何一个开关名（`gradient_checkpointing`、`zero_stage`、`--fsdp`）。整份材料是纯概念账本。而讲义 §4 的 warn 还明确禁止往下讲（「不要讲 ZeRO 各级的通信量公式，那是专题五的事」「如果有人问 TP/PP，答『下一讲』」）—— 于是**这个问题在 §4 会被挡回去，而它恰恰是爱好者唯一能立刻动手验证的东西。** 建议准备一张三行的「名词 → 框架里那个开关」小抄，就算不投屏，口头给也行。
