[focus] 运行时还是编译期，这对词大家已经见过四次了：第二节那个四对零，第三节哪几层是运行时才定的，那三套电路，还有刚才六站里两边分岔的那两站。每一次都停在同一个决定上，只是换了个部件。这一节把这件事本身拿出来讲：谁来安排，这个决定怎样从硬件一路流到你写代码的那只手上。

[thinking] 从最底下一层开始，因为它最能说明问题。取一次数要等几百个周期，这段时间干什么？两边的答案不是快慢之分，是谁负责之分。

[casually] GPU 的答案是：一个 warp 卡住了，就换下一个上来跑。请看这张甘特图，虚线框是在等数据，而别的 warp 照常在发指令。藏得住的前提是，同时驻留的 warp 够多，这就是占用率这个词的全部含义。

[focus] 那能驻留几个，由什么决定？由寄存器。一个 SM 有六万五千五百三十六个三十二位寄存器，最多驻留六十四个 warp。warp 要随时切得回来，整个现场就得一直留在寄存器堆里。每个线程用三十二个寄存器，能塞满六十四个 warp；用到一百二十八个，只剩十六个，就开始吃紧了；用到上限二百五十五个，只剩八个，气泡成片。所以 CUDA 调优第一步，常常是砍寄存器用量。

[friendly] TPU 的答案完全不同：班表在编译期就排好了，跑的时候改不了。请看这张图，一个 VLIW 指令包，就是这一拍要干的所有事打成一包：标量槽发 DMA，向量槽做归一化，矩阵槽往阵列里推乘法，杂项槽放一条等待，同一拍一起发出去。

[curiosity] 它凭什么敢排这么准？因为延迟是常数。这两句要连起来听，它们是同一件事的两面。有 cache，延迟就不是常数；不是常数，编译期就排不了班，于是只能准备一大批替补。没有 cache，延迟就是常数；是常数，就能在编译期把每一拍排满，于是不需要替补。

[seriously] 但看这张图要看那些灰格子。灰的是真的空着，而且不会有任何东西自动顶上来。编译器要么找到别的独立的活填进去，要么就认了。

[realization] 这一对图真正的价值不在机制，在失效条件。GPU 那套，在备选不够的时候失效：寄存器一吃紧，能驻留的少了，延迟就藏不住。TPU 那套，在算不准的时候失效：形状是动态的，访问位置要跑起来才知道，编译期排的班就成了空班。所以两边怕的东西正好相反，一边怕资源紧，一边怕不确定。

[casually] 硬件上的这个差别，会原样出现在你敲的代码里。请看这两段代码。左边 CUDA，里面有 blockIdx、threadIdx，我是第几号、我负责哪一格，写在代码里。右边 JAX，一个下标都没有，你只声明这个数组按哪根轴切，切完谁跑哪一块，编译器安排。再往上一层，集合通信也是同一个模式：all-reduce 在 GPU 那边是你亲手写的一步，在 TPU 那边你从头到尾没写过，它是编译器按你声明的并行方式自己插进去的。

[thinking] 讲到这儿，会有一个很自然的反应：那什么都交给编译器，不就行了？不行，而且边界画得相当清楚。请看这张图，这是这一节的中心。

[focus] 左边四样是编排：算子融合，通信与计算重叠，内存复用，布局与切分。这四样都不改变算的是什么，只改变怎么排，排错了顶多慢，不会错，所以编译器有资格自己决定。右边是换算法。越过这条线，编译器就帮不上忙了。FlashAttention 在右边，而且两边都得手写。GPU 那边是研究者写出来再被库收编的，TPU 那边的 Splash 同样是人一行一行写的，没有任何一侧的编译器自己长出了它。一个两边都失效的反例，比任何一边的成功案例都更能定义边界。这也把刚才那张对照表补全了：TPU 那边少写的是搬运，不是算法。

[curiosity] 说到这里，大家可能已经绊了一下：左边第一格明明写着算子融合是编译器的领地，可 FlashAttention 编译器又做不到。两句都对，因为那是两种融合。

[friendly] 第一种，不用改数学的融合，编译器替你做。算的还是原来那些式子，只是不再走一趟冷库。这一类你一行都不用写，两边的编译器都在默默做。

[seriously] 第二种，要改数学才能成立的融合，永远归人。原来的 softmax 融不了，卡在分母是整行求和：没看完整行，就算不出任何一个数，也就没法只留一小块在灶台上。online softmax 换的就是这一点：边走边更新最大值和分母，最后补一次缩放，结果一模一样。顺带按住一个误读：每一块多做的那次缩放，量级只是序列长度乘头维，跟矩阵乘那个序列长度平方的量比，可以忽略。不改数学，说的是结果等价，不是一条指令都没多。

[realization] 所以不是先有融合再顺便改算法，是为了让融合成立而换了算法。编译器有资格决定怎么排，没有资格决定算的是什么。

[contemplative] 于是融合由谁决定，答案要拆成两半。能不能融、能融多大，硬件说了算，就是刚才那个灶台和刀宽，两个数一起卡死。谁动手融，看要不要改数学：不改的，编译器做；改的，只能你自己写。这也解释了一件乍看矛盾的事：融合是这门课里唯一贯穿始终的话题，但它既不是纯硬件问题，也不是纯软件问题，它恰好卡在两者交界上，所以研究硬件，最后都会落到它上面。

[thinking] 那 Triton 和 Pallas 算什么？它们是越过边界以后你拿什么写的答案，定位几乎一样，都不用你自己写每一次读写。但需要它们，恰恰说明这件事编译器自动做不了。

[casually] 还有人会问，TPU 编译那么慢，是不是个大问题？在 v7 上，一次 XLA 编译常见十到十七分钟。它是问题，但性质要说清楚：这是成本挪了位置，不是多出来的成本。它不是在翻译，是在替硬件把整张班表排完。GPU 那边同一件事是每次运行时由调度器现做的，成本摊在跑的时候。换来的是跑起来非常稳，同一个形状重复跑，步时几乎没有抖动，因为根本没有运行时决策可抖。真正的痛点是形状一变就要重编。

[curiosity] 讲到这里，最强的一个反驳一定会出现，而且它有一半完全成立：CUDA Graph 不就是 GPU 也编译期了吗？

[seriously] 先把它成立的部分说足。整个 step 的 kernel 图提前录好，之后一条道跑到黑，收益是真的，很多负载上开与不开是数量级的差别。但要判断它推翻了什么，得先讲准它为什么快，最常见的解释是错的。它省掉的不是分支，是 CPU 一条一条发 kernel 的开销。单次启动，主机端大概五到十微秒；一个 MoE 的 step 可以有上万个 kernel，光是发就要几十毫秒。开了 graph，这一整笔变成一次重放。

[focus] 所以问题落在位置上。请看这张图，把通路切成三层。编排层，下一个 kernel 是什么；落地层，这个 kernel 的块放到哪个 SM；发射层，下一拍执行哪条指令。CUDA Graph 只把第一层冻住了，后面两层一个都没动。graph 里每个节点仍然是一次正常的 kernel 启动，调度器、记分板、warp 槽、常驻上下文，全都还在工作。它操作的是 kernel 的外面，连 kernel 里面有什么都不知道，所以它在架构上就够不着后两层。而 TPU 是三层全冻，第三层冻到具体哪个周期、哪个发射槽。

[thinking] 位置定下来之后，这个反驳反而成了前面几节最好的佐证，三条理由指向同一处。第一，CUDA Graph 自己也要求形状静态，形状一变就得重录，这正是 TPU 被诟病的同一笔静态税。第二，TPU 压根不需要它，XLA 本来就把整个 step 编成一个程序，CUDA Graph 是 GPU 在补自己架构带来的问题。

[realization] 第三条最要紧：硬件成本由必须支持的最坏情况决定，不由你实际跑的情况决定。哪怕百分之百的负载都开 graph，上半节里那五样部件一个都省不掉，因为芯片流片的时候，并不知道你会不会开。所以真正值得说的是反过来那个方向：GPU 想要这份性能，办法就是让自己更像 TPU。而它能往前挪的只有最上面那一层，下面两层挪不动。挪得动的话，那些晶体管早就省下来了。

[curiosity] 还有第二句反驳，比上一句强得多，因为它说的方向是对的：搬运这条路，GPU 不是也在往 TPU 那边挪吗？

[friendly] 对，而且趋势藏不住。最早的普通取数，数据要在寄存器里过一道，地址、跨步、边界全靠线程自己算。Ampere 起，砍掉了寄存器那一道，地址仍然自己算。Hopper 起有了 TMA，一个线程填一张描述符发出去就走，跨步、偏移、边界整个交给硬件，三十二条 lane 各算一个地址这件事主动放弃了。Blackwell 起这一步最狠：矩阵指令由单个线程代表整个线程块发射，操作数和累加器搬进一块专用的矩阵暂存，连结果都不回寄存器堆。四代下来，那条通路的终点是：整块搬，按描述符搬，不占线程，落在一块软件说了算的专用暂存里。而这正是 TPU 第一天的样子。

[seriously] 但这条趋势线只走了一半。收敛的是怎么搬：粒度、谁来算地址、操作数落在哪。没收敛的是谁决定，这一层一步都没动。TMA 那张描述符是运行时建的，不是编译期烤进二进制的；L1 和 L2 还在，命中不命中照样跑起来才知道；warp 调度器照样每个周期现挑。

[realization] 所以准确的说法不是 GPU 在变成 TPU，而是 GPU 把喂料这件事做成了 TPU 的样子，而谁来发号令那一层一动没动。两边的分歧从来不在终点，在谁来发这条 DMA。

[contemplative] 这条趋势也不是谁抄谁。矩阵单元越快，喂料这件事就越不能占着算的人。一条矩阵指令几拍里就吃掉几十 KB，你还让三十二个线程轮流去算地址，那些线程就成了自己算力的看门人。两家面对的是同一道物理题，于是给出了同一个答案，只不过一家走了四代，另一家出厂就在终点。

[friendly] 这一节就到这里，大家有问题吗？
