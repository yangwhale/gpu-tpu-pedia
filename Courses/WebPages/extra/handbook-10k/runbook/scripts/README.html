脚本参考

本目录每个文件都有一节：干什么、什么时候跑、前置条件、参数、示例、注意。内容按脚本源码核对过（文件头注释、参数解析、环境变量）。脚本和本页说法不一致时，以脚本为准，并回来改本页。

脚本整包下载：runbook-scripts.tar（与本页同一版本）。解压后照 01 §1.0 复制 env.sh、填好再用。

通用约定

以下各条都从脚本源码里来；个别脚本例外时，在它自己那一节写明。

  • 变量从哪来。 env.sh 是模板：cp env.sh ~/runbook-env.sh，填 <…> 占位，每个终端先 source ~/runbook-env.sh。脚本自己会 source "$(dirname "$0")/env.sh" 读本目录的模板，但模板里每一行都写成 ${VAR:-默认}，终端里已 export 的值优先，所以填好的值不会被模板覆盖。例外：06a-aot-dsv3.sh 不读 env.sh，只读 06a-dsv3-recipe.env。

  • rb_env_check（env.sh 定义）。 不带参数时查 6 项：PROJECT REGION ZONE CLUSTER RESERVATION GKE_VERSION。带参数时只查列出的那几项。以下情况判失败：

    • 值为空，或以 < 开头（没填的占位）；
    • PROJECT 是纯数字（填成了项目编号）；
    • ZONE 不在 REGION 里；
    • RUNBOOK_DIR 下找不到 scripts/env.sh。

    调用时加前缀 RB_CREATING=1 还会查集群名长度：上限 = 63 − len(ZONE) − 33。脚本在入口按自己用到的变量调它，缺值就退出。04 系列、05-list-partitions.sh、06a-aot-dsv3.sh 没调。

  • 状态目录。 所有落盘的计划、日志、报表都在 $STATE_DIR（默认 $HOME/runbook-state/$CLUSTER），env.sh 被 source 时自动创建。

  • dry-run 有三种写法，看清再跑：

    1. 显式 --dry-run：打印 + 命令 不执行。用于 02-create-*、03-addons.sh 的改状态子命令、04-host-inspect.sh apply|cleanup、04-nic-check.sh fleet|cleanup、06-build-env.sh。注意 02-create-tpu-nodepools.sh --dry-run 仍会跑只读的前置查询。
    2. 默认 dry-run，要加 --execute 才动手：05-delete-slice-chain.sh、05-isolate-cube.sh、07-mtc-setup.sh、07-fault-drill.sh。02-delete-tpu-nodepools.sh 和 02-create-networks.sh --delete 要加 --yes。
    3. 只打印、从不 apply：04-gen-jobset.sh、04-bench.sh gen|gcsfuse、05-list-partitions.sh --emit、06-jobset.sh render|overlay-print。输出重定向到文件，看过再 kubectl apply -f。

  • 幂等。 建资源的脚本都先查后建：describe / helm upgrade --install / kubectl apply，已存在就跳过或收敛。各节的「注意」写了例外，比如会拒绝改已存在内容的情形。

  • 退出码。 0 = 通过 / 干净；1 = 检查不过或运行失败。用法错误时，05-*、07-fault-drill.sh 返回 64，06-jobset.sh 返回 2。有专门含义的码在各节单列，例如 02-delete-tpu-nodepools.sh 拒删时返回 2、08-daily-check.sh 要 page 时返回 2、06a-aot-dsv3.sh 显存超限时返回 3。不带子命令或子命令不认识时，多数脚本打印文件头里的用法后退出非 0。

  • 工具。 普遍要 gcloud、kubectl、jq。03-addons.sh 要 helm；envsubst（gettext）用于渲染 .tmpl / yaml；05-avoid-manual-slices.py 要 python3 + PyYAML；06a-aot-dsv3.sh 要 docker。kubectl 上下文必须指向 $CLUSTER（03-addons.sh 会核对）。

  • 实测标注。 各节「注意」里，「实测」= 文件头写了在集群上跑过；「未实测 / 需验证」= 文件头自己这么标，照抄，没有替它升级。

01· 建前预检

env.sh

  • 干什么：全书唯一的变量块（只 export，不动云资源），并定义 rb_env_check。

  • 什么时候跑：每个终端第一件事，01 §1.0；占位怎么填见 01 §1.5。

  • 前置条件：无。

  • 参数：无参数（被 source）。下表是常要改的变量，全部可在 source 前 export 覆盖：

    变量 含义 默认值 必填
    PROJECT REGION ZONE CLUSTER 项目 ID / 区域 / 可用区 / 集群名 <…> 占位 是
    RESERVATION reservation 名 空 是（建池前）
    GKE_VERSION GKE 版本 <…> 占位 是
    NS 训练作业的 namespace <…> 占位 是
    DATA_BUCKET 数据桶名（不带 gs://） <…> 占位 06 章起是
    RUNBOOK_DIR runbook 目录 若 env.sh 就在 runbook/scripts/ 下则自动推出，复制到别处时要填 复制后是
    SPARE_CUBES 每日留空的备件 cube 数 S 空（= 未约定） 配额重算时是
    TPU_QUOTA ClusterQueue 配额（芯片） 空 03-addons.sh queues 时是
    CUBES_EXPECTED / CUBES_MAX_JOB / CUBES_SLO sub-block 数 / 单作业最大 cube / SLO 线 144 / 128 / 130 否
    KUEUE_VERSION / JOBSET_VERSION Helm chart 版本 0.18.10 / 0.12.0 否
    INSPECT_NS 巡检 / 构建用的 namespace（在 Kueue 排除列表里） rb-inspect 否
    LOCAL_QUEUE / CLUSTER_QUEUE / TPU_FLAVOR Kueue 对象名 multislice-queue / cluster-queue / tpu7x-flavor-v2 否
    CLUSTER_DNS coredns 或 clouddns coredns 否
    STATE_DIR 状态目录 $HOME/runbook-state/$CLUSTER 否

    网段、池名前缀、MTC、RUN_NAME / JOBSET_NAME 等其余变量见文件本身，每行都有注释。

  • 示例：

    bash
    cp runbook/scripts/env.sh ~/runbook-env.sh && vi ~/runbook-env.sh   # 填 <…>
source ~/runbook-env.sh && rb_env_check                        # 缺值打印 env: … 并返回非 0

  • 注意：重复 source 是幂等的。SPARE_CUBES 故意不放进默认必填项，要它的脚本自己列。网络相关变量建池后不能改（02 §2.1）。

01-precheck.sh

  • 干什么：建集群前一次查完工具、项目 / API / IAM、reservation、block / sub-block、维护、配额、版本 / 桶，逐项打 PASS / FAIL / WARN / MANUAL。

  • 什么时候跑：01 §1.0，开工第一步；拿到 reservation 名后再跑一遍。

  • 前置条件：已 source env.sh，PROJECT REGION ZONE RESERVATION 已填（脚本调 rb_env_check PROJECT REGION ZONE RESERVATION）；gcloud（含 beta）、jq、python3；对项目有读权限，查配额要 quotas API 权限。

  • 参数：

    参数 含义 默认值 必填
    --skip-quota 跳过第 6 段配额检查（没有 quotas API 权限时） 不跳过 否

  • 示例：

    bash
    ./01-precheck.sh
./01-precheck.sh --skip-quota

    输出按段 == 0. 变量 … == 7. 版本 / 桶，每行 PASS <项> <值>；FAIL / WARN 下一行是 -> 怎么处理；最后一行 == 结果：FAIL=0 WARN=n。sub-block 清单存到 $STATE_DIR/subblocks-*.tsv。

  • 注意：只读，可随时重跑。退出码：有 FAIL → 1；只有 WARN / MANUAL → 0。第 7 段（版本 / 桶）文件头标「未实测」。helm 版本门槛（≥ 3.8.0）标「需验证」。

02· 建集群与节点池

02-create-networks.sh

  • 干什么：建主网络和两张 DCN 网络（VPC + 子网）、防火墙、Cloud Router、Cloud NAT；--delete 反向删。

  • 什么时候跑：02 §2.1，建集群之前。

  • 前置条件：env.sh 已填，网段变量已冻结；脚本调 RB_CREATING=1 rb_env_check PROJECT REGION ZONE CLUSTER（顺带查集群名长度）；有 compute 网络管理权限。

  • 参数：

    参数 含义 默认值 必填
    --dry-run 只打印 + 命令 关 否
    --delete 改为删除（NAT → Router → 防火墙 → 子网 → VPC 逆序） 关（= 创建） 否
    --yes 确认删除；--delete 不带它（也不带 --dry-run）就拒绝 关 删除时是

  • 示例：

    bash
    ./02-create-networks.sh --dry-run
./02-create-networks.sh
./02-create-networks.sh --delete --dry-run   # 看删除清单
./02-create-networks.sh --delete --yes

  • 注意：创建是幂等的：每个资源先 describe，存在就跳过，不会修改已存在资源的参数（MTU / 网段建后不可改，不一致要人工处理）。删除时如果还有集群在用这些网络，会拒绝并以退出码 2 退出。文件头未标实测 → 需验证。

02-create-cluster.sh

  • 干什么：建 zonal GKE 集群 + 系统池，get-credentials --dns-endpoint 取凭据，然后核对关键配置。

  • 什么时候跑：02 §2.2，网络建好之后。

  • 前置条件：02-create-networks.sh 已跑；RB_CREATING=1 rb_env_check PROJECT REGION ZONE CLUSTER GKE_VERSION 通过；CLUSTER_DNS 只能是 coredns 或 clouddns（否则退出 1）。

  • 参数：

    参数 含义 默认值 必填
    --dry-run 只打印命令 关 否

    主要配置都从 env.sh 来：版本、网段、系统池机型 / 节点数、CLUSTER_DNS。

  • 示例：

    bash
    ./02-create-cluster.sh --dry-run
./02-create-cluster.sh

    核对段里会打出 OK default-pool workloadMetadata=GKE_METADATA 这类逐项结果。

  • 注意：幂等：集群已存在就跳过 create，直接核对。回滚：gcloud container clusters delete "$CLUSTER" --location="$ZONE" --project="$PROJECT"。文件头标「需验证」（没有原样跑过）。

02-tpu-node-system-config.yaml

  • 干什么：TPU 节点池的 --system-config-from-file：topologyManager = best-effort / container，透明大页 = ALWAYS。
  • 什么时候跑：不单独用，02 §2.4 建池时由 02-create-tpu-nodepools.sh 传给 gcloud。
  • 前置条件：无。
  • 参数：无参数。
  • 示例：无需手工调用。
  • 注意：没开 cpuManagerPolicy: static。要走「每 VM 2 容器」方案时再加（文件头有说明）。节点池建好后改这个文件不影响已建的池。

02-create-tpu-nodepools.sh

  • 干什么：列出 reservation 里健康的 sub-block（HEALTHY 且 healthyHostCount=16），每个 sub-block 建一个 1-cube TPU 节点池。并发建，失败自动退避重试，最后调 02-check-nodepools.sh。

  • 什么时候跑：02 §2.4；ERROR 池的处置见 02 §2.5。

  • 前置条件：默认 rb_env_check 6 项全过；集群已建；workload policy 为 READY、DCN 子网存在（脚本会先查，dry-run 也查）。

  • 参数：

    参数 含义 默认值 必填
    --dry-run 只生成计划和命令 关 否
    --parallel N 并发建池数 10 否
    --only <sb-A>,<sb-B> 只建指定 sub-block（4 位编号，逗号分隔） 全部 否
    --include-degraded 连 DEGRADED sub-block 也建（预期起不全） 关 否
    --watch-only 不建，只盯状态 + 跑健康检查 关 否
    --timeout-min N 等待池就绪的超时（分钟） 45 否

  • 示例：

    bash
    ./02-create-tpu-nodepools.sh --dry-run          # 看 $STATE_DIR/nodepools-<时间>/plan.tsv 和 *.cmd
./02-create-tpu-nodepools.sh
./02-create-tpu-nodepools.sh --only <sb-A>,<sb-B>
./02-create-tpu-nodepools.sh --watch-only

  • 注意：幂等：已存在的池一律跳过（不论状态），重跑只补缺的。ERROR 的池不会自动删。单池失败最多重试 5 次，退避 30 → 240 s。回滚用 02-delete-tpu-nodepools.sh，容量事故期间不要删健康的池。文件头标「需验证」。

02-delete-tpu-nodepools.sh

  • 干什么：删指定的或全部（$POOL_PREFIX*）TPU 节点池。

  • 什么时候跑：02 §2.5（重建坏池）、拆集群前。

  • 前置条件：rb_env_check PROJECT ZONE CLUSTER；池上没有活着的切片。

  • 参数：

    参数 含义 默认值 必填
    --only a,b 要删的池名（逗号分隔） — 与 --all 二选一
    --all 删全部 $POOL_PREFIX* 池 关 与 --only 二选一
    --yes 真删；不带它就只打印 关（= dry-run） 真删时是
    --parallel N 并发删除数 10 否

    参数 含义 默认值 必填

    子命令 / 变量 含义 默认值 必填
    render 打印渲染后的 YAML — —
    notin-pools 列出提交前该排除的节点池（只读；池名到 stdout，原因到 stderr） — —

  • 干什么：DeepSeek-V3 671B 公开配置配方的唯一参数源：镜像 digest、MaxText 模型参数、编译 / 运行 flag、XLA_FLAGS。
  • 什么时候跑：06b §2；被 06-jobset.sh（RECIPE=dsv3）和 06a-aot-dsv3.sh 同时 source。
  • 前置条件：无。
  • 参数：无参数（被 source）。导出 RECIPE_IMAGE、RECIPE_MODEL_ARGS、RECIPE_XLA_FLAGS、RECIPE_RUNTIME_FLAGS、RECIPE_XLA_FLAGS_ENV。
  • 示例：改配方只改这里，AOT 与真跑同时生效。
  • 注意：XLA_FLAGS 里的 --xla_disable_hlo_passes=…collective-pipeliner-forward 不能删，多片不带它会 OOM（AOT 实测）。06-jobset.sh preflight 在多片时会查。

06a-jobset-dsv3.yaml

  • 干什么：DeepSeek-V3 训练 JobSet 模板。不需要 env tar、PVC、overlay、Secret，公开镜像里已经有代码和依赖。
  • 什么时候跑：06b §3，由 RECIPE=dsv3 ./06-jobset.sh render|apply 渲染。
  • 前置条件：镜像能拉；OUTPUT_DIR 写到桶时，KSA 对桶有 objectUser。
  • 参数：envsubst 变量 $JOBSET_NAME $NS $LOCAL_QUEUE $RUN_NAME $OUTPUT_DIR $RECIPE_IMAGE $RECIPE_MODEL_ARGS $RECIPE_LIBTPU_ARGS $RECIPE_XLA_FLAGS_ENV。片数、形状、步数、flag、优先级由 06-jobset.sh 再改写。
  • 示例：RECIPE=dsv3 ./06-jobset.sh render > js.yaml。
  • 注意：不要直接 kubectl apply 这个文件。

06a-aot-dsv3.sh

  • 干什么：在 CPU 上用配方同一个镜像和同一份参数跑 MaxText train_compile，按目标拓扑把训练步完整编一遍，打印每 device 的显存账（temp / argument / host temp），不占 TPU。

  • 什么时候跑：06b §5，提交多片作业之前。

  • 前置条件：本机能跑 docker、磁盘 ≥ 25 GB；镜像不能匿名拉，要先 gcloud auth configure-docker us-docker.pkg.dev。不需要集群、TPU、GCS 凭据。不读 env.sh。

  • 参数：

    参数 / 变量 含义 默认值 必填
    <名字> 本次编译名，日志写到 $OUT/aot-<名字>.log — 是
    [MaxText 参数 …] 追加给 train_compile（如 base_num_decoder_layers=5） — 否
    SLICES 目标片数 见脚本 否
    TOPO_NAME 目标拓扑，按 device 数写（4x8x8 = tpu7x-512，1 cube = tpu7x-128） tpu7x-512 否
    STEPS 步数 50 否
    CPUS docker --cpus min(64, nproc) 否
    OUT 输出目录 ~/runbook-state/aot 否
    IMAGE 镜像 recipe.env 的 digest 否
    XLA_FLAGS_ENV 容器的 XLA_FLAGS recipe.env 的值 否
    EXTRA_XLA 追加到 compile_xla_flags（单 flag A/B） 空 否

  • 示例：

    bash
    runbook/scripts/06a-aot-dsv3.sh smoke base_num_decoder_layers=5   # 先试通链路（显存不作数）
SLICES=1 runbook/scripts/06a-aot-dsv3.sh s1
SLICES=2 runbook/scripts/06a-aot-dsv3.sh s2

    结尾打印 每 device：temp x GiB（判据，上限 94.74） argument … host temp …，然后 ✓ 装得下 或 ✗ temp 超过 94.74 GiB。

  • 注意：退出码：编译失败 → docker 的返回码；temp > 94.74 GiB → 3。日志里有 Finished train_compile.py successfully! 不等于装得下，以脚本打印的 temp 为准。AOT 显存是编译期估计，与实机峰值能差几到十几 GiB，OOM 最终以实机 peakBytesInUse 为准。TOPO_NAME 写错（按芯片数写）不会报错，编出来的是另一个形状。

07· 容错与恢复

07-checkpoint-configuration.yaml

  • 干什么：MTC 的 CheckpointConfiguration（集群级 CR）。建了它，GKE 才会在 TPU 节点上起 multitier-driver DaemonSet。
  • 什么时候跑：07 §7.1，由 07-mtc-setup.sh --execute 渲染并 apply。
  • 前置条件：HighScaleCheckpointing addon 已开（否则 apply 报 no matches for kind "CheckpointConfiguration"）。
  • 参数：envsubst 变量 MTC_CONFIG_NAME MTC_BUCKET MTC_INMEM_SIZE。
  • 示例：envsubst < 07-checkpoint-configuration.yaml | kubectl apply -f -（或 ./07-mtc-setup.sh --execute）。
  • 注意：inMemoryVolumeSize ≈ 本地检查点大小 × 2.2，从每台 host 内存里扣。CR 写法由已有 DaemonSet 反推而来，属于推断。集群升级前后要删了重建 CR。

07-mtc-setup.sh

  • 干什么：打开 Multi-Tier Checkpointing：addon → HNS 桶 → IAM → CheckpointConfiguration → 验证。缺什么补什么。

  • 什么时候跑：07 §7.1。

  • 前置条件：rb_env_check PROJECT REGION ZONE CLUSTER MTC_BUCKET MTC_CONFIG_NAME MTC_INMEM_SIZE；container.clusters.update、storage.buckets.create / setIamPolicy；kubectl 集群管理员；envsubst；GKE 版本满足 multitier driver 下限（见文件头）。

  • 参数：

    参数 含义 默认值 必填
    （无） dry-run：检查现状、打印将执行的命令 — —
    --execute 真改 关 真改时是
    --verify 只验证 — 否
    --delete 删 CR（driver 撤掉、ramdisk 释放）；配 --execute 才真删 — 否

  • 示例：

    bash
    ./07-mtc-setup.sh
./07-mtc-setup.sh --execute
./07-mtc-setup.sh --verify
./07-mtc-setup.sh --delete --execute

  • 注意：幂等：每步先查，addon 已开 / 桶已存在 / IAM 已绑 / CR 已存在都跳过（CR 用 apply，改了 env 重跑即更新）。--delete 不删桶、不关 addon。桶已存在但没开 HNS 时退出 1（HNS 建后不能再开，只能换名重建）。文件头未标实测 → 需验证。

07-jobset-mtc.yaml

  • 干什么：开 MTC + 容错重启（failurePolicy maxRestarts + Recreate）的训练 JobSet 模板，/local 挂 multitier-checkpoint CSI 卷。
  • 什么时候跑：07 §7.1 第 6 步；故障演练（07 §7.3）用它起作业。
  • 前置条件：07-mtc-setup.sh 已跑；env tar 里的训练代码读 MTC 相关 env，且 orbax ≥ 0.12.3（否则 MTC 被静默忽略）；跨片只做纯数据并行。
  • 参数：envsubst 变量 $JOBSET_NAME $NS $LOCAL_QUEUE $DATA_PVC $DATA_BUCKET $RUN_NAME $ENV_TAR $GITHUB_SECRET，加上自己 export 的 $SLICES $MTC_STEPS $LOCAL_CKPT_PERIOD $PERSIST_CKPT_PERIOD $OWNER $PROJECT（后几个 env.sh 里没有）。
  • 示例（文件头原样）：
    bash
    source "$RUNBOOK_DIR"/scripts/env.sh
export SLICES=2 MTC_STEPS=2000 LOCAL_CKPT_PERIOD=20 PERSIST_CKPT_PERIOD=40 RUN_NAME=mtc-demo JOBSET_NAME=mtc-demo OWNER=<标签值> GITHUB_SECRET=<secret 名>
envsubst '$JOBSET_NAME $NS $LOCAL_QUEUE $DATA_PVC $DATA_BUCKET $RUN_NAME $ENV_TAR $GITHUB_SECRET $SLICES $MTC_STEPS $LOCAL_CKPT_PERIOD $PERSIST_CKPT_PERIOD $OWNER $PROJECT' \
  < runbook/scripts/07-jobset-mtc.yaml > js-mtc.yaml
  • 注意：启动命令和训练参数 env（模型 / 优化器 / 并行 / batch / 序列长度）都要按你们的启动脚本补——模板里训练参数只留了一行占位 # <你的训练参数>，公开配方可以参照 06a-dsv3-recipe.env；不补就提交，作业缺参数起不来。文件头标「未实测」，演练前要先在 2 片上验证。completions: 64 只对 4x8x8 成立，换拓扑要同时改 completions / parallelism / 注解 / ICI_FSDP_PARALLELISM。${OWNER} 没加引号就写在 flow map（{…}）里，所以未渲染的原文件不能当 YAML 解析，envsubst 之后才是合法 YAML。OWNER 只能是字母数字和 -_.。

07-fault-drill.sh

  • 干什么：对一个在跑、开了 MTC 的多片 JobSet 注入一种故障（pod-kill / slice-delete / vm-stop），后台用 kubectl get -w 录 workloads / slices / jobset / pods 的时间线。

  • 什么时候跑：07 §7.3；演练梯子见 07a §7a.1，各手段走哪条路见 §7a.2。

  • 前置条件：rb_env_check PROJECT REGION ZONE CLUSTER；作业 ≥ 2 片（目标取第 2 片）；已经存过至少一次本地检查点；空闲健康 cube ≥ 该作业的 cube 数；compute.instances.stop/start 权限；jq。

  • 参数：

    参数 含义 默认值 必填
    --jobset <name> 目标 JobSet — 是
    --mode pod-kill|slice-delete|vm-stop 故障类型 — 是
    --minutes N 时间线录制时长 45 否
    --execute 真注入并录制 关（= 只打印目标和命令） 真注入时是
    --restore-vm <node> vm-stop 之后把 VM 拉回来（配 --execute） — 否

  • 示例：

    bash
    ./07-fault-drill.sh --jobset <name> --mode slice-delete            # dry-run：看选中的目标
./07-fault-drill.sh --jobset <name> --mode slice-delete --execute
./07-fault-drill.sh --restore-vm <node> --execute

  • 注意：每运行一次就注入一次故障，上一次恢复完之前不要重跑。录制进程都套了 timeout，脚本被杀也不留孤儿。找不到目标时退出 1。vm-stop 路径标「未实测」（同类故障是手工打的）。另外两种模式文件头未标脚本本身的实测状态。

08· 日常运维

08-alert-sources.yaml

  • 干什么：08 §8.1 告警表每一条的「数据从哪来」清单（编号与告警表一致），写数据源类型（promql / logging / kubectl / gcloud）、查询、阈值。不是可以 apply 的 K8s 对象。
  • 什么时候跑：08 §8.1 搭监控时照着建策略。
  • 前置条件：无。
  • 参数：占位 $PROJECT $CLUSTER $ZONE $RESERVATION $BLOCK $NS，同 env.sh。
  • 示例：无（清单）。
  • 注意：依赖 tpu_ac_* / kueue_* 指标的条目标「需验证」，要先有能通过 :8443 鉴权的抓取配置。GKE 系统指标比 kubectl 慢 2–3 分钟。建成 Cloud Monitoring 策略的模板标「未实测」。

08-daily-check.sh

  • 干什么：每日容量报表，共 8 段：

    • cube 视图与配额上限；
    • sub-block 健康；
    • reservation 到期；
    • REPAIRING 实例；
    • 节点池状态；
    • Slice 过渡态；
    • pod 总数；
    • Kueue 日志。

    --probe 只跑前两段，给 cron 高频用。

  • 什么时候跑：08 §8.4 每天；部分告警的手动巡检（08 §8.1）。

  • 前置条件：rb_env_check PROJECT REGION ZONE CLUSTER RESERVATION；kubectl / gcloud 读权限；SPARE_CUBES（不填按 0 算并提示）。

  • 参数：

    参数 含义 默认值 必填
    --include-degraded 健康口径算上 DEGRADED 只算 HEALTHY 否
    --probe 只跑第 1–2 段（纯 kubectl），给 cron 每 5–10 min 用 关 否
    环境变量 SPARE_CUBES 备件 S 空 → 按 0 否

  • 示例：

    bash
    ./08-daily-check.sh                # 报表写 $STATE_DIR/daily-<UTC 时间>.txt，明细 TSV 写 $STATE_DIR/cubes-*.tsv
./08-daily-check.sh --probe        # cron 用

  • 注意：只读，可随时重跑。退出码：

    • 2（page）：健康 cube < CUBES_SLO；
    • 1（通知）：以下任一：
      • 健康 cube < CUBES_SLO+2；
      • 配额超过健康容量；
      • 有 Slice 非 ACTIVE ≥ 60 min；
      • pod 总数 > 100k；
      • reservation ≤ 30 天。

    高频告警别用完整版，它会因为「reservation ≤ 30 天」连续几周每次退出 1。8 段整体实测跑通过；第 1–2 段的隔离 cube 排除与 min(128) 封顶只过了 bash -n，未在集群上跑过。
