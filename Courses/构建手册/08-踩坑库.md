## 一、渲染：文件合法，浏览器里出事

| 症状 | 根因 | 修法 | 判据 |
|---|---|---|---|
| 一张图的两条曲线一根都没画，读者看到空坐标系，旁边还有文字框在解释它 | `path()` 收到 Python 点列表，写出 `d="[(1.0, 2.0), …]"`，是良构 XML | 基元接受结构化输入，断言 `d` 以 `M` 开头；去姐妹基元上查一遍 | **产物合法 ≠ 产物正确**。凡是接受 DSL 字符串的基元，要么接受结构化输入，要么当场校验 |
| 图的落点带只显示两行，另外四行跑到图下面 | 内联 SVG 里写了 `<u>`／`<b>`，HTML 解析器退出 SVG 模式，等于就地补了个 `</svg>` | 只用 `tspan`；全页兜底检查 | 读 SVG 源码查不出来，只有渲染才看得见 |
| 14 张图各有一段内容被擦掉 | 面板外框是白色实心矩形，盖住了上一块画出界的内容 | 面板外框改 `fill="none"`，一行救回 14 张 | **跟背景同色的填充不是「没填」，它照样是一次覆盖** |
| 出处行、落点带像「这句话没写完」 | 文字溢出不报错也不产生滚动条，只是被裁掉 | 一整行文字的基元都自带宽度断言 | —— |
| 渲染出来全课最小的字（11px，专题二最小的是 12.2px） | `cell()` 的说明文字写死 `size=9`，从默认参数绕过了字号地板 | 所有字号走同一个出口 | **护栏只能拦住经过它的路径** |
| 宽图左边被裁掉一截，溢出探针报 0 | 往左溢出不增大 scrollWidth | 量 `getBoundingClientRect().x < 0` | 两个方向都要量 |
| 直接打开 SVG 看，字是 16px 衬线体 | 图是给内联用的片段，单独打开没有页面 CSS | 从成品页面里截图 | 看到的是假的 |
| 循环动画首帧那颗小球没了，不一致度却跟正常片子同一档 | 小元素在整幅画的平均差异里几乎不占面积 | 复位时清干净再摆静态件；看拼接图 | **数字告诉你有问题，图告诉你是什么问题** |
| 三支已上线的动画每轮循环都跳一下 | 「构建全绿」只覆盖单帧的几何和文字，没覆盖时间维度 | `check-loop.py` 接进构建 | —— |
| 守卫连着报绿，其实一支片子都没查 | 通用版脚本默认目录是 cwd，而构建时 cwd 是 `tools/` | 显式传目录和基线；空集合不算通过 | —— |

## 二、事实与口径

| 症状 | 根因 | 修法 | 判据 |
|---|---|---|---|
| TPU v7 硬件门槛写成 1,922、TP 上限「17 路」 | 常说的 1.2 TB/s 是收发合计，而通信量算的是每卡发出，只能跟单向 0.6 TB/s 比 | 改为 3,845、约 8.4 路；台账写清拆分是推算 | 比较两个量之前先对口径 |
| 「7168 = 128 头 × 56」 | 把标准 MHA 的关系套到了 MLA 上 | 扒 config | **最危险的是听起来像常识的架构关系** |
| 运行手册把 DeepSeek-V4 写成 MLA；第一次更正只写了「不是 MLA，是共享 KV 的 MQA」 | 照搬 MLA 的解释；更正时只否定没写全 | 按 config 与专题三写全：CSA 与 HCA 交错堆叠 | **发现错误当场改源头；更正要写出正确的是什么** |
| 「KV 传输实测约 100 ms」 | 原始记录没有计时，是按带宽算的 | 改成「按带宽估算」，出处写清三段各多少字节 | 估算必须标估算 |
| GB300 头条「3.09 倍」「2.47 倍」 | 比的是总量（卡数不同）、挑的是最好的并发点（首字延迟 95 秒） | 头条改为同并发、每卡的 2.09 倍 | 同条件比较 |
| 「序列比维度短时 RNN 计算量更小」 | 不等式方向写反 | 解一遍不等式 | **比较类断言最容易在方向上翻车，而它读起来完全通顺** |
| KV 跨度算成 1152 倍 | 极值统计自动挑出了最不可比的一行（一个 7B 小模型） | 两端都限定 ≥100B 后是 846 倍 | min／max 不知道什么叫可比 |
| 两个年份写错（KDA、GDN） | 听起来合理，所以没被质疑 | 查 arXiv 号 | 越顺口越危险 |
| 撤回的说法在别处还活着（专题二 5 处） | 一个事实有 N 个落点，撤回时只改了一处 | grep 全仓库；`lint-retired` | 一个事实有 N 个落点，就会长出 N 个版本 |
| 讲义说「图里三行都是并发 512」 | 第一行其实是并发 256；讲义是手打的 | 对账轮逐条核 | 漂的一定是手打的那份 |

## 三、编号、链接、模板

| 症状 | 根因 | 修法 | 判据 |
|---|---|---|---|
| 分享专题三的链接，卡片标题、摘要、跳转全是专题二的 | 用 `replace("<title>TPU 与 GPU", …)` 改标题，真实标题多了「专题二 · 」，**没匹配上** | `_sub()` 断言替换真的发生了；`lint-meta` | **「改了」和「没改成」在代码里长得一模一样** |
| 6 处论文节号被改成了本课节号（DeepSeek-V3 的 sec. 2.1 变成 §4.1……） | 两次整体重编号用 `§(\d+)\.` 机械 +1，而「§X.Y」有两种含义 | 论文节号一律写 `sec. X.Y`，本课节号才用 `§` | **最毒的是污染后的号码恰好都落在真实存在的小节上，跨节指针体检全绿** |
| 正文「技术报告 §2.1.2」被自动链到本讲 §2.1 | `anchorize` 不认识「技术报告」这个引文词 | 引文词表加「技术报告／报告／README／原文」 | 比死链更难发现的是指向一个真实存在、但不相干的地方 |
| 图里写着「§零 那张…」，而 L200 根本没有 §零 | 共用图里写了本课节号，两档编号不同 | `save()` 断言共用图不许有本课节号 | 共用资产里放名字，不放指针 |
| 改了图，页面里还是旧图 | 只跑了页面脚本，没跑图脚本 | 改节号 ＝ build 脚本 ＋ 全部 fig 脚本一起改，并重跑 | —— |
| 删掉了图的出处，页面里还挂着旧出处 | 上一次留下的 `.src.html` 还躺在目录里 | `save()` 没有出处时主动删掉旧片段 | 产物目录里的陈旧文件不会报错，只会安静地继续生效 |
| 一张图写「会出现两次」，后文数到了第四次 | 先画的图预见不到后来加的两处 | 要么别写计数，要么让脚本替你数（`lint-xref`） | 写死「一共 N 次」的地方都是会过期的断言 |

## 四、构建与工具链

| 症状 | 根因 | 修法 | 判据 |
|---|---|---|---|
| lint 报了几个月的绿 | 它只检查了五份讲义里的一份 | 未登记的讲义主动点名；打印检查条数 | 「0 条对不上」和「0 条被检查」长得一样 |
| 死指针打印出来了，构建照样绿 | `main()` 没有 return，退出码恒为 0 | 返回非 0 | 打印出错误 ≠ 报告了失败 |
| 修了一处误报，构建照样红，报错换了措辞 | 兜底检查把库函数的正则抄了一份 | 兜底复用函数 | 复刻的第二份只会跟着一起被信任 |
| 讲义地板表合计写着 83′，计划早改成了 77′，页面上写「剩 -84 分钟」 | 合计和缓冲写死在字符串里 | 从节标题现算；超时直说超多少 | 写死的数字都会过期 |
| 两套时长各自求和都对，互相对不上 | 同一个量有两处写法 | 断言两处之间相等 | 求和自洽证明不了任何事 |
| 精度边界断言 `> 30` 没拦住错值 | 33.7 和 30.7 都能通过 | `abs(x - 30.7) < 0.05` | 断言要窄 |
| 注释指向一个已经不存在的脚本 | 重构后没回头改注释 | —— | 注释里的路径也是一种会过期的断言 |

## 五、流程与协作

| 症状 | 根因 | 修法 | 判据 |
|---|---|---|---|
| 照审稿意见修了，结果修错了 | 认了它给的根因（或算式） | 认现象，根因自己查 | 算术对，模型错 |
| 「讲义缺了一段」连续几轮误报 | 关键词扫描，其实只是措辞不同 | 按顺序读 | 真缺口是读出来的 |
| 一次提交误带了另一个人正在改的另一讲 | 共享仓库里 `git add -A` | 只 add 自己改的文件 | —— |
| 隔一夜，「还剩几轮」谁都答不出 | 口头约定的轮数没落盘 | 当场写进追踪文件 | —— |
| 提交后空转了 9 小时 | 说了「继续做」，但没有任何机制会把人叫回来 | 挂定时唤醒或监控 | 承诺不是机制 |
| 第一版第一课整体废弃（3.4 万字 ＋ 54 页幻灯片） | 先打磨大纲和渲染环境，成品最后仓促补；主线被现成素材带偏 | 尽早拿能看的成品撞方向 | 成品比大纲便宜；主线由问题定，不由素材定 |
| 一个开场数字让台下从头到尾只想着显存 | 开场钩子没落在主线上 | 换成能被指认的问题或冷开场 | —— |
