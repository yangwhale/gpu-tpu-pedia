# 十份外部评审 · 专题四《反向与优化器》

2026-09-18 夜，按现场要求「用 5 个麻瓜去学习课程，再用 5 个专家，分别提修改意见」
派出的评审。每个 agent 只带一副眼镜、互不通气、只读不改。

## ⛔ 为什么这些要落在磁盘上

**跨 turn 的交接，凭据必须落在磁盘上，不能留在上下文里。**
T 轮打磨由 cron 触发，每一轮都是一个**全新的 turn** —— 它看不到派活时的那段对话。
评审只活在对话里 ＝ 等于没做。

## 怎么用

**先读 [`_CONVERGENT.md`](_CONVERGENT.md)** —— 被 2 位以上互不通气的评审各自撞到的问题。
同一处被多副眼镜分别看见，可信度远高于任何单份报告。A 级四条已独立 grep 复核。

然后按需翻单份原文。**它们是原始输出，未经加工。**

## ⭐ 两条使用纪律

**① 认它报的现象，不认它给的根因。**
实测多轮：事实性发现基本成立，**因果解释常常是错的**。
现象对（内容确实没了），根因错（不是它说的那个原因），而两种根因的修法完全不同。

**② 能 grep 的一律 grep，不要照着报告改。**
已经这么抓到过：报告说「§4.1 是空节」→ `grep` 出正文 81 字符、0 图 0 表，**成立**；
报告说「loss 计算缺失」→ `负对数`/`−log`/`对数似然`/`困惑度` 全文 **0 次**，**成立**。
也抓到过反例，所以两边都要验。

## ⚠️ 文件名的来历（别当成派活时的角色名）

这些名字是**按每份自己的标题起的**，不是当初派活时的眼镜名。

我试过用关键词把 agent 日志映射回原来的眼镜名 —— **四份里错了三份**：
「KV cache」「梯度消失」这类词在别的专题里一样高频，结果把**专题三**的评审
和一份 FlashAttention 论文核查贴上了专题四的名字。

改成两道关卡：① 必须命中专题四独有的指纹（`topic04-build` / `106.75` /
`fig-per-byte` / `recompute_modules` / `5,734` …）；② 按它自己的首行标题命名。
`X-` 前缀 ＝ 这一批里的额外视角，不属于最初那十副眼镜的编号。

> ⭐ 教训：**匹配到一个文件 ≠ 匹配对了文件。** 启发式给出的名字看起来总是合理的 ——
> 跟「空结果不等于没有」是同一个家族的反面：**有结果不等于是对的结果。**
