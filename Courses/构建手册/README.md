# 课程构建手册

> 这个目录把「怎么做出一门能上台讲的技术课」的全部做法写下来：
> 理念、架构、质量保证、绘图、讲义、评审迭代、检查器、踩过的坑、开工清单，
> 外加能直接拿来用的模板和脚本。
>
> 它不是凭空设计出来的。这里的每一条规矩，背后都有一次真实的翻车 ——
> 一张图的曲线没画出来而所有检查都是绿的、一个硬件门槛算错了一倍、
> 一份讲义让讲师「指右边那列的 1.23 TiB」而那个数其实在倒数第二列。
> 这些事故和它们留下的判据，散落在 `tools/` 下几百个脚本的注释、
> `DESIGN-NOTES.md`、`reviews/` 和提交历史里。这里把它们收拢成一处。
>
> 覆盖范围：2026-08-21 开工到 2026-09-25，专题一到五、二外传、八，约一千个提交。

## 一页纸：如果只能记住十条

1. **先有问题，再有名词。** 每一节只立一个问题，后面每个概念都是那个问题的下一步。
   名词一上来就是一堵墙。（→ [01 理念](01-理念.md)）
2. **一讲只立一句话，每一节接着上一节：前面没管到什么，这一节就补什么。**
   讲成「接下来介绍另一种 X」，主线就断了；硬凑的因果也会断 —— 每一环都要站得住。（→ [03 四个保证 · 故事性](03-四个保证.md#三故事性一讲是一个故事不是一份目录)）
3. **HTML 是唯一真源。** md 只是大纲，不做 md→HTML 转换，不留两份。（→ [02 架构](02-架构.md)）
4. **不确定就查，绝不编。** 数字在脚本里现算并加断言，能对上一个外部锚点才算数；
   推出来的标「本课推导」，估算标「估算」，每个说法进出处台账。（→ [03 · 准确](03-四个保证.md#二准确不确定就查绝不编)）
5. **图是用来画原理的，不是写字的板子。** 把图里的字全删掉，剩下的形状还能让人猜出在讲什么。
   只有「时间」或「第三维」才值得做成动画。（→ [04 绘图](04-绘图.md)）
6. **产物合法 ≠ 产物正确。** SVG 是良构 XML、构建全绿，浏览器里那张图照样可以是空的。
   几何类的判断必须渲染成 PNG 用眼睛看。（→ [04 · 目检](04-绘图.md#五目检)）
7. **讲义和课件是两份东西，但要互相对账。** 讲义里报的数、指的图、说的小节，
   课件里必须存在；讲义照念一遍要多少分钟，每次构建现数。（→ [05 讲义](05-讲义.md)）
8. **一个审稿 agent 只戴一副眼镜。** 外行、逐图、文字、讲师、分领域专家、对抗式、台账抽查 ——
   「全面审一遍」只会得到四平八稳、没法动手的摘要。（→ [06 评审与迭代](06-评审与迭代.md)）
9. **认现象，不认根因。** 审稿报来的问题先核实再动手；它说的现象常常是真的，给的原因常常是错的。
   （→ [06 · 核实](06-评审与迭代.md#二核实之后才动手)）
10. **修基元不修实例，判据做成断言。** 同一个毛病出现在八张图上，病根在共用库里。
    写在注释里的规矩只在那一个文件生效，写成断言才会一直生效。（→ [07 检查器](07-检查器与断言.md)）

## 三十秒上手

```bash
cd Courses/tools
bash build-all.sh                     # 全量构建：所有图 → 所有页面 → 全部体检
python3 topic05-fig-zero.py           # 只重画某一组图
python3 topic05-build.py              # 只重建某一讲课件（会跑查重、锚点、目录）
python3 topic05-build-lecture.py      # 只重建讲义（会跟课件对账、现数时长）
python3 ../构建手册/脚本/course-metrics.py ../WebPages/topic-05.html   # 派审稿前先体检
cd .. && python3 构建手册/脚本/shot-figs.py WebPages/topic-05.html       # 每张图截图，目检
```

环境前提：Python 3、`playwright`（含 chromium）、`pillow`；做动画还要 Manim 和 ffmpeg。见 [09 · 阶段 −1](09-新专题开工清单.md#阶段-1--环境第一次在这台机器上干活时)。

想看一份「完整走过全套流程」的样板：专题五。
课件 [`WebPages/topic-05.html`](../WebPages/topic-05.html)，
讲义 [`WebPages/topic-05-lecture.html`](../WebPages/topic-05-lecture.html)，
源码 `tools/topic05-*.py`，
三十轮迭代的逐轮记录摘要见 [06 评审与迭代](06-评审与迭代.md#三两阶段迭代协议)。

## 术语

| 词 | 意思 |
|---|---|
| 课件 | `topic-0N.html`，给人自学和投屏的那一页 |
| 讲义 | `topic-0N-lecture.html`，讲师上台照着讲的授课稿 |
| L200 ／ L300 | 课件的两档体裁：L300 档案版（齐全），L200 故事版（从 L300 蒸馏） |
| R1–R10 ／ L1–L20 | 专题五两个迭代阶段的**轮次编号**：R 是评审轮，L 是试讲轮。这个 L 跟 L200／L300 没有关系，沿用了当时的叫法 |
| 基元 | `tools/topic03_draw.py` 里的绘图函数（`header`、`panel`、`band`……），所有图共用 |
| 落点带 | 图最下面那条带左侧竖色条的框：一行「换来了什么」、一行「代价是什么」 |
| 读图钥匙 | 「这张图怎么读」那一句（例：「条长 ＝ 每张卡要发出多少份数据」），放在图的副标题里 |
| 出处与口径 | 图下面默认收起的折叠块：数字来源、推导、口径、免责 |
| 地板 | 把讲稿一字不落念完、再加切屏的时间，一句现场发挥都没有。每次构建现数 |
| 炼钢 ／ 出率 | 专门做减法的轮次（删元评论、合并铺垫、删重复）／ 一轮能削掉多少比例的字 |
| 眼镜 | 审稿 agent 的单一视角：外行、逐图、文字、讲师、专家…… |
| og 信息 | 页面 `<head>` 里给分享卡片用的标题、描述、图片（Open Graph） |

## 这份手册自己的维护规矩

- **新规矩要带着事故来。** 每加一条，写清是哪次翻车逼出来的；没有事故撑着的规矩，下一个人不会信，也不知道边界在哪。
- **能做成断言的就别只写在这里。** 这里是给人读的索引和理由，真正拦住错误的是 `tools/` 里的断言和 lint。
- **推翻旧规矩时，旧的和推翻理由一起留着。** 否则过几个月会绕回同一个已经否决过的做法。`DESIGN-NOTES.md` 是这条规矩的原型。
- 本目录在公开仓库里：不放内部链接，不放个人信息。
