[friendly] 好，第三节，第二刀：切权重。

[curiosity] 上一节最后说，每张卡分到的 token 太少，FSDP 就会被搬权重拖住。那「少」到底是多少？我们先问一个朴素的问题：一份东西搬过来一次，能被用几回？

[friendly] 想象一间做门的工坊。师傅干一件活要两秒，小工送一趟东西要五秒，师傅手再快，也得等着。每张卡就是师傅，网络就是跑腿的小工。小工搬两样东西：一样是工具，电刨、模具，这就是权重；另一样是门板，一块块正在加工的门，一道工序做完递给下一道，这就是激活，每个字一块。我们要看的是：小工每送来一个字节，够师傅忙多久。

[thinking] 这把尺子的一头是硬件：师傅的手速，除以小工的腿速。TPU v7 一颗芯片，每秒能算两千三百多万亿次；网络每秒能给它收进来大约六千亿字节。一除，是三千八百多。

[focus] 注意，这里说的是「收进来」。FSDP 要算这一层，得先把别人手里那几段权重收进来，收不齐就没法算。环上每张卡收多少就发多少，两个方向各六千亿，常听到的一万二千亿，是收发加在一起。所以意思是：每收进来一个字节，得有三千八百多次活等着，师傅才不用干等。

[seriously] 还有一件事要分清：这里卡的是网络，不是显存。权重收进来以后，还要从显存里读出来算，可显存每秒能读七万三千多亿字节，比网络快十二倍多，它对应的那条线只有三百一十多，就是图最下面那条灰色虚线，远不是瓶颈。真正让师傅干等的，是网络这条腿。

[focus] 请看这张图，先看那条红色横虚线。横轴是每张卡这一步分到多少个 token，竖轴是每收进来一个字节换来多少次计算。红线就是那个三千八百多，线下涂红的那一片，就是师傅在等小工。

[realization] 蓝色的斜线是 FSDP。它让小工搬的是工具，也就是权重，就是上一节每层都要抄齐拼回的那间书房。一件工具送到，这个师傅手上的每块门板都要拿它过一遍，门板越多，同一趟送货就够师傅忙越久。这笔账算出来特别干净：一个参数两个字节，每个字拿它做一次乘加，正好两次运算，一约就掉。所以每收进来一个字节换来的计算，正好等于每张卡分到的 token 数。每张卡一步分不到三千八百多个 token，FSDP 就被拖住了。这是我们按最乐观的情况自己推的。

[casually] 三千八百多个 token 是什么概念？V3 预训练一条样本是 4K 个 token，差不多就是每颗芯片一条。再少，搬权重的时间就露出来了。

[seriously] 分母还有一个坑：网络这条腿，不能抄规格表。规格表上写的是物理带宽，可真拼一次权重，路上有各种损耗。该用的是你在自己网络上实测出来的数：真跑一次 AllGather，GPU 上就是跑 nccl-tests，看它报的 busbw，它已经扣掉了算法本身的账，就是每张卡每秒实际收进来多少字节。看红线上面那条细虚线：假如实测只跑到规格的七成，门槛就从三千八百多抬到五千五左右。要是 FSDP 只占了几根链路，还跟别的并行抢线，门槛还得往上走。

[excitement] batch 再小，就不能再搬权重了。第二刀的办法是：直接把权重矩阵切开，这叫张量并行，TP。

[focus] 请看这张图。一个 MLP 有两块权重，先放大的叫 UP，再缩回来的叫 DOWN。英伟达的 Megatron 用了一个巧思：第一块权重按输出维切一刀，第二块按输入维切一刀。两个人各拿一半，蓝的只跟蓝的乘，橙的只跟橙的乘，中间谁也不用问谁。通信被整个推到了出口，只在最后做一次 AllReduce，加一下。用工坊的话说：两个师傅合干同一批门板，各做一半工序，做完得把门板凑到一起合成，这一凑，就是那次 AllReduce。

[realization] 这里有两个容易绕晕的地方。第一，每张卡两块都有份：卡 0 拿 UP 的一半，也拿 DOWN 的一半，不是一张卡管 UP、另一张管 DOWN，那是后面要讲的按层切。UP 和 DOWN 之间不说话，DOWN 算完才加一次，传的是激活。第二，横着切还是竖着切，只是画法。我们把权重画成「输入维乘输出维」，第一刀切输出维，看着是竖的；PyTorch 把权重存成「输出维乘输入维」，同一刀在它那儿就是横的。所以别记横竖，记住：第一块切输出维，第二块切输入维。

[curiosity] 为什么非得先切输出维？反过来试试。请看这张图。如果先切输入维，每张卡手里拿的是同一个数的一部分，加起来才是它：卡 0 是 2，卡 1 是负 3，真值是负 1。可 GeLU 不是一条直线：先加再过 GeLU，得负零点一五九；各过各的再加，得一点九五零，连符号都反了。所以只能先加，平白多一次通信。先切输出维，每个数完整地落在一张卡上，GeLU 各算各的。

[seriously] 数一下一层要通信几次。前向，MLP 出口一次，attention 按头切，出口也一次。反向倒过来：输入 X 是两张卡共用的，两边各算出 X 的一半梯度，入口处又得加一次。一层前向两次、反向两次，每一层都有，而且要等算完才能送，藏不进计算里。所以 TP 只能待在最快的那一片互联里，GPU 上一般不出一台机器。

[realization] 回到刚才那张图，看两条橙色的平线。TP 的线为什么是平的？因为 TP 让小工递的不是工具，是门板，也就是算到一半的激活。每个字一块门板，字多一倍，要递的多一倍，活也多一倍，一除就约掉了。所以 TP 跟 batch 无关，只看两件事：每个字在模型里用多长一串数表示，这叫隐藏维，就是门板的尺寸，板子越大，每递一趟要干的活越多，线越高；再就是切几份，切得越碎，每人的活越少，要递的却没少，线就往下掉。V3 切 8 份是那条实线，按最乐观的红线刚好贴线，实际已在线下；切 32 份是下面那条虚线。

[suggestion] 所以两把刀各管一边：一次喂进去的那一批数据叫 batch，batch 小的时候多用 TP，batch 大的时候多用 FSDP。图上就是：左边蓝线还没爬上来，靠橙线顶着；右边蓝线爬过去了，交给 FSDP。

[contemplative] 那 FSDP 和 TP 能不能一起用？能，而且大模型训练里常常一起用。诀窍是两刀切在不同的维上。请看这张图，8 张卡排成两行四列。TP 先按输出维把权重切成四条，一列一条；FSDP 再把每一条上下劈成两半。每张卡只存八分之一。一行四张卡是一组 TP，看的是同一份数据；一列两张卡是一组 FSDP，数据各不相同。

[thinking] 算一层分三步。第一步，列里 AllGather：同一列的两张卡把上下两半拼齐。注意，拼回来的只是自己那一条，整个矩阵的四分之一，不是整个矩阵。第二步，各算各的，一行四张卡拿着同一份数据，各算四分之一。第三步，行里 AllReduce，把部分和加起来，传的是激活。

[excitement] 最妙的是账。只用 FSDP 的时候，每张卡拼一整层，只给自己那些 token 用。两个一起用时，每张卡只拼四分之一条，却是给这一行四张卡的全部 token 用。所以 FSDP 的门槛按一行的 token 数来算，摊到每张卡只要九百六十个左右。这才是「batch 小多用 TP」的真正意思：TP 把一行的 token，借给了 FSDP。代价是 TP 那根轴每层都要对账，得占最快的线。

[focus] 可 TP 出不了最快的那一片。要横跨很多台机器、走慢线，又不想每层搬权重，就换个方向切。请看这张图，数红点。TP 是切宽：每一层切成四条，所以每一层都得对账，左边一层一个红点。PP 是切深：前两层给卡 0，再两层给卡 1，只在段和段的交界递一次门板，用的是第一节那个一对一收发，右边只有三个红点，所以敢走慢线。

[thinking] 可是朴素地切深，得到的是四张卡的显存、一张卡的速度：同一时刻只有一段在干活。所以要把一批数据切成几份，轮着灌进去。还是那间门厂，换成流水线：刨光、开孔、上漆三道工序各守一个工位，门板一摞一摞往下传。第一摞刚进刨光时，后两个工位只能干等。

[focus] 请看这段动画。工位上干等的那段，就是这些灰色的格子，叫气泡：开头要等后面几段灌满，结尾要等前面排空。一批数据切得越碎，气泡越小，你看同样多的活切成 8 份，灰色短了一半。可也不是越碎越好，每一份太小，卡就吃不饱。

[curiosity] 这一刀留下的问题，要从一个反常的例子说起：V3 训练的时候，一点 TP 都没用。报告说，是显存抠得够细，用不着。再看它的参数都在哪：几乎全在一种叫专家的窄网络里。切一个很窄的矩阵，每人分到的活更少，要递的门板一块不少，跟刚才那条平线往下掉是同一个道理。那就别劈矩阵，按专家切。这就是第三刀。
