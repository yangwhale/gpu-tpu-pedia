# 05 · 讲义（授课稿）

> 课件给眼睛，讲义给嘴。讲义是讲师上台前准备、上台时照着走的那份东西。
> 这一篇讲讲义的块结构、时间怎么管、它跟课件怎么对账、写作原则，以及讲义和课件怎么互相回填。
> 最规整的样板是专题五：`tools/topic05-build-lecture.py` → `WebPages/topic-05-lecture.html`。

---

## 一、块结构

每一节在脚本里是一个五元组：`(标题含分钟, 课件锚点, 主图 id, 正文, 别讲什么)`，由同一个函数渲染。
页首有一张图例（专题五列了 🎯、🗣 台词、🖥 屏幕、⚠️ 四种）。各专题讲义用过的块：

| 块 | 样子 | 写什么 | 规则 |
|---|---|---|---|
| 🎯 本节只留一句 | 每节第一行 | 讲完后台下脑子里该剩的那一句 | 通常一句；个别节写「这一节留两样」 |
| **say**（台词） | 黄底 `<p class="say">` | 要说出口的话 | 默认每个字都出口；**一块不超过 200 汉字**（一块台词对应一个动作）；舞台提示不许写进来 |
| **say q** | 灰底斜体 | 当事人原话（论文作者、事故现场） | 必须念。专题三用过，专题五没用 |
| **board**（屏幕） | `🖥 屏幕` | 去课件哪儿、指哪一格、放哪段动画 | 只写动作不写台词；指的东西必须在课件里存在（lint 对账） |
| 💬 互动 | | 问台下什么、等到什么答案再往下讲 | 写成「问什么 ＋ 等什么答案」；可以写「举手就行，不点人答」 |
| ⚠️ 最容易跑偏的地方 | 每节末尾 | ⛔ 不讲什么、⚠️ 容易说错的口径、「被追问时」的备答 | 备答要跟课件一致；答不上的写「这个我不确定」 |
| 本节主屏 | 节尾 | 链到课件对应位置 | 无图的节写「本节无图（故意的）」 |

一个真实片段（专题五第二节）：

```html
<p class="board"><b>🖥 屏幕</b>：<code>anim-fsdp</code>，<b>先闭嘴等它转完一圈</b>（14 秒）。</p>
<p class="say">「看计数器：前向每层借一次，反向每层再借一次、再分一次梯度，三层走完是九次。…」</p>
```

### 两类最容易写错的

- **舞台提示漏进台词。** 专题四曾把「⛔ 这里不要再展开讲二阶导」写在了 say 块里 —— 讲师照念就出事。
  现在构建断言拿黑名单（「不要在这里」「别念」「台上不用念」「先只放」……）扫所有台词块。
- **台词写进 board。** board 引号里带换行、或者引号里有 40 个汉字以上又没标明是要念的（「说一句／说／念／原话／台词」这类词），会被 `topic02-lint-cues.py` 拦下。

### 舞台指示要到了台上还能执行

专题二讲义有一张「舞台指示词表」，判据是：**到了台上会失效的指令，等于没写。**

| 写法 | 台上怎么做 |
|---|---|
| 停死 | 心里默数两拍 |
| 语速放慢 | 拆成两个短句说 |
| 指着 | 指完立刻念出那一格上的字 |

## 二、时间管理：计划和地板

讲义页上有两张表：

- **计划表**：每节给几分钟、能不能砍、这一节必须保住什么。写在脚本的 `PLAN` 里。
- **地板表**：把讲稿一字不落念完、再加切屏的时间，**一句现场发挥都没有**。每次构建从成品 HTML 现数：

```
地板（分钟）＝ 台词汉字数 ÷ 200 ＋ 切屏（board）次数 × 0.25
```

地板不含等动画转完一圈的时间，也不含互动。页面上要写明这一点。

### 构建断言

| 断言 | 起因 |
|---|---|
| 节数 ＝ 章节条数 ＝ 计划表条数 | —— |
| **节标题里的分钟 ＝ 计划表** | 专题四有两套时长，各自求和都自洽，互相对不上；超时警报拿作废的那套去比，第一节被虚报超时，真超时的节一声不吭 |
| 分项之和 ＝ 合计 | 专题四时间表各行加起来 77，合计写着 80 |
| 地板超过计划 → 告警（不拦构建） | 讲稿是给准备用的全量，超了要知道，但不一定要砍 |
| 写了「可压到 N」的节，N ≥ 地板 | 专题五 L19：五节写的「可压到」全都比照稿念完还短，压不到的承诺比不写更坑讲师 |
| 台词数字密度：每百汉字超过 12 个数字就点名（只报告；**目前只在专题四的讲义脚本里**） | 判据是「这个数是内容还是证据」：内容要报，证据说「有人量过」就够 |

⭐ 一张「分项 ＋ 合计」的表，永远要断言加得起来。**同一个量有两处写法时，「求和自洽」证明不了任何事** —— 要断的是两处之间。

## 三、讲义和课件对账

讲义是手打的，课件是算出来的，漂的一定是讲义。所以讲义构建时读成品课件，逐项对：

| 对什么 | 怎么对 | 在哪 |
|---|---|---|
| board 里的「滚到 X」「停在 X」 | X（引号里的文字、图 id、小节号）必须在课件里存在 | `topic02-lint-cues.py`（没登记进 `PAIRS` 的讲义会被点名） |
| 讲稿里报的 TiB／GiB 大数 | 课件页面上必须也有这个数 | 讲义脚本断言 |
| 讲稿指的 `anim-*` 动画 id | 必须存在于课件（cues 只对 `fig-` 开头的 id） | 讲义脚本断言 |
| 收尾语气（「数字会过期」「念完就停」） | 只许出现在最后一节 | 讲义脚本断言。起因：专题四的四条判据原来放在倒数第二节，等于谢了两次幕 |
| 课件主线小节 | 讲义里都要有讲稿 | `topic02-lint-coverage.py`（⚠️ 目前只查专题二 L200，只报告） |

cues 这条 lint 自己也翻过车：曾经只检查了五份讲义里的一份，251 条提示从没对过账；
`main()` 没有 return，退出码恒为 0。判据：**「0 条对不上」和「0 条被检查」在输出里长得一模一样。**

对账之外，还有两类只有人能查的：

- **说法一致**：讲义说「最后一行只换一件事：decode 换成 DEP8」，而课件那张图明写 decode 卡也从 4 张变成了 8 张 —— 数字都存在，意思对不上（专题五 L19 抓到）。
- **指向的列、格对不对**：讲义让讲师「指右边那列的 1.23 TiB」，而 1.23 TiB 在倒数第二列。

这两类靠 [06](06-评审与迭代.md) 里的「讲义↔课件对账」一轮来抓。

## 四、写作原则

### 先直觉，后机制

- 专题四第一节不从链式法则讲起，先让台下感受「笨办法有多笨」，再用淋浴旋钮讲「兑换率」。
- 每个名词出现之前，先让它的理由出现（[01 · 二](01-理念.md#二讲课的顺序先有问题再有答案)）。
- 比值用「时间」当分母讲，不用「配料」。
- 一句话里出现两个以上抽象名词就改成有画面的人话。

### 接力线：首尾是接口

每节最后一句「这一节留下的问题」就是下一节的开场，**时间再紧也要念 —— 压中间不压首尾**。
专题三讲义的写法更硬：「讲稿里每一节的第一句和最后一句都是接口，不许改。」

### 暗线和那一句话

页首「🧵 上台之前」列两三条暗线，外加「如果只能让台下带走一句话」。每节讲到时点名一次暗线。

### 动画和投屏

- **放无声动画时，先闭嘴看一遍，等它转完一圈再开口。** 边放边讲，台下眼睛和耳朵会打架。专题五讲义里有 12 处「闭嘴」提示。
- **课件右上角的「只看图」开关，投屏前打开**，否则台下会低头读字不听你讲。
  例外：需要框里那句话的那一屏，先关掉再切过去（开关会把它收起来）。
- 整张图投到 720p 最小字只剩几像素的，一次只放大一格讲（投屏读数见 [04 · 三](04-绘图.md#三视觉规范)）。

### 互动放哪

专题五五处互动：开场猜卡数、切数据「你先削哪块」、切序列之字形、切工作举手、摆到机器上投票。
这五处有个共同点（归纳，不是既有规矩）：都放在**一个结论即将揭晓之前**，让台下先押一个答案，而不是讲完之后问「大家有没有问题」。

### 两种稿分开

专题二外传把讲稿和**逐字稿**分开：讲稿（say）服务准备，逐字稿（折叠的 `details.oral`）服务临场。
判据：同一份内容服务两个时刻，就该是两份。

⛔ **没写完的节不许编逐字稿**（专题三 L300 讲义、专题八讲义都这么写）：「编一段，现场你会照着念。」

### 口径

一个数是内容才报，是证据就说「有人量过」；查来的和推来的分开说。

## 五、讲义和课件互相回填

- **试讲 → 两边一起改。** 试讲现场被问出来的问题，讲稿里主动讲掉（标「试讲现场被问出来」），同样的内容也写进课件。
  专题五第二遍（L10–L17）专门做这件事：讲义里好用的比方和推导，搬回课件，让自学的人也拿得到。
- **双向对账**。专题四课件注明过「课件有最准那一步，讲稿没有；讲稿有三句，课件没有。已双向补齐」。
- **同一个话题只在一处讲。** 同一张图两边各指各的，要定下来谁讲。
- **方向**：讲不通时先改讲义；讲义是课件的下游，讲之前先翻课件那一节，不要只照着讲义念。
- **串讲后砍料**：全篇串讲一遍，节奏拖的地方（专题五 7.5 节）在讲义里标「台上跳过」，课件保留给自学。

## 六、「把讲义丢给 AI」那一格

每讲课件开头有一格：把讲义整份丢给一个 AI，让它当助教给你讲一遍。
这一格的文字只有一个正本（`tools/course_ai_trainer.py`），各页面由构建时生成；
手写维护的页面由 `lint-ai-trainer.py` 逐字比对，防止粘贴出去的副本不跟着源头改。

## 七、讲义规范是怎么一步步长出来的

| 阶段 | 加了什么 |
|---|---|
| 专题二 L200 | 讲次表是侧栏和排期的唯一来源；舞台指示词表；❓ 备答。时间靠手填，没有地板 |
| 专题二外传 | 逐字稿层；「主线 ＝ 17′」硬断言 |
| 专题三主线 | 五元组结构；board 接入 cues 对账；**地板第一次从 HTML 现数**（起因：手写的字数已经偏了 600 多字） |
| 专题四 | 分项＝合计、节标题＝计划、大数对账、200 字上限、舞台提示泄漏、谢幕位置、数字密度；开场热身连线题（数据只从模型表取，断言排列里没有送分的不动点） |
| 专题五 | 把专题四的大部分断言压成约 80 行带过来；新增 `anim-*` 对账、「可压到 ≥ 地板」、💬 互动块、「先闭嘴」动画提示。**没带过来的两条**：台词数字密度、一块台词不许跨多个面板 —— 新开一讲时从 `topic04-build-lecture.py` 补回 |

新开一讲的讲义，从专题五的脚本复制起步，复制后要改的地方和两个硬坑见 [09 · 阶段 3](09-新专题开工清单.md#阶段-3--讲义)。
