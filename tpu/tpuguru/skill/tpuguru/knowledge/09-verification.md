# 怎么验「改了之后还是同一个模型」

## ❌ 三个不成立的判据

**比 loss**：归约成一个标量、只打三位小数。能证伪，**不能证实**。
**尤其前十步测不出分片错误** —— 那时模型在学词频先验，
那部分信息来自 embedding 与输出投影，跟 MoE 算 3 个还是 192 个专家几乎无关。
（文献佐证：模型在相同阶段学到相同的语言泛化，与架构、初始化、数据无关；
且全局 loss 由高频 token 主导。）

**比逐位相同**：浮点加法不满足结合律，换分块就换累加顺序。
**它失败不代表实现错了，成功也只是运气。**

**比中间层张量指纹**：在手动分片区域内部算的归约是本卡局部值，
两次跑天然对不上 —— **那是采样噪声，不是数值差异**。

## ✅ 正确判据：logits 上的 KL 散度

比的是**模型对下一个 token 的概率分布**是否等价。

**实现三个坑**：
1. **归一化必须在图里做**（`log_softmax`），让编译器处理跨分片的 max/sum。
   直接把分片存盘再离线归一化是错的
2. 分片按序一一对应，离线逐片求和 = 整词表上的精确 KL
3. **同一个 .py 会被以两条路径导入成两个模块对象**，打补丁要两个都打，
   否则静默不生效（打印了「已安装」，一条数据都没有）

**阈值**：

| KL（nats/token） | 结论 |
|---|---|
| `0` ~ `1e-7` | 等价 |
| `1e-7` ~ `1e-4` | 数值噪声级 |
| `1e-4` ~ `1e-2` | 可疑 |
| `> 1e-2` | 算错了 |

**必须同时报对照尺度**（当前分布相对均匀分布的 KL），否则数字没有意义。

## ★ 最容易漏的一步：证明被测代码路径真的被走到

实测教训：第一轮用 BF16 测 KL，得到漂亮的 `0`，
**但那个配置根本没走到要测的那段代码**（前置条件不满足，两条分支都跳过了）。
换成 FP8 重测，KL 立刻从 0 变成 1e-3。

**把被测路径上的每一个前置条件列出来，逐个从日志确认为真。**
光确认「我传了那个开关」不够 —— 它可能被另一个条件否决。

## 其他完整性检查

- 证明开关真生效：从两次日志抓被测参数对一眼，**性能差异本身也是旁证**
- 证明两份输出不是同一个文件：在**产出端**校验哈希，不是拷贝之后
- 证明输入是同一份：确认合成数据是固定种子（很多框架生成一次后每步复用同一批）
