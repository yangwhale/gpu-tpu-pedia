## 2026-08-21 · 起手点应该是「大模型是什么」，不是「加速器是什么」

### 原始想法

1. 首先要讲大模型是什么，**从 Transformer 讲起**
2. 让大家理解了大模型之后，才会知道**为什么大模型需要 GPU、需要 TPU** ——
   Attention 需要什么样的算力、MLP 需要什么样的算力、训练和推理有什么区别，
   这些**全都需要模型的知识**才能讲清楚
3. 人们也要知道**模型的智商是从哪来的** ——
   Attention 决定「自己关注自己」，MLP 里存的是**事实**

### 这推翻了什么

v0.1 大纲的第 0 部分是「为什么需要另一种加速器」，从矩阵乘和脉动阵列讲起。
**这个起手点错了。**

错在哪：它默认读者已经接受「大模型就是要算很多矩阵乘」这个前提，
然后去讲怎么算得快。但读者并不知道**为什么**要算这些矩阵乘、
为什么是这个形状、为什么这一部分卡带宽而另一部分卡算力。
于是硬件部分只能靠背 —— 而背下来的东西没法迁移到新硬件上。

正确的顺序是：**先有模型，才有对硬件的需求，才有硬件的样子。**

### 为什么这条特别重要（我的理解）

这不只是「顺序好看一点」的问题，它决定了后面性能工程那部分能不能讲透。

Transformer 里两大块的计算特征是**根本不同**的：

| | Attention | MLP / FFN |
|---|---|---|
| 干什么 | token 之间**路由信息** —— 决定"这个词该看哪些词" | 存放并检索**事实** |
| 计算形状 | 序列长度的平方项，矩阵瘦长 | 稠密 GEMM，矩阵方正 |
| 推理时的瓶颈 | **带宽受限** —— KV cache 要反复读 | **算力受限** |
| 长序列时 | 占比迅速上升 | 相对稳定 |
| MoE 改的是谁 | 不是它 | **是它** —— 稀疏化的是 MLP |

一旦读者理解了这张表，后面很多结论就不用死记：

- 为什么长序列推理要盯着显存带宽而不是 TFLOPS
- 为什么 MoE 省的是算力不是显存
- 为什么训练和推理的硬件取舍不一样（训练全是稠密大矩阵，推理是一个 token 一个 token 挤）
- 为什么会有 KV cache、为什么它那么占地方
- 为什么 attention 有那么多变体（MQA/GQA/MLA/线性注意力），而它们**都在省同一样东西**

**反过来，如果先讲硬件再讲模型，上面每一条都变成孤立的结论，只能背。**

### 「智商从哪来」这条要单独展开

这是一个大多数系统课程**完全不讲**的角度，但它恰恰是让人真正理解模型的入口。

- **Attention 负责关联** —— 它决定在当前上下文里该关注什么。
  「自己关注自己」（self-attention）这个名字里就写着答案：
  一句话里的每个词都去看这句话里的其它词，从而知道自己在这里是什么意思。
  能力体现在：指代消解、上下文一致、把远处的信息拉过来。
- **MLP 负责记忆** —— 事实性知识主要存在这里。
  可以理解成一组 key-value：前一层矩阵在做"这是在问什么"的匹配，
  后一层矩阵吐出"那答案是什么"。
  （这个观点有论文支撑，写的时候要把出处找出来补上 —— Geva 等人关于
  FFN 作为 key-value memory 的工作。**待核实原文，不要凭记忆写。**）
- 于是能顺理成章地解释很多现象：
  为什么模型「知道」很多事却「推不动」几步逻辑；
  为什么扩参数量主要是在扩 MLP；
  为什么 MoE 是在扩"记得多少"而不是"想得多深"。

### 对大纲的影响（草记，不定稿）

新的第 0 / 1 部分大概应该是：

```
第 0 部分 · 大模型是什么
  0.1 从一句话预测下一个词说起
  0.2 Transformer 的两个零件：Attention 与 MLP
  0.3 智商从哪来 —— 关联在 Attention，事实在 MLP
  0.4 训练与推理是两件不同的事
  0.5 规模是怎么长起来的：参数量、上下文、MoE

第 1 部分 · 于是它需要什么样的机器
  1.1 把 0.2 的两个零件翻译成算力和带宽的需求
  1.2 Attention 卡带宽，MLP 卡算力 —— 两种瓶颈
  1.3 训练卡吞吐，推理卡延迟
  1.4 单卡装不下：于是需要互联
  1.5 到这里才引出 GPU 和 TPU 各自的答案
```

原来的「脉动阵列 / 为什么 CPU 不够」下沉到 1.5 里，
从"历史叙事"变成"对一个已经提出来的需求的回答"。

- 注意力一族：`flash-attention` `mla` `gated-mla` `swa` `attention-sink`
  `linear-attention` `hybrid-attention` `deltanet` `gdn` `kda` `rope`
- MLP / MoE 一族：`moe` `swiglu` `megablocks` `expert-parallelism` `eplb`
  `latent-moe` `noaux-tc` `mtp`
- 推理：`kv-cache` `static-shape-bucketing` `cuda-graph`
- 并行：`fsdp` `2d-fsdp` `tensor-parallelism` `pipeline-parallelism`
  `context-parallelism` `sequence-parallelism` `tp-pp-cp-ep` `spmd-gspmd`
- 精度：`fp8` `fp4-quantization` `mixed-precision` `qat` `matmul-precision`
- 系统：`xla` `hlo` `jit-xla` `pallas` `mxu` `hbm-vmem` `mfu` `3d-torus`

**这些能直接当课程的参考层用，不用重写。**

### 结论二 · 但入门那一层是**完全空的**

`concepts/` 里**没有任何一页**讲：

- Transformer 整体是怎么运作的
- 为什么「预测下一个词」这件事能长出智能

`Learning/` 那 6 篇（DeepSeek V3 / R1 / V3.2、Kimi Linear、mHC、Engram）
全都**默认你已经懂 Transformer**，它们讲的是"某个模型在标准架构上改了什么"。

> **这正好印证了 08-21 的理念。**
> Chris 要求的起手点（大模型是什么 → 于是需要什么样的机器），
> 恰恰是这堆积累里**唯一没有的部分**。

### 为什么这条线值得当主线

**他的讲法天然就是 Chris 要的顺序。** 从第 5 章到第 7 章，Grant 一路在**数参数**：
嵌入 6.18 亿 → 注意力 580 亿 → MLP 1160 亿 → 正好凑成 1750 亿。

数完之后，硬件需求**自己就浮出来了**，不用我们硬拗过渡：
1750 亿参数光权重就 350 GB，训练加上优化器状态约 2.1 TB，
而 v7 一个 device 只有 94.74 GB。

**「从模型推出硬件需求」这个我们本来以为要原创的枢纽，
3b1b 已经把前半截铺好了 —— 我们要接的是后半截。**

### 三个可以直接改编的桥段

1. **撕掉 AI 回答的剧本** —— LLM 定义的最好入口，比任何定义式讲法都直观
2. **Michael Jordan plays basketball** —— 把「一个事实怎么存进两个矩阵」讲成一个 AND 门：
   升维矩阵某行在问「是不是这个人」，ReLU 变成是/否，降维矩阵对应列把「篮球」加回去
3. **每秒 10 亿次运算要算一亿年** —— 引出硬件需求的震撼锚点

### 一个必须成对出现的修正

第 2 条那个例子**必须紧跟 superposition 讲**，否则误导。
真实模型里单个神经元几乎从不对应一个干净概念 ——
Johnson-Lindenstrauss：允许「近似垂直」而非严格垂直后，
可容纳的方向数随维度指数增长（85 度容差 + GPT-3 的 12,288 维 → 400 亿个以上）。

这同时解释了两件事：模型为什么难解释，以及**为什么放大收益这么大**。
—— 跟 `transformer-circuits` 那边的 superposition 是同一条，两边可以互相印证。
