# 硬件与工具常数

> 出处：2026-08-15/16，Hunyuan3-295B-A21B，64 芯片 TPU v7，MaxText。

## TPU v7 (Ironwood)

| | |
|---|---|
| **2 device / chip** | `tpu7x-128` = **64 芯片**。最常见的规模误判来源 |
| 单 device HBM 上限 | **94.74 GB**（编译器报的 available） |
| 单 device bf16 峰值 | ≈ **1,154 TFLOP/s**（单芯片 2,307 ÷ 2） |
| 频率档 `dvfs_p_state` | 合法 `[0,7]`，**默认 3**，每档约 +2.4%，单调无拐点，7 已顶格 |

**判据**：任何算子报出的 `Model GFLOP/s` **超过 1,154 就是假的**，
不是硬件超频，是那个数来自代码里手写的 `cost_estimate`（`flops = 2*m*k*n`），
它按输出张量的完整形状算，不看实际激活了多少行。

## AOT 的可信度

- **对显存的预测逐位准确。** 两次独立验证：
  一次成功配置（temp 74.95 GiB vs 实测 75.0），
  一次 OOM 配置（**两边都报 `95.51G`**）
- **对时间不可信** —— AOT 没有实测时间，不要用它预测吞吐
- 编译时间：80 层 + `scan_layers=True` 约 3 分钟（CPU，64 核）；
  4 层约 1 分钟。**调配置用 4–8 层，问显存必须用生产层数**

## 单次成本对比

| | 时间 | 卡 |
|---|---|---|
| CPU AOT | ~3 min | **0** |
| 64 芯片真机 | ~6 min | 64 + 排队 |

**结论：任何会改变显存占用或代码路径的改动，先问 AOT。**
