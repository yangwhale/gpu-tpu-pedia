# 02 · 架构：从一行 Python 到一页上线的课

> 这一篇讲整套东西怎么拼起来：有哪些文件、谁产出谁、按什么顺序跑、为什么这么排。
> 读完应该能回答「我要改 X，该去哪个文件」。

## 一、全貌

```
作者写的源（全是 Python）                       产物（WebPages/，GitHub Pages 从这里发布）
─────────────────────────                        ─────────────────────────────────────
tools/topic0N-fig-*.py  ──Fig.save()──▶ tools/fig*.svg ＋ fig*.src.html（出处片段）
        │  数字在脚本里现算 ＋ assert                         │
        │                                                     ▼
tools/manim/topic0N-anim-*.py ──render.sh──▶ WebPages/media/*.mp4（无声循环）
                                                              │
tools/topic0N-build.py  ── BODY 里直接写正文 HTML ──┐          │
   make_head → place_figs(内联 SVG ＋ 图注 ＋ 出处折叠) → add_figonly_toggle
   → finish(查重 → 锚点 → 吸顶目录 → arXiv 链接 → 写盘 → 写盘后断言)
                                                    ▼
                                         WebPages/topic-0N.html        （课件）
                                                    │  讲义脚本读成品课件对账
tools/topic0N-build-lecture.py ─────────────────────▼
                                         WebPages/topic-0N-lecture.html（讲义）
                                                    │
                             build-all.sh 最后跑一整套体检（版面、投屏、对账、指针、元信息、循环接缝）
```

三句话概括：

1. **图和页面分开生成**。每组图一个脚本，产出独立的 SVG；页面脚本只负责把 SVG 内联进来、配图注。
2. **页面是 HTML 直接写在 Python 字符串里**，没有中间格式。HTML 是唯一真源（见 [01 · 三](01-理念.md#三html-是唯一真源)）。
3. **讲义排在课件后面构建**，因为它要读成品课件来对账：讲义里指的图、报的数、说的小节，课件里必须真的有。

## 二、文件分工

### 每一讲自己的文件（以专题五为例）

| 文件 | 干什么 |
|---|---|
| `tools/topic05-build.py` | 课件正文。文件头写主线和核对过的事实；`BODY` 是正文 HTML；`FIGS` 表登记每张图的占位符、文件名、脚本名、图注 |
| `tools/topic05-fig-*.py` | 按小节分组的静态图脚本（`-coll` 集合通信、`-zero` 切数据、`-tp` 切权重……） |
| `tools/manim/topic05-anim-*.py` | Manim 动画场景 |
| `tools/topic05-build-lecture.py` | 讲义。每节一个五元组（标题含分钟、课件锚点、主图、正文、别讲什么）；`PLAN` 时间表；文末一组对账断言 |
| `专题05-并行策略.md` | 大纲和素材落点，不必与页面同步 |

### 全课共用的文件

| 文件 | 干什么 |
|---|---|
| `tools/topic03_draw.py` | **绘图基元库**：`Fig` 类（`header / panel / band / src / box / t / line / path / cell / icon / elbow …`）、配色、字号地板和天花板、保存时的一系列断言。所有专题的图都走它，保证「看起来是同一个人画的」 |
| `tools/topic03_page.py` | **页面脚手架**：`make_head`、`place_figs`、`anchorize`、`build_nav`、只看图开关、查重、`finish` |

| `tools/course_ai_trainer.py` | 每讲开头「把讲义丢给 AI 当助教」那一格的**唯一正本** |
| `tools/topic0N_family.py` | 同一讲几页之间（L200／L300／讲义）的互跳导航；清单只放一处，漏登记就断言失败 |

## 三、构建顺序和为什么这么排

`bash tools/build-all.sh` 大致按这个顺序跑（开着 `set -e`，任何一步非 0 退出就中止）：

1. **专题二 L300**：它是全课 CSS 的来源，其他页面的 `<head>` 从它切出来，所以必须最先。
2. **各专题的图**：`rm -f` 旧 SVG，再用 glob 把该专题所有图脚本跑一遍。
   用 glob 而不是手写清单，理由写在脚本里：
   > 「一份要手工维护的清单」＋「漏了不报错」＝ 一定会漂 …… 是让清单消失。
3. **各专题课件 → 各专题讲义**：讲义要读成品课件，所以永远排在自己那讲的课件后面。
4. **配色收尾**（`topic-repalette.py`）：直接改 `WebPages/` 产物（主色文字降深色、大面板去底色），
   所以必须在所有生成器之后、所有体检之前。
5. **体检套件**：版面、渲染后几何、投屏字号、讲义↔课件对账、跨节指针、讲义覆盖、节号对账、
   退役说法、英文副标题、「丢给 AI」那一格、head 元信息、内联 SVG 标签、动画接缝。
6. 打印产物清单（每页大小、图数）。

两条顺序上的硬约束：

- **图必须先于页面生成。** 页面脚本找不到 SVG 会直接断言失败 —— 这是故意做成硬失败的，
  否则页面会悄悄内联一张旧图。
- **改了图脚本，要重跑图脚本再重跑页面。** 只跑页面，内联进去的还是旧 SVG。

## 四、页面脚手架提供了什么

`topic03_page.py` 让每一讲不用重复造这些轮子：

| 能力 | 说明 |
|---|---|
| `make_head` | 从 L300 切出 `<head>`，替换标题、og 信息，并**断言替换真的发生了**（见 [08 踩坑库 · str.replace 静默失败](08-踩坑库.md)） |
| `place_figs` | 把 SVG 内联进页面；图注按第一个 `<br>` 切开，后半段折叠；`.src.html` 包成默认收起的「出处与口径」；找不到图或占位符就断言失败 |
| `anchorize` | 给小节标题加 id；把正文里的 `§X.Y` 变成页内链接 —— 但跳过引文（arXiv 号、「论文 / 报告 / README / 原文」后面的节号属于别的文档） |
| `build_nav` | 阅读进度条、吸顶目录（从 section 自动生成）、回到顶部、打印前自动展开出处 |
| 只看图开关 | 按 T 切换，收起正文只留图、导语和落点句；状态存 localStorage。投屏时用 |
| `.foldfig` | 整张图可折叠（用于次要的图或术语框） |
| 查重 | 图内文字、图注、正文三方两两比对，连续 14 字重合就报 |
| `finish` | 串起全部体检，写盘 |

## 五、改一处东西，该动哪里

| 我要…… | 改这里 | 然后跑 |
|---|---|---|
| 改一句正文 | `topic0N-build.py` 的 `BODY` | `python3 topic0N-build.py` |
| 改一张图 | 对应的 `topic0N-fig-*.py` | 该图脚本 → `topic0N-build.py` |
| 改一个图注 | `topic0N-build.py` 的 `FIGS` 表 | `python3 topic0N-build.py` |
| 改动画 | `manim/topic0N-anim-*.py` | `render.sh`（见 [04 · Manim](04-绘图.md#四manim-动画)）→ 看拼接图 → 登记基线 → 页面脚本 |
| 改讲义 | `topic0N-build-lecture.py` | `python3 topic0N-build-lecture.py`（必须在课件之后） |
| 改所有图的某种样式 | `topic03_draw.py`（基元） | `bash build-all.sh`，并对比改动前后的布局告警 |
| 新增一讲 | 见 [09 开工清单](09-新专题开工清单.md) | 在 `build-all.sh`、讲义对账表 `PAIRS`、`course_ai_trainer.py` 的 `DECKS`、`WebPages/index.html` 里登记 |

提交前最少跑一次 `bash build-all.sh`，看退出码和末尾的体检输出。
