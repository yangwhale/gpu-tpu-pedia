## 这个专题要回答的一个问题

MLA、GQA、SWA、DSA、NSA、CSA、HCA、DeltaNet、GDN、KDA、Gated MLA……

名词多到像是各搞各的。**但它们其实在解同一道题，而且只有三个旋钮可以拧。**

讲完这个专题，看到任何一个新变体，应该能立刻说出：
**它在拧哪个旋钮、省了什么、赔了什么。**

---

## 一切从长上下文说起 —— 两条独立的动机

**这两条要分开讲。** 它们指向同一批技术，但出发点完全不同，
混在一起讲就变成了名词罗列。

### 线索 A · 硬件账算不过来

上下文一长，**KV cache 就爆**。

它的增长是双重的：**随序列长度线性增长，又随层数线性增长**。
而且它跟参数不一样 —— **参数是固定的一次性开销，KV cache 是随用户输入长度涨的**。

这一节要用具体数字砸出体感：

- 标准 MHA，128K 上下文，一个 61 层的模型，KV cache 多少 GB？
- 对照：模型权重多少？**发现 KV cache 可以比权重还大**
- 再对照一块卡的 HBM
- 推理场景更狠：**并发用户越多，KV cache 线性叠加**，它直接决定你能服务多少人

> 这一条是**工程账**：不解决它，长上下文根本上不了线。

### 线索 B · 信息本身不需要那么多

这条更有意思，也更少被讲。

**一个 128K 的序列，真的需要 128K 份独立的 KV 吗？**

几个可以摆出来的观察：

- **注意力矩阵实测是极其稀疏的** —— 绝大部分权重集中在很少的位置上，
  剩下的近乎为零。那么把那些近零的算出来，算的是什么？
- **Attention sink** —— 模型会把大量注意力"停放"在序列最开头的几个 token 上，
  跟内容无关。这说明注意力权重里有一部分根本不是在做检索
- **远近有别** —— 邻近几十个 token 的关注是密集、细粒度的；
  几万 token 之外的关注是稀疏、粗粒度的。
  **凭什么用同一套精度去处理这两种？**
- 于是：**压缩**（远处的多个 token 合并成一个）、
  **稀疏**（只挑相关的看）、**分层**（近处精细远处粗糙）都变得合理

> 这一条是**信息账**：即使显存无限，把全部算力花在一个高度冗余的矩阵上也是浪费。

**两条线的关系**：A 说「必须省」，B 说「可以省而不太亏」。
**所有变体都活在这两条线的交汇处。**

---

## 分类学：只有三个旋钮

这是这个专题的骨架。把所有名词收进一张表：

| 旋钮 | 在改什么 | 代表 |
|---|---|---|
| **① 每个 token 存多少** | 减少 KV 的**份数**或**维度** | MQA → GQA → **MLA** |
| **② 每个 query 看多少** | 限制**范围**或**动态挑选** | **SWA** · NSA · **DSA** · **CSA** |
| **③ 换一套数学** | 用**固定大小的状态**代替不断变长的 KV | 线性注意力：DeltaNet → **GDN** → **KDA** |
| **①+②+③ 混着来** | 不同层用不同方案 | **Hybrid** · V4 的 **CSA + HCA** |

> ⭐ **前两个旋钮省的是同一样东西的两个不同侧面**：
> 旋钮 ① 让每份 KV 更小，旋钮 ② 让读的份数更少。**它们可以叠加。**
>
> ⭐ **旋钮 ③ 是换赛道**：它不再有"随长度增长的 KV"这个概念，
> 代价是把无损的检索换成了有损的状态压缩。

## 逐支展开

### 支线 ① · 把每份 KV 做小

**MHA → MQA → GQA**
- 多头各存一份 K/V → 所有头共用一份 → 分组共用
- 省得很直接，但**质量掉**，因为表达能力被砍了

**MLA（DeepSeek V2/V3）**
- 不砍头，改成**低秩压缩**：KV 压成一个 512 维隐向量，用的时候再升回 128 头
- 位置信息单独走 64 维一路 RoPE —— **为什么必须分开走**，这是理解 MLA 的关键一步
- 每 token 每层只存 **512 + 64 = 576** 个数
- 代价：**用计算换显存**（多了升降维的矩阵乘）
- ⚠️ 落到硬件上有个反直觉的后果：MLA 在推理时可以"吸收"投影矩阵改变计算形状，
  **同一个数学式子有多种算法实现，选哪种取决于是 prefill 还是 decode**

**Gated MLA**
- 在解压缩端加门控，按 head 粒度动态选择要不要激活
- K3、Ling V3 采用

### 支线 ② · 少看一点

**SWA（滑动窗口）**
- 每个 token 只看自己前面固定窗口内的
- 最简单，但**长距离信息只能靠层层传递间接到达**
- 所以一般不单用，跟全注意力混排

**Attention sink**
- 不是一种方案，是一个**现象**，但它解释了为什么朴素的窗口裁剪会崩
- —— 你把开头几个 token 扔了，模型就坏了

**NSA（Native Sparse Attention）**
- 三条支路并行：压缩 / 选择 / 滑窗，然后融合
- 「native」的意思是**训练时就这么做**，不是训练完再加的推理优化。
  这个区别很重要，值得单独说

**DSA（DeepSeek V3.2）**
- **Lightning Indexer**：一个轻量的 MQA 打分网络，为每个 query 挑 top-K（默认 2048）个 KV
- 128K 上下文下，参与 attention 的从 128K 降到 2K —— **64 倍**
- 复杂度从 O(n²) 变成 O(n·k)
- 我们**有一手实测材料**（`tpu/` 下 DSA 相关项目）

**CSA + HCA（DeepSeek V4）**
- **CSA**（Compressed Sparse Attention）：每 4 个 token 压成 1 个 KV entry，
  再用 Lightning Indexer 挑 top-1024 个 block
- **HCA**（Heavily Compressed Attention）：每 128 个 token 压成 1 个，然后**密集**注意力
- 两者混用 → 支持 1M 上下文
- ⭐ **这正是线索 B「远近有别」的最直接体现**：
  近处用轻压缩 + 稀疏挑选，远处用重压缩 + 全看。
  **压缩率和稀疏度按距离分层配置。**

### 支线 ③ · 换一套数学：线性注意力

**核心思想**
- 把 softmax attention 改写成 RNN 形式：维护一个**固定大小的状态**，
  逐 token 更新
- 复杂度 O(n²) → O(n·d²)，而且**没有随长度增长的 KV cache**
- 代价：状态大小固定 → **信息必然有损**，长程精确检索会力不从心

**演进**
- **DeltaNet**（2024）：引入 delta rule，把状态更新变成「擦除旧的 + 写入新的」
- **GDN**（2024-11）：加 per-token 遗忘门，解决 DeltaNet 记住陈年旧事的问题
- **KDA**（Moonshot 2026-02）：遗忘门从标量升级为 per-channel 向量 ——
  不同通道能学出不同的遗忘速度

**硬件视角**（这一段是我们的角度）
- 状态更新天然是**串行**的 → 靠 chunk 化恢复并行度
- kernel 实现难度远高于标准 attention —— 我们在 TPU 上写过 KDA kernel，有实战

### 支线 ④ · 混合

- 几层线性配一层全注意力；或几层 SWA 配一层全局
- **为什么混合有效**：全局层负责精确长程检索，线性/窗口层负责局部，各司其职
- 配比是个超参 —— K3 是 KDA 与 Gated MLA **3:1**

## 代价：没有免费的午餐

一张表把所有方案摆在一起对比，纵轴：

| | KV 显存 | 计算量 | 长程质量 | kernel 复杂度 | 训练兼容性 |
|---|---|---|---|---|---|
| MHA | 基准 | 基准 | 基准 | 简单 | — |
| GQA | ↓↓ | — | ↓ | 简单 | 好 |
| MLA | ↓↓↓ | ↑ | ≈ | 中 | 好 |
| SWA | ↓↓↓ | ↓↓ | ↓↓↓ | 简单 | 好 |
| DSA | ↓ | ↓↓↓ | ≈ | **高** | 需要专门训练 |
| 线性 | **无 KV** | ↓↓↓ | ↓↓ | **很高** | 需要从头训 |

要讲透的三个取舍：

1. **省显存 ≠ 省计算。** MLA 省了显存但增加了计算；DSA 省了计算但 KV 还在那儿
2. **训练时省和推理时省是两回事。** 有的方案只能推理时用，有的必须训练时就采用
3. **不规则访存的代价常常被低估。** 稀疏方案在纸面上是 64 倍，
   落到硬件上是 gather、是不连续访问、是 kernel 难写 ——
   **实际加速比远小于理论值**。这一点我们有实测可以摆

## 落到硬件（本专题的落点）

回到全课那条主线：**每一个变体都是被硬件逼出来的，也都对硬件提出了新要求。**

- MLA 用计算换显存 → 前提是**算力相对充裕、显存相对紧张**。
  这个前提在什么硬件上成立？不成立的时候呢？
- 稀疏注意力要 gather → **对规整访存友好的加速器反而吃亏**
- 线性注意力状态串行 → chunk 并行，chunk 大小又是个跟片上内存相关的选择
- MoE + 长上下文一起上 → all-to-all 与 KV cache 抢的是同一份 HBM 带宽

> **一句话收尾**：注意力的变体史，就是一部「在显存、算力、访存规整度三者之间反复搬家」的历史。
