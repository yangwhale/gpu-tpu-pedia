# 12 · 翻译成英文：把一讲中文课做成英文版

> 一讲中文课（课件 ＋ 讲义）已经定稿、上过台，这一篇讲怎么把它做成**英文版**：
> 不是机器翻译，是让一位懂行的英文作者**按同样的事实、同样的图、同样的版面重写一遍**。
>
> 它是 2026-10-17 一天一夜做专题一到五英文版的总结。每一讲走的是同一条流水线：
> 切块 → 并行写作 → 十一轮单维度评审 → 中英并排终审 → 讲义两轮 → 回头修中文源 → 同步 → 发布。
> 规范和工具都在 [`i18n/`](../i18n/)：`STYLE.md`（文风与 HTML／SVG 硬规则）、`GLOSSARY.md`（术语表）、
> `AGENT-PROMPT.md`（写作任务书）、`REVIEW-PLAN-topic-0N.md`（各轮维度）、`ISSUES-topic-0N.md`（翻译时查出的中文问题）、`tools/`。
>
> 一句话：**英文版是中文版的第二次严格通读。** 每一讲翻下来都查出几十条中文自己的错
> （专题一 58 条、专题二 54 条、专题三 92 条），比任何一轮中文评审都多。

## 一、原则

### 1. 重写，不逐字译

标准：NVIDIA、Google 或前沿实验室的资深工程师读完，**看不出它原来是中文**。文风对标 *How to Scale Your Model*、Stanford CS336 讲义这一类：短句、陈述、第二人称、用数字和原因说话。

中文是**事实、数字、结构、图**的唯一真源，**不是措辞、语序、修辞**的真源。中文的修辞残片、成串破折号、到处是「算账」、讲汉字字源的双关（「束」字抓到了重点），在英文里一律改写或删掉（对照表见 `STYLE.md` §2）。

⛔ 直译出的英文惯用语会读错意思。专题三收尾「把开场那把枪打响」（契诃夫之枪）被译成 *the opening gun*，英文里那是「发令枪」。冷读轮才抓到，改成 *the cover's gun goes off*。

### 2. 只翻主线，只翻定稿

- 每个专题**只翻一份课件（L200）＋ 一份讲义**。L300 档案版、外传、显微镜、brief 都不翻；讲课录音和视频也不做（`split.py` 切块时直接去掉）。
- **英文页不许链去任何纯中文页**：英文读者点进去是一墙中文。`assemble.py` 拼页时自动处理：有英文版的链到英文版，没有的去掉链接留文字，整颗跳转按钮直接删。
- **还在迭代的专题先不翻**。中文还在改，英文就得跟着同步，每改一次多一轮工。专题六当时还在逐节加内容，就没进这一批。

### 3. 版面「一眼看去一样」

作者的要求：中文版是多轮美化后的定稿，**翻译不能改掉它的样子** —— 大小、配色、位置、组织方式、图文比例，一眼看过去要一样。

最大的坑是**字量**。讲课时折叠全收，观众看到的是图加图之间那几行字（「默认可见层」）。同字号下一个英文字符约 0.55 em，所以**可见层英文字符数超过中文的 1.9 倍，屏幕上就比中文挤**。
专题二初稿可见层是中文的 2.1–2.8 倍，作者一眼看出「字太多」，于是插入了专门压可见层的一轮（R6），之后每一轮都守着 ≤1.9。

### 4. 讲义过时，跟课件走

中文讲义和课件 HTML 里的静态数常常过时：专题一页面上写死「5.5 张卡／10%」，脚本加载后按 GiB 口径实算是 5.2／9%。
判据：**英文一律以课件渲染后的实算值为准**（JS 覆盖之后的值，不是 HTML 里的占位初值）。讲义跟中文讲义对不上课件时，英文跟课件，中文原句记进 NOTES。
比法：同一页开、关 JS 各取一次 `[data-v]` 文本。

### 5. 不增不减事实；中文的错记下来，回中文源修

- 不许加中文里没有的事实、出处、数字；也不许丢任何事实、数字、限定语、出处。英文可以比直译短，那是好事。
- **译者不许悄悄改中文的错。** 发现了照原样翻，同时写进本块的 `NOTES-NN.md`；协调者汇总进 `i18n/ISSUES-topic-NN.md`。
- 作者授权后，**在中文的源脚本里改**（`tools/topic0N-*.py`，页面是生成的，不手改 HTML），重建，再把改动同步进英文（第二节阶段 E）。英文自己先改对了的，中文照着英文的改法修。

查出来的错大致五类，下一讲翻译时可以照着找：
- **写死的结论配实时的数**：参数一调，旁边的数变了，结论还在说原来那句。
- **数目对不上**：「三条边界」列了四条、「七个追问」写了八个。
- **引号里的话不是原话**：一位研究者博客的转述被加了引号像原文；转述的论文结论被标成「原话」。
- **口径混用**：同页 GiB 和 GB 混写、chip 和 device 混写 —— 专题五一处「每颗芯片」其实是「每张卡」，阈值差两倍。
- **过时的指向**：「下一小节」「右下角那把尺子」，指的东西已经挪走或删掉了。

## 二、流水线：每一轮查一个维度

原则同 [06 评审与迭代](06-评审与迭代.md)：**一轮只查一个之前没查过的维度**，「全面再看一遍」查不出东西。第二轮起以删为主，词数只降不升。

### 阶段 A · 切块

```bash
cd Courses/i18n/tools
python3 split.py topic-0N $W/chunks          # 产出 skeleton.html ＋ NN.zh.html
python3 zhref.py $W/chunks $W/zh-ref.html    # 中文按英文同一条流水线拼一份对照页（版面对比用）
```

- 按 `<section>` 切，超过 `MAX_CJK` 个汉字的节再按 `<h3>` 切。专题三切成 8 块（讲义 9 块）。
- `skeleton.html` 留着 `<head>`、CSS、`<script>`，译者只拿正文块。
- 工作区结构见第六节。所有工具靠环境变量 `I18N_WORK=$W I18N_TOPIC=topic-0N` 切换专题。

### 阶段 B · R0 并行写作

每块一个 agent，任务书照 `AGENT-PROMPT.md` 改：讲清这一讲的主线、先读 `STYLE.md` 和 `GLOSSARY.md`、对照已上线的英文专题统一口吻和术语。

- **共享术语表 `TERMS.md`**：开工前协调者写好节标题和贯穿比方的固定译法（专题三：「记事板」→ *notepad*，绝不用 *scratchpad*，免得撞片上 SRAM 的术语）；译者造了新的常用词就用 `cat >>` 追加，八个人并行也不各叫各的。
- **结构一字不动**：只译文本节点和 `title／alt／aria-label／placeholder`。大块用脚本做「中文原串 → 英文」的精确替换，不手敲 SVG 几何。
- **小批量干活**：每次工具调用译百来段就存盘。⛔ 专题二 8 个写作 agent 里 3 个一次吐巨型输出，被 10 分钟看门狗判卡死。
- 自查到过关为止：`check.py NN.zh.html NN.en.html --render`。

### 阶段 C · 课件十一轮 ＋ 并排终审

| 轮 | 查什么 | 过关判据 | 工具 |
|---|---|---|---|
| R1 | 逐句保真（全量，不抽查）：漏掉的分句、丢掉或加上的限定语、比较方向反了、数字挂错对象 | 每句中文的主张在英文里强度、范围、因果方向都一样 | 人工逐段配对 |
| R2 | 数字与单位：逐个配对，**不看结论先独立复算**每个推出来的数 | 值和精度一致；亿／万换算精确；MiB／MB 照抄中文；「B」不会被同时读成字节和十亿 | `check.py` 数字对账 ＋ 人工 |
| R3 | 英文出处与官方名：引号里的话找原文替换回译；模型名、方法名、config 字段名、论文标题、arXiv 号逐个核 | 直接引语逐字对上原文；找不到原文就去掉引号改成转述 | 联网读原文、本地源码 grep |
| R4 | 母语流畅度第二遍，换人设（技术出版社编辑）：先只读英文标记，再回看中文 | 标题像英文标题；没有生造缩写；同一种强调手法不滥用 | 人工 |
| R5 | 淬炼：删复述图注的句子、合并重复、压句子 | 正文词数降 10–15%，图内词数不升，不丢事实 | `wc.py` |
| R6 | 默认可见层字量 | 每块可见层 en/zh 字符比 ≤ 1.9 | `visible.py NN` |
| R7 | 逐图截图目检（中英同图对看） | 每个标签一眼能解；不压框、不撞字；视觉分量和中文相当 | `figidx.py N`、check 白名单 |
| R8 | 版面对齐：计算样式逐元素比 ＋ 锚点对齐的中英并排切片（桌面、手机） | 计算样式 0 差异；行数跟中文一样（±0）；只许比中文短 | `layout.py`、`sbs.py 1280／390`、`chunkview.py` |
| R9 | **全页闭环，只派一个 agent**：每个「Section N／§n.m／Figure／面板 Ⓐ」都找得到；跨块一物一名；交互文案；点开关、点测验 | 页内引用全通；控制台无错、DOM 无中文 | `assemble.py` 私有拼页、`dom.py` |
| R10 | 冷读：目标读者（母语资深工程师）从没见过这门课，折叠全收读一遍、全展开再读一遍，然后用自己的话回答这一讲的五个核心问题 | 五问都答得出；答不出的指出是页面哪里没讲到 | 人工 |
| R11 | 图内字号统一 ＋ 修碰撞（这一轮才许动几何） | 达到第三节的字号标准；`overlap.py` 英文新增碰撞 0 | `overlap.py`、`boxfit.py`、`figidx.py` |
| PAR | 中英并排终审：作者看过上线版后再提「一眼看去要一样」，按当前这一对重新切片、修 | 图内字不比中文小、不挤；标题按钮不比中文多折行；手机上表格关键列不被挤出屏幕；**折叠模式也要看一遍** | `sbs.py`、`chunkview.py` |

每轮的固定动作：先备份要改的块（`NN.en.R3bak`）→ 改 → 全部块过 `check.py --render` → 写日志 `rounds/LOG-<轮>-<块>.md` → 整轮快照进 `rounds/Rn/`。

几条轮次设计的来由：
- **R6、R8 是作者中途插进来的**，不是一开始就想到的。字量和版面不单列一轮，前面几轮都不会去管。
- **R3 不能省。** 写作 agent 会把中文转述的英文名句「回译」成自己的英文。专题三这一轮把多处回译换回了原文（《Attention Is All You Need》§3.2.1 那句补回 *of 1/√d_k*，一篇博客的 *Power Washer* 被回译成 *pressure washer*）。
- **R9 只派一个 agent**，因为跨块一致性只有看得到全页的人能管。

结果（专题二）：正文词数 36.4K → 28.6K（−21%），可见层 2.1–2.8 → 1.87，计算样式 0 差异，页高桌面 0.98×、手机 0.97×，新增文字重叠 0。专题三页高 0.99×／0.97×。

### 阶段 D · 讲义两轮

讲义**等课件英文定稿后再翻**：讲义里引的每个屏幕上的字、图标题、数字，都要跟英文课件逐字一致。先照课件那套任务书写出初稿，再走两轮：

| 轮 | 做什么 | 判据 |
|---|---|---|
| L-R1 | 保真 → 屏幕引文和数字对英文课件（grep 定稿页）→ 讲稿逐句念一遍（一句一口气）→ 压缩 → 跨块标签统一 | 讲义里写的内部图 id 改成观众看得见的图标题；可见字符比从 2.6–2.8 压到 ≤ 2.4 |
| L-R2 | 第二次压缩 ＋ 一致性：先砍讲师备注、舞台提示、「别讲什么」、节奏、备答，最后才动台词 | 每块 ≤ 2.30；台词外面不套引号；标签全课统一 |

讲义的标尺是**页高**：专题三英文讲义初稿比中文高 18%（桌面）／22%（手机），两轮后 +5.2%／+7.1%；专题一 +5.9%／+10.5%。

### 阶段 E · 修中文源，再同步英文

1. 一个 agent 按 `ISSUES-topic-0N.md` 改中文源脚本，每条前面标 ✅（或 ⏭ ＋ 一句理由），日志记「条目 → 文件 → 旧 → 新」。只跑自己这一讲需要的构建步骤（见第五节）。
2. 改完把**新旧两份中文页按同一切法**各切一遍：`SPLIT_SRC=<页面> MAX_CJK=<和当初同一个值> python3 split.py ...`，块边界才能和英文块一一对上；逐块出 unified diff。
3. 同步 agent 逐个 hunk 归类：
   - **a** 英文已经改过 → 不动；
   - **b** 文字、数字、事实的改动英文还没有 → 用地道英文移植；
   - **c** 纯几何改动 → **不抄中文坐标**（英文的图是单独调过的）；但中文增删或调换了 SVG 元素，英文要跟着改结构，标签序列必须一致。
4. **先**把新中文块拷进英文工作区覆盖旧的 `NN.zh.html`，**再**跑 `check.py` —— 否则对的是旧中文。

### 阶段 F · 拼页与发布

```bash
python3 assemble.py topic-0N $W/chunks       # → WebPages/topic-0N.en.html
python3 overlap.py $W/zh-ref.html ../../WebPages/topic-0N.en.html   # new in en 应为 0
python3 dom.py /abs/path/topic-0N.en.html     # 控制台错误 ＋ DOM 残留中文
```

`assemble.py` 做的事：去掉指向纯中文页的链接；内嵌 Source Sans 3 字体；注入「折叠讲解」开关（英文默认折叠）；加 🌐 中文 按钮；手机端表头可换行；去重图号；残留的 `**…**` 转粗体。

发布清单：
- [ ] 中文课件、讲义加 🌐 English 按钮 —— **写进中文的构建脚本**（例：`topic03-build-L200.py`），不手改生成的 HTML
- [ ] `WebPages/index.en.html` 挂卡片；中文总纲加入口
- [ ] 公开仓库闸门过一遍（第五节最后一条）
- [ ] 提交、推送。GitHub Pages 是 legacy build，推送后不一定自动刷新：`gh api -X POST repos/<owner>/<repo>/pages/builds` 手动触发，等一两分钟
- [ ] `curl -sI <站点>/Courses/WebPages/topic-0N.en.html` 看到 200，再 `curl -s … | grep -c '<一个刚改的英文短语>'` 确认是新版本

## 三、图内英文字的标准

**一句话：放不下先缩短英文，不许往小里缩。**

- **字体：拉丁无衬线，不用等宽。** 中文图的文字类名写的是等宽，可汉字落回了无衬线；英文整串等宽，看着像代码。专题三起图内文字类改用内嵌的 Source Sans 3，加 `font-size-adjust: 0.53`（同 px 下拉丁字看着比中文小，这样补大约 9%）。由 `assemble.py` 里该专题 `HEAD` 表的 `fsa` 开关控制；专题一二开了之后多出几处碰撞，逐图复核修完才打开。
- **字号**（`STYLE.md`「图内英文字号规范」）：图标题、分区标题约 14px，最大 15px；正文标签 13.5px；小字 11.5px；**最小 11px**（等宽数字 10.5px）。中文图自带大字号的（专题三常见 15–27px），按中文字号的 1.0–1.1 倍，不低于 85%，图标题不超过中文 × 1.1。
- **同级同号**：成对的标题（A／B、①②③、左右两栏、列头、图例项）在一张图里必须一样大。⛔ 专题一并排审时，作者指出图内字忽大忽小：早期的自动放大工具把少数标题放到了 17.4px，同一张图里别的字没跟着放。
- **改字号只能用内联 `style="font-size:…"`**：类 CSS（`.lbl{font:…}`）会盖掉 `font-size=` 属性，写了等于没写。
- **宽度闸门**：`check.py --render` 在浏览器里量每个 SVG 文字，英文宽度超过中文 108% 就报。目检确认不压框、不撞字（离边框、箭头、别的字 ≥ 4px）的，连同理由登记进 `rounds/ACCEPTED-WIDTH.md` 白名单（`tools/accept.py NN "理由"` 把这一块当前报的全部追加进去，所以要先逐个看过渲染再跑）。
- ⚠️ `check.py` 是在块自己的 CSS（等宽）里量宽度的，而上线页用的是 Source Sans ＋ fsa：**它的结论偏保守**，别为了过闸把字缩过头。
- **几何默认锁死**：`check.py` 要求 SVG 几何属性一字不差。只在 R11、并排终审、同步这几轮用 `I18N_GEOM_FREE=x,y,width,height,…` 放开，并且每处移动都写进日志（图、元素、旧 → 新）。
- **字号放大的基准是放大前的快照**，不是当前值。⛔ 早期 `svgfit.py` 拿当前字号当基准，一列字跑三遍放到原来的两倍多（R11 抓到）；现在基准取 `rounds/prefit/`。
- **JS 画的图**要在全部参数组合下（序列 512／4K／128K／1M × batch 1／8／64 × 三种精度）都不溢出、不重叠。

## 四、并行 agent 的协调纪律

一讲课件八块、十一轮，每轮五六个 agent 并行；讲义、修中文、下一讲的写作可能同时在跑。下面每条都是撞过之后补的。

- **块归属**：每个 agent 只改分给它的 `NN.en.html`。中文问题只在回复里列出，**追加进 `ISSUES` 是协调者的事** —— 几个人同时往一个文件里追加会互相盖掉。
- **临时文件放自己的子目录**（`$W/w-<轮>-<块>/`）。专题三的工作区根目录堆了上百个 `_ed06.py`、`r5_07b.py` 这类脚本，名字随时可能撞；专题四起写进了公共任务书。
- **前一轮还在改的块，下一轮不许开工。** 跨轮要做的事（统一某个译法、某块要同步一处中文改动）记进协调者的待办 `COORD-TODO.md`，写明「R6 之后做」「R9 之后做」，到点再派。
- **别让 agent 读太多截图。** 一次请求里塞的图片超过上限（30 MB），整个会话直接崩掉 —— 专题四 R8 有一组就这样中途死掉，重派时改成先用行数测量找出差异点、只看那几处（≤ 20 张）。并排切片按块分给多个 agent，每人只读自己的范围。另外，整页截图太高时，Chromium 截出来的下半截是空白（专题四 1280 宽有四十几张切片是白的），那一段改用 `chunkview.py` 按块截。
- **单个 agent 说「不存在」，不能直接信。** ⛔ 专题四 R3 的 agent 在本地一份 fork 的 MaxText 里没搜到 `xent_sum`，就把出处注里的「loss ＝ xent_sum ÷ total_weights」改成了 `sum(xent)`；上游主干的 `gradient_accumulation.py` 里明明有。协调者改了回来。判据：「X 不存在」要对着**上游主干**核，最好两个来源。
- **撤回要写在下一轮会读的地方。** ⛔ 接着 R4 的 agent 读了 R3 的日志，以为那处修改「丢了」，又改了一遍。之后的做法：撤回的同时，在原日志那一条下面写 `CORRECTION（协调者）：……已撤回，不要再改`。
- **跨块漂移，靠协调者统一一遍。** 每块各压各的，同一句套话会被压成好几种样子：专题五十支动画下面那行说明（「Manim 渲染，默认自动播放，取消勾选可单步」）在不同块里被压成了好几种写法；R8 为了手机上不折行把一个节标题改成「Second cut: weights」，其余节标题、目录、术语表、讲义里的引用就得一起改成短式。这类事放在 R9 前后，由一个人全页 grep 一次改完。
- **一份公共任务书 ＋ 每轮一份短任务书。** `ROUND-COMMON.md` 写硬规则（只改自己的块、结构不动、过 `check.py`、小批量、日志位置、中文问题怎么报）；`R1.md`…`R11.md` 只写这一轮的维度和判据，派活时填上 `{chunks}`。下一讲把专题名、路径替换一遍就能复用。
